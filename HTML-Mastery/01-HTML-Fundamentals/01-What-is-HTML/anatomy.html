Anatomy of an HTML Document

Every HTML page on the web is built from the same five ingredients: tags, elements, attributes, content, and comments. Let's dissect one.

1 The Five Ingredients

HTML is made of five kinds of text:

1. Tags

Keywords wrapped in angle brackets — <p>, <h1>, <a>.

2. Elements

A complete tag, its content, and its closing tag — <p>Hello</p>.

3. Attributes

Name="value" pairs on a tag — href="...", class="...".

4. Content

The text or nested elements between the opening and closing tags.

5. Comments

Notes for developers, ignored by browsers — <!-- ... -->.

+ Document Prolog

The <!DOCTYPE html> declaration at the very top.

3 Tags

A tag is the angle-bracket-wrapped keyword that tells the browser "this is an element of type X". Tags come in three flavours:

TypeFormExamples
Opening tag<name><p>, <div>, <a>
Closing tag</name></p>, </div>, </a>
Self-closing / void<name> (no closing tag)<br>, <img>, <input>
 
<p>             ← opening tag
Hello world       ← content
</p>            ← closing tag

<br>             ← void element (no content, no closing tag)
<img src="x">   ← void element with an attribute
Common Mistake <p> is a tag. <p>Hello</p> is an element. Don't use the terms interchangeably. A tag is the markup; an element is the whole unit including content.

4 Elements

An element is the complete unit: opening tag + content + closing tag. Some elements have no content (void elements like <br>); most do.

<p>Hello world!</p>
└┬┘ └────┬────┘ └┬┘
 │      │       │
 │      │       └─ closing tag
 │      │
 │      └─ content
 │
 └─ opening tag
Together: the <p> element

Elements can be nested — one inside another:

<article>
  <h2>Post Title</h2>
  <p>Body paragraph.</p>
</article>

The <article> element contains an <h2> element and a <p> element as children. This nesting creates a tree — the DOM.

5 Attributes

An attribute is a name="value" pair on an opening tag that configures the element. They appear after the tag name, separated by spaces.

<a href="https://example.com" target="_blank" rel="noopener">Link</a>
    └─┬─┘ └────────┬─────────┘ └──┬──┘ └────┬────┘
      │            │              │         │
      │            │              │         └─ third attribute
      │            │              └─ second attribute
      │            └─ first attribute value
      └─ first attribute name

Attribute rules

  • Names are case-insensitive, but lowercase is the convention.
  • Values should be quoted with double (") or single (') quotes. Unquoted is allowed but fragile.
  • Boolean attributes like disabled or checked may have no value: <input disabled> is the same as <input disabled="disabled">.
  • Order doesn't matter: href="x" class="y" equals class="y" href="x".
  • Some attributes are global (id, class) — work on every element. Others are element-specific (href only on <a>).

6 Content

Content is everything between the opening and closing tags. It can be:

  • Text: <p>Hello!</p>
  • Other elements: <div><p>Hi</p></div>
  • Empty: <div></div> — still a valid element
  • Entities: <p>5 &lt; 10</p> renders as "5 < 10"

HTML entities

Certain characters are special in HTML — <, >, &, ", ' — and must be escaped with entities when used as content:

CharacterEntityWhen to use
<&lt;Whenever you want a literal < in text
>&gt;Literal >
&&amp;Literal &
"&quot;Inside an attribute value quoted with "
'&apos;Inside an attribute value quoted with '
non-breaking space&nbsp;Prevents line wrap at this point
©&copy;Copyright symbol
—&mdash;Em dash
→&rarr;Right arrow
Common Mistake Typing 5 < 10 directly in HTML may work in some browsers (they recover), but it's invalid. The < starts a tag. Always write 5 &lt; 10.

7 Comments

Comments are notes for developers. They are ignored by the browser when rendering, but visible in "View Source". They cannot be nested.

<!-- This is a single-line comment -->

<!--
  This is a multi-line comment.
  Useful for explaining a complex block.
  Note: you cannot put --> inside a comment.
-->

<p>Hello</p> <!-- inline comment after a paragraph -->
Pro Tip Use comments to mark sections in long documents — <!-- ===== Navigation ===== --> makes skimming much easier. But don't over-comment obvious code; it becomes noise.
Common Mistake Comments are not secure. They appear in the page source. Don't put secrets, API keys, or rude notes about clients in HTML comments. They are public.

8 Parts of a Document

Every HTML document follows this skeleton:

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>...</title>
    <meta name="description" content="...">
    <link rel="stylesheet" href="style.css">
  </head>
  <body>
    <!-- all visible content -->
    <script src="app.js"></script>
  </body>
</html>
PartPurposeVisible?
<!DOCTYPE html>Activates standards modeNo
<html>Root element of the documentNo
<head>Metadata: title, charset, links to CSS/JSNo
<body>All visible contentYes

9 Case Sensitivity

HTML is case-insensitive for tag and attribute names. <P>, <p>, and <P> are all the same tag. However, the convention — universally — is lowercase.

Attribute values, however, can be case-sensitive. class="Card" and class="card" are different classes. URLs are usually case-sensitive too. Entity names like &copy; are case-sensitive (capitalised &COPY; is invalid).

Common Mistake Don't write <DIV CLASS="foo">. It works, but it's an XHTML/legacy habit. Use lowercase everywhere. The one exception is the doctype, which is conventionally <!DOCTYPE html> — though <!doctype html> also works.
Try it yourself — 5 minutes Recreate the annotated example from memory. Then:
  1. Add a new <p> with the text "HTML is fun!" and a class of intro.
  2. Add a comment above it: <!-- intro paragraph -->
  3. View the page in your browser — the comment should be invisible.
  4. View Source (right-click → View Page Source) — the comment should be visible in the source.
