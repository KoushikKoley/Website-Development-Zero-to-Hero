What Is HTML?

1 Learning Objectives

By the end of this sub-section you will be able to:

  • Define HTML in one clear sentence and explain its role on the web.
  • Describe the major milestones in HTML's history (1989 → HTML5 → Living Standard).
  • Explain the difference between HTML, CSS, and JavaScript at a high level.
  • Identify the four core building blocks of every HTML document: tags, elements, attributes, and content.
  • Read a complete HTML document and explain what each part does.
  • Distinguish between the WHATWG Living Standard and the legacy W3C versioning system.
Pro Tip Before reading the other files in this folder, write down your own one-sentence definition of HTML. After you finish, rewrite it. The before/after contrast is a powerful learning signal.

3 Section Summary

HTML stands for HyperText Markup Language. It is the standard markup language for documents on the World Wide Web. HTML describes the structure and meaning (semantics) of web content — what is a heading, what is a paragraph, what is a link, what is an image — leaving the visual styling to CSS and the interactivity to JavaScript.

HTML is:

  • A markup language, not a programming language. There are no loops, no variables, no conditionals in HTML. It's a way to label parts of a document.
  • Declarative. You describe what the page should look like, not how to build it.
  • Forgiving. Browsers are designed to render almost any input without crashing. This is both a blessing (quick to learn) and a curse (easy to write invalid code).
  • Living. Since 2019, HTML has no version numbers in the spec — it is continually updated as the WHATWG Living Standard.
Common Mistake Don't think of HTML as "programming". If you approach it expecting loops and functions, you'll be confused. Think of HTML as writing a structured document — like an outline for a book — that the browser turns into an interactive page.

4 Quick Definitions

TermDefinition
HTMLThe markup language of the web.
TagA keyword wrapped in angle brackets: <p>, <h1>, <a>.
ElementA tag plus its content and any closing tag: <p>Hello</p>.
AttributeExtra info on a tag, in name="value" pairs: <a href="...">.
DocumentOne .html file — the complete unit a browser loads.
DOMDocument Object Model — the tree of elements the browser builds from your HTML.
WHATWGWeb Hypertext Application Technology Working Group — maintains HTML today.
W3CWorld Wide Web Consortium — original standards body, now defers to WHATWG for HTML.
MDNMozilla Developer Network — the best HTML reference on the web.

5 HTML vs Other Web Technologies

Three core languages make up the front-end web. They have distinct, complementary roles:

LanguageRoleAnalogy
HTMLStructure & meaningThe skeleton and organs of a body
CSSStyle & layoutThe skin, clothes, makeup
JavaScriptBehaviour & interactivityThe muscles and nervous system
 
<!-- HTML gives the page its structure -->
<article>
  <h1>My First Blog Post</h1>
  <p>This is the content.</p>
  <button>Like</button>
</article>

/* CSS would style it: */
article { max-width: 600px; margin: 0 auto; }
h1 { color: navy; }

// JavaScript would make it interactive:
document.querySelector('button').addEventListener('click', () => {
  alert('Thanks for liking!');
});
Pro Tip Learn HTML thoroughly before touching CSS or JavaScript. Trying to learn all three at once is the most common reason beginners quit. Master the foundation first.

6 How Browsers Read HTML

When you point a browser at an HTML file, the following happens in roughly 50 milliseconds:

  1. Fetch — the browser downloads the .html file over HTTP.
  2. Parse — the browser reads the raw bytes, decodes them as text, then tokenises the tags into a tree.
  3. Build the DOM — the tree of nodes is constructed in memory. This is the Document Object Model.
  4. Apply CSS — if any stylesheets are linked, they're fetched and matched against DOM nodes.
  5. Layout — the browser computes the geometry of each element (where it sits on screen).
  6. Paint — pixels are drawn to your screen.
  7. Execute JS — any <script> tags run, possibly modifying the DOM and triggering re-layouts.
Common Mistake Don't expect HTML changes to be visible until you refresh the page. The DOM is built once on load; only JavaScript (or CSS via :hover) modifies it after. To see edits to your .html file, save and refresh — or use Live Server to do it automatically.

7 Before You Start

Make sure you've completed Section 0 (Getting Started). Specifically:

  • VS Code and Live Server are installed.
  • You can open a .html file in a browser.
  • You know how to open DevTools (right-click → Inspect).
  • You've bookmarked MDN.
Try it yourself — 5 minutes In your html-mastery folder, create a new file called section-1-start.html. Type out the boilerplate by hand (no Emmet): 
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Section 1 Start</title>
</head>
<body>
  <h1>I am learning HTML</h1>
</body>
</html>
Open it with Live Server. You should see "I am learning HTML" rendered as a large heading. If yes — you're ready. Head to History of HTML.
