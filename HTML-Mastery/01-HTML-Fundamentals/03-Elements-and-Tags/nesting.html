Nesting Rules & Content Categories

Not every element can sit inside every other. The WHATWG spec defines content categories that govern what can contain what — and getting it wrong causes subtle bugs.

1 Proper Nesting

The first rule of HTML nesting: tags must be properly nested. If you open <a> then <span>, you must close </span> before </a>.

<!-- GOOD: properly nested -->
<p>Visit <a href="x">our <em>wonderful</em> site</a>.</p>
              └─ a opens ──── em opens ──── em closes ── a closes ─┘
<!-- BAD: overlapping tags -->
<p>Visit <a href="x">our <em>wonderful</a> site</em>.</p>
                          └─ a closes here, but em is still open ─┘

Browsers will silently "fix" overlapping tags by closing the inner tag early, but the resulting DOM may not match what you wrote. Always close inner tags before outer ones.

Common Mistake The classic overlap mistake: <b>Bold <i>both</b> italic</i>. The browser will close <i> when it sees </b>, then reopen it after — producing <b>Bold <i>both</i></b><i> italic</i>. Always write <b>Bold <i>both</i></b>.

2 Content Categories

The WHATWG spec groups every element into one or more content categories. Each category has rules about what its members can contain. The seven main categories:

CategoryWhat it isWhere it can live
Metadata contentPage metadataOnly in <head>
Flow contentMost body contentIn <body> and most flow containers
Sectioning contentDefines document sectionsIn flow content
Heading contentHeadingsIn flow content
Phrasing contentInline text and markupInside phrasing or flow that allows phrasing
Embedded contentImports another resourceIn flow content
Interactive contentUser interactionIn flow content; some restrictions

Most elements belong to multiple categories. For example, <a> is flow, phrasing, interactive, and palpable content all at once.

3 Flow Content

Most elements that can appear in the document body are flow content. There are over 100 flow elements — basically everything except head-only elements and a few rare ones.

Common flow elements: <p>, <div>, <article>, <section>, <header>, <footer>, <main>, <aside>, <nav>, <ul>, <ol>, <li>, <table>, <form>, <figure>, <blockquote>, <pre>, <hr>, <h1>–<h6>, plus all phrasing content.

<body>
  <header>...</header>
  <main>
    <article>
      <h1>Title</h1>
      <p>Body paragraph.</p>
      <ul><li>Item</li></ul>
    </article>
  </main>
</body>

4 Phrasing Content

Phrasing content is the inline text and markup of a document. The key rule: phrasing content can only contain other phrasing content.

Phrasing elements include: <a>, <abbr>, <b>, <bdi>, <bdo>, <br>, <cite>, <code>, <data>, <dfn>, <em>, <i>, <kbd>, <mark>, <q>, <ruby>, <s>, <samp>, <small>, <span>, <strong>, <sub>, <sup>, <time>, <u>, <var>, <wbr>, plus images, form inputs, and more.

Phrasing elements go inside <p>, <h1>–<h6>, <span>, <a>, <em>, <strong>, etc.

<!-- Valid: phrasing inside phrasing -->
<p>You can <em>emphasise</em> words like <strong>this</strong>.</p>
<span>Hello <a href="x">world</a>!</span>
<!-- INVALID: block element inside phrasing -->
<p>You can <div>not do this</div>.</p>
<span>Or <p>this</p></span>
<a href="x">Link with <h1>a heading</h1> inside</a>

The browser will recover by closing the paragraph, span, or anchor early. This usually results in a layout you didn't intend.

Pro Tip A useful mental model: if it produces a new line by default, it's not phrasing content. <p>, <div>, <ul>, <h1> — all block-level, all cannot go inside <span>, <a>, or another phrasing element.

5 Embedded Content

Elements that import another resource into the document.

Embedded elements: <audio>, <canvas>, <embed>, <iframe>, <img>, <math>, <object>, <picture>, <svg>, <video>.

<!-- An image is embedded content -->
<p>Here is a photo: <img src="cat.jpg" alt="A cat"> of my cat.</p>

<!-- An iframe is embedded content -->
<iframe src="https://www.youtube.com/embed/abc" title="My video"></iframe>

Embedded content can usually appear in both flow and phrasing contexts.

6 Interactive Content

Elements specifically designed for user interaction: <a> (with href), <button>, <details>, <embed>, <iframe>, <label>, <select>, <textarea>, <input> (except type="hidden").

The key rule: interactive content cannot contain other interactive content. You cannot nest a button inside a link, or a link inside a button.

<!-- INVALID: button inside a link -->
<a href="x"><button>Click</button></a>

<!-- INVALID: link inside a button -->
<button><a href="x">Click</a></button>

<!-- INVALID: button inside a label -->
<label><button>Click</button></label>

If you need a "button that links somewhere", use a <button> with a click handler that navigates, or style an <a> to look like a button.

Common Mistake Don't put an <a> inside a <button> or vice versa. The HTML is invalid, and browsers handle it inconsistently — some clicks will trigger the button, others the link, and screen readers get confused.

7 Sectioning Content

Elements that create a new section in the document outline: <article>, <aside>, <nav>, <section>.

Sectioning elements typically contain flow content. They can be nested — an <article> can contain <section>s, and vice versa.

<article>
  <h1>Blog Post</h1>
  <section>
    <h2>Introduction</h2>
    <p>...</p>
  </section>
  <section>
    <h2>Method</h2>
    <p>...</p>
  </section>
</article>

Each sectioning element creates its own heading scope — an <h1> inside a <section> is the top of that section, not the page. (Though most documents still use <h1> only once at the page level — see Section 7.)

8 Heading Content

Just the six: <h1>, <h2>, <h3>, <h4>, <h5>, <h6>.

Rules:

  • Heading content can only contain phrasing content (text and inline markup).
  • One <h1> per page is the convention (though technically you can have more).
  • Don't skip levels: don't go from <h1> directly to <h4>.
  • Don't use headings for visual size; use CSS.
<!-- INVALID: h1 cannot contain a div -->
<h1>Title with <div>subtext</div></h1>

<!-- INVALID: heading skipped -->
<h1>Title</h1>
<h4>Subtitle</h4>   <!-- skipped h2 and h3 -->

9 Transparent Content

Some elements have a "transparent" content model — they allow whatever their parent allows. The most common is <a> and <object>.

<!-- a inside a p (phrasing parent): a contains phrasing -->
<p>Visit <a href="x">our site</a>.</p>

<!-- a inside a div (flow parent): a can contain flow -->
<div>
  <a href="x">
    <article>
      <h2>Card title</h2>
      <p>Card body</p>
    </article>
  </a>
</div>

This is why an <a> can wrap a whole "card" of block content today (HTML5 changed this from HTML4, where <a> could only contain inline content).

Common Mistake Even with transparent content, you can't nest interactive content inside interactive content. <a> cannot contain <a>, <button>, or any other interactive element.

11 Common Mistakes

<!-- 1. Block element inside inline phrasing -->
<p>Some text <div>not allowed here</div></p>
<!-- 2. List item outside a list -->
<li>Orphan list item</li>
<!-- 3. Direct text inside <ul> -->
<ul>
  Random text
  <li>Item</li>
</ul>
<!-- 4. <a> inside <a> -->
<a href="x">Outer <a href="y">inner</a></a>
<!-- 5. <button> inside <a> or vice versa -->
<a href="x"><button>Click</button></a>
<!-- 6. Skipped heading level -->
<h1>Title</h1>
<h3>Subtitle</h3>   <!-- skipped h2 -->
<!-- 7. Heading inside a <p> -->
<p>Intro <h2>Heading</h2> rest</p>
<!-- 8. <tr> or <td> outside a <table> -->
<div>
  <tr><td>Cell</td></tr>
</div>
<!-- 9. Form inside a form -->
<form action="x">
  <form action="y">...</form>
</form>
<!-- 10. Block content directly inside <select> -->
<select>
  <option>A</option>
  <div>not allowed</div>
</select>

12 Validation

How do you know your nesting is correct? Three approaches:

  1. The W3C Validator. Paste your HTML into validator.w3.org. It will flag every nesting violation explicitly.
  2. Browser DevTools. Open the Elements panel. If the DOM doesn't match your source, the browser "fixed" an invalid nesting. Notice the differences — that's where you violated the rules.
  3. HTMLHint / eslint-plugin-html. Inline linting in your editor catches most issues as you type.
<ul> ← expected <li> Item </li> </ul>

If you wrote <ul>text<li>item</li></ul>, the browser will silently wrap the loose text in a <li> for you. The DevTools will show you that. The validator will tell you the source was invalid.

Try it yourself — 15 minutes Write a complete page that demonstrates valid nesting of every structure below:
  1. An <a> wrapping an <article> (entire card is clickable).
  2. A <dl> with three <dt>/<dd> pairs.
  3. A <table> with <thead>, <tbody>, <caption>, and a <colgroup> with two <col>s.
  4. A <form> with <fieldset>, <legend>, and inputs with associated <label>s.
  5. A <picture> with two <source>s and an <img>.
Run it through the W3C Validator. If it passes, you've internalised content categories.
