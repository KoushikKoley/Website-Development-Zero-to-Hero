Element Syntax

The grammar of HTML: opening tags, closing tags, void elements, attributes, content models, and the foundational distinction between block and inline elements.

1 The Parts of an Element

An HTML element has up to four parts. The complete anatomy of a paragraph element:

<p class="intro" id="first">Hello, world!</p> │└─┬─┘ │ │ │ │ │ │ │ │ │ └─ closing tag │ │ │ │ └─ content │ │ │ └─ second attribute value │ │ └─ second attribute name │ └─ tag name └─ opening angle bracket

Together, this is the element. The tag is just the angle-bracket part. The complete unit — opening tag, content, closing tag — is the element.

2 Opening Tag

The opening tag begins an element. It is composed of:

  1. A < (less-than sign)
  2. The tag name (lowercase by convention)
  3. Zero or more attributes, each separated by whitespace
  4. A > (greater-than sign)
<p>                  ← no attributes
<p class="lead">      ← one attribute
<a href="x" target="_blank" rel="noopener">   ← three attributes

3 Closing Tag

The closing tag ends an element. It is composed of:

  1. A <
  2. A / (forward slash)
  3. The same tag name as the opening tag
  4. A >
</p>     ← closing tag for <p>
</div>   ← closing tag for <div>

Closing tags are required for all non-void elements. Browsers will try to insert missing ones for you, but the result is often not what you intended.

Common Mistake Forgetting to close a tag can cascade errors through the rest of the document. If a single <p> isn't closed, every subsequent element may be treated as inside it. Always close what you open.

4 Void (Self-Closing) Elements

A small set of elements have no content and therefore no closing tag. These are called void elements. The full list (15 elements) is the topic of the next page, but here are the most common:

<br>             ← line break
<hr>             ← horizontal rule (thematic break)
<img src="x" alt="...">
<input type="text">
<meta charset="UTF-8">
<link rel="stylesheet" href="x">

In HTML5, you may write a trailing slash if you like — <br /> — but it has no effect. Pick a style and be consistent.

Pro Tip The XML/XHTML convention is <br />. The HTML5 convention is <br>. Most modern codebases omit the slash.

5 Attributes

Attributes configure elements. They live in the opening tag, after the tag name, separated by spaces. Each attribute is a name="value" pair.

<a href="https://example.com" target="_blank" rel="noopener noreferrer">Link</a>
    └─┬─┘ └────────┬────────┘ └────┬────┘ └─────────┬─────────┘
      │            │               │                   │
      │            │               │                   └─ third attribute
      │            │               └─ second attribute
      │            └─ first attribute
      └─ tag name

Attribute value quoting

Values should always be quoted. Both single and double quotes work:

<a href="https://example.com">      ← double quotes (most common)
<a href='https://example.com'>      ← single quotes
<a href=https://example.com>        ← unquoted (allowed but fragile)

Unquoted values cannot contain spaces, quotes, =, <, >, or `. Just always quote — it's safer.

Empty attribute values

<input value="">   ← empty string value, explicitly quoted
<div data-x>       ← boolean attribute, no value

6 Boolean Attributes

Some attributes are boolean — their mere presence means "true", and their absence means "false". The value doesn't matter.

<input type="checkbox" checked>           ← checked
<input type="checkbox" checked="checked"> ← also checked
<input type="checkbox" checked="">        ← also checked
<input type="checkbox" checked="false">   ← STILL CHECKED! Presence = true.
<input type="checkbox">                   ← not checked (attribute absent)

Common boolean attributes:

  • disabled — on <button>, <input>, <select>, <textarea>, <option>, <fieldset>
  • checked — on <input type="checkbox"> and <input type="radio">
  • selected — on <option>
  • readonly — on <input> and <textarea>
  • required — on form fields
  • multiple — on <input type="file"> and <select>
  • autofocus — on focusable elements
  • hidden — global attribute, hides element
  • async, defer — on <script>
  • reversed — on <ol>
  • nowrap — deprecated, do not use
Common Mistake Writing checked="false" does not uncheck a checkbox. The presence of the attribute is what matters, regardless of value. To uncheck, remove the attribute entirely (or use JavaScript: el.checked = false).

7 Nested Elements

Elements can contain other elements. This is what creates the document tree.

<article>
  <h2>Title</h2>
  <p>A paragraph with <a href="x">a link</a> in it.</p>
  <ul>
    <li>First</li>
    <li>Second</li>
  </ul>
</article>

Two rules:

  1. Tags must be properly nested. If you open <a> then <b>, you must close </b> before </a>.
  2. Content models must be respected. Not every element can be a child of every other. See Content Models below.
Common Mistake — Improper Nesting 
<b>Bold <i>both</b> italic</i>   ← INVALID: tags overlap
The browser will silently fix this — usually by closing the inner tag early — but the resulting DOM won't match what you wrote. Always close inner tags before outer ones.

8 Content Models

Every HTML element belongs to one or more content categories defined by the WHATWG spec. These categories determine what each element can contain and where it can be placed.

CategoryDescriptionExamples
Flow contentMost elements that can appear in <body><p>, <div>, <article>, <img>
Phrasing contentInline text and markup<span>, <a>, <em>, <strong>
Heading contentSection headings<h1>–<h6>
Sectioning contentDefine document sections<article>, <aside>, <nav>, <section>
Interactive contentUser-interaction elements<a> with href, <button>, <input>
Embedded contentExternal resources<img>, <video>, <iframe>, <canvas>
Metadata contentFor <head><title>, <meta>, <link>, <style>
Form-associated contentSubmit with a form<input>, <button>, <select>, <label>
Palpable contentShould have visible contentMost elements

The most important practical rule: phrasing content can contain only other phrasing content. A <span> cannot contain a <div>. A <p> cannot contain another <p> or a <div>.

<!-- Valid: span contains phrasing only -->
<span>Hello <em>world</em>!</span>

<!-- INVALID: span cannot contain a div -->
<span>Hello <div>world</div></span>

<!-- INVALID: p cannot contain a div -->
<p>Hello <div>world</div></p>

9 Block vs Inline

Before HTML5, HTML elements were classified as either block-level or inline. HTML5 replaced this with the content model system above, but the old terms remain useful because they describe how elements behave visually by default.

Block-level

Starts on a new line. Takes full available width. Width, height, margin, padding all apply.

Examples: <div>, <p>, <h1>–<h6>, <ul>, <ol>, <li>, <section>, <article>, <header>, <footer>, <table>, <form>

Inline

Does not start a new line. Takes only as much width as needed. Vertical margin/padding behave oddly. Width/height usually ignored.

Examples: <span>, <a>, <em>, <strong>, <code>, <img>, <br>, <sub>, <sup>

The modern reality

With CSS, you can make any element behave either way: display: block on an inline element, or display: inline on a block. The block/inline distinction is now about defaults and semantics, not hard rules. But choosing the right element by its semantics — not by its default styling — remains the right approach.

Pro Tip A useful middle ground is display: inline-block — sits inline but accepts width, height, padding. Commonly used for buttons inside text.

10 Syntax Rules Summary

  • Tags are wrapped in < and >.
  • Tag names are lowercase by convention.
  • Most elements need a closing tag with /.
  • Void elements (like <br>, <img>) have no closing tag.
  • Attributes are name="value" pairs in the opening tag.
  • Always quote attribute values.
  • Boolean attributes can appear without a value.
  • Tags must be properly nested (inner closed before outer).
  • Content models determine what can contain what.
  • Block elements stack vertically; inline elements flow horizontally.
  • HTML is case-insensitive for tag/attribute names but lowercase is convention.
  • Comments use <!-- ... --> and cannot be nested.
Try it yourself — 10 minutes Write a complete document from scratch (no Emmet). Include:
  1. A <header> with an <h1> and a <p> containing an <a> link.
  2. A <main> with two <section>s, each with an <h2> and a paragraph.
  3. A list (<ul>) with at least three <li> items, one of which contains an <a> link.
  4. An image (<img> — use any URL).
  5. A horizontal rule (<hr>) and a line break (<br>).
Open it in your browser. Inspect each element. Validate the HTML at validator.w3.org.
