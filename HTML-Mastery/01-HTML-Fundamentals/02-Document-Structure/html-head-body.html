Section 1.2 · Document Structure

The <html>, <head>, and <body> Elements

Three nested containers carry every HTML document. Each has a distinct role, distinct rules, and distinct ways to misuse it.

1 The Big Picture

Every HTML document is a tree with three layers:

<!DOCTYPE html>
<html lang="en">             ← root element (one per document)
  <head>                     ← metadata: not rendered on the page
    <title>...</title>
    <meta charset="UTF-8">
    <link rel="stylesheet" href="style.css">
  </head>
  <body>                      ← all visible content goes here
    <h1>Hello!</h1>
    <p>...</p>
  </body>
</html>

<html> — the root

Contains everything else. Exactly one per document. Carries the lang attribute.

<head> — the metadata

Carries info about the page: title, encoding, links to CSS and JS, social sharing tags. Not shown on the page.

<body> — the content

Everything the user sees: headings, paragraphs, images, buttons, forms.

The order is fixed

<head> must come before <body>, and both must be inside <html>.

2 The <html> Element

The <html> element is the root element of every HTML document. It is the ancestor of every other element. There can be only one <html> per document, and it must be the direct child of the DOCTYPE.

<!DOCTYPE html>
<html lang="en">
  ...
</html>

What goes on the <html> tag?

  • lang — declares the document's primary language. Required for accessibility and SEO. (See below.)
  • dir — text direction: "ltr" (default) or "rtl" for right-to-left languages like Arabic or Hebrew.
  • xmlns — XML namespace. Only needed if you're serving the page as XML (rare). Harmless on normal HTML pages.
  • Global attributes like class, id, data-* are technically allowed but rarely useful here.
<!-- English page, left-to-right (default) -->
<html lang="en">

<!-- Arabic page, right-to-left -->
<html lang="ar" dir="rtl">

<!-- Chinese (Simplified) page -->
<html lang="zh-Hans">

<!-- Page served as XHTML -->
<html lang="en" xmlns="http://www.w3.org/1999/xhtml">

3 The lang Attribute

The lang attribute on <html> declares the document's primary language. This is one of the most important and most-forgotten attributes in all of HTML.

Why it matters

Screen readers

Determine pronunciation rules. An English screen reader reading German text without lang="de" butchers it.

Search engines

Google uses lang to serve the right language version to users.

Browser translation

Chrome's "Translate this page" feature relies on lang to know what to translate from.

Hyphenation & spell-check

Browsers use lang to apply correct hyphenation rules and dictionary.

Common Mistake Don't put the wrong language on purpose. Setting lang="en" on a page written entirely in Spanish causes screen readers to mispronounce every word and breaks Google's translation feature.
Pro Tip You can override lang on individual elements when a page mixes languages: <p>The German word <span lang="de">Schadenfreude</span> means...</p>. The screen reader will switch pronunciation for that word.

4 The <head> Element

The <head> element is the container for metadata — information about the page that the browser uses but does not show as content.

What belongs in the <head>:

<title>

The page title shown in the browser tab and used as the default bookmark name. Required. One per page. Limited to ~60 characters for SEO (Google truncates longer titles).

<meta>

Various metadata: charset, viewport, description, author, social media tags. Multiple <meta> tags are common. Covered in detail on the next page.

<link>

Links to external resources: stylesheets, favicons, preconnect hints, RSS feeds.

<link rel="stylesheet" href="styles.css">
<link rel="icon" href="favicon.ico">
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="alternate" type="application/rss+xml" href="feed.xml">

<style>

Inline CSS. Useful for tiny, page-specific styles. Generally, prefer external <link> stylesheets.

<script>

JavaScript. Can be in <head> (often with defer) or at the end of <body>.

<script src="app.js" defer></script>
<script type="application/ld+json">{ ... }</script>

<base>

Sets the default URL and target for all relative links on the page. Use sparingly; it's easy to confuse yourself.

<noscript>

Content shown only when JavaScript is disabled.

What does not belong in the <head>: anything you can see on the page. No headings, paragraphs, images, divs, sections, etc.

5 The <body> Element

The <body> element contains everything the user sees: text, images, links, forms, scripts that affect the page. There is exactly one <body> per document, and it must be the second child of <html> (after <head>).

<body>
  <header>
    <nav>...</nav>
  </header>
  <main>
    <article>
      <h1>Post Title</h1>
      <p>...</p>
    </article>
  </main>
  <footer>...</footer>
  <script src="app.js"></script>
</body>

Useful attributes on <body>

  • class — common pattern: class="home", class="article dark-mode" for page-specific styling.
  • id — sometimes used for JavaScript targeting.
  • onload, onresize, onscroll — event handlers. Modern code prefers addEventListener in a separate script, but inline handlers are valid.
  • Old presentational attributes like bgcolor, text, margin — obsolete. Use CSS.
Common Mistake Don't put <script> tags that block rendering at the top of <body> — they'll delay the page's first paint. Either add defer, or put them at the bottom of <body>.

7 Are They Required?

Technically, the HTML5 parser will infer missing <html>, <head>, and <body> tags. This document is valid (if ugly):

<!DOCTYPE html>
<meta charset="UTF-8">
<title>Lazy</title>
<p>Hello!</p>

The parser sees the <meta> and <title> (which are head-only elements) and infers a <head>. It sees the <p> (a body-only element) and infers a <body>. The DOM ends up the same as if you'd written all the tags explicitly.

Don't do this. Even though it's valid, it's harder to read, harder to maintain, and breaks tools that expect explicit structure. Always write all three tags.

Pro Tip Run DevTools → Elements on any page. Notice the browser has inserted <html>, <head>, and <body> even if the source didn't have them. The DOM is the normalised form; the source is your responsibility.

8 Common Mistakes

MistakeWhy it's wrong
Putting <meta> inside <body>Invalid; the parser moves it to <head> for you, but tools complain. Keep it in <head>.
Putting <p> inside <head>Invalid; parser implicitly closes <head> and opens <body>.
Multiple <body> tagsInvalid; only the first is kept.
Forgetting lang on <html>Valid HTML but fails accessibility best practice. Always set it.
<html lang="english">Invalid language code. Use "en", not the full word.
Two <title> tagsInvalid; only one is allowed.
<head> after <body>Invalid order; <head> must come first.
Try it yourself — 10 minutes Build a complete document from scratch (no Emmet) that includes:
  1. A <title> of "Document Structure Practice".
  2. lang="en" on <html>.
  3. A <meta charset="UTF-8">.
  4. A viewport meta tag.
  5. A description meta tag.
  6. A linked stylesheet (you can create style.css with one rule).
  7. An <h1> and a <p> in the body.
  8. A <script> at the bottom of the body with console.log('Page loaded').
Validate it at validator.w3.org. If it passes, you've internalised document structure.
