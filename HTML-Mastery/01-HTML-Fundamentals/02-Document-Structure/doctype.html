The <!DOCTYPE html> Declaration

Five characters that decide whether your page renders in modern standards mode or 1999-era quirks mode. Easy to write, easy to forget, expensive to get wrong.

1 What Is DOCTYPE?

The DOCTYPE (short for "document type declaration") is the very first line of every HTML document. It is not an HTML tag — it's an instruction to the browser about which version of HTML the page is using.

<!DOCTYPE html>

In HTML5, the DOCTYPE is intentionally minimal. It says one thing: "Treat this document as modern HTML, rendered in standards mode."

The DOCTYPE must be:

  • The first thing in the file — before any whitespace, before any HTML, before the <html> tag.
  • Present once. Multiple DOCTYPEs are invalid.
  • Exactly <!DOCTYPE html> (case-insensitive, but uppercase is the convention).
Pro Tip Type ! in an empty HTML file in VS Code and press Tab. Emmet generates the full boilerplate, starting with <!DOCTYPE html>. Memorise the boilerplate anyway — knowing what's in it matters.

2 A Brief History of DOCTYPEs

Before HTML5, the DOCTYPE had to reference a specific Document Type Definition (DTD) — a formal SGML/XML specification that listed every allowed element and attribute. These DTDs were long and easy to mistype.

HTML 4.01 — three flavours, three doctypes

<!-- HTML 4.01 Strict -->
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN"
   "http://www.w3.org/TR/html4/strict.dtd">

<!-- HTML 4.01 Transitional (allowed presentational tags) -->
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN"
   "http://www.w3.org/TR/html4/loose.dtd">

<!-- HTML 4.01 Frameset (for <frameset>) -->
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Frameset//EN"
   "http://www.w3.org/TR/html4/frameset.dtd">

XHTML 1.0 — the same DTDs, just stricter

<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Strict//EN"
   "http://www.w3.org/TR/xhtml1/DTD/xhtml1-strict.dtd">

XHTML 1.1

<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.1//EN"
   "http://www.w3.org/TR/xhtml11/DTD/xhtml11.dtd">

These long DOCTYPEs did real work — they pointed browsers at a DTD that listed every allowed element. But they were impossible to memorise. Authors copied them from a cheatsheet. The WHATWG's design insight for HTML5 was that none of this was necessary: the browser only needs to know "this is HTML, render in standards mode".

Common Mistake Some template generators still output old-style DOCTYPEs like <!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" ...>. There is no reason to use these today. Replace with <!DOCTYPE html>.

3 Quirks Mode vs Standards Mode

Browsers have three rendering modes. The DOCTYPE determines which one is used.

✓ Standards Mode (No Quirks)

The browser renders the page according to the modern CSS and HTML specifications. This is what you want. Triggered by <!DOCTYPE html>.

✗ Quirks Mode

The browser emulates the buggy behaviour of IE5 (1999). Layout breaks in mysterious ways. Triggered by omitting the DOCTYPE or using an invalid one.

⚠ Limited Quirks Mode

A halfway house for documents using the old HTML 4.01 Transitional or Frameset DOCTYPEs. Mostly standards-compliant but with some legacy behaviours around tables and inline blocks.

Why it matters

In Quirks Mode: width includes padding and border (the old IE box model). Inline elements behave like the 90s. New CSS features may not work. Avoid at all costs.

Concrete example of the box model difference

Consider this CSS:

.box {
  width: 200px;
  padding: 20px;
  border: 5px solid black;
}
ModeTotal element widthWhy
Standards250px200 (content) + 20+20 (padding) + 5+5 (border) = 250
Quirks200px200 includes padding and border (the IE5 box model)

This single difference is why an entire generation of CSS layouts "broke in IE" — authors had been testing in standards mode and IE6 was rendering in quirks mode due to a missing DOCTYPE.

Pro Tip To check which mode your page is in: open DevTools → Console and run document.compatMode. "CSS1Compat" means standards; "BackCompat" means quirks. Run it now on this page — you'll see "CSS1Compat".

4 The Modern Form

HTML5 introduced the universal DOCTYPE:

<!DOCTYPE html>

That's it. No version, no DTD URL, no PUBLIC keyword. It works for every HTML5 document forever. Case-insensitive — <!doctype html> and <!DOCTYPE html> are equivalent — but the uppercase form is the universal convention.

The full minimal HTML5 document:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Document</title>
</head>
<body>
  <p>Hello, world!</p>
</body>
</html>

5 What Happens If You Omit the DOCTYPE?

Browsers do not refuse to render your page. They render it — in quirks mode. This produces subtle, hard-to-debug problems:

  • Box model is the old IE5 one (width includes padding and border).
  • CSS units like vh and vw may behave oddly.
  • Inline-block elements get unwanted whitespace between them.
  • Some CSS3 features are silently unsupported.
  • JavaScript APIs may report different values for document.documentElement.clientHeight.

The browser will not warn you. You'll spend hours wondering why a 200-pixel-wide box is 200 pixels wide instead of 250. Always start with the DOCTYPE.

Common Mistake A common "skeleton" mistake is starting the file with a comment: 
<!-- My awesome page -->
<!DOCTYPE html>
...
This is fine in modern browsers (comments before the DOCTYPE don't trigger quirks mode), but it's fragile and a validator will complain. Always put the DOCTYPE first, before any comments.

7 The XML Declaration Confusion

If you ever see this at the top of a file:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE html>
...

…that's the XML declaration, not the DOCTYPE. It was used in XHTML and is unnecessary (and harmful) in HTML5. Remove it. In old IE versions, this XML declaration actually triggered quirks mode because it pushed the DOCTYPE below the first line — yet another reason to forget XHTML.

Pro Tip If you're ever debugging a layout and CSS units aren't behaving as expected, the first check is: is the page in standards mode? Run document.compatMode in the console. The second check is: is the DOCTYPE the first thing in the file?

8 Summary

  • Always start every HTML document with <!DOCTYPE html>.
  • It must be the first line — no whitespace, no comments before it.
  • It's case-insensitive but conventionally uppercase.
  • It is not a tag — it's a processing instruction.
  • It tells the browser to use standards mode, not quirks mode.
  • Modern HTML5 has no other valid DOCTYPE.
Try it yourself — 5 minutes Create two files:
  1. with-doctype.html — full HTML5 boilerplate with <!DOCTYPE html>. Include a <div> styled with width: 200px; padding: 20px; border: 5px solid red; and a background.
  2. without-doctype.html — same content but omit the DOCTYPE entirely.
Open both. Open DevTools Console and run document.compatMode on each. Notice the difference in the rendered width of the box. That's the box model in action.
