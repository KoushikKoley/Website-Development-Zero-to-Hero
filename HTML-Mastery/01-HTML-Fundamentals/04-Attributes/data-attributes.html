The data-* Attributes

The official HTML escape hatch for attaching custom data to elements — read and written by JavaScript, ignored by the browser, infinitely flexible.

1 What Are data-* Attributes?

Any attribute whose name begins with data- is treated as a custom data attribute. The browser doesn't act on it; it just stores the value for your JavaScript to read or write.

<article
  data-post-id="42"
  data-author="jane"
  data-tags="html, web, beginner"
  data-published="2024-03-15"
>
  <h2>My Post</h2>
</article>

The browser ignores these attributes entirely — they don't affect rendering, accessibility, or behaviour. They exist purely so your JavaScript can attach data to elements without using global variables or class-name hacks.

2 Why Use Them?

Before HTML5, developers stored data in all sorts of hacky ways:

  • Encoding data in class names: class="post-id-42 author-jane"
  • Stashing data in rel attributes (which is invalid)
  • Using jQuery's $.data() (which kept an internal cache, fragile)
  • Inline onclick="doThing(42)" handlers

The data-* family is the official, sanctioned way. Benefits:

Valid HTML

The validator accepts any data-* attribute on any element.

Self-documenting

data-post-id="42" reads more clearly than class="post-42".

Persistent in DOM

Unlike JS variables, data attributes survive page reloads and are visible in the DOM tree.

Queryable

document.querySelector('[data-post-id="42"]') finds the element by its data.

CSS-hookable

Style based on data: [data-state="loading"] { opacity: 0.5; }

No name conflicts

The data- prefix means you'll never clash with a future HTML attribute.

3 Naming Conventions

Rules for data-* attribute names:

  • Must start with data-.
  • The part after data- can include letters, numbers, dashes, and dots.
  • Cannot include uppercase letters. data-postId is invalid; use data-post-id.
  • XML rules apply — no colons in HTML5, but the spec actually disallows them in practice.
<!-- GOOD — lowercase, dash-separated -->
data-post-id="42"
data-user-role="admin"
data-product-sku="ABC-123"

<!-- BAD — uppercase (will be lowercased, breaks dataset access) -->
data-postId="42"           ← won't work as expected
data-UserID="42"           ← same problem

<!-- BAD — leading digit after data- -->
data-3d-mode="true"        ← actually allowed but discouraged; prefer data-mode-3d
Pro Tip Use kebab-case (lowercase with dashes) consistently: data-user-id, data-post-id, data-cart-total. This is the universal convention and works smoothly with the dataset API.

4 Reading via JavaScript

Two ways to read a data-* attribute:

Method 1 — getAttribute

const article = document.querySelector('article[data-post-id="42"]')

const id = article.getAttribute('data-post-id')         // "42" (string)
const author = article.getAttribute('data-author')      // "jane"
const tags = article.getAttribute('data-tags')         // "html, web, beginner"

Always returns a string (or null if the attribute is absent). You'll need to convert numbers manually: Number(id) or parseInt(id, 10).

Method 2 — dataset API

const article = document.querySelector('article[data-post-id="42"]')

article.dataset.postId        // "42"
article.dataset.author        // "jane"
article.dataset.tags          // "html, web, beginner"

The dataset property is a DOMStringMap. Each data-foo-bar becomes dataset.fooBar (camelCase). Dashes are stripped and the next letter is capitalised.

data-post-id     → dataset.postId
data-user-role   → dataset.userRole
data-cart-total  → dataset.cartTotal
data-foo         → dataset.foo

5 Writing via JavaScript

const el = document.getElementById('card')

// Method 1: setAttribute
el.setAttribute('data-state', 'loading')

// Method 2: dataset
el.dataset.state = 'loading'
el.dataset.userId = '42'     // automatically becomes data-user-id="42"
el.dataset.lastLogin = '2024-03-15'

Both methods update the DOM, so DevTools shows the new value immediately. Both trigger attribute-change observers (via MutationObserver).

Deleting

// Method 1: removeAttribute
el.removeAttribute('data-state')

// Method 2: delete on dataset
delete el.dataset.state

6 The dataset API in Depth

The dataset property is a DOMStringMap — a special object that maps camelCase property names to data-* attributes.

<div id="x" data-foo="1" data-foo-bar="2" data-foo-bar-baz="3"></div>

<script>
  const x = document.getElementById('x')
  console.log(x.dataset)              // DOMStringMap { foo: "1", fooBar: "2", fooBarBaz: "3" }

  // Iterate:
  for (const [key, value] of Object.entries(x.dataset)) {
    console.log(key, '=', value)
  }

  // Read all into a plain object:
  const data = { ...x.dataset }
  console.log(data)                   // { foo: "1", fooBar: "2", fooBarBaz: "3" }
</script>
Common Mistake Values are always strings. Setting el.dataset.count = 5 stores the string "5", not the number. When reading, convert as needed: Number(el.dataset.count), JSON.parse(el.dataset.config), el.dataset.isActive === 'true'.

Storing complex data

<!-- Store JSON in a data attribute -->
<div id="card"
     data-config='{"theme":"dark","size":"lg","closable":true}'>
</div>

<script>
  const card = document.getElementById('card')
  const config = JSON.parse(card.dataset.config)
  console.log(config.theme)        // "dark"
  console.log(config.closable)     // true (boolean)
</script>

Use single quotes around the JSON so you can use double quotes inside the JSON without escaping.

7 Styling with data Attributes

The attribute selector [data-...] is a powerful CSS hook.

/* Style by data-state */
[data-state="loading"] { opacity: 0.5; pointer-events: none; }
[data-state="error"]   { color: red; }
[data-state="success"] { color: green; }

/* Generic — any element with data-tooltip */
[data-tooltip] {
  position: relative;
  cursor: help;
}

/* Children based on parent's data */
.tabs[data-active-tab="2"] .tab:nth-child(2) {
  background: navy;
  color: white;
}
<button data-state="loading">Saving...</button>
<div class="tabs" data-active-tab="2">
  <div class="tab">Tab 1</div>
  <div class="tab">Tab 2</div>
  <div class="tab">Tab 3</div>
</div>

Combined with JavaScript state changes, this is a lightweight state-driven styling system — no framework needed.

8 Real-World Patterns

Pattern 1: Pure-HTML Tooltips

<style>
  [data-tooltip] { position: relative; cursor: help; border-bottom: 1px dotted; }
  [data-tooltip]::after {
    content: attr(data-tooltip);
    position: absolute;
    bottom: 100%;
    left: 50%;
    transform: translateX(-50%);
    background: black;
    color: white;
    padding: 4px 8px;
    border-radius: 4px;
    opacity: 0;
    pointer-events: none;
    transition: opacity 0.2s;
    white-space: nowrap;
  }
  [data-tooltip]:hover::after { opacity: 1; }
</style>

<span data-tooltip="HyperText Markup Language">HTML</span>
<abbr data-tooltip="World Wide Web Consortium">W3C</abbr>

Pattern 2: Analytics Tracking

<button data-track="cta-click" data-track-location="hero">Get Started</button>
<button data-track="cta-click" data-track-location="footer">Sign Up</button>

<script>
  document.addEventListener('click', e => {
    const trackable = e.target.closest('[data-track]')
    if (!trackable) return

    analytics.track(trackable.dataset.track, {
      location: trackable.dataset.trackLocation,
      url: location.pathname,
      ts: Date.now()
    })
  })
</script>

Pattern 3: Single Event Handler for Many Buttons

<ul id="cart">
  <li>
    <span>Apple</span>
    <button data-action="remove" data-item-id="1">Remove</button>
  </li>
  <li>
    <span>Pear</span>
    <button data-action="remove" data-item-id="2">Remove</button>
  </li>
</ul>

<script>
  document.getElementById('cart').addEventListener('click', e => {
    const btn = e.target.closest('[data-action="remove"]')
    if (!btn) return

    const itemId = btn.dataset.itemId
    removeFromCart(itemId)
  })
</script>

This is the event delegation pattern: one listener handles all current and future buttons, instead of attaching a handler to each.

Pattern 4: Tab Interface State

<div class="tabs" data-active-tab="0">
  <button data-tab="0">Overview</button>
  <button data-tab="1">Reviews</button>
  <button data-tab="2">Specs</button>

  <section data-panel="0">Overview content</section>
  <section data-panel="1">Reviews content</section>
  <section data-panel="2">Specs content</section>
</div>

<style>
  [data-panel] { display: none; }
  .tabs[data-active-tab="0"] [data-panel="0"],
  .tabs[data-active-tab="1"] [data-panel="1"],
  .tabs[data-active-tab="2"] [data-panel="2"] {
    display: block;
  }
</style>

<script>
  document.querySelectorAll('[data-tab]').forEach(btn => {
    btn.addEventListener('click', () => {
      const tabs = btn.closest('.tabs')
      tabs.dataset.activeTab = btn.dataset.tab
    })
  })
</script>

Pattern 5: Lazy-loaded Content

<div data-lazy-url="/api/comments/42">
  Loading comments...
</div>

<script>
  const observer = new IntersectionObserver(entries => {
    entries.forEach(entry => {
      if (entry.isIntersecting) {
        const url = entry.target.dataset.lazyUrl
        fetch(url).then(r => r.text()).then(html => {
          entry.target.innerHTML = html
          observer.unobserve(entry.target)
        })
      }
    })
  })
  document.querySelectorAll('[data-lazy-url]').forEach(el => observer.observe(el))
</script>

9 Common Mistakes

MistakeFix
Using uppercase: data-postIdUse kebab-case: data-post-id — read as dataset.postId
Storing secrets (API keys, passwords)Don't. data-* values are visible in View Source and DevTools.
Storing large data (10KB+)Use a fetch from JS, or store in IndexedDB. Big attributes bloat the HTML and slow parsing.
Storing unescaped user inputAlways HTML-escape user-provided strings before inserting into data-* attributes.
Forgetting values are always stringsConvert: Number(dataset.count), dataset.flag === 'true'.
Using data-* for styling-only "class"Use class for styling hooks. Use data-* for data + state.
Putting HTML inside data attributesUse a hidden <template> instead — cleaner and faster.
Naming conflict with framework (Vue, React)Some frameworks reserve data- prefixes. Check the docs.

10 Rules Summary

  • Any attribute named data-* is a custom data attribute.
  • Names must be lowercase (after data-), dash-separated.
  • Values are always strings; convert to other types in JS.
  • Read via el.getAttribute('data-foo') or el.dataset.foo.
  • Camel-case conversion: data-foo-bar → dataset.fooBar.
  • Valid on every HTML element.
  • Don't store secrets, large data, or unescaped user input.
  • Great for: tooltips, analytics, event delegation, state, lazy loading.
