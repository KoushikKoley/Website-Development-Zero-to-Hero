ARIA Attributes — Introduction

ARIA is how HTML talks to assistive technology. Learn the eight attributes you'll use most: role, aria-label, aria-labelledby, aria-describedby, aria-hidden, aria-live, aria-expanded, and aria-current.

1 What Is ARIA?

ARIA stands for Accessible Rich Internet Applications. It's a W3C specification that adds attributes to HTML so that screen readers and other assistive technologies can understand dynamic, complex UIs that native HTML can't express.

HTML has built-in semantics. A <button> is automatically announced as "button" by screen readers. A <nav> is "navigation". An <input type="checkbox"> is "checkbox, unchecked". These semantics are baked in.

But what if you build a custom widget — say, an accordion — using <div>s? Screen readers have no idea it's an accordion. ARIA lets you tell them: "this div is a button, this div is expanded, this div controls that div".

<!-- Native button: screen reader knows it's a button -->
<button onclick="toggle()">Open menu</button>

<!-- Custom div: screen reader has no idea -->
<div onclick="toggle()">Open menu</div>   ← inaccessible!

<!-- With ARIA: screen reader knows -->
<div role="button" tabindex="0" aria-expanded="false"
     onclick="toggle()" onkeydown="handleKey(event)">
  Open menu
</div>
Pro Tip ARIA doesn't add behaviour. The div with role="button" still doesn't actually behave like a button — you have to implement keyboard handling (Enter, Space), focus management, and click handling yourself. ARIA only changes how the screen reader announces the element.

2 The First Rule of ARIA

No ARIA is better than bad ARIA.

The official first rule of ARIA use, from the W3C: "If you can use a native HTML element or attribute with the semantics and behaviour you require already built in, instead of re-purposing an element and adding an ARIA role, state or property to make it accessible, then do so."

In practice:

  • Use <button> instead of <div role="button">.
  • Use <a href> instead of <span role="link">.
  • Use <input type="checkbox"> instead of <div role="checkbox">.
  • Use <nav>, <main>, <header>, <footer>, <article> instead of role="navigation", role="main", etc.

Native HTML elements come with keyboard handling, focus management, and consistent screen-reader support for free. Rebuilding them with divs + ARIA is rarely as good.

Common Mistake Adding role="button" to a <button> is redundant at best and harmful at worst (if you also set role="link", you've just told the screen reader the button is a link). Don't add ARIA to elements that already have the right semantics.

3 role

The role attribute tells assistive tech what an element is. There are dozens of roles, but the most common ones you'll add to custom widgets:

RoleUse case
role="button"Custom button (e.g. clickable div)
role="link"Custom link
role="checkbox"Custom checkbox
role="radio"Custom radio button
role="tab", role="tablist", role="tabpanel"Custom tabs interface
role="dialog", role="alertdialog"Modal dialog
role="alert"Inline alert (e.g. form error)
role="status"Status update (e.g. "Saved")
role="navigation"Use <nav> instead
role="main"Use <main> instead
role="banner"Use <header> instead
role="contentinfo"Use <footer> instead
role="search"Use <search> instead (2023+)
 
<div role="tablist">
  <button role="tab" aria-selected="true" aria-controls="panel1">Tab 1</button>
  <button role="tab" aria-selected="false" aria-controls="panel2">Tab 2</button>
</div>

<div role="tabpanel" id="panel1">Tab 1 content</div>
<div role="tabpanel" id="panel2" hidden>Tab 2 content</div>

4 aria-label

Provides an accessible name for an element when no visible text is available. Most commonly used on icon-only buttons.

<button aria-label="Close dialog">
  <svg><!-- X icon --></svg>
</button>

<button aria-label="Search">
  <svg><!-- magnifying glass icon --></svg>
</button>

<button aria-label="Previous slide">‹</button>
<button aria-label="Next slide">›</button>
Common Mistake Don't add aria-label to elements that already have visible text — it overrides the visible text. <button aria-label="Save">Delete</button> announces "Save" but shows "Delete". Don't confuse your users.
Pro Tip For icon-only buttons, always provide aria-label. For text buttons, the visible text is enough — no ARIA needed.

5 aria-labelledby

Like aria-label, but instead of providing the text directly, it points to the ID of an element whose text should be used as the label. Useful when the visible label is already in the DOM.

<section aria-labelledby="section-heading">
  <h2 id="section-heading">Latest News</h2>
  <article>...</article>
</section>

<button aria-labelledby="save-text">
  <svg>...</svg>
  <span id="save-text" class="sr-only">Save changes</span>
</button>

<input type="text" aria-labelledby="first-name-label">
<label id="first-name-label">First name</label>
<!-- (Prefer <label for="..."> here — this is just to show the pattern) -->

Differences from aria-label:

  • aria-label takes a string. aria-labelledby takes one or more IDs.
  • aria-labelledby takes priority if both are set.
  • aria-labelledby re-uses visible text — easier to keep in sync.
  • Multiple IDs allowed: aria-labelledby="label-1 label-2" concatenates them.

6 aria-describedby

Points to one or more IDs whose content provides an extended description for an element. Often used for form fields with help text.

<label for="password">Password</label>
<input
  type="password"
  id="password"
  aria-describedby="password-help"
>
<small id="password-help">
  Must be at least 8 characters, including one number and one symbol.
</small>

The screen reader announces "Password, edit field. Must be at least 8 characters, including one number and one symbol." — the description is appended after the label.

<button aria-describedby="delete-warning">Delete account</button>
<div id="delete-warning" class="sr-only">
  This action is permanent and cannot be undone.
</div>

7 aria-hidden

Tells screen readers to ignore an element entirely. Useful for purely decorative content.

<button>
  <svg aria-hidden="true"><!-- decorative icon --></svg>
  <span>Save</span>
</button>

<div class="background-pattern" aria-hidden="true">
  <!-- purely decorative -->
</div>
Common Mistake Never set aria-hidden="true" on a focusable element. A sighted keyboard user can Tab to it but the screen reader is told to ignore it — they get focus on something invisible. Also, don't hide entire sections of the page from screen readers just because they're complex. Hide only truly decorative or duplicated content.

The CSS pattern display: none already hides content from screen readers. aria-hidden="true" is for cases where you want the content visible to sighted users but not announced — like a duplicate icon next to a text label.

8 aria-live

Marks an element as a live region — content that updates dynamically, which the screen reader should announce without the user navigating to it. Essential for SPAs.

ValueWhen it announces
off (default)Never (user must navigate to the region)
politeWhen the user is idle — doesn't interrupt
assertiveImmediately — interrupts current speech
 
<div aria-live="polite" id="status">
  <!-- "Saved" appears here when JS updates it -->
</div>

<div aria-live="assertive" role="alert" id="errors">
  <!-- Form validation errors appear here -->
</div>

<script>
  document.getElementById('status').textContent = 'Saved at ' + new Date().toLocaleTimeString()
</script>
Pro Tip Prefer polite for most updates. Use assertive only for urgent messages like errors that block the user. assertive interrupts whatever the screen reader was saying, which can be disorienting.

Related attributes: aria-atomic="true" (announce the whole region, not just the changed part) and aria-relevant="additions text" (what changes to announce).

9 aria-expanded

Tells screen readers whether an expandable element (accordion, dropdown, collapsible panel) is currently expanded or collapsed.

<button
  aria-expanded="false"
  aria-controls="panel-1"
  onclick="toggle()"
>
  Show details
</button>

<div id="panel-1" hidden>
  <p>Hidden content revealed when expanded.</p>
</div>

Update with JavaScript:

function toggle() {
  const btn = event.currentTarget
  const panel = document.getElementById(btn.getAttribute('aria-controls'))
  const isExpanded = btn.getAttribute('aria-expanded') === 'true'

  btn.setAttribute('aria-expanded', String(!isExpanded))
  panel.hidden = isExpanded
  btn.textContent = isExpanded ? 'Show details' : 'Hide details'
}
Pro Tip If you build an accordion with native <details> and <summary>, the browser handles aria-expanded for you. Use native elements when you can.

10 aria-current

Indicates the current item in a set of related elements — the active page in pagination, the current step in a wizard, the active filter.

ValueUse
pageCurrent page in a navigation/breadcrumb
stepCurrent step in a multi-step process
locationCurrent location (e.g. in breadcrumbs)
dateCurrent date in a calendar
trueGeneric "this is the current item"
false (default)Not current
 
<nav aria-label="Pagination">
  <ul>
    <li><a href="?page=1">1</a></li>
    <li><a href="?page=2" aria-current="page">2</a></li>
    <li><a href="?page=3">3</a></li>
  </ul>
</nav>

<nav aria-label="Breadcrumb">
  <ol>
    <li><a href="/">Home</a></li>
    <li><a href="/blog">Blog</a></li>
    <li><a href="/blog/post" aria-current="page">Post Title</a></li>
  </ol>
</nav>

Screen readers announce "current page" for the active link. Browsers also add a default visual indicator (varies).

Try it yourself — 15 minutes Build an accessible accordion using <button>s and <div>s:
  1. Three buttons, each with aria-expanded="false" and aria-controls="panel-N".
  2. Three panels with matching id="panel-N" and hidden.
  3. JavaScript that toggles both aria-expanded on the button and hidden on the panel.
  4. Run it in your browser and verify with the DevTools Accessibility panel.
Then rewrite it using native <details> and <summary>. Notice how much code you didn't have to write.
