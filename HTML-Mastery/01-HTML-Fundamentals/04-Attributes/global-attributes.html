1 What Is a Global Attribute?

A global attribute is an attribute that can be applied to any HTML element. Compare with element-specific attributes — href only works on <a>, src on <img>/<script>, etc. Global attributes work everywhere.

The WHATWG spec lists about 30 global attributes. The most important ones, in order of frequency of use:

  1. id — unique identifier
  2. class — CSS class(es)
  3. style — inline styles
  4. title — tooltip text
  5. lang, dir — language and direction
  6. tabindex — keyboard focus order
  7. hidden — hide element
  8. contenteditable — make editable
  9. spellcheck — enable/disable spell check
  10. translate — hint for translation tools
  11. draggable — make draggable
  12. accesskey — keyboard shortcut
  13. data-* — custom data (separate page)
  14. role and aria-* — accessibility (separate page)

2 id

The id attribute gives an element a unique identifier on the page. No two elements in the same document can share an id.

<h2 id="introduction">Introduction</h2>

<a href="#introduction">Jump to intro</a>

<script>
  document.getElementById('introduction').scrollIntoView();
</script>

Rules:

  • Must be unique within the document.
  • Must contain at least one character.
  • Cannot contain spaces.
  • Is case-sensitive: intro and Intro are different IDs.
  • Should start with a letter (no leading digit), though HTML5 technically allows it.
  • Should be meaningful: id="main-nav", not id="nav3".
Common Mistake Reusing the same ID on multiple elements is invalid HTML. Browsers will silently keep only the first when you call getElementById. Always ensure IDs are unique.
Pro Tip Use id sparingly. For styling, prefer class. Reserve id for: anchor targets (href="#section"), JavaScript targeting, and form label association (<label for="id">).

3 class

The class attribute assigns one or more CSS classes to an element. Multiple elements can share a class, and one element can have multiple classes (space-separated).

<button class="btn btn-primary">Save</button>
<button class="btn btn-secondary">Cancel</button>
<p class="lead text-muted">Intro paragraph</p>

Class names:

  • Are case-sensitive: btn ≠ Btn ≠ BTN.
  • Must start with a letter, hyphen-plus-letter, or underscore (HTML5 allows almost anything but stick to ASCII).
  • Can be hyphen-separated: btn-primary, card-header.
  • Conventional naming systems: BEM (block__element--modifier), utility-first (Tailwind: flex p-4).

Querying classes with JavaScript

document.getElementsByClassName('btn')        // HTMLCollection
document.querySelectorAll('.btn-primary')     // NodeList

el.classList.add('active')
el.classList.remove('active')
el.classList.toggle('active')
el.classList.contains('active')  // true/false

4 style

The style attribute applies inline CSS directly to an element. Properties are separated by semicolons.

<p style="color: navy; font-size: 18px; line-height: 1.6;">
  This paragraph has inline styles.
</p>
Common Mistake Inline styles are bad practice in production code because:
  • They mix presentation with structure.
  • They have higher specificity than stylesheet rules, making overrides hard.
  • They can't be cached separately.
  • They can't respond to media queries or pseudo-classes.
Use the style attribute only for one-off styles that genuinely can't be expressed in CSS — typically dynamic values from JavaScript. 
<!-- Acceptable: dynamic style set by JS -->
<div id="progress" style="width: 67%;"></div>

<script>
  // Update as data loads
  document.getElementById('progress').style.width = '87%'
</script>

5 title

The title attribute provides advisory information — usually shown as a browser tooltip when the user hovers. Useful for abbreviations, link destinations, and small explanations.

<abbr title="HyperText Markup Language">HTML</abbr>

<a href="report.pdf" title="PDF, 2.4 MB">Download report</a>

<span title="World Health Organization, founded 1948">WHO</span>

<input type="text" title="Your full legal name as on your ID">

Hover over this: HTML is the language of the web.

Common Mistake The title tooltip is:
  • Not accessible by default (screen readers ignore title on most elements).
  • Not visible on touch devices (no hover).
  • Often slow to appear (~2 second delay in most browsers).
Don't rely on title for important info. Use visible text or ARIA labels instead.

6 lang and dir

lang

Declares the language of an element's content. Browsers use it for pronunciation, hyphenation, spell check, and translation.

<p>The German word <span lang="de">Schadenfreude</span> means joy at others' misfortune.</p>
<p lang="fr">Bonjour le monde!</p>
<q lang="es">Hola mundo</q>

Should always be set on the <html> element first (see html / head / body).

dir

Sets the text direction: ltr (default, left-to-right) or rtl (right-to-left, for Arabic, Hebrew, Persian, Urdu).

<html lang="ar" dir="rtl">
  <body>
    <p>مرحبا بالعالم</p>
  </body>
</html>

Also useful for mixing directions:

<p>The Hebrew word <span dir="rtl" lang="he">שלום</span> means peace.</p>

A third value, auto, lets the browser guess based on character analysis — useful for user-generated content.

7 tabindex

Controls whether an element can receive keyboard focus, and in what order. Critical for keyboard accessibility.

ValueMeaning
tabindex="0"Element is focusable in normal tab order (after native-focusable elements). Use for elements that should be keyboard-reachable but aren't by default (e.g. a custom <div> button).
tabindex="-1"Element is focusable programmatically (el.focus()) but skipped by Tab key. Useful for dialogs, etc.
tabindex="1"+Anti-pattern. Forces a positive tab order that overrides the document's natural order. Avoid.
(absent)Element is focusable only if it's a native focusable element (link, button, input, etc.).
 
<!-- Make a custom div focusable -->
<div tabindex="0" role="button" onclick="doThing()">Click me</div>

<!-- Skip link, programmatically focusable -->
<a href="#main" tabindex="-1" id="skip-link">Skip to content</a>
Common Mistake Don't use tabindex="1", tabindex="2", etc. Positive tabindexes create an unnatural tab order that confuses screen-reader users. Use tabindex="0" (default order) or tabindex="-1" (programmatically focusable only).

8 accesskey

Defines a keyboard shortcut to activate or focus an element.

<button accesskey="s">Save</button>
<a href="/" accesskey="h">Home</a>

Modifier keys vary by platform and browser:

  • Chrome / Firefox on Windows: Alt + S
  • Chrome / Firefox on macOS: ⌃ + ⌥ + S
  • Safari on macOS: ⌃ + ⌥ + S
Common Mistake accesskey is widely considered an accessibility anti-pattern:
  • The modifier keys conflict with OS and screen-reader shortcuts.
  • Users have no way to discover the shortcuts without reading the source.
  • Different browsers use different modifiers, making the shortcuts inconsistent.
Prefer visible keyboard UI (real buttons) or full keyboard-navigation patterns via JavaScript.

9 hidden

The boolean hidden attribute hides an element entirely. It's equivalent to display: none in CSS but is declarative — works even before CSS loads.

<div hidden>
  This content is hidden from all users — sighted, screen-reader, and DOM-tree viewers (well, it's still in the DOM but not rendered).
</div>

<details>
  <summary>Click to expand</summary>
  <p>Revealed content</p>
</details>

<template id="card-template">
  <!-- Templates are inherently hidden -->
</template>
Common Mistake If you apply hidden to an element that has display: flex or display: block via CSS, the CSS wins and the element stays visible. Either remove the CSS or use style="display: none". The CSS [hidden] { display: none !important; } rule is sometimes added to restore expected behaviour.

10 contenteditable

Makes any element editable by the user, like a text field. Useful for in-place editing experiences.

<div contenteditable="true">
  Click and edit me. The text changes as you type.
</div>

<blockquote contenteditable="true">
  Editable quote.
</blockquote>

Try editing this paragraph. Click here and start typing.

Values: true (editable), false (not editable, overrides ancestor's true), inherit (default, inherits from parent).

Common Mistake contenteditable doesn't save changes anywhere — they're lost on refresh. You need JavaScript to read el.innerText and persist it (to localStorage, a server, etc.). Also, browser implementations of contenteditable are notoriously inconsistent — for rich text editors, use a library like ProseMirror or TipTap rather than raw contenteditable.

11 spellcheck

Enables or disables browser spell checking on a text element. Mostly affects <input>, <textarea>, and contenteditable elements.

<input type="text" spellcheck="true">          ← enabled (default for text inputs)
<input type="email" spellcheck="false">       ← disable (emails aren't words)
<textarea spellcheck="true"></textarea>

<div contenteditable="true" spellcheck="true">...</div>

Values: true, false, or empty (browser default).

Pro Tip Disable spellcheck on fields that contain identifiers, code, or technical strings: usernames, API keys, code editors, logins, email addresses. Users get frustrated when their username is underlined in red.

12 translate

Tells translation tools (Google Translate, browser auto-translate, etc.) whether to translate the element's content.

<p>
  <span translate="no">Dropbox</span> is a cloud storage service.
</p>

<!-- Brand names, code, technical terms -->
<code translate="no">const x = 5;</code>

<!-- Username in a comment -->
<a href="/u/123" translate="no">@jane_doe</a>

<!-- Whole document -->
<html lang="en" translate="no">   ← don't translate this page

Values: yes (translate — default), no (don't translate).

13 draggable

Makes an element draggable. Used with the HTML Drag and Drop API.

<div id="card" draggable="true">
  Drag me around.
</div>

<script>
  const card = document.getElementById('card')
  card.addEventListener('dragstart', e => {
    e.dataTransfer.setData('text/plain', 'card-data')
  })

  const dropZone = document.getElementById('drop-zone')
  dropZone.addEventListener('dragover', e => e.preventDefault())
  dropZone.addEventListener('drop', e => {
    e.preventDefault()
    const data = e.dataTransfer.getData('text/plain')
    console.log('Dropped:', data)
  })
</script>

Values: true, false, or auto (browser default — images and links are draggable by default, other elements aren't).

Common Mistake The native Drag and Drop API is famously clunky. For complex drag-and-drop UIs (sortable lists, kanban boards), use a library like SortableJS. For touch devices, native HTML5 drag-and-drop doesn't work — you need a polyfill or pointer events.
