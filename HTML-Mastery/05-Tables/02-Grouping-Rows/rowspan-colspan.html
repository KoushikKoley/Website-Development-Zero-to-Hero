1 What rowspan and colspan do

By default, every cell occupies exactly one row and one column. The rowspan and colspan attributes (only valid on <th> and <td>) let a cell span multiple rows or columns.

Cells E and I use colspan. Visually, they appear to span 2 and 3 cells respectively — but in the source HTML, they're still single cells. The "empty" divs above are placeholders to show what slots the spanning cell occupies.

AttributeAllowed onValueEffect
colspan<th>, <td>Positive integer (default 1)Cell spans N columns horizontally
rowspan<th>, <td>Positive integer (default 1)Cell spans N rows vertically

The catch: every row of the table must still account for the same total number of columns. When a cell spans 2 columns, the next cell in the same row is pushed one column to the right — so you must not add an extra <td> to compensate.

2 The colspan attribute

colspan="N" makes a single cell occupy N columns. The browser visually merges them. Common use: a "no data" message spanning an entire row, or a sub-header above grouped columns.

<table>
  <tr>
    <th scope="col">Name</th>
    <th scope="col">Math</th>
    <th scope="col">Science</th>
  </tr>
  <tr>
    <th scope="row">Ada</th>
    <td>A</td>
    <td>A</td>
  </tr>
  <tr>
    <td colspan="3">No data for second student</td>
    <!-- NO extra <td> here! colspan already covers all 3 -->
  </tr>
</table>

3 The rowspan attribute

rowspan="N" makes a single cell occupy N rows. The browser renders the cell as a tall block. Subsequent rows must not include a cell in that column — the rowspanning cell already fills it.

<table>
  <tr>
    <th scope="col">Day</th>
    <th scope="col">Session</th>
    <th scope="col">Topic</th>
  </tr>
  <tr>
    <td rowspan="2">Monday</td>     <!-- spans 2 rows -->
    <td>Morning</td>
    <td>Algebra</td>
  </tr>
  <tr>
    <!-- NO <td> for "Day" here! rowspan covers it -->
    <td>Afternoon</td>
    <td>Geometry</td>
  </tr>
</table>

4 The calculation rule

The golden rule of merged cells: every row must cover the same number of columns, counting spans. If your table has 4 columns total, every row's cells (summing spans) must equal 4.

The formula For each row: sum of colspan values on cells in this row + count of cells (treating cells already covered by an earlier rowspan as 0) must equal the table's total column count.

Example — a 4-column table with a spanning cell:

<!-- 4 columns total -->
<tr>
  <td>A</td>             <!-- col 1 -->
  <td colspan="2">B</td>  <!-- cols 2-3 (counts as 2) -->
  <td>C</td>             <!-- col 4 -->
</tr>
<!-- Total: 1 + 2 + 1 = 4 ✓ -->

If you accidentally added another <td> after C, the total would be 5 and the browser would render an extra phantom column.

5 Example: weekly schedule

A classic use case — a class timetable where some classes span multiple periods:

<table>
  <caption>Class Schedule — Week of Mar 10</caption>
  <thead>
    <tr>
      <th scope="col">Time</th>
      <th scope="col">Mon</th>
      <th scope="col">Tue</th>
      <th scope="col">Wed</th>
      <th scope="col">Thu</th>
      <th scope="col">Fri</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">9:00</th>
      <td rowspan="2">Math</td>          <!-- 2-period block -->
      <td>English</td>
      <td rowspan="3">Lab</td>           <!-- 3-period lab -->
      <td>History</td>
      <td>English</td>
    </tr>
    <tr>
      <th scope="row">10:00</th>
      <!-- no <td> for Mon — rowspan covers it -->
      <td>Geography</td>
      <!-- no <td> for Wed -->
      <td>Art</td>
      <td>Music</td>
    </tr>
    <tr>
      <th scope="row">11:00</th>
      <td>PE</td>
      <td>Geography</td>
      <!-- no <td> for Wed -->
      <td>English</td>
      <td>Free</td>
    </tr>
  </tbody>
</table>

7 Grouped headers with colspan

When you have nested column headers (e.g., semesters grouping months), you need colspan on the top row plus scope="colgroup" for accessibility:

<table>
  <caption>Student Grades</caption>
  <thead>
    <tr>
      <th scope="col" rowspan="2">Student</th>
      <th scope="colgroup" colspan="2">First Semester</th>
      <th scope="colgroup" colspan="2">Second Semester</th>
    </tr>
    <tr>
      <!-- no <th> for Student — rowspan covers it -->
      <th scope="col">Math</th>
      <th scope="col">Science</th>
      <th scope="col">Math</th>
      <th scope="col">Science</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Ada</th>
      <td>A</td><td>A</td><td>B</td><td>A</td>
    </tr>
  </tbody>
</table>

8 Calculation gotchas

Gotcha 1: Forgetting to remove cells When a cell uses rowspan="3", the next 2 rows must not include a <td> in that column. If you forget and add one anyway, the browser will render an extra column for that row only — visually broken, semantically wrong.
Gotcha 2: Counting with mixed spans In a 4-column row with one cell having colspan="2", you write 3 <td> elements — not 4. The colspanning cell counts as 2.
Gotcha 3: rowspan extending beyond table If rowspan="5" is used in the last row of the table, the extra span is silently ignored by the browser. But it's confusing — set the value to the actual number of rows spanned.
Gotcha 4: colspan="0" The spec says colspan="0" should mean "span all remaining columns", but browser support is inconsistent. Don't use it. Always specify the exact integer.

9 Accessibility with merged cells

Screen readers try to map each cell to its proper row and column header. With merged cells, this gets tricky:

  • Use scope="colgroup" on a header cell that uses colspan.
  • Use scope="rowgroup" on a header cell that uses rowspan.
  • For very complex tables (3+ header levels), scope alone may not be enough — use the headers + id approach instead (see the Scope & Headers deep dive).
<!-- Grouped header with colgroup scope -->
<th scope="colgroup" colspan="2">First Semester</th>

<!-- Complex cell with explicit header references -->
<td headers="q1-math ada q1">A</td>
<th id="q1-math" scope="col">Math</th>
<th id="ada" scope="row">Ada</th>
<th id="q1" scope="colgroup" colspan="2">Q1</th>
Pro Tip Test complex tables with a screen reader. NVDA, JAWS, and VoiceOver all have table navigation modes. Try navigating cell-by-cell with Ctrl+Alt+→ in NVDA and listen to whether the headers are correctly announced.

12 Browser support

Chrome Edge Firefox Safari Opera All mobile browsers

Both attributes have universal support since HTML 3.2 (1997). The only edge case is colspan="0", which has inconsistent support — avoid it. Positive integer values work everywhere.

13 Real-world use cases

Timetables

School/university class schedules where classes span multiple periods.

Conference agendas

Multi-day events with tracks. Keynote sessions span all tracks via colspan.

Comparison tables

"All plans include..." rows spanning every column to announce shared features.

Financial reports

Quarterly grouping with scope="colgroup". "Total" rows with colspan for the label.

Organizational charts

Hierarchy where a manager cell spans multiple subordinate rows.

Sport brackets

Tournament trees with merged cells representing advancing teams.
