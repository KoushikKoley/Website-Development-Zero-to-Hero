<thead>, <tbody>, <tfoot>

The three semantic row-grouping elements. They make tables printable (with repeating headers), screen-reader-friendly, and infinitely more styleable. Plus a tiny HTML5 surprise: <tfoot> can come before <tbody> in source.

1 Why group rows?

Without grouping elements, a table is just a flat sequence of <tr> elements. The browser (and CSS, JavaScript, and screen readers) has no semantic way to distinguish "header rows" from "body rows" from "summary rows".

The three row-grouping elements solve this:

<thead>

"Table head" — wraps the header row(s). One per table. Browsers repeat this on every printed page.

<tbody>

"Table body" — wraps the data rows. There can be more than one <tbody> per table for sub-grouping.

<tfoot>

"Table foot" — wraps summary/total rows. Renders at the bottom; one per table.

Why it matters Grouping gives you semantic hooks for CSS (style the whole <tbody> at once), JavaScript ("select all rows in <tbody>"), and accessibility (screen readers announce section boundaries). It also unlocks print-mode header repetition.

2 The <thead> element

<thead> wraps one or more header rows. It must contain at least one <tr>, and that row should contain <th> cells (not <td>).

<table>
  <caption>Quarterly Sales</caption>
  <thead>
    <tr>
      <th scope="col">Quarter</th>
      <th scope="col">Revenue</th>
      <th scope="col">Growth</th>
    </tr>
  </thead>
  <tbody>
    <!-- data rows -->
  </tbody>
</table>

Rules:

  • Only one <thead> per table.
  • Must come before any <tbody> or <tfoot> in source.
  • Cells inside should typically be <th> — using <td> is allowed but semantically odd.

3 The <tbody> element

<tbody> wraps the main data rows. Unlike <thead> and <tfoot>, you can have multiple <tbody> elements in a single table — useful for sub-grouping data by category:

<table>
  <caption>Employee Directory</caption>
  <thead>
    <tr><th scope="col">Name</th><th scope="col">Role</th></tr>
  </thead>
  <tbody>
    <tr><td>Ada Lovelace</td><td>Engineer</td></tr>
    <tr><td>Alan Turing</td><td>Engineer</td></tr>
  </tbody>
  <tbody>
    <tr><td>Grace Hopper</td><td>Manager</td></tr>
    <tr><td>Linus Torvalds</td><td>Manager</td></tr>
  </tbody>
</table>
Pro Tip The implicit <tbody>: if you write a table with <tr> rows directly inside <table> (no explicit <tbody>), the browser automatically wraps them in a <tbody> in the DOM. You can verify this in DevTools. CSS selectors like tbody td will work even when you didn't write the <tbody> tag.

4 The <tfoot> element

<tfoot> wraps summary rows — totals, averages, footnotes. Visually rendered at the bottom of the table regardless of where it appears in source.

<tfoot>
  <tr>
    <th scope="row">Total</th>
    <td>$162,100</td>
  </tr>
</tfoot>

Rules:

  • One <tfoot> per table (you can technically nest more, but it's invalid and bad practice).
  • Rendered at the bottom of the table in all modern browsers — even if you place it before <tbody> in source.
  • Commonly used for column totals or summary statistics.

5 Source order surprise

Here's an HTML5 fact most developers miss: <tfoot> can come before <tbody> in the source code, and the browser will still render it at the bottom of the table.

<table>
  <caption>Sales Summary</caption>
  <thead>
    <tr><th scope="col">Region</th><th scope="col">Revenue</th></tr>
  </thead>
  <tfoot>
    <tr><th scope="row">Total</th><td>$1.2M</td></tr>
  </tfoot>
  <tbody>
    <tr><th scope="row">North</th><td>$450K</td></tr>
    <tr><th scope="row">South</th><td>$750K</td></tr>
  </tbody>
</table>

Why would you do this? Performance — the browser can start rendering the footer before the entire body is downloaded. In HTML4, this was actually required. In HTML5, both orders are valid.

Common Mistake Some developers write <tfoot> after <tbody> because it reads naturally. That's fine — both orders are valid HTML5. But mixing styles inconsistently across a codebase causes confusion. Pick one and stick with it.

6 Print: repeating headers

When a long table spans multiple printed pages, the browser automatically repeats the <thead> on every page. Without <thead>, the header is printed only once on page 1, and the user has no context for the data on later pages.

7 Sticky headers with <thead>

One of the most common UI patterns: a long scrollable table whose header row sticks to the top of the viewport. This is trivial with <thead> + CSS position: sticky:

.scroll-table-wrap { height: 240px; overflow-y: auto; }
.scroll-table thead th {
  position: sticky;
  top: 0;
  background: #1e293b;   /* opaque! */
  color: white;
  z-index: 1;            /* keep above body cells */
}
Pro Tip The background must be opaque — otherwise the body cells show through as you scroll. The z-index is required because sticky elements create a new stacking context.

8 Styling hooks

The row-group elements give you targeted CSS hooks without needing extra classes:

table { border-collapse: collapse; width: 100%; }

thead th {
  background: #1e293b; color: white;
  font-weight: 600;
  text-align: left;
  padding: 12px;
}

tbody td {
  padding: 10px 12px;
  border-bottom: 1px solid #e2e8f0;
}

/* Zebra striping — only body rows */
tbody tr:nth-child(even) td { background: #f8fafc; }

/* Hover state — only body rows */
tbody tr:hover td { background: #eff6ff; }

tfoot td {
  background: #fef3c7;     /* amber tint */
  font-weight: 600;
  border-top: 2px solid #0f172a;
  padding: 12px;
}

Notice how tbody tr:hover excludes the header and footer from the hover effect — exactly what you want. Without <tbody>, you'd need :not(:first-child):not(:last-child) gymnastics.

10 Common mistakes

MistakeConsequenceFix
Putting <td> directly inside <thead>Invalid HTML. Browsers may auto-wrap or move cells.Always wrap header cells in a <tr>.
Multiple <thead> elementsInvalid HTML. Only one allowed.Merge them, or use multiple <tbody> sections instead.
Forgetting <tbody> when styling body cellsCSS targeting tbody td may behave unexpectedly because the browser auto-inserts <tbody>.Browser's auto-insertion usually works. But be explicit for clarity.
Using <tr> directly inside <table> alongside <thead>The stray <tr> gets auto-wrapped in an implicit <tbody>, breaking intended grouping.Place all body rows inside an explicit <tbody>.
Transparent sticky header backgroundBody cells bleed through the sticky <thead> on scroll.Set an opaque background and a z-index.
Putting <caption> after <thead>Invalid HTML — caption must come first.Caption goes immediately after <table>.

11 Try it yourself

Exercise 1 — Group a table Take any simple table you have and wrap its header row in <thead>, body rows in <tbody>, and add a totals row in <tfoot>. Verify the footer renders at the bottom.
Exercise 2 — Sticky header Build a table with at least 15 body rows. Wrap it in a scrollable container with height: 200px; overflow-y: auto; and apply position: sticky; top: 0; to thead th. Don't forget the opaque background!
Exercise 3 — Test source order Create two identical tables. In the first, place <tfoot> after <tbody>. In the second, place <tfoot> before <tbody>. Confirm both render identically.
Exercise 4 — Print preview Create a long table with 40+ rows that won't fit on one printed page. Add <thead>. Open Print Preview and verify the header repeats on every page.

12 Browser support

Chrome Edge Firefox Safari Opera All mobile browsers Print: header repetition — supported all position: sticky on thead — supported all

All three elements have been supported since the very beginning of HTML 4 (1997). Print-mode header repetition and sticky positioning on <thead> work in every modern browser.

13 Real-world use cases

Financial tables

Income statements with headers, line items in body, totals (revenue, expenses, net income) in footer.

Admin data tables

Sortable columns with sticky headers, summary statistics in <tfoot>.

Shopping carts

Line items in body, subtotal/tax/shipping/total in footer.

Invoices

Items in <tbody>, "Total Due" in <tfoot> with distinct background color.

Sports results

Sticky header rows in long league tables that scroll. Repeated headers when printed.

Reports / dashboards

Multi-section data tables with several <tbody> blocks, each preceded by a section row.
