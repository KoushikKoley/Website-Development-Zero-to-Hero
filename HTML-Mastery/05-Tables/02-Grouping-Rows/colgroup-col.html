Section 5 · Tables · Lesson 5

<colgroup> and <col>

The only HTML mechanism for applying CSS to entire columns. The browser lays out tables row-by-row, so without <colgroup> you'd have to repeat the same style on every cell of a column. <colgroup> fixes that.

1 Why column styling is special

HTML tables are stored and laid out row by row. A <tr> contains cells, and each cell belongs to a "column" only implicitly — there is no <column> element wrapping cells vertically. This means CSS selectors like td:first-child work, but they require every row to be styled individually.

What if you want column 3 to have a fixed width of 200px and a light-blue background? You'd have to:

td:nth-child(3),
th:nth-child(3) {
  width: 200px;
  background: #eff6ff;
}

That works, but it's brittle — if you insert a column later, every selector breaks. Worse: setting width on individual cells doesn't reliably control column width in all browsers — the algorithm is column-based.

Definition The <colgroup> and <col> elements describe the columns of the table as first-class entities. CSS applied to them controls the column's width, background, borders, and visibility — applied once, not per cell.

2 The <colgroup> element

<colgroup> ("column group") is a container that sits inside <table> right after <caption> and before <thead>. It holds one or more <col> elements, or it can apply a span itself.

<table>
  <caption>Project Timeline</caption>
  <colgroup>
    <col>                          <!-- column 1 -->
    <col style="width: 200px;">     <!-- column 2 -->
    <col style="background: #fef3c7;">  <!-- column 3 -->
  </colgroup>
  <thead>
    <tr><th>Task</th><th>Owner</th><th>Due</th></tr>
  </thead>
  <tbody>
    <tr><td>Design mockup</td><td>Ada</td><td>Mar 15</td></tr>
  </tbody>
</table>

Rules:

  • Must be a direct child of <table>.
  • Must come after <caption> (if present) and before <thead>, <tbody>, or <tr>.
  • Can hold zero or more <col> children, OR use its own span attribute (but not both meaningfully).
  • You can have multiple <colgroup> elements in the same table.

3 The <col> element

<col> represents a single column. It's a void element — no closing tag, no content. It applies styling to all cells in that column.

<colgroup>
  <col style="background: #f1f5f9;">   <!-- col 1 -->
  <col>                                <!-- col 2 (no styling) -->
  <col style="width: 80px; text-align: right;">  <!-- col 3 -->
</colgroup>

Each <col> in source order corresponds to one column. The browser matches them positionally — first <col> = column 1, second = column 2, etc.

4 The span attribute

Both <colgroup> and <col> accept a span attribute, an integer specifying how many columns the element covers. This is the short form when you want to style several columns identically:

<!-- Equivalent ways to style 3 columns identically -->

<!-- Verbose: three col elements -->
<colgroup>
  <col style="width: 100px;">
  <col style="width: 100px;">
  <col style="width: 100px;">
</colgroup>

<!-- Concise: one col with span -->
<colgroup>
  <col span="3" style="width: 100px;">
</colgroup>

<!-- Or colgroup itself with span (when all cols share styling) -->
<colgroup span="3" style="width: 100px;"></colgroup>
Common Mistake Mixing span on <colgroup> with child <col> elements is invalid. If <colgroup> has a span attribute, it must be empty (no <col> children). The browser will silently drop the children.

5 Setting column widths

The most common use of <colgroup> is to declare column widths upfront. This speeds up rendering — the browser knows the column widths before processing body cells.

<colgroup>
  <col style="width: 40px;">            <!-- narrow ID column -->
  <col style="width: 200px;">           <!-- medium name column -->
  <col style="width: 60%;">             <!-- description takes remaining -->
</colgroup>

6 Column backgrounds

background applied to a <col> paints the entire column — including header and footer cells. This is the canonical way to highlight a "highlighted" pricing column or a "selected" row indicator column.

7 Column alignment (the text-align trick)

For a long time, text-align on <col> didn't work consistently across browsers. The modern workaround is the CSS :nth-child approach, or to apply text-align to individual cells via td:nth-child(N). However, the new text-align on <col> does work in modern Chrome/Firefox/Safari:

<colgroup>
  <col>                                <!-- left (default) -->
  <col style="text-align: right;">     <!-- right-aligned price -->
  <col style="text-align: center;">    <!-- centered status -->
</colgroup>

8 Pattern: fixed left column

A common UI pattern: the first column (typically row labels) stays fixed while the rest of the table scrolls horizontally. Combined with position: sticky on both <col> and the cells, this is achievable:

<style>
  .freeze-table-wrap { overflow-x: auto; }
  .freeze-table { border-collapse: collapse; }
  .freeze-table thead th { position: sticky; top: 0; background: #1e293b; color: white; z-index: 2; }
  .freeze-table tbody th { position: sticky; left: 0; background: #f1f5f9; z-index: 1; }
  .freeze-table thead th:first-child { z-index: 3; } /* corner */
</style>

<div class="freeze-table-wrap">
  <table class="freeze-table">
    <caption>Sales by Region × Month</caption>
    <colgroup>
      <col style="width: 120px;">     <!-- fixed region column -->
      <col span="12" style="width: 80px;">  <!-- 12 month columns -->
    </colgroup>
    <thead>
      <tr>
        <th scope="col">Region</th>
        <th scope="col">Jan</th> ... <th scope="col">Dec</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <th scope="row">North</th>
        <td>...</td> ... <td>...</td>
      </tr>
    </tbody>
  </table>
</div>
Pro Tip The corner cell (top-left) needs a higher z-index than the body cells because both the sticky header and sticky body want to render there. Set the corner cell's z-index to 2 or 3 to keep it visible.

9 CSS limitations on <col>

Because the table layout algorithm is row-major, most CSS properties don't apply cleanly to <col>. Here's the truth table:

CSS propertyApplies to <col>?Notes
width✅ YesThe primary use case.
background✅ YesPaints all cells in the column.
visibility: collapse✅ YesHides the entire column (modern browsers).
border⚠️ LimitedWorks in some browsers when border-collapse: collapse; unreliable otherwise.
text-align⚠️ Modern onlyWorks in current Chrome/Firefox/Safari. Older browsers ignore it.
color⚠️ InheritsSets the inherited color, but explicit cell color wins.
padding❌ NoUse padding on td/th instead.
font-weight⚠️ InheritsInherited but not reliably applied to cell text.
vertical-align❌ NoApply to individual cells.
Recommendation Use <colgroup>/<col> only for width, background, and visibility. For everything else, use cell-level selectors (td:nth-child(N)).

10 Common mistakes

MistakeWhy it failsFix
Putting <colgroup> after <thead>Invalid HTML; browser may drop the <colgroup>.Place <colgroup> immediately after <caption>, before <thead>.
Putting text inside <colgroup> or <col>Both are contentless elements.<col> is void; <colgroup> only holds <col> children.
Using span on <colgroup> while also having <col> childrenInvalid; the children are dropped.Pick one: span on <colgroup>, or children.
Trying to apply padding via <col>Property doesn't propagate.Use td:nth-child(N) { padding: ... }.
Mismatched column countHaving 5 columns of data but only 4 <col> elements — the 5th column gets default width.Ensure <col> count matches actual column count (counting spans).
Using border on <col> with border-collapse: separateBorder doesn't render.Switch to border-collapse: collapse, or border the cells instead.

11 Try it yourself

Exercise 1 — Set column widths Create a 4-column table (Name, Email, Phone, Status). Use <colgroup> and <col> to give the Name column 150px, Email 25%, Phone 150px, and Status the rest.
Exercise 2 — Highlight a column Build a 3-tier pricing table (Basic, Pro, Enterprise). Use <col> with a background color on the middle column to highlight the "Pro" plan as recommended.
Exercise 3 — Use the span shortcut Create a 12-column table (one per month) where all columns should be 80px wide. Use a single <col span="12"> instead of 12 separate <col> elements.
Exercise 4 — Sticky left column Build a sales matrix with 5 regions (rows) and 12 months (columns). Apply position: sticky; left: 0; to the first column's <th> and <td>. Wrap the table in a horizontally-scrollable container. Verify the region labels stay visible as you scroll right.

12 Browser support

Chrome — full Edge — full Firefox — full Safari — full Opera — full width / background / visibility — universal text-align on col — modern only padding / vertical-align on col — not supported

The elements themselves work everywhere. The variation is which CSS properties actually take effect. For maximum browser compatibility, use <col> only for width, background, and visibility: collapse.

13 Real-world use cases

Pricing tables

Highlight the recommended plan with a column background. Set fixed widths so all plans align side-by-side.

Schedule / matrix grids

Equal-width columns for time slots or categories. Fixed first column for row labels.

Financial reports

Set the account-name column to 200px and number columns to right-aligned 100px.

Data dashboards

Use visibility: collapse on a <col> for a "hide column" UI feature — no DOM rebuild required.

Comparison tables

Wider first column for feature names; narrower columns for each product's data.

Calendars

7 equal-width day columns. <col span="7" style="width: 14.28%;"> is a clean one-liner.
