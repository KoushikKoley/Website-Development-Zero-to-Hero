1 Why tables exist

HTML tables were introduced in HTML 2.0 (1995) for one purpose: to display tabular data — information that naturally lives in a grid of rows and columns. Think spreadsheets, price lists, train schedules, sports results, comparison charts, financial reports.

The element model is simple but powerful: a <table> contains one or more <tr> rows, each of which contains one or more <td> cells. The browser takes care of computing column widths, row heights, and alignment so you don't have to.

Definition Tabular data is data where each row represents one record and each column represents one attribute of that record. If you can describe your data as "a list of things, each with the same set of properties", you have tabular data.

2 Anatomy of a table

The minimal valid table has three nested elements:

<table> <tr> <td>Cell A</td> <td>Cell B</td> </tr> <tr> <td>Cell C</td> <td>Cell D</td> </tr> </table> <!-- 2 rows × 2 columns -->

The hierarchy is strict: you cannot place a <td> directly inside <table> without a <tr> wrapper, and you cannot place text directly inside <table>. The browser may auto-correct malformed markup, but the result is unpredictable.

<table>

The container. Represents the entire grid. Block-level. No default border.

<tr>

"Table Row". A horizontal slice of the table. Cannot hold text directly — only cells.

<td>

"Table Data". A single cell. Holds the actual content: text, images, even other tables.

3 The <table> element

The <table> element is the root container. It establishes a grid context in which its descendant rows and cells are laid out by a special table layout algorithm, distinct from normal CSS block-and-inline flow.

Useful attributes

AttributePurposeNotes
borderLegacy border thicknessDeprecated for styling. Use CSS border instead.
cellpaddingPadding inside cellsDeprecated. Use CSS padding on td.
cellspacingSpace between cellsDeprecated. Use CSS border-spacing.
widthTable widthDeprecated. Use CSS width.
summaryAccessibility descriptionDeprecated in HTML5. Use <caption> or <figcaption> instead.
Common Mistake Never write <table border="1" cellpadding="8"> in modern code. These presentational attributes are deprecated in HTML5 and were always a maintainability nightmare — they mix structure with style. Use the CSS equivalents shown above.

4 The <tr> element

A <tr> ("table row") groups horizontally adjacent cells into a single row. The browser determines the row's height as the maximum of all its cells' contents. Every <tr> must live directly inside a <table>, <thead>, <tbody>, or <tfoot>.

<table>
  <tr>                   <!-- Row 1 -->
    <td>Apple</td>
    <td>Banana</td>
  </tr>
  <tr>                   <!-- Row 2 -->
    <td>Cherry</td>
    <td>Date</td>
  </tr>
</table>

A <tr> has very few meaningful attributes in modern HTML. The old bgcolor, align, and valign attributes are all deprecated — target rows with CSS (tr:nth-child(even), classes, or data-*) instead.

5 The <td> element

<td> ("table data") is the workhorse — a single cell that holds content. It can contain almost anything: text, links, images, lists, even nested tables (though nesting tables is usually a design smell).

Important attributes

AttributePurposeExample
colspanCell spans N columns<td colspan="2">
rowspanCell spans N rows<td rowspan="3">
headersIDs of associated header cells (a11y)<td headers="q1-total">
abbrAbbreviated form for screen readers<td abbr="USD">US Dollars</td>

colspan and rowspan are covered in depth in the Rowspan & Colspan lesson. For now, focus on plain cells.

6 Default browser styling

If you write a table with no CSS, every browser renders it the same minimal way:

  • No border — cells touch each other invisibly.
  • Cell padding is zero — text butts up against the cell edge.
  • No background — transparent.
  • Auto width — columns size to their widest content.
  • Left-aligned horizontally, middle-aligned vertically.
  • border-collapse: separate — cells have a small gap you cannot see without borders.

7 Your first 3-column table

Let's build a small product table from scratch, adding just enough CSS to be readable. Notice we use scope="col" on the header cells — we'll explain why in the TH & Scope lesson.

<table>
  <caption>Top-selling fruit this week</caption>
  <tr>
    <th scope="col">Product</th>
    <th scope="col">Price</th>
    <th scope="col">Stock</th>
  </tr>
  <tr>
    <td>Apple</td>
    <td>$1.20</td>
    <td>128 in stock</td>
  </tr>
  <tr>
    <td>Banana</td>
    <td>$0.50</td>
    <td>240 in stock</td>
  </tr>
  <tr>
    <td>Cherry</td>
    <td>$3.99</td>
    <td>Sold out</td>
  </tr>
</table>

<style>
  table { border-collapse: collapse; width: 100%; }
  th, td { border: 1px solid #cbd5e1; padding: 8px 12px; text-align: left; }
  th { background: #f1f5f9; }
</style>

Pro Tip Note how the <caption> is the first child of <table>. That's mandatory. Putting it elsewhere means browsers may silently move it (or ignore it). More on <caption> in the dedicated Caption lesson.

8 Never use tables for layout

In the late 1990s and early 2000s, before CSS was powerful enough, developers abused tables to create multi-column page layouts: header on top, sidebar on the left, content on the right, footer on the bottom. This practice is dead and you must not revive it.

Why table layouts are harmful

ProblemExplanation
Accessibility disasterScreen readers announce the page linearly. A table layout forces a visually-impaired user to navigate meaningless "row/column" semantics instead of headings, regions, and landmarks.
RigidYou cannot reorder columns responsively without rewriting the markup. A CSS Grid or Flexbox layout reflows with one media query.
Slow renderingBrowsers must compute the entire table before painting. Modern layout engines are much faster for non-table layouts.
SEO penaltySearch engines expect content order to follow the document outline. Table layouts scramble the reading order.
Maintenance painNested tables-within-tables-within-tables ("table soup") were the original "spaghetti markup". You will cry.
Hard rule Use <table> only for tabular data. Use CSS Grid, Flexbox, or Multi-column layout for visual page structure. No exceptions.
Wrong (don't do this)
<table>
  <tr>
    <td colspan="2">Header</td>
  </tr>
  <tr>
    <td>Sidebar</td>
    <td>Main content</td>
  </tr>
</table>
Right (use CSS Grid)
<div class="layout">
  <header>Header</header>
  <aside>Sidebar</aside>
  <main>Main content</main>
</div>

<style>
  .layout { display: grid;
    grid-template-areas: "header header" "sidebar main";
    grid-template-columns: 200px 1fr; }
  header { grid-area: header; }
  aside  { grid-area: sidebar; }
  main   { grid-area: main; }
</style>

9 Common mistakes

MistakeWhy it breaksFix
Putting <td> directly inside <table>Invalid HTML; browser may auto-insert a <tr> in unexpected places.Always wrap cells in <tr>.
Using border="1", cellpadding, cellspacingDeprecated presentational attributes. Hard to override with CSS.Use CSS properties on table, th, td.
Ragged rows (varying cell counts)Browser must guess where columns go; layout shifts.Every row should have the same number of cells (counting spans).
Using tables for layoutBreaks accessibility, responsiveness, and SEO.Use CSS Grid or Flexbox.
Forgetting <caption> or headersScreen reader users can't understand the table's purpose.Add <caption> and use <th scope>.
Whitespace between <td> tagsWhitespace inside cells collapses, but stray text nodes between cells can confuse the parser.Keep cell content inside <td>.

11 Browser support

<table>, <tr>, and <td> are some of the oldest elements in HTML. They work everywhere — every browser, every screen reader, every rendering engine.

Chrome Edge Firefox Safari Opera All mobile browsers Screen readers (NVDA, JAWS, VoiceOver)

The only "support" caveat is that the deprecated presentational attributes (border, cellpadding, cellspacing) still render visually in most browsers — but they are marked deprecated in the HTML spec and may be removed. Don't rely on them.

12 Real-world use cases

Product comparison

Feature-by-feature comparison of two or more products (e.g., phone specs, SaaS plans). The natural fit for tabular data.

Financial statements

Income statements, balance sheets, cash-flow tables — built on <thead>, <tbody>, and number-aligned cells.

Schedules

Train timetables, class schedules, conference agendas. Often use rowspan/colspan to merge cells.

Admin dashboards

User lists, order logs, server metrics tables in admin panels. Frequently paired with sortable columns via JS.

Sports results

League tables, scoreboards, fixtures. Cells often contain both text and small images (team crests).

Pricing tables

Side-by-side subscription tiers with checkmarks/crosses per feature. Often styled as cards on mobile.
