The <caption> element

The right way to title a table. Not an <h3> floating above it. Not a <p> outside the <table>. <caption> lives inside the table, binds semantically to it, and is announced by screen readers as the table's title.

1 Why <caption> exists

Every table needs a title — a short, human-readable description of what the data shows. Without a title, a screen reader user navigating by table element hears "Table with 4 rows and 3 columns" and has no idea what the data is about until they explore every cell.

The <caption> element provides that title semantically bound to the table. Screen readers announce it as the table's name when the user first encounters the table, giving context before they dive in.

Definition The <caption> element represents the title of its parent <table>. It must be the first child of the table. Each table may have at most one caption.

2 Placement rules

The HTML spec is strict: a <caption> must be the first child of the <table> element — before any <tr>, <thead>, <tbody>, or <colgroup>.

<table>
  <caption>Monthly Sales Report — Q1 2025</caption>   <!-- first! -->
  <thead>
    <tr>
      <th scope="col">Month</th>
      <th scope="col">Revenue</th>
    </tr>
  </thead>
  <tbody>
    <tr><th scope="row">January</th><td>$48,200</td></tr>
    <tr><th scope="row">February</th><td>$52,100</td></tr>
    <tr><th scope="row">March</th><td>$61,800</td></tr>
  </tbody>
</table>
Common Mistake Putting <caption> anywhere other than immediately after <table> is invalid HTML. Some browsers silently relocate stray captions; others drop them. Always place it first.

Without any CSS, browsers render the caption above the table, centered, with normal text weight. Almost every real-world project restyles this — but the default is acceptable and accessible.

4 <caption> vs <h3> vs <figcaption>

Developers often title tables by sticking an <h3> above them:

<h3>Monthly Sales Report</h3>
<table>
  <!-- ... -->
</table>

This works visually but is semantically wrong. The heading and the table are now separate elements — a screen reader user has no way to know the heading applies to the table. When they jump straight to the table (which screen readers let them do), they miss the title.

ElementWhen to useAccessibility
<caption>Inside a <table>, providing its titleAnnounced as the table's name. Best practice.
<h3> above tableNever — use <caption> insteadDisjointed from the table. Screen reader users may miss the link.
<figcaption>Inside a <figure> wrapping the table, when the table is referenced by surrounding textGood if you're treating the table as a figure with a number ("Table 1: ...")
<p> above tableNever for titlesNo semantic link to the table.
Pro Tip Use <caption> for "this is what this table shows". Use <figcaption> inside a <figure> when you're labeling the table as a numbered reference (e.g., in academic articles or technical reports). The patterns can be combined: a <figure> with a <figcaption> can wrap a <table> that has its own internal <caption>.

5 The caption-side CSS property

CSS lets you move the caption above or below the table without changing the HTML:

table { caption-side: top; }    /* default */
table { caption-side: bottom; } /* caption below */
/* CSS Logical Properties (newer, supports RTL writing modes) */
table { caption-side: inline-end; }
table { caption-side: inline-start; }
caption-side: bottom (common in financial reports)
Source: WHO Global Health Observatory, 2024
Country Life expectancy
Japan84.6
Switzerland83.9
Spain83.6

Move the caption to the bottom when it acts as a footnote (e.g., source citation) rather than a title. Keep it on top when it acts as a title.

6 Styling captions

The caption inherits font properties from the table but is otherwise plain. Common styling patterns:

caption {
  text-align: left;
  font-weight: 600;
  font-size: 1.05rem;
  padding: 8px 0 12px;
  color: #0f172a;
}

/* Subtitle pattern: main title + description below */
caption .subtitle {
  display: block;
  font-weight: 400;
  font-size: 0.9rem;
  color: #64748b;
  margin-top: 2px;
}
Styled caption with subtitle
Q1 2025 Revenue Breakdown All figures in USD. Source: Internal Finance System.

Pro Tip You can put <span>, <strong>, or even <a> inside <caption>. Avoid block elements like <div> or <p> — they're technically permitted in HTML5 but break rendering in some older browsers.

7 Accessibility benefits

Screen readers expose tables as navigable landmarks. When the user presses their "next table" key (in NVDA: T; in JAWS: T; in VoiceOver: VO+Cmd+T), the first thing they hear is the caption.

Without caption

"Table. 4 rows, 3 columns. Row 1 of 4. Rank, header. 1."

With caption

"Top 3 cities by population. Table. 4 rows, 3 columns. Row 1 of 4. Rank, header. 1."

The difference is night and day. The caption gives users an immediate mental model of the data before they explore it.

WCAG 2.1 Success Criterion 1.3.1 (Info and Relationships) recommends captions for tables. SC 2.4.6 (Headings and Labels) requires that labels be descriptive — your caption must actually describe the table, not just say "Data".

8 Multiple captions pattern

HTML allows only one <caption> per table. But you often need both a title and a description. The pattern is:

<table>
  <caption>
    <!-- Main title -->
    Employee Salaries 2025
    <!-- Description as a styled inline span -->
    <span class="desc">
      Annual base salary in USD. Excludes bonuses and equity.
    </span>
  </caption>
  ...
</table>

For longer descriptions (e.g., methodology notes), use the <details> element inside or after the caption:

<table>
  <caption>Q1 Financial Summary</caption>
  <colgroup><col><col></colgroup>
  <tr><th>Metric</th><th>Value</th></tr>
  <tr><td>Revenue</td><td>$162K</td></tr>
</table>
<details>
  <summary>Methodology</summary>
  <p>Figures derived from internal Salesforce export...</p>
</details>
Pro Tip For tables inside <figure>, use <figcaption> for the figure caption AND <caption> for the table's own accessible name. They serve different roles: <figcaption> labels the figure (often "Table 1: ..."), while <caption> labels the table itself for screen readers.

9 Common mistakes

MistakeWhy it's wrongFix
Using <h3> above the tableHeading and table are separate elements; screen reader users miss the connection.Use <caption> inside the table.
Putting <caption> after <thead> or <tr>Invalid HTML. Browser may move it or drop it.Caption must be the first child of <table>.
Empty <caption>Screen reader announces "Table." with no title — confusing.Always write a meaningful caption.
Vague captions like "Data"Doesn't help users understand the table's purpose.Write a descriptive title: "Q1 2025 Sales by Region".
Multiple <caption> elementsInvalid HTML; only the first is used.Combine title + description into one caption with a span, or use <details>.
Putting block elements inside <caption>Permitted in HTML5 but renders inconsistently.Use inline elements: <span>, <strong>, <a>.

10 Try it yourself

Exercise 1 — Add a caption Take any table you've built so far. Add a descriptive <caption> as the first child of the <table>. Verify in your browser that it renders above the table by default.
Exercise 2 — Move it below Use caption-side: bottom to move the caption below the table. Add a small italic style to make it look like a source citation.
Exercise 3 — Caption with subtitle Create a caption that shows a main title in bold and a smaller subtitle below it using a <span> with display: block. The subtitle should describe the units of measurement.
Exercise 4 — Caption vs h3 Build two versions of the same table: one with an <h3> above, and one with <caption> inside. Open the Web Developer Tools Accessibility tree (Firefox/Chrome) and notice how only the <caption> version shows the table with a proper accessible name.

11 Browser support

Chrome Edge Firefox Safari Opera All mobile browsers NVDA / JAWS / VoiceOver

The caption-side property has full support including the newer logical-property values (inline-start / inline-end) in all modern browsers since 2021. The legacy top / bottom values are universally supported.

12 Real-world use cases

Financial reports

Q1 earnings, balance sheets, cash flow tables. Caption doubles as the report title; subtitle gives units.

Sports standings

"Premier League Table 2024/25" — screen reader users jump straight to it.

Schedule tables

"Week 12 Bus Timetable" — captions help commuters using assistive tech find the right schedule.

Academic papers

Combined with <figure>+<figcaption> for "Table 1: ..." numbering.

Admin dashboards

"Recent orders" panel — caption identifies the table to screen reader users navigating by table landmark.

Pricing pages

"Plan comparison" caption makes the comparison clear to everyone, including search engines.
