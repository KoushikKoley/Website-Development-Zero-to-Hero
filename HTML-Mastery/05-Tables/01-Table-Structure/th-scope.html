<th> and the scope attribute

The header cell is the single most powerful accessibility feature in HTML tables. Without scope, a screen reader user is lost. With it, every cell announces its row and column context — like a coordinate readout.

1 What is <th>?

<th> stands for "table header". It marks a cell as a header rather than a data cell. Headers describe the meaning of the cells around them: column headers describe the cells below them, row headers describe the cells to their right.

<table>
  <tr>
    <th scope="col">Name</th>
    <th scope="col">Email</th>
    <th scope="col">Role</th>
  </tr>
  <tr>
    <td>Ada Lovelace</td>
    <td>ada@example.com</td>
    <td>Admin</td>
  </tr>
</table>

Visually, the <th> cells get rendered bold and centered by default — but that's not what makes them important. The semantic role is what counts: it tells assistive technology (and search engines) "this cell describes a row or column of data".

2 <th> vs <td>

The two cell elements look similar but serve very different purposes:

Aspect<th><td>
Semantic roleHeader — describes other cellsData — holds a value
Default weightBoldNormal
Default alignmentCenterLeft
Implicit scopeIf no scope attr, treated as col when in <thead> or first row, row when in first column — but explicit is betterNot applicable

Pro Tip You can put a <th> anywhere — including in the middle of a table — but the convention is to keep headers in the first row, first column, or both. Reserve <th> for cells whose primary job is labeling, not holding data.

3 Default styling

Every browser styles <th> cells with:

  • font-weight: bold
  • text-align: center (most browsers — Chrome/Firefox/Safari)
  • A small default padding (varies by browser)
Default rendering (no CSS)
NameEmail
Adaada@example.com

You can override any of this with CSS. A common pattern is th { text-align: left; } to match Western reading flow, and a subtle background color to make headers stand out:

th {
  text-align: left;
  background: #f1f5f9;
  font-weight: 600;
  padding: 10px 12px;
  border-bottom: 2px solid #cbd5e1;
}

4 The scope attribute

The scope attribute tells screen readers which cells a given header cell describes. Without it, screen readers must guess based on position — and they often guess wrong, especially in complex tables.

+-------+-------+-------+ | TH col | TH col | TH col | <-- scope="col" applied to each +-------+-------+-------+ |TH row | td | td | <-- scope="row" applied to first cell +-------+-------+-------+ |TH row | td | td | +-------+-------+-------+

The four allowed values

ValueApplies toUse case
colHeader cells in the first rowEach header describes one column of data below it
rowHeader cells in the first columnEach header describes one row of data to its right
colgroupHeader cells spanning multiple columns (with colspan)The header describes several columns grouped together
rowgroupHeader cells spanning multiple rows (with rowspan)The header describes several rows grouped together
Key insight scope doesn't change anything visually. It only affects how assistive technology navigates the table. But that means it's essential for ~15% of users who depend on screen readers.

5 scope="col"

Use scope="col" on header cells in the first row of the table. Each such header describes the column beneath it.

<table>
  <tr>
    <th scope="col">Product</th>
    <th scope="col">Price</th>
    <th scope="col">Stock</th>
  </tr>
  <tr><td>Apple</td><td>$1.20</td><td>128</td></tr>
  <tr><td>Banana</td><td>$0.50</td><td>240</td></tr>
</table>
Rendered output — Apple cell announced as "Product, Apple"
Product Price Stock
Apple$1.20128
Banana$0.50240
Pro Tip Screen reader narration with proper scope: "Product, Apple, Price, one dollar twenty, Stock, one hundred twenty eight". Without scope, the user just hears "Apple, one dollar twenty, one hundred twenty eight" — no context.

6 scope="row"

Use scope="row" on the first cell of each data row when that cell identifies the row. This is common for tables where each row is a named entity (a person, a country, a product):

<table>
  <tr>
    <th scope="col">Country</th>
    <th scope="col">Capital</th>
    <th scope="col">Population</th>
  </tr>
  <tr>
    <th scope="row">France</th>
    <td>Paris</td>
    <td>67M</td>
  </tr>
  <tr>
    <th scope="row">Japan</th>
    <td>Tokyo</td>
    <td>125M</td>
  </tr>
</table>
Rendered output — Paris announced as "Capital, France, Paris"
Country Capital Population
France Paris 67M
Japan Tokyo 125M

Notice that the first column now mixes <th scope="row"> (in body rows) and <th scope="col"> (in the header row). That's perfectly valid and extremely common.

7 scope="colgroup" and scope="rowgroup"

When a header cell spans multiple columns (using colspan), you should use scope="colgroup". Likewise for rowspan and scope="rowgroup".

<table>
  <tr>
    <th scope="col" rowspan="2">Student</th>
    <th scope="colgroup" colspan="2">First Semester</th>
    <th scope="colgroup" colspan="2">Second Semester</th>
  </tr>
  <tr>
    <!-- Nested column headers, each scope="col" -->
    <th scope="col">Math</th>
    <th scope="col">Science</th>
    <th scope="col">Math</th>
    <th scope="col">Science</th>
  </tr>
  <tr>
    <th scope="row">Ada</th>
    <td>A</td>
    <td>A</td>
    <td>B</td>
    <td>A</td>
  </tr>
</table>
Rendered output — grouped headers
Student First Semester Second Semester
Math Science Math Science
Ada A A B A
Alan B A A B
Common Mistake Forgetting scope="colgroup" on grouped headers means screen readers can't connect the group header (e.g., "First Semester") with the sub-headers (e.g., "Math", "Science"). For very complex tables, scope alone is not enough — see the Scope & Headers deep dive.

8 Why this matters

According to the World Health Organization, an estimated 2.2 billion people worldwide have some form of vision impairment. Many of them rely on screen readers to navigate the web. When you skip scope, you make every table on your site a maze.

WCAG 2.1 Success Criterion 1.3.1

"Info and Relationships" requires that information and relationships conveyed through presentation are programmatically determined. scope is exactly that: it makes row/column relationships explicit.

Section 508 / EAA

Government and EU public-sector sites are legally required to use proper table headers. Skipping scope is a real compliance violation.

SEO benefit

Search engines parse tables for structured data (recipes, prices, schedules). Proper headers improve how your data appears in rich results.

Maintainability

Headers also help human developers understand the table structure six months later. Future-you will thank present-you.

9 Common mistakes

MistakeImpactFix
Using <td> with font-weight: bold instead of <th>Screen reader treats it as data, not a header. Loses semantic meaning.Use <th>; style with CSS if needed.
Using <th> without scopeScreen readers guess based on position — usually right for simple tables, wrong for complex ones.Always add scope explicitly.
Adding scope to a <td>Invalid HTML. scope only belongs on <th>.Use <th> instead.
Setting scope="col" on row headers (or vice versa)Screen reader announces wrong context, confusing users.Double-check the value matches the header's actual role.
Naming headers vaguely ("Column 1", "Data")Screen reader wastes time on useless labels.Use descriptive labels: "Quarterly Revenue", not "Q1".

Exercise 2 — Grouped headers Build a sales table with a top row grouped by region ("North America", "Europe"), and a sub-row of months ("Jan", "Feb"). Use scope="colgroup" on the region headers.
Exercise 3 — Screen reader test Turn on VoiceOver (Mac: Cmd+F5), NVDA (Windows: free download), or ChromeVox (Chrome extension). Navigate your Exercise 1 table with the Tab key. Listen for how it announces headers. Now compare with a version that lacks scope — what changes?
Exercise 4 — CSS restyle Take your Exercise 1 table and write CSS that styles <th> differently from <td>: bold dark header background, white text, left-aligned. Confirm scope itself does not change the visual appearance.

11 Browser support

The scope attribute has universal browser support. The variation is in how well different screen readers use it:

HTML5 spec — supported NVDA — full JAWS — full VoiceOver (Mac/iOS) — full TalkBack (Android) — full Chrome / Edge / Firefox / Safari

Note: very old screen readers (2005-era) sometimes ignored scope in favor of the more verbose headers/id approach. Modern screen readers all honor scope properly. For complex tables where scope is insufficient, see the Scope & Headers lesson.

12 Real-world use cases

Data grids

Sortable admin tables always use <th scope="col"> so users navigating by header can find the sort buttons.

Pricing tables

Feature comparison with feature names in the first column (scope="row") and plan names in the header row (scope="col").

Forms in tables

Form-field labels in the first column become <th scope="row"> for clean a11y.

Schedule grids

Conference schedules with time slots as row headers and rooms as column headers.

Stat dashboards

Year/quarter grouping with colgroup for grouped headers.

Exam results

Student names as row headers, subjects as column headers, grade in cells.
