1 The styling landscape

Tables have a special CSS layout algorithm with several properties that apply only to tables — there's nothing like border-collapse for flexbox or grid. Mastering these properties is the difference between "the table looks OK" and "the table looks professional".

The core properties:

  • border-collapse — merge or separate cell borders
  • border-spacing — gap between cells in separate mode
  • empty-cells — show/hide borders on empty cells
  • table-layout — auto vs fixed column width algorithm
  • caption-side — where the caption sits
  • vertical-align — cell content alignment (also works on cells)

Plus regular CSS properties (background, color, padding, border) applied to table, th, and td.

2 border-collapse

This single property is the foundation of table styling. Two values:

ValueEffectUse when
separate (default)Each cell has its own borders; border-spacing creates gaps between them.You want visible spacing between cells, or sticky headers with separate background.
collapseAdjacent cells share a single border line. No gaps.You want clean, continuous borders. The standard for data tables.
 
/* The standard modern table reset */
table {
  border-collapse: collapse;
  width: 100%;
}
th, td {
  border: 1px solid #cbd5e1;
  padding: 8px 12px;
}

Pro Tip Always set border-collapse explicitly. Relying on the default separate value is the source of countless "why does my table have weird gaps?" tickets.

3 border-spacing

Only applies when border-collapse: separate. Sets the gap between cells. Accepts one or two lengths:

table {
  border-collapse: separate;
  border-spacing: 4px;             /* uniform gap */
  border-spacing: 4px 8px;        /* 4px horizontal, 8px vertical */
}

This replaces the deprecated cellspacing HTML attribute. The two-value form takes (horizontal, vertical) — same convention as margin shorthand.

4 empty-cells

Also requires border-collapse: separate. Controls whether empty cells render their borders:

table { border-collapse: separate; }
table { empty-cells: show; }   /* default — borders visible */
table { empty-cells: hide; }  /* empty cells lose their borders */

Most modern designs use border-collapse: collapse instead, which makes empty-cells irrelevant. But for designs that need visible cell spacing, empty-cells: hide can prevent ugly empty cells in sparse data.

Pro Tip For real "no data" cells, use an explicit placeholder like — or N/A rather than relying on empty cells. Screen reader users get nothing from an empty cell.

5 table-layout

The most important performance property for tables. Two algorithms:

ValueAlgorithmSpeedUse when
auto (default)Browser reads all rows to find the widest content per column, then sizes columns. Reflows on every row.Slow for big tablesSmall tables (<50 rows), or content width varies wildly
fixedBrowser uses only the first row (or <col> widths) to set column widths. No reflow as more rows load.FastLarge tables, dynamic data, streaming rows
 
table {
  table-layout: fixed;
  width: 100%;
}

/* With table-layout: fixed, you MUST declare column widths */
colgroup col:nth-child(1) { width: 120px; }
colgroup col:nth-child(2) { width: 200px; }
colgroup col:nth-child(3) { width: auto; }   /* takes remaining */
Gotcha With table-layout: fixed, if you don't specify column widths, the browser distributes widths equally — which is rarely what you want. Always pair table-layout: fixed with explicit widths via <colgroup>/<col> or <th> widths.

6 Cell padding

Padding on <th> and <td> gives text room to breathe. The default is zero in most browsers — always set it explicitly. This replaces the deprecated cellpadding HTML attribute.

th, td {
  padding: 10px 14px;   /* generous for desktop */
  line-height: 1.5;
}

@media (max-width: 600px) {
  th, td { padding: 6px 8px; }   /* tighter on mobile */
}
Pro Tip For dense data tables, prefer 8px-12px padding. For marketing/pricing tables, 16px-20px. Never use less than 6px — the table feels cramped and rows become hard to scan.

7 Zebra striping

The classic pattern: alternating row backgrounds for visual scannability. Use :nth-child(even) (or odd) on body rows only — never header or footer:

tbody tr:nth-child(even) td {
  background: #f8fafc;
}

/* Make sure hover overrides stripe */
tbody tr:hover td {
  background: #dbeafe;
}

8 Hover states

Hover highlights the entire row, helping users track which row they're scanning. Apply the hover to the <tr> but the background to the <td> — because cells, not rows, hold the background in collapsed-border tables:

tbody tr:hover td {
  background: #eff6ff;
}

/* For a "selected" state */
tbody tr.selected td {
  background: #dbeafe;
  font-weight: 600;
}
Common Mistake Setting background on tr:hover directly works in some browsers but is unreliable. Always target the cells: tr:hover td.
Pro Tip Add a CSS transition for smoothness: tbody td { transition: background 0.15s ease; }. Avoid longer transitions — they make data tables feel sluggish.

9 Sticky headers

The pattern: wrap the table in a scrollable container, set position: sticky; top: 0; on the <thead>'s <th> cells. The header stays visible while body rows scroll under it.

.table-scroll {
  max-height: 240px;
  overflow-y: auto;
  border: 1px solid #cbd5e1;
}

.table-scroll thead th {
  position: sticky;
  top: 0;
  background: #1e293b;   /* MUST be opaque */
  color: white;
  z-index: 1;
}

Sticky header gotchas
  • The background must be opaque — otherwise body cells bleed through as you scroll.
  • Set z-index: 1 (or higher) so the header paints above the body.
  • If you have sticky body columns too (horizontal + vertical scroll), the corner cell needs a higher z-index than both.

10 Number alignment

Numeric columns should be right-aligned (or decimal-aligned) so digits line up. This is the most common table styling oversight in the wild.

/* Right-align numeric columns */
tbody td.num { text-align: right; }
th.num { text-align: right; }

/* Decimal alignment via tabular figures */
.num { font-variant-numeric: tabular-nums; }
Pro Tip Use font-variant-numeric: tabular-nums on numeric cells. It makes digits monospace-width so columns line up vertically even with proportional fonts.

12 Try it yourself

Exercise 1 — Full reset Take a bare HTML table with no styling. Apply: border-collapse: collapse, 1px gray borders on cells, 10px padding, header background, left text alignment. Notice the dramatic improvement.
Exercise 2 — Zebra + hover Add zebra striping to alternate body rows. Add a hover state that overrides the stripe color. Test that hover works on both even and odd rows.
Exercise 3 — Sticky header Build a table with 12+ rows. Wrap it in a container with max-height: 200px; overflow-y: auto. Apply position: sticky; top: 0 to header cells. Don't forget the opaque background!
Exercise 4 — Fixed layout Build a 3-column table. Set table-layout: fixed and declare column widths via <colgroup>. Compare rendering speed and column widths vs an auto layout version of the same table.
Exercise 5 — Number alignment Build a financial table with currency values. Right-align numeric columns and apply font-variant-numeric: tabular-nums. Confirm digits line up vertically.

13 Browser support

border-collapse — universal border-spacing — universal empty-cells — universal table-layout — universal position: sticky — all modern browsers font-variant-numeric — modern only :nth-child — IE9+

Everything you need for production tables works in every modern browser. position: sticky on <thead> works in all browsers since 2017. tabular-nums works in modern Chrome/Firefox/Safari but may not affect older browsers (graceful fallback — text remains visible).

14 Real-world use cases

Admin data grids

Sticky headers, zebra rows, hover states, sortable columns. The "enterprise table" look.

Financial reports

Right-aligned numbers with tabular figures. Bold totals in footer with amber background.

Pricing tables

Highlighted middle column via <col> background. Center-aligned checkmarks for "included" features.

Directory lists

Tight padding, hover-to-reveal actions, avatar + name + status layout.

Sports standings

Top row sticky, position column highlighted, alternating row colors for scannability.

Calendars

7-column grid with table-layout: fixed, current-day cell highlighted, weekend columns tinted.
