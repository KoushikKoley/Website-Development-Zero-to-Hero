The Paragraph <p> Element

The most frequently used element on the web — a single tag that carries the body of human language. Learn when to use it, how it spaces itself, and the surprising rules that govern what it can contain.

1 What Is a Paragraph?

The <p> element represents a block-level paragraph of text. It is the default container for prose content and is one of the original elements from HTML 1.0 (1993). Semantically, a paragraph groups sentences that share a single idea or topic.

Browsers render <p> as a block: it takes the full available width, and the next element appears below it on a new line. Vertical space (margin) is added above and below by default so that consecutive paragraphs are visually separated.

Pro Tip Think of <p> as a "thought unit" — when the topic shifts, start a new paragraph. This matches how readers scan text on the web.

2 Syntax & Anatomy

A paragraph has an opening <p> tag, phrasing content inside, and a closing </p> tag. It accepts all global attributes (class, id, lang, dir, style, title, data-* attributes, ARIA attributes).

<p class="lead" lang="en">
  The quick brown fox jumps over the lazy dog.
</p>

The closing tag is technically optional — but always write it

HTML5 says you may omit </p> because the parser automatically closes a paragraph when it encounters a block-level element such as <h2>, <ul>, <div>, or another <p>. In practice, always write the closing tag — it makes your code easier to read, edit, and validate.

<!-- Valid HTML5, but discouraged -->
<p>First paragraph.
<p>Second paragraph.

<!-- Preferred -->
<p>First paragraph.</p>
<p>Second paragraph.</p>

3 Default Spacing

The browser's user-agent stylesheet applies roughly margin: 1em 0 to every paragraph. This vertical margin is what creates the visible gap between paragraphs.

This is the second paragraph. The two paragraphs are separated by 1em of vertical margin on each side, which collapses to a single 1em gap.

Info Adjacent vertical margins collapse: two paragraphs with margin: 1em 0 each are separated by 1em, not 2em. The larger margin wins.

4 Controlling Spacing with CSS

Almost every design system overrides the default paragraph margin. The most common pattern is to remove top margin and keep a bottom margin, so the first paragraph in a container sits flush against its parent.

p {
  margin: 0 0 1.25em 0;
  line-height: 1.7;
  max-width: 65ch;       /* optimal line length for reading */
  color: #1f2937;
}

/* Tighter spacing inside tight UI regions */
.card p { margin-bottom: 0.75em; }

/* First paragraph after a heading: no extra top margin */
h2 + p { margin-top: 0; }

/* Drop cap on the first paragraph of an article */
article > p:first-of-type::first-letter {
  font-size: 3.5rem;
  float: left;
  line-height: 0.9;
  padding: 0.05em 0.1em 0 0;
  color: #2563eb;
  font-weight: 700;
}

The 65ch rule

Reading research shows the optimal line length is roughly 45–75 characters. Setting max-width: 65ch on paragraphs makes long-form text much more comfortable to read on wide screens.

Pro Tip For accessibility, never set line-height below 1.4 on body text. Dyslexic and low-vision readers benefit from 1.6–1.8.

5 Why You Cannot Nest Paragraphs

A <p> element's content model is phrasing content only. That means it may contain text and inline elements like <strong>, <a>, <code>, <br>, and <span> — but not other block elements, including other paragraphs.

If you write a paragraph inside a paragraph, the parser silently closes the outer one for you:

<!-- What you wrote -->
<p>Outer paragraph
  <p>Inner paragraph</p>
</p>

<!-- How the browser parses it -->
<p>Outer paragraph</p>
<p>Inner paragraph</p>
<p></p>   <!-- empty paragraph from the stray </p> -->
Common Mistake Nesting a <div>, <ul>, <blockquote>, or another <p> inside a paragraph is invalid HTML and produces unpredictable DOM trees. Use <div> as the outer container instead.

Want a "paragraph with a sub-block"? Use <div>

<div class="card">
  <p>Main text…</p>
  <ul>
    <li>Sub-item one</li>
    <li>Sub-item two</li>
  </ul>
</div>

6 <br> vs <p>

Many beginners hit <br> twice to create paragraph spacing. This is wrong. <br> is for a line break within the same paragraph (e.g. postal addresses or poetry), not for separating paragraphs.

Use <p>…Use <br>…
When the new block of text is a different idea or topic When the line break is part of the same thought (address, poem, lyrics)
For all body copy and prose Inside <p>, <address>, or <h1>–<h6>
When you want consistent, semantic spacing When CSS margins alone cannot express the desired structure 
<!-- WRONG: stacking <br> for spacing -->
<p>First paragraph.<br><br>Second paragraph.</p>

<!-- RIGHT -->
<p>First paragraph.</p>
<p>Second paragraph.</p>

<!-- RIGHT use of br: postal address -->
<address>
  Ada Lovelace<br>
  123 Analytical Engine Way<br>
  London, UK
</address>
Common Mistake Using <br><br> to add space is a classic beginner anti-pattern. It breaks screen-reader pronunciation, creates unpredictable spacing, and ignores CSS. Use margins on real paragraphs.

7 Blank Lines & Whitespace

HTML collapses all whitespace (spaces, tabs, newlines) inside a paragraph into a single space when rendering. You can put one space or fifty line breaks in your source — the output is identical.

<!-- Source: many spaces -->
<p>Hello          there</p>
<!-- Renders as: "Hello there" -->

<!-- Source: multiple lines -->
<p>Roses are red,
   Violets are blue,</p>
<!-- Renders as: "Roses are red, Violets are blue," -->

Preserving whitespace with white-space

If you need to preserve newlines (e.g. ASCII art, code samples), use the CSS white-space property or the <pre> element.

.preserve {
  white-space: pre;       /* preserve newlines and spaces */
  white-space: pre-wrap; /* preserve, but wrap long lines */
  white-space: pre-line; /* collapse spaces, preserve newlines */
}

The non-breaking space &nbsp;

Use &nbsp; when you want to prevent a line break between two words (e.g. "10 kg", "Chapter 3").

<p>Water boils at 100&nbsp;°C at sea level.</p>
<p>See Chapter&nbsp;5 for details.</p>

8 RTL & Bidi Support

For languages written right-to-left — Arabic, Hebrew, Persian, Urdu — set dir="rtl" on the paragraph (or the <html> root). The dir attribute tells the browser to reverse the inline direction so text flows correctly.

مرحبا بالعالم! هذه فقرة تجريبية باللغة العربية.

<!-- A single RTL paragraph in an otherwise LTR page -->
<p dir="rtl" lang="ar">مرحبا بالعالم!</p>

<!-- Set the whole document to RTL -->
<html lang="ar" dir="rtl">

<!-- Auto direction (useful for user-generated content) -->
<p dir="auto">...user comment...</p>

Direction values

  • ltr — left-to-right (default, English, Spanish, Chinese…)
  • rtl — right-to-left (Arabic, Hebrew, Persian…)
  • auto — browser chooses based on first strong-directional character
Pro Tip Always pair dir with the matching lang attribute. Screen readers use lang to pick the correct pronunciation engine — without it, an Arabic paragraph might be read aloud with an English voice.

The <bdo> element for forced override

For rare cases where you need to forcibly reverse character order (e.g. displaying mixed-direction text), use <bdo dir="rtl">:

<p>The word <bdo dir="rtl">Hello</bdo> rendered RTL.</p>

9 Real-World Examples

Lead paragraph

<article>
  <h1>Mars Mission Launches Successfully</h1>
  <p class="lead">
    After a two-day delay caused by weather, the Perseverance
    rover lifted off from Cape Canaveral at 7:50 AM EDT Thursday,
    beginning a seven-month journey to the red planet.
  </p>
  <p>The Atlas V rocket performed flawlessly…</p>
</article>

Disclaimer with smaller text

<p>
  <small>
    Prices shown exclude taxes and shipping. Offers expire
    December 31, 2024. See <a href="/terms">full terms</a>.
  </small>
</p>

Multilingual paragraph

<p>
  The French word for "hello" is
  <span lang="fr">bonjour</span>,
  and the Japanese greeting is
  <span lang="ja">こんにちは</span>.
</p>

Paragraph with inline quote and citation

<p>
  As Ada Lovelace once wrote,
  <q>The analytical engine weaves algebraic patterns
     just as the Jacquard loom weaves flowers and leaves.</q>
  Her note appeared in <cite>Sketch of the Analytical Engine</cite> (1843).
</p>

10 Common Mistakes

MistakeWhy It HurtsFix
<br><br> for paragraph spacing Breaks screen readers, unpredictable spacing Use separate <p> elements
Nesting <div> inside <p> Invalid HTML, parser closes <p> early Use <div> as the outer container
Missing closing </p> tag Works in browsers but breaks maintenance & validation Always write the closing tag
Using <p> for non-prose (button, image gallery) Misleading semantics; block elements inside are invalid Use <div>, <figure>, or <section>
Setting line-height: 1 Lines overlap; very hard to read Use 1.5–1.7 for body text
Long unbroken lines (no max-width) Hard to read on wide screens Set max-width: 65ch
Using &nbsp; for indentation Brittle, ignores CSS, hurts translation Use padding-left or text-indent
Forgetting lang on foreign-language paragraphs Screen reader uses wrong voice Add lang="xx" to the paragraph

12 Summary

  • <p> is the block element for prose — one paragraph per idea.
  • Default browser margin is ~1em vertical; override with CSS for predictable spacing.
  • Paragraphs can only contain phrasing content — never nest block elements.
  • Use <p> for paragraph breaks, <br> only for line breaks within the same thought.
  • Whitespace collapses — use white-space CSS or <pre> to preserve it.
  • For RTL languages, set dir="rtl" and the matching lang.
  • Always write the closing </p> tag, even though it is optional.
