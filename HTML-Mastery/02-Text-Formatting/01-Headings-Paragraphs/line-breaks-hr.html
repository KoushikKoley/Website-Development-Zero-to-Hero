Line Breaks <br> & Thematic Breaks <hr>

Two void elements that look tiny but carry big semantic weight. <br> forces a line break inside text. <hr> marks a thematic shift between sections. Both are easy to abuse — here is how to use them well.

1 The <br> Element

The <br> element produces a line break within a run of text — the same effect as pressing Shift+Enter in a word processor. It is a void element, so it has no closing tag and cannot contain children.

Semantically, <br> means "the following text belongs to the same paragraph but starts on a new line." It is most commonly used for postal addresses, poems, song lyrics, and signatures.

Info In XHTML you wrote <br />. In HTML5, <br> is correct. Both forms are accepted by the parser, but plain <br> is idiomatic in modern HTML.

2 Syntax

<p>
  Ada Lovelace<br>
  123 Analytical Engine Way<br>
  London, UK
</p>

Ada Lovelace
123 Analytical Engine Way
London, UK

<br> accepts only global attributes. The most useful is class for styling hooks, and occasionally title for a tooltip.

Pro Tip If the content between two line breaks is a separate idea, use two paragraphs instead. <br> is for line breaks, <p> is for paragraph breaks.

4 Abuse Cases

The most common beginner mistake is to use <br> as a substitute for margins. The browser will render it, but it produces broken semantics, awkward spacing, and screen-reader confusion.

<!-- ❌ Wrong: br for spacing -->
<p>Welcome to our shop.<br><br><br>
   Check out our latest products.</p>

<!-- ❌ Wrong: br instead of list items -->
<p>
  Apples<br>
  Oranges<br>
  Bananas
</p>

<!-- ❌ Wrong: br for button spacing -->
<button>Buy</button><br><br><button>Cancel</button>
<!-- ✅ Correct: use paragraphs -->
<p>Welcome to our shop.</p>
<p>Check out our latest products.</p>

<!-- ✅ Correct: use a list -->
<ul>
  <li>Apples</li>
  <li>Oranges</li>
  <li>Bananas</li>
</ul>

<!-- ✅ Correct: use CSS margin on buttons -->
<button style="margin-right: 12px;">Buy</button>
<button>Cancel</button>
Common Mistake Stacking multiple <br> tags for vertical space is the single most common HTML abuse. It produces inconsistent spacing across browsers, confuses screen readers (which read each break as a pause), and is impossible to maintain responsively.

5 The Deprecated clear Attribute

Older HTML supported <br clear="all"> to clear floated elements. This attribute is obsolete. Use the CSS clear property, or better yet, switch to modern flex/grid layout.

<!-- ❌ Deprecated -->
<img src="photo.jpg" style="float:left">
<br clear="all">

<!-- ✅ Modern alternative -->
<div style="overflow:hidden">
  <img src="photo.jpg" style="float:left">
  <p>Caption...</p>
</div>

<!-- ✅ Even better: flexbox -->
<div style="display:flex; gap:16px; align-items:start;">
  <img src="photo.jpg">
  <p>Caption...</p>
</div>

6 The <hr> Element

<hr> stands for "horizontal rule" but in modern HTML its semantic meaning is "thematic break" — a transition between two topics within the same section. Visually it renders as a horizontal line, but the meaning is structural, not decorative.

This is the end of the introduction.

This is the beginning of the main content — a thematic shift.

<section>
  <h2>Chapter 1: The Beginning</h2>
  <p>It was the best of times…</p>

  <hr>

  <h2>Chapter 2: The Middle</h2>
  <p>Years later, the protagonist returned…</p>
</section>

7 Semantics of <hr>

Use <hr> only when there is a real shift in topic, scene, or section that you cannot express with a proper heading or section element. It is a fallback when no heading is appropriate.

SituationUse <hr>?
Scene change in a story✓ Yes
Switch from article to footer notes✓ Yes
Separator between blog post and comments✓ Yes
Decorative divider because it looks nice✗ No — use a styled <div>
Splitting sections with their own headings✗ No — use <section> + headings
Top/bottom of a layout section✗ No — use border or margin

8 Accessibility of <hr>

Screen readers expose <hr> as an implicit separator landmark with role separator. Most screen readers announce something like "separator" or "horizontal separator" when they encounter one. This is helpful — it tells the user "we're moving to a new topic."

If your <hr> is purely decorative, hide it from assistive tech:

<hr aria-hidden="true">

Conversely, if you want to add a meaningful label (rare), use aria-label:

<hr aria-label="End of introduction">
Pro Tip When in doubt, ask: "Would a screen-reader user benefit from hearing 'separator' here?" If yes, leave it. If no, mark it aria-hidden or replace it with CSS.

9 Styling <hr> with CSS

Browser default styling for <hr> is unattractive: a thin gray line with a 3D border. Almost every design system overrides it. Because <hr> is a void element with no content, you style the box itself.

Reset and customize

hr {
  border: 0;             /* remove default 3D border */
  height: 2px;
  background: linear-gradient(90deg, #2563eb, #7c3aed);
  margin: 2.5rem 0;
  border-radius: 1px;
}

Dotted divider

hr.dots {
  border: 0;
  height: 12px;
  background-image: radial-gradient(circle, #475569 2px, transparent 3px);
  background-size: 16px 16px;
  background-repeat: repeat-x;
  background-position: center;
}

Faded gradient with center icon

hr.ornament {
  border: 0;
  height: 24px;
  background-image:
    linear-gradient(to right, transparent, #cbd5e1, transparent);
  background-position: center;
  background-repeat: no-repeat;
  background-size: 60% 1px;
  position: relative;
  margin: 3rem 0;
}
hr.ornament::after {
  content: "✦";
  position: absolute;
  left: 50%; top: 50%;
  transform: translate(-50%, -50%);
  background: #fff;
  padding: 0 12px;
  color: #7c3aed;
}
Pro Tip The safest cross-browser recipe is border: 0; height: Npx; background: ...;. Avoid setting both border-bottom and a background on the same hr — they will overlap unpredictably in older browsers.

10 Modern Alternatives

Often the best <hr> is no <hr> at all. Modern layout gives you several cleaner options:

Section borders

Use border-top on a <section> or <article> element for visual separation that is also semantically meaningful.

Spacing with margins

Often all you need is generous margin-top on the next section. White space itself can be the divider.

Decorative <div>

If you only want a decorative line, use <div class="divider"></div> with aria-hidden="true". No fake semantics.

Headings

A new <h2> already signals a topic change. Don't add a redundant <hr> on top of it.

11 Common Mistakes

MistakeWhy It HurtsFix
<br><br><br> for spacing Breaks semantics, awkward pausing for screen readers Use CSS margin on real elements
Using <br> for list items No list semantics; no bullet/number; no navigation Use <ul> or <ol>
<br> inside <title> or <button> text Does not render where expected; weird behavior Use CSS white-space or restructure markup
Decorative <hr> without aria-hidden Screen reader announces pointless "separator" Add aria-hidden="true"
<hr> next to a heading Redundant — heading already signals topic change Drop the hr, or style the heading instead
<br clear="all"> Obsolete, removed from spec Use modern flex/grid layout
Self-closing in HTML5: <br/> Valid but inconsistent with idiomatic HTML5 Use plain <br>

13 Summary

  • <br> forces a line break within text — perfect for addresses, poems, signatures.
  • Never use <br> for spacing between paragraphs — use CSS margins instead.
  • <hr> marks a thematic break between sections of the same article.
  • Screen readers announce <hr> as a separator — add aria-hidden="true" if decorative.
  • Style <hr> with border: 0 + background + height for predictable cross-browser results.
  • For purely visual dividers, prefer a styled <div> over fake semantic <hr>.
