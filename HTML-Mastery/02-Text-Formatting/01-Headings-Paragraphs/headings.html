Headings <h1>–<h6>

Six levels of section headings form the skeleton of every HTML page — they shape the visual hierarchy, the SEO ranking, and the screen-reader outline of your document.

1 What Is a Heading?

A heading element represents a short title or label for the section of content that follows it. HTML provides six levels, <h1> through <h6>, where <h1> is the highest rank (most important) and <h6> is the lowest. Browsers render headings in increasingly smaller bold text by default, but the real purpose of a heading is semantic: it tells browsers, search engines, and assistive technologies how your content is structured.

Headings are the table of contents of the web. A screen-reader user can pull up a list of all headings on a page and jump straight to the section they need — but only if you use them correctly.

Pro Tip A heading is structural, not decorative. If you only want big bold text, use CSS on a <p> or <span> instead — never abuse a heading for its visual styling.

2 The Six Heading Levels

Every browser applies default styling that makes higher-ranked headings larger and bolder. Here is how each level renders out of the box:

h1 — Main page title

h2 — Major section

h3 — Subsection

h4 — Sub-subsection

h5 — Minor heading
h6 — Lowest-priority heading

Notice that the visual size decreases with rank. This is the browser's hint about importance — but remember, you should always control final appearance with CSS and use the element rank for its meaning, not its size.

LevelTypical Use CaseSuggested Frequency per Page
<h1>Page or article titleExactly 1
<h2>Major sections2–8
<h3>Subsections of an h2As needed
<h4>Sub-subsectionsAs needed
<h5>Rarely needed; sidebar itemsSparingly
<h6>Very fine-grained structureVery rare

3 Anatomy & Syntax

A heading is a simple element with an opening tag, text content, and a closing tag. It accepts global attributes such as id (for fragment links), class, lang, and dir.

<h2 id="pricing">Pricing Plans</h2>
<p>Choose the plan that fits your team…</p>

The id attribute creates anchor targets

Adding id="pricing" means visitors can jump straight to the heading with the URL /#pricing. This is how every link in the table of contents on the left of this page works.

<!-- Same-page navigation -->
<a href="#pricing">Jump to Pricing</a>

<!-- ... later in the document ... -->
<h2 id="pricing">Pricing Plans</h2>
Info Headings are flow content and may contain only phrasing content (text, <span>, <a>, <code>, <em>, etc.). You cannot nest a <div>, <p>, or another heading inside a heading.

4 Hierarchy Rules

The web platform does not technically forbid skipping levels, but the W3C and WAI-ARIA guidelines ask authors to follow a strict order. Always start at h1, then nest sections going no more than one level deeper at a time.

Correct — levels descend by one

<h1>The Complete Guide to Sourdough</h1>
<h2>Choosing a Flour</h2>
<h3>Bread Flour vs. All-Purpose</h3>
<h3>Whole-Grain Options</h3>
<h2>Building a Starter</h2>
<h3>Day 1: Mixing</h3>
<h4>Hydration Ratio</h4>

Incorrect — skips from h2 to h4

<h1>The Complete Guide to Sourdough</h1>
<h2>Building a Starter</h2>
<h4>Hydration Ratio</h4> <!-- skipped h3! -->
Common Mistake Skipping levels (e.g. h2 → h4) breaks the screen-reader outline and confuses users navigating by headings. Always step down one level at a time.

5 SEO Importance

Search engines like Google use headings to understand the topic and structure of a page. The <h1> in particular is one of the strongest on-page ranking signals — usually treated as the page's main title and weighted similarly to the <title> element.

One h1 per page — the modern rule

Older SEO advice warned against multiple h1s. With HTML5's <section> and <article> elements, the spec technically allows one h1 per sectioning root — but in practice, Google and accessibility experts still recommend exactly one top-level h1 per page describing the page as a whole.

Do

Use one h1 matching the page's main topic. Use h2–h3 for sub-sections. Include target keywords naturally.

Don't

Stuff keywords into headings. Use multiple h1s. Hide headings with display:none for SEO. Use heading levels for visual size.

Pro Tip Match your <title> element and your <h1> closely — they describe the same page. Google often uses the h1 as the clickable link in search results if no better title is found.

6 Accessibility

Screen readers such as NVDA, JAWS, and VoiceOver expose a "headings list" shortcut that lets users skip directly to any section. Proper headings are the #1 accessibility win on the web.

How screen readers use headings

  • H key in NVDA / JAWS jumps to the next heading.
  • 1–6 keys jump to the next heading of that level.
  • Insert+F6 (NVDA) opens the headings list dialog.
<h1>Order Confirmation</h1>
<p>Thank you for your purchase.</p>

<h2>Shipping Address</h2>
<address>123 Maple Street, Springfield</address>

<h2>Payment Summary</h2>
<p>Visa ending in 4242 — $128.40</p>
Info A page with no headings is essentially unreadable for a screen-reader user who wants to skim. Adding meaningful headings is the single highest-leverage accessibility improvement you can make.

7 Document Outline

The collection of all headings on a page forms its document outline. Tools like the W3C Validator, the Web Developer browser extension, and the ARC Toolkit can render this outline so you can spot skipped levels or duplicate h1s.

Example outline

1. The Complete Guide to Sourdough        (h1)
   1.1 Choosing a Flour                   (h2)
       1.1.1 Bread Flour vs. All-Purpose   (h3)
       1.1.2 Whole-Grain Options          (h3)
   1.2 Building a Starter                 (h2)
       1.2.1 Day 1: Mixing                 (h3)
             1.2.1.1 Hydration Ratio      (h4)

A clean, indented outline like this is the goal. If yours looks flat or jumps ranks, revisit your structure.

9 Styling Headings

Browser defaults are intentionally ugly. Almost every production site overrides them with CSS. Always size headings relative to your base font using rem units so they scale with user preferences.

:root {
  --font-base: 16px;
}

h1, h2, h3, h4, h5, h6 {
  font-family: "Inter", system-ui, sans-serif;
  line-height: 1.2;
  margin: 1.5em 0 0.5em;
  color: #0f172a;
}

h1 { font-size: 2.5rem; letter-spacing: -0.02em; }
h2 { font-size: 2rem; letter-spacing: -0.01em; }
h3 { font-size: 1.5rem; }
h4 { font-size: 1.25rem; }
h5 { font-size: 1rem; }
h6 { font-size: 0.875rem; text-transform: uppercase; letter-spacing: 0.05em; }

/* Anchor link appears on hover */
h2:hover .anchor-link { opacity: 1; }
.anchor-link {
  opacity: 0;
  margin-left: 0.5em;
  color: #2563eb;
  text-decoration: none;
  font-size: 0.85em;
}
<h2>Pricing
  <a class="anchor-link" href="#pricing" aria-label="Permalink to Pricing">#</a>
</h2>
Pro Tip Add a small "#" link next to each heading that becomes visible on hover. Readers can right-click → "Copy link" to share a deep link straight to that section.

10 Common Mistakes

MistakeWhy It's WrongFix
Using <h4> for big text on a landing page Browsers and SEO read it as "minor sub-section" Use <h1> or <h2> for the page title
Multiple <h1>s on one page Dilutes the page's primary topic signal Use exactly one h1 per document
Skipping levels (h2 → h4) Breaks screen-reader navigation Step down one rank at a time
Using headings for button/link text Headings are not interactive and confuse assistive tech Use <a>, <button>, or style a <span>
Nesting a <div> inside a heading Headings only accept phrasing content Move the div outside or use a <span>
Empty headings for spacing Shows up as a blank entry in screen-reader outline Use CSS margin for spacing
Styling headings with <font size> or inline styles Hard to maintain, hurts SEO consistency Use external CSS

11 Try It Yourself

Exercise 1 — Fix the broken outline The markup below has three problems. Find and fix them all. 
<h2>My Recipe Blog</h2>
<h4>Today's Dish</h4>
<p>A simple pasta…</p>
<h4>Ingredients</h4>
<h1>Penne Arrabbiata</h1>

Hint: wrong first heading, skipped levels, h1 appears too late.

Exercise 2 — Build a docs page outline Write the heading structure for an API docs page with the following sections: "Authentication" (sub: "Bearer Tokens", "OAuth 2.0"), "Endpoints" (sub: "List Users", "Create User", each with "Parameters" and "Response"), "Rate Limiting", "Changelog". Use only h1–h4.
Exercise 3 — Add anchor links Take any article you have written and add id attributes to each h2. Then add a "Table of Contents" at the top using <a href="#fragment"> links. Verify each link jumps to the right place.

12 Summary

  • Headings h1–h6 define the structural outline of your page.
  • Use exactly one h1 per page that describes the page as a whole.
  • Never skip levels — step from h2 to h3, not to h4.
  • Headings are semantic, not visual. Style with CSS, not by picking a rank.
  • Use id attributes for deep-link anchor targets.
  • Well-structured headings improve SEO, accessibility, and reader navigation simultaneously.
