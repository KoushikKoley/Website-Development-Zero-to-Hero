Description Lists <dl> · <dt> · <dd>

The third list type, often overlooked. Description lists pair terms with their descriptions — the semantic choice for glossaries, FAQs, metadata, key-value pairs, and any time you need to associate a label with one or more values.

1 What Is a Description List?

A description list (formerly called a "definition list") associates terms with their descriptions. It uses three elements together:

  • <dl> — description list (the container)
  • <dt> — description term (the label)
  • <dd> — description details (the value)
<dl>
  <dt>HTML</dt>
  <dd>HyperText Markup Language, the standard markup language for web pages.</dd>

  <dt>CSS</dt>
  <dd>Cascading Style Sheets, used to style HTML documents.</dd>
</dl>
HTML
HyperText Markup Language, the standard markup language for web pages.
CSS
Cascading Style Sheets, used to style HTML documents.
Info Description lists were called "definition lists" in HTML 4. The name changed in HTML5 to reflect their broader use: not just definitions, but any term-value pairing.

2 Basic Syntax

The structure is simple: a <dl> container holds alternating <dt> (term) and <dd> (description) elements. There is no list-item wrapper — the pairs sit directly inside <dl>.

<dl>
  <dt>Term 1</dt>
  <dd>Description 1</dd>
  <dt>Term 2</dt>
  <dd>Description 2</dd>
</dl>

By default, browsers render <dd> with a left indent (about 40px). <dt> is bold by default in some browsers.

3 The <dt> Element

<dt> represents the term being described. It is short — usually a single word or short phrase. The content is phrasing (inline) only: text, <code>, <em>, <a>, etc.

<dt>Algorithm</dt>
<dt><abbr title="Application Programming Interface">API</abbr></dt>
<dt>Asynchronous</dt>

4 The <dd> Element

<dd> provides the description, definition, or value associated with the preceding <dt>. Unlike <dt>, <dd> can contain flow content: paragraphs, lists, images, blockquotes, even another description list.

<dl>
  <dt>Photosynthesis</dt>
  <dd>
    <p>The process by which plants convert light energy
       into chemical energy stored in glucose.</p>
    <p>The general equation is:
       6CO₂ + 6H₂O → C₆H₁₂O₆ + 6O₂</p>
  </dd>
</dl>

Default left indent

Browsers apply margin-left: 40px (or 1rem) to <dd> by default. This is the visual cue that the description is "subordinate" to the term. Many designs reset this.

5 Multiple <dd> per <dt>

A single term can have multiple descriptions. This is useful when a term has several distinct meanings, examples, or facets.

<dl>
  <dt>Java</dt>
  <dd>An island in Indonesia, southeast of Sumatra.</dd>
  <dd>A programming language developed by Sun Microsystems in 1995.</dd>
  <dd>A colloquial term for coffee (from Java's coffee exports).</dd>
</dl>
Java
An island in Indonesia, southeast of Sumatra.
A programming language developed by Sun Microsystems in 1995.
A colloquial term for coffee (from Java's coffee exports).

6 Multiple <dt> for One <dd>

Conversely, you can stack multiple <dt> elements before a single <dd>. This is useful when a term has synonyms or alternate spellings.

<dl>
  <dt>Color</dt>
  <dt>Colour</dt>
  <dd>The visual perception of different wavelengths of light.</dd>

  <dt>Cookie</dt>
  <dt>Biscuit</dt>
  <dd>A small, flat, baked treat.</dd>
</dl>
Color
Colour
The visual perception of different wavelengths of light.
Cookie
Biscuit
A small, flat, baked treat.

7 Wrapping in <div> (HTML 5.2+)

Since HTML 5.2, you can wrap each term/description pair in a <div> for styling or to group related pairs. This is useful for adding borders, backgrounds, or hover effects to individual entries.

<dl>
  <div class="entry">
    <dt>HTML</dt>
    <dd>HyperText Markup Language</dd>
  </div>
  <div class="entry">
    <dt>CSS</dt>
    <dd>Cascading Style Sheets</dd>
  </div>
</dl>
dl > div.entry {
  padding: 12px 16px;
  border: 1px solid var(--line);
  border-radius: 8px;
  margin-bottom: 8px;
  background: white;
}
dl > div.entry:hover {
  border-color: var(--brand);
}
Info This <div> wrapper is the only block-level element allowed directly inside <dl> (besides <dt> and <dd>). It does not affect semantics.

8 Use Cases

Glossary

Term + definition pairs. The classic case. Perfect for technical docs, dictionaries, encyclopedias.

FAQ

Question (dt) + answer (dd). Cleaner than h3+p pairs and more semantic than divs.

Metadata display

Property + value pairs: "Author: Jane Doe", "Published: 2024-03-12". Great for product specs and article metadata.

Speaker list

Speaker name (dt) + bio (dd). Multiple talks per speaker? Multiple dd elements.

Recipe ingredients

Ingredient (dt) + quantity/notes (dd). Naturally structured.

Event schedule

Time (dt) + activity (dd). Clear two-column layout.

Configuration reference

Setting name (dt) + description + default value + type. Multiple dd per setting.

Dictionary entries

Word (dt) + part of speech, pronunciation, definition (multiple dd).

9 Real-World Examples

Glossary

<h2>Glossary of Web Terms</h2>
<dl>
  <dt>API</dt>
  <dd>Application Programming Interface; a set of rules for how software components communicate.</dd>

  <dt>CDN</dt>
  <dd>Content Delivery Network; a distributed server system that delivers web content based on user location.</dd>

  <dt>DOM</dt>
  <dd>Document Object Model; a programming interface for HTML/XML documents.</dd>
</dl>

FAQ

<h2>Frequently Asked Questions</h2>
<dl>
  <dt>How do I reset my password?</dt>
  <dd>Click "Forgot password" on the login page and follow the email instructions.</dd>

  <dt>Can I cancel my subscription anytime?</dt>
  <dd>Yes. Visit Settings → Subscription and click "Cancel". Your access continues until the end of the billing period.</dd>
</dl>

10 Styling

Default styling reset

dl, dt, dd {
  margin: 0;
  padding: 0;
}
dd { padding-left: 0; }

Two-column grid layout (modern)

For metadata display, a grid layout puts the term on the left and the description on the right:

dl.metadata {
  display: grid;
  grid-template-columns: max-content 1fr;
  gap: 8px 16px;
  margin: 0;
}
dl.metadata dt {
  font-weight: 600;
  color: var(--ink);
}
dl.metadata dd {
  margin: 0;
  color: var(--ink-soft);
}

Interactivity with <details>

For collapsible FAQs, you can wrap each pair inside <details> and use <summary> for the question:

<details>
  <summary>How do I reset my password?</summary>
  <p>Click "Forgot password" on the login page and follow the email instructions.</p>
</details>

11 Accessibility

  • Screen readers announce <dl> as a "description list" with N entries.
  • Each <dt>/<dd> pair is announced together as "term" and "description".
  • Some screen readers do not strongly distinguish <dt> from a regular bold heading. The semantic structure still helps users navigate.
  • For interactive FAQs, prefer <details>/<summary> over custom JavaScript — it is keyboard-accessible out of the box.
Pro Tip If a term has multiple descriptions, do not split them across multiple <dd> elements unless each is a distinct meaning. For a single multi-paragraph description, use one <dd> containing multiple <p> tags — this preserves the "one term, one description" semantic.

12 Common Mistakes

MistakeWhy It HurtsFix
Using <table> for term/value pairs Tables imply tabular data; wrong semantics Use <dl>
Using <div> + <span> for metadata No semantic relationship between label and value Use <dl>
Mixing <dt> and <dd> inside other containers Invalid HTML; only <dl> may contain them Always wrap pairs in <dl>
Putting <dt> after <dd> (term after description) Wrong order; confusing for screen readers Always dt then dd
Using <dd> without a preceding <dt> Invalid HTML Always start a pair with <dt>
Wrapping pairs in <li> <li> is not valid inside <dl> Use <div> (HTML 5.2+) instead
Forgetting to reset default <dd> margin Indent looks inconsistent with design Reset dd { margin: 0; padding-left: ...; }

13 Try It Yourself

Exercise 1 — Glossary Build a glossary of 5 web-development terms. Use <dl>, <dt>, and <dd>. Style it with a two-column grid layout.
Exercise 2 — Product specs Create a product specification list (Weight, Dimensions, Materials, Color, Warranty) using a description list. Style it with the term bold and the value indented. Add a divider between entries.
Exercise 3 — FAQ with details Build an FAQ with 4 questions. Use <details>/<summary> for each question so users can expand/collapse them. Add CSS to style the open state.
Exercise 4 — Multi-meaning term Pick a word with multiple meanings (e.g. "bank", "match", "spring"). Build a description list where one <dt> has multiple <dd> elements, one per meaning.
Exercise 5 — Dictionary entry Build a rich dictionary entry for one word. Include: the word with pronunciation, part of speech, multiple definitions, and synonyms — using nested structure inside <dd>.

14 Summary

  • <dl> = description list; <dt> = term; <dd> = description.
  • Use for glossaries, FAQs, metadata, key-value pairs, schedules, speaker bios.
  • One <dt> can have multiple <dd> (multi-meaning terms).
  • Multiple <dt> can precede one <dd> (synonyms).
  • Since HTML 5.2, you can wrap each pair in <div> for styling.
  • <dd> can contain any flow content: paragraphs, lists, images, even nested <dl>.
  • For interactive FAQs, prefer native <details>/<summary> for accessibility.
  • Use grid CSS to create clean two-column term/value layouts.
