Form Attributes

Eight attributes on the <form> element control where data goes, how it's encoded, what happens to the result window, and whether the browser applies its built-in validation. Master them and you'll never write a broken form again.

1 Attribute overview

The <form> element accepts eight attributes that shape how it submits. None are mandatory — defaults cover many cases — but real-world forms almost always set action and method explicitly.

AttributeDefaultPurpose
actionCurrent URLWhere to submit the form
methodgetHTTP method: get / post / dialog
enctypeapplication/x-www-form-urlencodedHow the body is encoded (POST only)
target_selfWhere to display the response
autocompleteonWhether browser autofill is allowed
novalidatefalseDisable browser-native validation
accept-charsetPage encodingCharacter encodings the server accepts
name(none)Form name (used in JS / older scripts)

2 action

The URL where the form submits. May be absolute, relative, or empty:

<!-- Absolute URL (cross-site) -->
<form action="https://api.example.com/submit">

<!-- Relative URL (same site) -->
<form action="/api/login">

<!-- Anchor (jump to element with id="results") -->
<form action="#results">

<!-- Empty: submit to current URL -->
<form action="">

<!-- Omitted entirely: same as empty -->
<form>
Common mistake Don't put user-controlled data directly into the action attribute via JavaScript — it's an open redirect vector. Always validate / sanitize before constructing the action URL.

3 method (GET / POST / dialog)

The HTTP method the browser uses when submitting the form:

GET (default)

Appends form data to the action URL as a query string. The full URL becomes action?name1=value1&name2=value2. Visible, bookmarkable, cached, length-limited.

POST

Sends form data in the HTTP request body. Hidden from URL, no practical length limit, supports file uploads, never cached. Use for any state-changing or sensitive operation.

dialog (special)

Not an HTTP method. When a form is inside a <dialog> element and method="dialog" is set, submitting the form closes the dialog (sets dialog.returnValue to the submit button's value) without any network request.

<dialog id="confirm">
  <form method="dialog">
    <p>Delete this file?</p>
    <button value="cancel">Cancel</button>
    <button value="delete">Delete</button>
  </form>
</dialog>

<script>
  const d = document.getElementById('confirm');
  d.showModal();
  d.addEventListener('close', () => {
    if (d.returnValue === 'delete') doDelete();
  });
</script>
Pro tip Some teams route all forms through JavaScript handlers via fetch() to use PUT / PATCH / DELETE. That's fine for SPAs, but it breaks progressive enhancement — users with JS disabled see nothing work. Default to native GET/POST where possible.

4 enctype

Only applies to method="post". Three values:

enctypeWhenBody format
application/x-www-form-urlencoded (default)Text fields, normal formsname=value&name2=value2, with URL-encoding
multipart/form-dataFile uploads (<input type="file">)MIME multipart boundary parts
text/plainDebugging only — almost never usedname=value\nname2=value2 raw text
 
<!-- File upload REQUIRES multipart/form-data -->
<form action="/upload" method="post" enctype="multipart/form-data">
  <input type="file" name="avatar">
  <button>Upload</button>
</form>
Common mistake Forgetting enctype="multipart/form-data" on a file upload form. The browser sends the filename as a string instead of the file bytes — the server sees avatar="photo.jpg" instead of the binary content.

5 target

Like the target attribute on <a>, but for form submission results:

ValueBehavior
_self (default)Replace current tab
_blankOpen in new tab/window
_parentReplace parent frame (in iframes)
_topReplace topmost window (breaks out of all iframes)
custom nameSubmit to a named window/iframe, opening one if needed
 
<!-- Submit to hidden iframe (legacy file upload pattern) -->
<iframe name="upload-target" hidden></iframe>
<form action="/upload" method="post"
      enctype="multipart/form-data" target="upload-target">
  <input type="file" name="file">
  <button>Upload</button>
</form>
Common mistake target="_blank" on form submissions opens the result in a new tab with window.opener access — a phishing vector if the response page is untrusted. Modern browsers add rel="noopener" by default for links, but form target="_blank" historically did not. Avoid unless you control the result page.

6 autocomplete

Controls whether the browser may autofill form fields based on past values or the user's profile. Accepts on, off, or a token hint (or space-separated list of tokens).

<!-- Allow autofill -->
<form action="/register" method="post" autocomplete="on">

<!-- Disable autofill for the entire form -->
<form action="/checkout" method="post" autocomplete="off">

<!-- Hint specific categories (form-level) -->
<form autocomplete="section-shipping street-address postal-code">

Token values like username, current-password, email, tel, given-name, family-name, address-line1, postal-code, cc-number, cc-exp can be set per-control via the same attribute. We cover these in Input Attributes.

Common mistake Setting autocomplete="off" on password fields to "prevent saving passwords." Modern browsers ignore this for password managers because users should be allowed to use their password manager. Only use autocomplete="new-password" on a registration form to hint "don't autofill the existing password."

7 novalidate

A boolean attribute. When present, the browser skips native HTML5 validation (required, type="email", pattern, etc.) and submits the form regardless of field validity. Useful when you want full JS control over validation, or for "Save draft" buttons.

<form action="/save-draft" method="post" novalidate>
  <input type="email" name="email" required>
  <!-- Submits even if email is blank or invalid -->
  <button>Save draft</button>
</form>
Pro tip For per-button control, use formnovalidate on a submit button. This lets one form have a "Save draft (no validation)" button alongside a "Publish (with validation)" button.

8 accept-charset

A space- or comma-separated list of character encodings the server accepts. Modern servers handle UTF-8 universally, so this attribute is rarely needed. Useful for legacy systems that require Latin-1 or Shift-JIS:

<form action="/legacy-api" method="post" accept-charset="Shift_JIS">
  ...
</form>

If omitted, the form uses the page's own encoding (typically UTF-8 via <meta charset="UTF-8">).

9 name

Gives the form a name. Used in JavaScript via document.forms.loginForm and in older server-side frameworks. Largely superseded by id for direct DOM access, but still useful for forms collections.

<form name="loginForm" action="/login" method="post">
  ...
</form>

<script>
  // Two equivalent ways to access:
  const f1 = document.forms.loginForm;
  const f2 = document.forms['loginForm'];
  const f3 = document.querySelector('form[name="loginForm"]');
</script>

10 Common mistakes

MistakeConsequenceFix
Missing enctype="multipart/form-data" on file uploadsServer receives filename string, not file bytesAlways set when using <input type="file">
method="GET" on a password formPassword visible in URLUse POST
autocomplete="off" on username/password fieldsBrowsers ignore it; users can't use password managerUse proper token values like current-password
target="_blank" on cross-domain formOpens untrusted result in new tab with opener accessDon't use; or guarantee server response is trusted
Forgetting novalidate when handling validation via JSBrowser blocks submit before JS can runAdd novalidate and validate via Constraint Validation API

12 Browser support

action, method, enctype — universal target — universal autocomplete — universal (token values in modern browsers) novalidate — universal accept-charset — universal name — universal method="dialog" — Chrome 37+, Firefox 59+, Safari 15.4+

The dialog method is the only attribute value with non-universal support; all modern browsers handle it as of 2022+.

13 Real-world use cases

Login forms

method="post", autocomplete="username current-password", no enctype override.

Registration

method="post", autocomplete="new-password" on password field to prevent autofill of existing.

File uploads

method="post" + enctype="multipart/form-data". Multiple files via multiple attribute on input.

Search forms

method="get", default enctype. Bookmarkable results.

Modal confirmations

method="dialog" inside <dialog>; capture button value on close event.

Save Draft / Publish

Same form, two submit buttons; draft button uses formnovalidate.
