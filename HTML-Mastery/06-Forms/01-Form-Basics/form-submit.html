Form Submission

What actually happens when the user clicks "Submit"? The browser collects every named control, encodes the values, builds an HTTP request, and sends it to the action URL. Let's trace every step — and learn how JavaScript can intercept and reshape the whole process via the FormData API.

1 The submission flow

When a form submits, the browser follows a precise sequence:

  1. Validation — runs native HTML5 validation (required, type="email", pattern, etc.). If any field is invalid, the browser cancels submission and shows the first invalid field's error.
  2. Construct entry list — gathers all "submittable" elements with a name attribute that aren't disabled. Each contributes one or more [name, value] entries.
  3. Encoding — applies the enctype rules to produce the body or query string.
  4. Request build — creates an HTTP request with the chosen method, target action URL, encoded data, and fires it.
  5. Response handling — the result page (HTML, JSON, redirect) replaces the current page (or loads in the target window).
Key insight Only "submittable" elements contribute: <input> (except type="image", type="submit", type="reset", type="button" unless they're the submitter), <textarea>, <select>, <output>, and <button type="submit"> (its name/value, when activated). A <button type="button"> or disabled field contributes nothing.

2 GET: query string building

With method="get" (the default), the browser takes the entry list and appends it to the action URL as a query string:

<form action="/search" method="get">
  <input name="q" value="html forms">
  <input name="lang" value="en">
</form>

<!-- Resulting request URL: -->
/search?q=html+forms&lang=en

Rules:

  • Each entry is name=value, joined by &
  • Spaces become + (or %20)
  • Special characters are percent-encoded (& → %26, = → %3D, etc.)
  • If the action URL already has a query string, the existing one is replaced (not merged)
  • Fragment identifiers (#section) in the action URL are stripped

3 POST: body building

With method="post", the entry list goes in the HTTP request body instead of the URL. The encoding depends on enctype:

application/x-www-form-urlencoded (default)

Same encoding as a query string, but in the body:

POST /login HTTP/1.1
Content-Type: application/x-www-form-urlencoded

email=alice%40example.com&password=secret

multipart/form-data

Each entry becomes a MIME part with its own headers. Larger payload, but required for file uploads and binary data:

POST /upload HTTP/1.1
Content-Type: multipart/form-data; boundary=----WebKitFormBoundary7MA4YWxkTrZu0gW

------WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="title"

My Photo
------WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="file"; filename="photo.jpg"
Content-Type: image/jpeg

<binary bytes>
------WebKitFormBoundary7MA4YWxkTrZu0gW--

4 File uploads (multipart)

File uploads require three things working together:

  1. <form method="post"> (GET can't carry files)
  2. enctype="multipart/form-data"
  3. <input type="file" name="...">
<form action="/upload" method="post" enctype="multipart/form-data">
  <label for="u-file">Choose file</label>
  <input type="file" id="u-file" name="attachment" required>

  <label for="u-desc">Description</label>
  <input type="text" id="u-desc" name="description">

  <button>Upload</button>
</form>
Common mistake Forgetting enctype="multipart/form-data" silently breaks the upload — the server receives the filename string, not the file content. Always set it on file upload forms.
Pro tip On the server side, frameworks expose multipart uploads through request parsers: req.files.attachment (Express + multer), request.FILES['attachment'] (Django), $_FILES['attachment'] (PHP). Each handles boundary parsing transparently.

5 Implicit submission (Enter key)

A form can be submitted without clicking any button — pressing Enter while focused on a single-line input triggers "implicit submission." The browser's rules:

  • The form must contain at least one submittable element.
  • If the form has exactly one <input> (any type except image), Enter submits the form even with no submit button.
  • If the form has multiple inputs, Enter submits if there's a default submit button (the first <button type="submit"> or <input type="submit"> in source order).
  • Pressing Enter on a <textarea> inserts a newline — does not submit.
Common mistake Removing the submit button on a search form (relying on JS to handle Enter) breaks accessibility. Always include a submit button — screen readers and keyboard users expect it.

7 Preventing default with JS

The submit event fires before the request is sent — the last chance to intercept and customize:

const form = document.querySelector('form');

form.addEventListener('submit', (event) => {
  event.preventDefault();          // stop the native submission
  // ... do custom work here (validate, fetch, etc.)
});

Important details:

  • The submit event fires on the <form>, not the button.
  • It does not fire if native validation fails (the browser shows the error first).
  • It does not fire on forms with method="dialog" (those just close the dialog).
  • Calling event.preventDefault() in a non-async handler is enough — for async work, use the FormData API (below).
Common mistake Listening for click on the submit button instead of submit on the form. Click misses Enter-key submissions and gets the wrong timing relative to validation.

8 The FormData API

FormData is the modern, idiomatic way to serialize a form for JavaScript-driven submission (AJAX via fetch()). It handles all field types — including files — correctly.

const form = document.querySelector('form');

form.addEventListener('submit', async (event) => {
  event.preventDefault();
  const data = new FormData(form);   // captures all named fields + files

  // Inspect
  for (const [name, value] of data.entries()) {
    console.log(name, value);
  }

  // Send via fetch (multipart auto-set)
  const res = await fetch('/api/save', {
    method: 'POST',
    body: data,                  // NO Content-Type header — fetch sets boundary
  });
  console.log(await res.json());
});

Key methods

MethodPurpose
append(name, value)Add a new entry (allows duplicates)
set(name, value)Replace all entries for name with one
get(name)First value for name (or null)
getAll(name)Array of all values for name (checkbox groups)
has(name)Boolean: any entry with name?
delete(name)Remove all entries for name
entries() / keys() / values()Iterators for traversal
Pro tip Never set Content-Type manually when sending FormData via fetch() — the browser sets it to multipart/form-data with the correct boundary. Setting it yourself strips the boundary, and the server rejects the parse.

9 Common mistakes

MistakeConsequenceFix
Missing name on a controlField never submittedAlways set name on every control whose value you need
disabled instead of readonlyDisabled fields are not submitted at allUse readonly if you need the value sent
Listening to click on submit buttonMisses Enter-key submitsListen to submit on the form

Using <input type="submit"> and wanting an iconCan't add HTML inside an inputUse <button type="submit">

10 Try it yourself

Exercise 1 — Trace a GET request Build a search form with three fields. Submit it. Look at the URL bar. Decode the query string by hand and verify each name=value pair matches your inputs.
Exercise 2 — Submit via fetch Build a contact form. Attach a submit handler that calls event.preventDefault(), builds a FormData, and console.log()s every entry. Verify your file input's value is a File object — not a string.
Exercise 3 — Two submit buttons Add two submit buttons to a single form. Use the same name ("action") with different values ("save" and "publish"). In your JS, read event.submitter.value to find out which button was clicked.

11 Browser support

Form submission — universal multipart/form-data — universal FormData API — universal in modern browsers event.submitter — Chrome 82+, Firefox 87+, Safari 14.1+ Implicit submission — universal

event.submitter (the element that triggered submit) is the only modern addition; older code uses document.activeElement workaround.

12 Real-world use cases

Search filters

GET form: changes URL on submit so users can bookmark or share filtered views.

SPA form submission

FormData + fetch — single-page apps submit without page reload.

Drag-and-drop uploads

Build FormData programmatically with appended File objects, send via fetch.

Multi-action toolbars

One form, multiple submit buttons with different name=value pairs.

Progressive enhancement

Native submit works without JS; JS intercepts submit for better UX when available.

Save Draft / Publish

Different submit buttons: draft uses formnovalidate, publish runs full validation.
