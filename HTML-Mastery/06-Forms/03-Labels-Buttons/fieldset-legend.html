<fieldset> & <legend>

Forms get confusing fast: address, payment, shipping, billing, preferences — all in one page. <fieldset> groups related controls together, and <legend> labels the group. Screen readers announce the legend with each field — turning "Email [input]" into "Shipping address, Email [input]" with no extra code.

1 Why group controls?

Long forms with many fields are overwhelming. Users need visual structure and semantic structure. A <fieldset> provides both: a visual boundary (default border) and a semantic grouping that assistive technologies announce.

Key benefits:

  • Visual organization: Boxes around related fields help users scan.
  • Screen-reader context: The <legend> is announced with each field inside, giving context.
  • Bulk disable: Setting disabled on a <fieldset> disables all controls inside.
  • Semantic meaning: Screen readers can navigate by fieldset groups, jumping between sections.
Key insight Without <fieldset>, screen reader users hear only field labels. With it, they hear "Shipping address, Email [input]" — the group context is announced automatically. This is one of the cheapest, highest-impact accessibility wins available.

2 Basic fieldset + legend

The structure: <fieldset> wraps the group; <legend> is the first child and provides the group label.

<fieldset>
  <legend>Shipping address</legend>

  <label for="ship-name">Full name</label>
  <input type="text" id="ship-name" name="ship-name" required>

  <label for="ship-street">Street address</label>
  <input type="text" id="ship-street" name="ship-street" required>

  <label for="ship-city">City</label>
  <input type="text" id="ship-city" name="ship-city" required>

  <label for="ship-zip">Postal code</label>
  <input type="text" id="ship-zip" name="ship-zip" required>
</fieldset>

3 Legend as group label

The <legend> element must be the first child of the fieldset. It's announced as part of each labeled control inside. For radio and checkbox groups, this is essential — without it, screen reader users would hear only "Yes" / "No" with no idea what the question is.

<fieldset>
  <legend>Subscribe to newsletter?</legend>
  <label><input type="radio" name="sub" value="yes"> Yes</label>
  <label><input type="radio" name="sub" value="no" checked> No</label>
</fieldset>

<!-- "Subscribe to newsletter? Yes. Radio button. Not selected." -->

4 Nested fieldsets

Fieldsets can nest — useful for hierarchical grouping like "Shipping address" containing "Recipient" and "Address" sub-groups:

<fieldset>
  <legend>Order details</legend>

  <fieldset>
    <legend>Recipient</legend>
    <label for="r-name">Name</label>
    <input type="text" id="r-name" name="r-name">
    <label for="r-phone">Phone</label>
    <input type="tel" id="r-phone" name="r-phone">
  </fieldset>

  <fieldset>
    <legend>Delivery address</legend>
    <label for="d-street">Street</label>
    <input type="text" id="d-street" name="d-street">
    <label for="d-city">City</label>
    <input type="text" id="d-city" name="d-city">
  </fieldset>
</fieldset>

5 disabled on fieldset

Setting disabled on a <fieldset> disables every form control inside it — inputs, buttons, selects, textareas. Inherited by descendants. Perfect for "lock this section until prerequisite is met" patterns.

<fieldset disabled>
  <legend>Billing (locked until shipping confirmed)</legend>
  <input type="text" name="bill-name">
  <input type="text" name="bill-cc">
  <button type="submit">Process payment</button>
</fieldset>

Common mistake <legend> inside a disabled fieldset is not disabled — it's not a form control. But the styling of disabled fieldsets varies; you may need to explicitly dim the legend or keep its contrast high.

6 Styling considerations

Default browser styling for fieldsets is a thin border with the legend breaking the top border line. Many teams reset and rebuild:

/* Reset to clean look */
fieldset {
  border: 1px solid var(--line);
  border-radius: 12px;
  padding: 16px 20px;
  margin: 16px 0;
}
legend {
  padding: 0 8px;
  font-weight: 600;
  font-size: 1.1rem;
}

/* Card-style legend (above the fieldset) */
fieldset {
  border: none;
  border-radius: 12px;
  background: #f8fafc;
  padding: 24px;
  margin: 16px 0;
  position: relative;
}
legend {
  position: absolute;
  top: -12px;
  background: white;
  padding: 0 8px;
  font-weight: 600;
}
Pro tip Avoid setting display: flex or display: grid directly on the fieldset — some browsers have legacy rendering quirks. Instead, wrap the inner controls in a <div> and apply flex/grid there.

7 form attribute

Like other form controls, a <fieldset> accepts a form attribute to associate it with a form even when not a DOM descendant. Useful when you want the visual grouping but the actual form lives elsewhere.

<form id="checkout" action="/checkout" method="post">
  <!-- main form content -->
</form>

<!-- Visual grouping referencing the form -->
<fieldset form="checkout">
  <legend>Coupon</legend>
  <input type="text" name="coupon" form="checkout">
</fieldset>

8 Accessible group labeling alternatives

Sometimes <fieldset> + <legend> isn't possible — for instance, when a layout library expects plain divs. ARIA alternatives exist but should be last resorts:

<!-- ARIA alternative: role="group" + aria-labelledby -->
<div role="group" aria-labelledby="addr-label">
  <h3 id="addr-label">Shipping address</h3>
  <input type="text" name="ship-name">
  ...
</div>

<!-- For radio groups: role="radiogroup" + aria-labelledby -->
<div role="radiogroup" aria-labelledby="plan-label">
  <h3 id="plan-label">Choose plan</h3>
  <label><input type="radio" name="plan" value="free"> Free</label>
  <label><input type="radio" name="plan" value="pro"> Pro</label>
</div>
Common mistake Reaching for ARIA role="group" when <fieldset> would do the same job. The First Rule of ARIA is "Don't use ARIA." Native HTML provides the same semantics for free, with better cross-browser and AT support.

9 Common mistakes

MistakeConsequenceFix
Missing <legend>Fieldset announces as "group" with no nameAlways include a <legend> as first child
<legend> not first childSome browsers ignore the legendAlways make legend the first child
No fieldset for radio groupsScreen readers can't announce the questionAlways wrap radio groups in fieldset + legend
Using div with role="group" instead of fieldsetMisses default styling; ARIA not always picked up consistentlyPrefer native <fieldset>
Display: flex / grid directly on fieldsetQuirky rendering in older browsersWrap inner content in a div and flex/grid that
Multiple legends in one fieldsetOnly the first is announcedUse one legend per fieldset; nest if needed

10 Try it yourself

Exercise 1 — Group a checkout form Take a checkout form with shipping address, billing address, and payment fields. Wrap each in a <fieldset> + <legend>. Test with a screen reader to verify the legend is announced per field.
Exercise 2 — Conditional disable Build a form where one fieldset (e.g., "Billing address") is disabled by default. Add a checkbox "Billing same as shipping" that toggles the fieldset's disabled attribute via JavaScript.
Exercise 3 — Nested fieldsets Build a job application form with a top-level "Personal Information" fieldset containing nested fieldsets for "Contact details" and "Address". Verify each section is announced correctly.

12 Real-world use cases

Checkout forms

Separate fieldsets for shipping, billing, payment.

Radio question groups

Each yes/no or multi-choice question wrapped with its legend.

Multi-step wizards

One fieldset per step; legend describes the step.

Settings panels

Fieldsets group "Account", "Notifications", "Privacy" sections.

Read-only review

Disabled fieldsets show submitted data without allowing edits.

Nested complex forms

Fieldset within fieldset for hierarchical data (order > recipient, address, etc.).
