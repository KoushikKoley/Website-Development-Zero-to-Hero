The <button> Element

Buttons are the action verbs of forms. The <button> element is more powerful than its older cousin <input type="submit"> — it supports HTML content, icons, and per-button overrides of the form's action, method, enctype, and validation.

1 Button types

The type attribute on <button> controls what happens when the button is activated:

TypeBehaviorSubmits form?Default?
submitSubmits the formYesYes (inside a form)
resetResets all form fields to defaultsNo—
buttonDoes nothing by default; JS attaches behaviorNoYes (outside a form)
 
<button type="submit">Save</button>
<button type="reset">Clear</button>
<button type="button" onclick="toggle()">Toggle</button>
Common mistake Forgetting type="button" on a button inside a form whose only purpose is to trigger JavaScript. Without it, the button defaults to type="submit" and submits the form on every click — usually not what you want.

2 type="submit" (default)

Inside a form, <button> with no type defaults to submit. Clicking it (or pressing Enter on a single-line input) triggers form submission. If the button has a name attribute, its value (or text content) is included in the submission.

<form action="/save" method="post">
  <input type="text" name="title" required>
  <button type="submit">Save</button>
</form>
type="submit" demo

3 type="reset"

Resets all fields to their default values (the value attributes in HTML). Use sparingly — accidental clicks erase all user input with no undo. Better patterns exist: a "Clear" button with a confirm dialog, or omitting reset entirely.

<button type="reset">Clear form</button>
type="reset" demo — type something then click Clear

4 type="button"

A button with no default behavior — only does what JavaScript attaches. Use for: opening modals, toggling UI, triggering calculations, opening menus, etc. Always set type="button" explicitly when the button is inside a form but should not submit.

<button type="button" onclick="openModal()">
  Open dialog
</button>

<button type="button" id="calculate">Calculate total</button>
type="button" demo

5 button vs input type="submit"

The two ways to make a submit control:

Aspect<button type="submit"><input type="submit">
HTML content insideYes — icons, spans, SVGNo — only value string
CSS pseudo-elements (::before, ::after)YesLimited
Default label when no value setBrowser-localized "Submit"Browser-localized "Submit"
Per-button overridesYes (formaction, formmethod, etc.)Yes (same attributes)
RecommendationModern default — prefer thisLegacy code only
 
<!-- Old: limited -->
<input type="submit" value="Save">

<!-- Modern: rich content allowed -->
<button type="submit">
  <svg aria-hidden="true"><use href="#save-icon"></use></svg>
  Save changes
</button>
Pro tip In old Internet Explorer (6-7), <button> submitted its text content as the value rather than its value attribute — a famous bug. This is no longer a concern in modern browsers; reach for <button> freely.

6 Inner HTML content

The killer feature of <button>: rich content. Add icons, spans, line breaks, anything that's "phrasing content":

<!-- Icon + text -->
<button type="submit">
  <svg aria-hidden="true" width="16" height="16" viewBox="0 0 16 16">
    <path d="M2 2 L8 11 L14 2" stroke="currentColor" fill="none"/>
  </svg>
  Submit
</button>

<!-- Icon-only (must have aria-label) -->
<button type="button" aria-label="Close dialog">
  <svg aria-hidden="true">...</svg>
</button>

<!-- Multi-line text -->
<button type="button">
  <strong>Delete account</strong><br>
  <small>This action cannot be undone</small>
</button>

7 disabled

A boolean attribute that prevents interaction and excludes the button from form submission. Disabled buttons don't fire click events and aren't focusable. Useful for "Submit" buttons that should be inactive until the form is valid.

<button type="submit" disabled>Submit (incomplete)</button>

<!-- Enable via JS once form is valid -->
<script>
  const form = document.querySelector('form');
  const submitBtn = form.querySelector('button[type="submit"]');
  form.addEventListener('input', () => {
    submitBtn.disabled = !form.checkValidity();
  });
</script>
disabled demo
Common mistake Disabling the submit button until form is valid sounds like good UX, but it hides the problem — users can't see what's wrong. Better: enable the button always; show validation errors on submit attempt. Disabled buttons also fail accessibility audits (keyboard users can't focus them to discover they exist).

8 formaction / formenctype / formmethod / formtarget / formnovalidate

Five attributes that override the form's settings for this one button only:

AttributeOverridesUse case
formactionform's actionMultiple submit destinations (Save vs Publish)
formenctypeform's enctypeOne button uploads files, another doesn't
formmethodform's methodGET button vs POST button
formtargetform's targetOpen result in new tab for one button only
formnovalidateform's novalidate"Save Draft" skips validation; "Publish" validates
 
<form action="/publish" method="post">
  <input type="text" name="title" required>
  <textarea name="body" required></textarea>

  <!-- Save draft: skips validation, different endpoint -->
  <button type="submit" name="action" value="draft"
          formaction="/save-draft"
          formnovalidate>Save draft</button>

  <!-- Publish: full validation, default action -->
  <button type="submit" name="action" value="publish">Publish</button>
</form>
Pro tip These overrides let one form have multiple submit destinations with different validation rules — no JavaScript required. Server-side, check the action field value to determine which button was clicked.

9 Styling & focus

Buttons accept full CSS. Reset the default look first, then style:

/* Reset cross-browser defaults */
button {
  font: inherit;
  color: inherit;
  background: none;
  border: none;
  padding: 0;
  cursor: pointer;
}

/* Build your design system */
.btn {
  padding: 8px 16px;
  border-radius: 8px;
  font-size: 0.95rem;
  background: var(--brand);
  color: white;
  transition: background 0.15s;
}
.btn:hover { background: #1d4ed8; }
.btn:focus-visible {
  outline: 3px solid var(--brand);
  outline-offset: 2px;
}
.btn:active { transform: translateY(1px); }
Common mistake Setting outline: none on buttons and forgetting a replacement. Keyboard users lose the visible focus indicator. Always style :focus-visible explicitly.

10 Accessibility

Rules for accessible buttons:

  • Always have an accessible name. Either visible text or an aria-label for icon-only buttons.
  • Use <button> for actions, <a> for navigation. Don't fake buttons with <div onclick> — they miss keyboard support.
  • Don't nest interactive elements. A <button> inside another <button> is invalid HTML. Same for <a> inside <button>.
  • Disabled buttons aren't focusable. If you want them discoverable by keyboard users, use aria-disabled="true" + custom JS instead of disabled.
  • Pressing Enter and Space both activate buttons. The browser handles this — don't reimplement with JS.
  • Visible focus state. Always style :focus-visible.

12 Try it yourself

Exercise 1 — Button types Build a small form with a submit button, a reset button, and a "Help" button (type="button" that opens an alert). Verify that only the submit button submits the form.
Exercise 2 — Icon + text button Create a "Save changes" button with an inline SVG checkmark icon. Add an icon-only "Close" button (×) with an aria-label. Verify both are announced correctly by a screen reader.
Exercise 3 — Per-button overrides Build a form with two submit buttons. One ("Save Draft") uses formaction="/draft" + formnovalidate. The other ("Publish") uses the default action. Test that draft works without filling required fields; publish fails validation.
