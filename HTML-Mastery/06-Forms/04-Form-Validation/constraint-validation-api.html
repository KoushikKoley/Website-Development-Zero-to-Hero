Constraint Validation API

HTML5's native validation has a JavaScript counterpart: the Constraint Validation API. Run checkValidity() programmatically, customize error messages with setCustomValidity(), inspect the validity object to see exactly which constraint failed, and build fully custom error UIs.

1 API overview

The Constraint Validation API exposes native validation through JavaScript properties and methods on form elements:

MemberTypePurpose
willValidateProperty (boolean)Whether the element participates in validation
validityObject (ValidityState)10+ flags showing which constraints failed
validationMessageProperty (string)Localized error message (empty if valid)
checkValidity()MethodReturns true/false; fires invalid event if false
reportValidity()MethodLike checkValidity, but also shows native UI
setCustomValidity(msg)MethodSet a custom error message (empty string to clear)

2 willValidate

Boolean property indicating whether the element participates in constraint validation. Returns false for elements like disabled fields, <input type="hidden">, or buttons that aren't submittable.

const input = document.querySelector('input[name="email"]');
console.log(input.willValidate); // true (typical text input)

const hidden = document.querySelector('input[type="hidden"]');
console.log(hidden.willValidate); // false

const disabled = document.querySelector('input:disabled');
console.log(disabled.willValidate); // false

3 The validity object

The validity property is a ValidityState object with 10 boolean flags:

FlagTrue when
valueMissingRequired field is empty
typeMismatchValue doesn't match the type (email/url format)
patternMismatchValue doesn't match pattern regex
tooLongValue exceeds maxlength
tooShortValue shorter than minlength
rangeUnderflowNumeric/date value below min
rangeOverflowNumeric/date value above max
stepMismatchValue not aligned to step
badInputBrowser can't parse the value (e.g., non-numeric in number field)
customErrorA custom error was set via setCustomValidity()
validTrue only when all other flags are false — the field is valid
 
const email = document.querySelector('input[type="email"]');
const v = email.validity;
console.log(v.valid);             // false if any constraint failed
console.log(v.valueMissing);      // true if required & empty
console.log(v.typeMismatch);      // true if format invalid
console.log(v.patternMismatch);   // true if pattern failed
validity object inspector — type and watch flags update
valid: false valueMissing: true

4 checkValidity()

Runs validation silently — returns true if valid, false if not. Also fires an invalid event if invalid (which you can prevent to suppress default UI).

const form = document.querySelector('form');

form.addEventListener('submit', (e) => {
  if (!form.checkValidity()) {
    e.preventDefault();    // stop native submit
    // ... show custom errors
  }
});

// Or check a single field
const email = document.querySelector('input[type="email"]');
if (!email.checkValidity()) {
  console.log(email.validationMessage);
}
Pro tip checkValidity() doesn't show the browser's native error UI — it just returns a boolean. To trigger the native UI programmatically, use reportValidity().

5 reportValidity()

Like checkValidity(), but also shows the browser's native error UI for invalid fields. Returns true if all valid.

const form = document.querySelector('form');

document.querySelector('#validate-btn').addEventListener('click', () => {
  if (form.reportValidity()) {
    console.log('All fields valid!');
  } else {
    console.log('Invalid — browser shows errors');
  }
});
reportValidity() demo — click to validate without submitting

6 setCustomValidity()

The key to custom validation messages. Pass a non-empty string to mark the field invalid with that message; pass an empty string to clear the custom error.

// Set a custom error
passwordInput.setCustomValidity('Password must include a number');

// Clear it
passwordInput.setCustomValidity('');

// Common pattern: check on input
passwordInput.addEventListener('input', () => {
  if (!/\d/.test(passwordInput.value)) {
    passwordInput.setCustomValidity('Password must include a number');
  } else {
    passwordInput.setCustomValidity('');  // clear
  }
});
setCustomValidity() demo — password must include a number
Common mistake Setting a custom error and forgetting to clear it. The field stays invalid forever, even after the user fixes the input. Always pair the set with a clear in your input/change handler.

7 validationMessage

Read-only property returning the localized error message the browser would show. Empty string if valid. Useful for displaying in custom UI:

const input = document.querySelector('input');
if (!input.checkValidity()) {
  errorElement.textContent = input.validationMessage;
  errorElement.style.display = 'block';
}

8 The invalid event

Fires on each invalid field during checkValidity() or form submission. Can be canceled (via event.preventDefault()) to suppress native UI and show your own:

document.querySelectorAll('input, textarea, select').forEach(el => {
  el.addEventListener('invalid', (e) => {
    e.preventDefault();        // suppress native tooltip
    // Show custom error UI for this element
    const error = document.createElement('div');
    error.className = 'error-message';
    error.textContent = e.target.validationMessage;
    e.target.after(error);
  });
});

9 Custom error UI patterns

Combining the API pieces, here's a complete custom error UI pattern:

// 1. Suppress native UI on each field
document.querySelectorAll('input, textarea, select').forEach(el => {
  el.addEventListener('invalid', (e) => {
    e.preventDefault();
    showCustomError(e.target);
  });
  el.addEventListener('input', () => {
    clearCustomError(el);
  });
});

function showCustomError(el) {
  const errId = el.id + '-error';
  let err = document.getElementById(errId);
  if (!err) {
    err = document.createElement('div');
    err.id = errId;
    err.className = 'error';
    err.setAttribute('role', 'alert');
    el.setAttribute('aria-describedby', errId);
    el.insertAdjacentElement('afterend', err);
  }
  err.textContent = el.validationMessage;
  el.setAttribute('aria-invalid', 'true');
}

function clearCustomError(el) {
  const err = document.getElementById(el.id + '-error');
  if (err) err.remove();
  el.removeAttribute('aria-invalid');
  el.removeAttribute('aria-describedby');
}

// 2. Intercept form submit
form.addEventListener('submit', (e) => {
  if (!form.checkValidity()) {
    e.preventDefault();
    // The invalid events fired above already showed errors.
  }
});
Pro tip Always use role="alert" and aria-describedby on error messages. Screen readers will announce the error when it appears, and read it when the user focuses the field.

11 Try it yourself

Exercise 1 — Validity inspector Build a small form with a text input + email input + number input. On each input, log the entire validity object to the console. Try empty values, invalid emails, out-of-range numbers — see which flags flip.
Exercise 2 — Custom password rules Build a password field with rules: 8+ chars, contains uppercase, lowercase, and a digit. Use setCustomValidity() in an input handler to set a descriptive error message. Clear it when the password matches all rules. Show the error in a custom div with role="alert".
Exercise 3 — Custom error UI Replace the browser's native error tooltips with your own styled error messages. Use the invalid event with preventDefault() and a showCustomError() function. Clear errors on input.

13 Real-world use cases

Custom error UI

Replace native tooltips with branded error messages below each field.

Async validation

Check username availability via fetch; set custom error if taken.

Multi-step forms

Validate one step at a time via checkValidity() before showing next.

Password strength

Custom rules beyond pattern; live feedback with setCustomValidity.

Conditional requirements

Fields required only if another field has a certain value.

Server-side validation echo

After server rejects, set custom errors on the relevant fields.
