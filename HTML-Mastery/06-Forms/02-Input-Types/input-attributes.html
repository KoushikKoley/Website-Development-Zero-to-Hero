Input Attributes

Beyond type, every input accepts a shared set of universal attributes. name and value control submission; disabled, readonly, required shape behavior; autocomplete unlocks password-manager integration with 50+ token values. Master these and your forms become effortless to fill in.

1 Universal attributes overview

These attributes apply to (most) input types regardless of type value:

2 name

The most fundamental attribute — without it, the control's value never reaches the server. Use lowercase, hyphen-separated names that match your server's expected keys.

<label for="email">Email</label>
<input type="email" id="email" name="email" required>

<!-- Array-style names (server-side frameworks like PHP parse these) -->
<input type="checkbox" name="tags[]" value="tech">
<input type="checkbox" name="tags[]" value="sports">
Common mistake Using id in place of name. id is for DOM access and label association; name is for form submission. They can differ, and often should — id should be unique per page, while name can repeat (e.g., for checkbox groups).

3 value

Sets the initial value of the control. For text inputs, the value users see; for checkboxes/radios, the value submitted when checked; for buttons, the label.

<input type="text" name="city" value="San Francisco">
<input type="checkbox" name="agree" value="yes">
<input type="radio" name="plan" value="pro">
<input type="submit" value="Save changes">
<input type="hidden" name="user_id" value="42">

4 disabled

Greys out the control and excludes it from submission. Useful for buttons that should be visible but inactive (e.g., "Submit" disabled until form is valid).

<input type="text" name="locked" value="Cannot edit" disabled>
<button type="submit" disabled>Submit (incomplete)</button>
disabled demo

5 readonly

Locks the field against user editing but includes it in submission. Useful for displaying a value the user can't change but the server needs (e.g., username on a profile-edit form).

<label for="username">Username (cannot change)</label>
<input type="text" id="username" name="username"
       value="alice42" readonly>
readonly demo — value still submitted
Pro tip Difference table: disabled = not editable, not focused, not submitted, greyed out. readonly = not editable, focusable (can copy text), submitted, looks normal. Pick based on whether you need the value sent.

6 required

Boolean attribute. The browser blocks submission and shows an error if the field is empty. Pair with a visible indicator (asterisk + accessible text).

<label for="email">Email <span aria-hidden="true" style="color:red">*</span>
  <span class="sr-only">(required)</span>
</label>
<input type="email" id="email" name="email" required>

7 placeholder

Hint text shown inside the field when empty. Disappears on focus/input. Never use as a label substitute — covered in detail in Text Inputs.

<input type="email" name="email"
       placeholder="you@example.com">

8 autofocus

Browser focuses this field on page load. Only one field per page can have it. Useful for search pages and login forms where users immediately start typing.

<input type="search" name="q" autofocus>
Common mistake Using autofocus on long forms. Screen-reader users get jumped to the form, missing the heading and intro text. Mobile users get the keyboard popping up over the page content. Reserve autofocus for forms that are the primary purpose of the page.

9 autocomplete (50+ tokens)

Controls browser autofill and gives password managers hints about what each field contains. The token values are standardized by WHATWG — modern browsers recognize dozens:

Namename, given-name, family-name, additional-name, honorific-prefix, honorific-suffix, nickname, organization-title
Email / phoneemail, tel, tel-national, tel-country-code, tel-area, tel-local
Addressstreet-address, address-line1, address-line2, address-line3, address-level1 (state), address-level2 (city), address-level3, address-level4, country, country-name, postal-code
Organizationorganization, organization-title, transaction-currency, transaction-amount
Credit cardcc-name, cc-number, cc-exp, cc-exp-month, cc-exp-year, cc-csc, cc-type
Date / timebday, bday-day, bday-month, bday-year, sex
URL / IMurl, photo, impp
Groupingsection-* (e.g., section-shipping), shipping, billing, home, work, mobile, fax, pager

<!-- Full checkout form with proper autocomplete tokens -->
<form action="/checkout" method="post" autocomplete="on">
  <fieldset>
    <legend>Shipping address</legend>
    <input type="text" name="ship-name" autocomplete="section-shipping name">
    <input type="text" name="ship-street" autocomplete="section-shipping street-address">
    <input type="text" name="ship-city" autocomplete="section-shipping address-level2">
    <input type="text" name="ship-state" autocomplete="section-shipping address-level1">
    <input type="text" name="ship-zip" autocomplete="section-shipping postal-code">
    <input type="text" name="ship-country" autocomplete="section-shipping country-name">
  </fieldset>

  <fieldset>
    <legend>Billing address</legend>
    <input type="text" name="bill-name" autocomplete="section-billing name">
    <input type="text" name="bill-cc" autocomplete="section-billing cc-number">
    <input type="text" name="bill-exp" autocomplete="section-billing cc-exp">
    <input type="text" name="bill-cvc" autocomplete="section-billing cc-csc">
  </fieldset>
</form>
Pro tip Setting autocomplete tokens dramatically improves conversion rates — users with saved autofill data can complete checkout in seconds. Skipping these tokens means users type everything manually, increasing abandonment.

10 inputmode

Hint to mobile browsers about which keyboard to show. Doesn't change validation or value — purely UX. Common values: text, numeric, decimal, tel, email, url, search, none. (Detailed in Text Inputs.)

<!-- PIN field: numeric keyboard, but stays a text input -->
<input type="text" name="pin" inputmode="numeric"
       pattern="[0-9]{4}" maxlength="4">

11 enterkeyhint

Customizes the Enter key's label on mobile keyboards. Values: enter, done, go, next, previous, search, send. (See Text Inputs for full table.)

<input type="search" name="q" enterkeyhint="search">
<input type="text" name="message" enterkeyhint="send">

12 list

References the id of a <datalist> element, turning a text input into one with autocomplete suggestions. Covered in detail in Choice Inputs.

<input type="text" name="city" list="cities">
<datalist id="cities">
  <option value="New York">
  <option value="London">
</datalist>

13 multiple

Allows multiple values. Applies to type="email" (comma-separated emails), type="file" (multiple files), and <select> (renders as multi-select list box).

<input type="email" name="recipients" multiple>
<input type="file" name="photos" accept="image/*" multiple>
<select name="skills" multiple>
  <option>HTML</option><option>CSS</option>
</select>

14 form

Associates a control with a <form> by id, even when the control is not a DOM descendant of the form. Useful for buttons outside the form area.

<form id="main-form" action="/save" method="post">
  <input type="text" name="title" required>
</form>

<!-- Submit button lives outside the form -->
<button type="submit" form="main-form">Save</button>

16 Try it yourself

Exercise 1 — Full checkout form Build a checkout form with shipping + billing addresses. Use proper autocomplete tokens including section-shipping and section-billing prefixes, so the browser fills them independently. Test by saving an address in your browser's autofill settings.
Exercise 2 — Login form Build a login form with email + password. Set autocomplete="username" on the email and autocomplete="current-password" on the password. Verify your browser's password manager offers to save credentials on submit.
Exercise 3 — Disabled vs readonly Build a small form with one disabled field and one readonly field. Submit the form (with method="get") and observe the URL — verify that the disabled field's value is missing but the readonly field's value is sent.

18 Real-world use cases

E-commerce checkout

Full autocomplete tokens per field → 1-click autofill → higher conversion.

Login / signup

Username + password tokens trigger password manager integration.

OTP / 2FA

autocomplete="one-time-code" auto-fills from SMS on iOS/Android.

Profile editors

Use readonly for non-editable fields (username, created-at).

Multi-section forms

Use section-* autocomplete prefix to keep shipping/billing distinct.

Search-focused pages

autofocus on search input — primary purpose of the page.
