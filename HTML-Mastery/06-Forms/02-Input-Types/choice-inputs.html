Choice Inputs

When users pick from a fixed set of options, the right element matters: checkbox for multi-select, radio for single-select, <select> for dropdowns, and <datalist> for free-text-with-suggestions. Pick wrong and users fight the UI; pick right and the form feels effortless.

1 Choice input types overview

ElementSelection modelUITypical use
<input type="checkbox">Multi-select (each is independent)Square check boxTags, preferences, "remember me"
<input type="radio">Single-select (within name group)Round radioPlan choice, gender, yes/no
<select> + <option>Single or multiDropdown listCountry, state, large option sets
<datalist>Free text + suggestionsText input with autocomplete dropdownCity, airport code, custom values
Key insight Radio buttons share state by name — pick one in a group and the others deselect. Checkboxes are independent even with the same name (you get multiple values submitted). The name attribute is the grouping mechanism, not the surrounding <fieldset>.

2 Checkbox (multiple selections)

Each checkbox is independent. Submitting a form with checkboxes of the same name sends multiple name=value entries — one per checked box.

<fieldset>
  <legend>Which languages do you speak?</legend>
  <label><input type="checkbox" name="lang" value="en"> English</label>
  <label><input type="checkbox" name="lang" value="fr"> French</label>
  <label><input type="checkbox" name="lang" value="es"> Spanish</label>
  <label><input type="checkbox" name="lang" value="de"> German</label>
</fieldset>

<!-- Single boolean -->
<label><input type="checkbox" name="agree" required>
  I accept the terms</label>
Checkbox demo — check multiple
Which languages do you speak?
Pro tip For boolean "yes/no" fields (like "Subscribe to newsletter"), use a single checkbox with a meaningful value (e.g., value="yes"). The server checks presence: if the field name appears in the submission, the user checked it; otherwise, they didn't.

3 Radio (single selection)

Radio buttons in the same name group are mutually exclusive — selecting one deselects the others. Always pre-check a default with checked to avoid "no selection" states (unless you genuinely need the user to choose).

<fieldset>
  <legend>Plan</legend>
  <label><input type="radio" name="plan" value="free" checked> Free</label>
  <label><input type="radio" name="plan" value="pro"> Pro ($9/mo)</label>
  <label><input type="radio" name="plan" value="team"> Team ($29/mo)</label>
</fieldset>

4 Name grouping for radios

The name attribute defines the radio group. All radios with the same name are exclusive; different names are independent. This lets you have multiple radio groups in the same form.

<fieldset>
  <legend>Delivery method</legend>
  <label><input type="radio" name="delivery" value="standard" checked> Standard</label>
  <label><input type="radio" name="delivery" value="express"> Express</label>
</fieldset>

<fieldset>
  <legend>Gift wrap?</legend>
  <label><input type="radio" name="wrap" value="no" checked> No</label>
  <label><input type="radio" name="wrap" value="yes"> Yes (+$5)</label>
</fieldset>

<!-- Server receives: delivery=express & wrap=yes -->
Common mistake Forgetting the name attribute on radios. Without it, each radio is its own group of one — you can select all of them, defeating the purpose.

5 select + option

Dropdown picker. The first <option> becomes the default (unless another has selected). The submitted value is the value attribute of the selected option, or the option's text content if value is omitted.

<label for="country">Country</label>
<select id="country" name="country" autocomplete="country">
  <option value="">Select a country...</option>
  <option value="us">United States</option>
  <option value="ca">Canada</option>
  <option value="uk">United Kingdom</option>
  <option value="au">Australia</option>
</select>

<!-- Pre-selected option -->
<select name="size">
  <option value="s">Small</option>
  <option value="m" selected>Medium</option>
  <option value="l">Large</option>
</select>
Select demo
Pro tip Include a "Select..." placeholder option with empty value as the first option (and add required if needed). This forces users to actively choose rather than accepting a default they didn't read.

6 optgroup (grouping options)

For long option lists, group options with <optgroup label="...">. Browsers render group headers (non-selectable) — users see structure.

<select name="car">
  <optgroup label="American">
    <option value="ford">Ford</option>
    <option value="chevy">Chevrolet</option>
    <option value="tesla">Tesla</option>
  </optgroup>
  <optgroup label="German">
    <option value="bmw">BMW</option>
    <option value="merc">Mercedes</option>
    <option value="audi">Audi</option>
  </optgroup>
  <optgroup label="Japanese">
    <option value="toyota">Toyota</option>
    <option value="honda">Honda</option>
    <option value="mazda">Mazda</option>
  </optgroup>
</select>

7 datalist (autocomplete suggestions)

A <datalist> provides suggestion values for a text input. Unlike a <select>, users can type their own value — suggestions are non-binding. Great for cities, airports, tags, or any value where you want to suggest common ones but allow custom.

<label for="city">City</label>
<input type="text" id="city" name="city" list="cities">
<datalist id="cities">
  <option value="New York">
  <option value="Los Angeles">
  <option value="Chicago">
  <option value="Houston">
  <option value="Phoenix">
</datalist>
datalist demo — type to filter suggestions, or pick from list
Pro tip <option> in <datalist> can also have a text content (e.g., <option value="NYC">New York City</option>) — some browsers show both. Useful when the value is an airport code but the user knows the city name.

9 When to use each

2-4 options, single selectRadio buttonsVisible at once; users see all choices
5-15 options, single selectSelect dropdownSaves space; manageable list length
16+ options, single selectSelect with optgroup, or datalistAvoid overwhelming users; grouping or autocomplete helps
Multiple selections from listCheckboxes, or select multipleCheckboxes are more discoverable
Suggestions but custom alloweddatalistCombines free text with hints
Yes/NoSingle checkbox, or two radiosCheckbox for "yes"; radios if you need explicit "no"

10 Common mistakes

MistakeConsequenceFix
Same value for all radiosServer can't tell which was selectedEach radio needs a unique value
Missing name on radiosAll become independently selectableAlways set name
Checkbox with no valueSubmits "on" if checked; useless valueAlways set explicit value
Using <select> for 2 optionsRequires extra click to see choicesUse radio buttons
Using <select> for searchable listsHard to find one item in 50+Use <datalist> or a custom autocomplete widget
No default checked on radiosForm submits with no value; user may not realize they need to pickPre-check a default
Forgetting <fieldset> + <legend>Screen readers can't announce group contextWrap related radios/checkboxes

11 Try it yourself

Exercise 1 — Build a preferences form Create a form with: gender (radio group), preferred contact method (radio group), and newsletter topics (checkboxes for Tech, Sports, Politics, Business). Use <fieldset> + <legend> for each group.
Exercise 2 — Country selector Build a <select> with at least 20 countries, grouped by continent using <optgroup>. Include a placeholder "Select..." option with empty value. Make the field required.
Exercise 3 — City autocomplete Create a text input with list pointing to a <datalist> of 10 major world cities. Verify that you can type a custom value (e.g., "Reykjavik") even if it's not in the suggestions.

12 Browser support

checkbox / radio — universal select / option / optgroup — universal datalist — all modern browsers (Safari 12.1+) multiple on select — universal checked / selected — universal

<datalist> is the only one with non-universal historical support — it works in all modern browsers including Safari 12.1+.

13 Real-world use cases

Country / region pickers

<select> with optgroup by continent. ~200 countries.

Subscription tiers

Radio buttons for Free / Pro / Team — visible, easy comparison.

Tag selectors

Checkboxes for multi-tag selection in CMS, social platforms.

City / airport lookup

<datalist> with suggestions; allows custom input.

Terms acceptance

Single required checkbox at signup.

Multi-skill selection

<select multiple> or checkboxes — depends on count.
