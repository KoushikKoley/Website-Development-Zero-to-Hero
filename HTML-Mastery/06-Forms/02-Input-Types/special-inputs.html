Special Inputs

HTML's input types include some specialized tools beyond text and numbers: color pickers, file uploads, hidden storage, image buttons, and the button-style inputs (submit, reset, button). Each has a specific role — and accessibility quirks worth knowing.

1 Special input types overview

TypePurposeSubmits data?
colorPick a hex colorYes — sends #rrggbb
fileUpload one or more filesYes — sends file bytes (multipart)
hiddenCarry server data invisible to userYes — sends value
imageImage as submit button; sends click coordinatesYes — sends name.x and name.y
submitSubmit button (text label only)Yes — sends name=value if name set
resetReset form to defaultsNo — clears the form instead
buttonGeneric button (JS only)No — no default behavior

2 type="color"

Renders a native color picker. The submitted value is always a 7-character hex string (#rrggbb), lowercase, including the leading #.

<label for="accent">Accent color</label>
<input type="color" id="accent" name="accent" value="#2563eb">

<!-- Server receives: accent=#2563eb -->
type="color" demo — click to open picker
#2563eb
Common mistake type="color" only supports 6-digit hex (no alpha, no named colors, no HSL). If you need transparency or other formats, use a custom widget. Setting value="#fff" or value="red" is invalid — defaults to #000000.

3 type="file" (accept, multiple, capture)

Renders a "Choose File" button. The selected file's content (not just its name) is submitted when paired with enctype="multipart/form-data".

accept — filter the file picker

<!-- Accept only images -->
<input type="file" name="avatar" accept="image/*">

<!-- Accept specific extensions -->
<input type="file" name="doc" accept=".pdf,.doc,.docx">

<!-- Accept specific MIME types -->
<input type="file" name="img" accept="image/png,image/jpeg">

<!-- Accept any audio file -->
<input type="file" name="track" accept="audio/*">

multiple — allow multiple files

<label for="photos">Upload photos</label>
<input type="file" id="photos" name="photos"
       accept="image/*" multiple>
<!-- Server receives an array of files under name "photos" -->

capture — use device camera/mic directly

<!-- On mobile, opens camera directly instead of file picker -->
<input type="file" name="selfie" accept="image/*" capture="user">

<!-- Opens rear camera -->
<input type="file" name="document-scan" accept="image/*" capture="environment">

<!-- Opens microphone for audio recording -->
<input type="file" name="voice-note" accept="audio/*" capture>
type="file" demos
Common mistake accept is a hint, not validation. Users can change the file picker filter and upload anything. Always validate file type and size on the server. Malicious users can submit any file regardless of accept.

4 type="hidden"

An invisible input whose value is submitted with the form. Common uses: database record IDs, CSRF tokens, redirect URLs, pre-computed values from server-side templating.

<form action="/update-profile" method="post">
  <!-- Hidden record ID -->
  <input type="hidden" name="user_id" value="42">

  <!-- CSRF protection token (server-generated) -->
  <input type="hidden" name="csrf_token" value="r9X2...long-random-string">

  <!-- Where to redirect after success -->
  <input type="hidden" name="redirect_to" value="/dashboard">

  <label for="email">Email</label>
  <input type="email" id="email" name="email" required>
  <button>Save</button>
</form>
Common mistake Hidden fields are not secure. Anyone can edit their value via dev tools. Never trust them for permissions (e.g., name="is_admin" value="true") — always verify on the server.
Pro tip For complex data, use a single hidden field with JSON or an ID, then look up details on the server. Avoid storing arrays or huge structures in hidden fields — they bloat the form payload.

5 type="image" (image submit button)

Displays an image that, when clicked, submits the form. Uniquely, it sends the click coordinates relative to the image — useful for image maps and "click on a region" interactions.

<form action="/map-click" method="post">
  <input type="hidden" name="map_id" value="world">
  <input type="image" src="world-map.png"
         alt="Click a region on the world map"
         name="location">
</form>

<!-- Server receives: map_id=world & location.x=348 & location.y=201 -->
type="image" demo — click anywhere on the image (no actual submit)
Common mistake Forgetting the alt attribute on type="image". Screen readers will announce "submit button" with no label, or worse, the image filename. Always provide descriptive alt.
Pro tip Prefer <button type="submit"> with an inline SVG or background image over <input type="image"> — buttons are more flexible, support icons and labels together, and don't require a separate HTTP request for the image.

6 type="submit"

The original submit button (pre-HTML4). Renders a button with text from the value attribute. Limited — can't contain icons or rich HTML. Prefer <button type="submit"> for modern code.

<!-- Old-school submit input -->
<input type="submit" value="Save changes">

<!-- With name (sends name=value) -->
<input type="submit" name="action" value="save">
<input type="submit" name="action" value="publish">

<!-- Per-button override -->
<input type="submit" value="Save draft"
       formaction="/save-draft" formnovalidate>
<input type="submit" value="Publish"
       formaction="/publish">
type="submit" demo

7 type="reset"

Resets all form fields to their default values (the value attributes set in HTML, or empty if unset). Use sparingly — accidental clicks erase user input with no undo.

<form>
  <label for="q">Search</label>
  <input type="text" id="q" name="q" value="">
  <input type="submit" value="Search">
  <input type="reset" value="Clear">
</form>
type="reset" demo — type something, then click Reset
Common mistake Putting a Reset button next to Submit. Users instinctively click the rightmost button — and "Reset" is usually on the right. Result: lost data, frustration. Avoid reset buttons entirely unless the form genuinely benefits from clearing (rare).

8 type="button"

A button with no default behavior — only does what JavaScript attaches. Useful for triggering JS handlers ("Add another", "Calculate total", "Show preview") without submitting the form.

<input type="button" value="Add field" onclick="addField()">

<!-- Better: use <button> element -->
<button type="button" onclick="addField()">
  <svg>...</svg> Add field
</button>
type="button" demo

9 Accessibility

Each special input type has accessibility considerations:

TypeA11y requirement
colorAlways pair with a visible <label>. The picker itself is keyboard-accessible on most browsers.
fileAlways pair with a <label>. Drag-and-drop alternatives should also support keyboard (focusable drop zone with Enter/Space).
hiddenInvisible — no a11y needs, but ensure value isn't relied on for security.
imageMandatory alt attribute — without it, screen readers announce "submit button" with no label.
submit / reset / buttonvalue attribute provides the accessible name. Make it descriptive ("Save changes", not "OK").
Pro tip For all button types, prefer the <button> element over <input type="submit|reset|button">. <button> supports HTML content (icons, spans), is easier to style with CSS, and is fully accessible.

11 Try it yourself

Exercise 1 — Theme picker Build a small form with a type="color" picker for an accent color. Use JavaScript to update the page's CSS custom property when the user picks a color, so they see their theme live.
Exercise 2 — Photo upload Build a file upload form: avatar (single image), gallery (multiple images), with appropriate accept. Add capture="user" on the avatar field so mobile users go straight to the selfie camera.
Exercise 3 — Compare button types Build the same form with three submit controls: <input type="submit">, <input type="image">, and <button type="submit">. Note what each submits (especially the image's x/y coordinates) and how accessible each is.

13 Real-world use cases

Theme customization

type="color" for accent / background color pickers in settings.

Avatar / profile photo

type="file" accept="image/*"; with capture="user" for mobile selfie flow.

Document upload

type="file" accept=".pdf,.doc,.docx" for resumes, contracts.

CSRF tokens

type="hidden" carries server-generated token with every POST.

Image-map interactions

type="image" for "click on the map to mark location" UX.

Multi-action forms

Multiple submit buttons with different formaction endpoints.
