Resource Hints

preload, prefetch, preconnect, dns-prefetch, modulepreload, prerender — six ways to tell the browser "start fetching this now so it's ready when I need it". Picking the right one is a major lever on perceived performance.

1 The Six Hints at a Glance

Resource hints are <link rel="..."> tags in the head (or HTTP Link headers) that tell the browser to start work on a resource before it's needed. Each has a different scope and priority.

HintWhat it doesPriorityUse case
preloadFetches resource for current page, with high priorityHighLCP image, critical font, late-discovered CSS
prefetchFetches resource for next navigation, low priorityLowestNext-page assets when user is likely to click
preconnectOpens DNS + TCP + TLS handshake to originHigh (cheap)Third-party hosts (CDN, analytics, fonts)
dns-prefetchResolves DNS onlyLowCheaper fallback for preconnect
modulepreloadPreloads ES module + its dependenciesHighApp bundles before they're imported
prerenderRenders entire next page in backgroundn/aDeprecated — use Speculation Rules API instead

2 preload

<link rel="preload"> tells the browser: "fetch this resource now, at high priority, because I'll need it during current-page rendering". The browser treats it as a hint, not a guarantee — but for critical resources it almost always complies.

<head>
  <!-- Preload the LCP image -->
  <link rel="preload" as="image" href="/img/hero.webp"
        fetchpriority="high">

  <!-- Preload a critical font -->
  <link rel="preload" as="font" type="font/woff2"
        href="/fonts/inter-var.woff2" crossorigin>

  <!-- Preload CSS that the parser discovers late (e.g. injected by JS) -->
  <link rel="preload" as="style" href="/css/late.css">

  <!-- Preload a JS module -->
  <link rel="preload" as="script" href="/js/critical.js">
</head>

The as attribute is mandatory

Without as, the browser can't set the right priority, content-type, or accept headers. Valid values: audio, document, embed, fetch, font, image, object, script, style, track, video, worker.

Common Mistake Preloading a resource you never actually use. The download still happens — wasting the user's bandwidth. Only preload things you're certain will be requested within seconds.

3 prefetch

<link rel="prefetch"> is for the next navigation. The browser fetches the resource at low priority during idle time and stores it in the HTTP cache. If the user does navigate to the page that needs it, the resource is already local.

<!-- Prefetch the next article the user will probably read -->
<link rel="prefetch" as="document" href="/blog/next-article">
<link rel="prefetch" as="script" href="/js/next-page-bundle.js">
<link rel="prefetch" as="image" href="/img/next-hero.webp">

Smart prefetch patterns

  • Next-page prediction — prefetch the URL the user is hovering over for 100ms+ ("quicklink" library)
  • Sequential content — on page 2 of a paginated list, prefetch page 3
  • Checkout flow — prefetch the next step's assets
<!-- "Quicklink" pattern: prefetch on hover -->
<script type="module">
  document.querySelectorAll('a').forEach(a => {
    a.addEventListener('mouseenter', () => {
      const link = document.createElement('link');
      link.rel = 'prefetch';
      link.href = a.href;
      document.head.appendChild(link);
    }, { once: true });
  });
</script>
Pro Tip Don't prefetch 50 links "just in case" — you'll burn mobile data plans. Limit to the next 1–2 likely destinations, and respect Save-Data header and slow-connection users.

4 preconnect

Before the browser fetches a resource from a new origin, it must: resolve DNS, open a TCP connection, and complete a TLS handshake. That's 100–500ms on mobile 4G. preconnect tells the browser to start this work now, so when a resource is needed the connection is already warm.

<head>
  <!-- Warm up connections to third-party hosts -->
  <link rel="preconnect" href="https://fonts.googleapis.com">
  <link rel="preconnect" href="https://cdn.example.com" crossorigin>
  <link rel="preconnect" href="https://api.example.com">

  <!-- Then load the resources -->
  <link rel="stylesheet"
        href="https://fonts.googleapis.com/css2?family=Inter:wght@400;700">
</head>

When to use crossorigin

If the resource will be fetched with CORS (fonts, fetch() with mode: cors, modules), add crossorigin to the preconnect. Otherwise the browser opens a non-CORS connection that the CORS request can't reuse.

Common Mistake Preconnecting to more than 3–4 origins. Each open connection consumes memory and network state. Limit preconnects to hosts you'll actually fetch from within 5 seconds.

5 dns-prefetch

A cheaper alternative to preconnect — only resolves DNS, doesn't open TCP/TLS. Useful for hosts you'll use later or that might not be needed at all.

<!-- DNS-only prefetch for analytics that may or may not load -->
<link rel="dns-prefetch" href="//www.google-analytics.com">
<link rel="dns-prefetch" href="//cdn.jsdelivr.net">

Many sites stack preconnect and dns-prefetch together — the latter is a fallback for browsers that don't support preconnect (essentially IE/old Safari).

<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link rel="dns-prefetch" href="https://fonts.gstatic.com">

6 modulepreload

Specifically for ES modules. modulepreload fetches the module and recursively fetches its dependencies, parses them, and prepares them for synchronous execution when imported.

<head>
  <link rel="modulepreload" href="/js/app.js">
</head>
<body>
  ...
  <script type="module">
    // app.js is already parsed and ready — this import resolves instantly
    import { init } from '/js/app.js';
    init();
  </script>
</body>

Without modulepreload, the browser discovers dependencies as it parses each module file — serially. For deep dependency trees this is a multi-hundred-millisecond cost.

Pro Tip Modern bundlers like Vite automatically inject modulepreload hints for the entry chunk and its imports. If you're hand-authoring modules, add these hints yourself for any module on the critical path.

7 prerender (deprecated)

The old <link rel="prerender"> hint asked the browser to load and render an entire next page in the background. It was unreliable — Chrome silently turned it into a prefetch in 2018, and other browsers never fully supported it. It is now deprecated.

The modern replacement is the Speculation Rules API:

<script type="speculationrules">
{
  "prerender": [
    {
      "where": { "href_matches": "/blog/*" },
      "eagerness": "moderate"
    }
  ]
}
</script>

This enables full prerendering (with JS execution) when the user hovers over or clicks matching links. Supported in Chrome 121+. Other browsers ignore the script tag safely.

8 When to Use Which

Use preload when

You're certain the current page will need this resource within seconds, and the browser would otherwise discover it too late. The LCP image, hero fonts, late-injected CSS.

Use prefetch when

The user is likely to navigate to a specific next page. Idle-time bandwidth is fine; this is a bet on user behavior.

Use preconnect when

You'll fetch from a third-party origin within 5 seconds and want to skip the connection setup cost. Fonts, CDNs, APIs.

Use dns-prefetch when

You might need a third-party host but aren't sure. Cheap insurance against the DNS lookup cost.

Use modulepreload when

Your app uses ES modules and the entry chunk has dependencies. Pre-parses the whole graph before the import statement runs.

Use Speculation Rules when

You want true instant page transitions on likely-next navigations. Falls back gracefully in unsupported browsers.

9 Priority & fetchpriority

Each hint has a default priority the browser assigns. You can override with the fetchpriority attribute — useful for telling the browser "this image really is the LCP element, prioritize it above other images".

HintDefault priorityNotes
preload as=imageHighBoost with fetchpriority="high" for LCP
preload as=styleHighEquivalent to a <link rel=stylesheet>
preload as=scriptHighDoesn't execute, just caches
preload as=fontHighRequires crossorigin attribute
prefetchLowestOnly runs in idle time
preconnectHigh (no payload)Cheap; do early
 
<!-- Hero image is LCP — boost it -->
<link rel="preload" as="image" href="/img/hero.webp"
      fetchpriority="high">

<!-- Below-the-fold images — de-prioritize -->
<img src="/img/footer-bg.webp" fetchpriority="low" alt="">

10 Common Mistakes

✗ Mistakes

  • preload without as — useless
  • preload as=font without crossorigin — fetches twice
  • Preloading 10 resources "just in case"
  • prefetch on every link on the page
  • preconnect to 12 origins
  • Using prerender in 2024 — deprecated, no-op

✓ Correct

  • Always specify as
  • Fonts need crossorigin (CORS-required by spec)
  • Preload only the 1–2 truly critical resources
  • Prefetch on hover, max 1–2 destinations
  • Preconnect to 3–4 hosts max
  • Use Speculation Rules API for true prerendering
Common Mistake Forgetting crossorigin on a font preload. The browser fetches the font via CORS for the actual @font-face request. If your preload wasn't a CORS request, the browser caches a non-CORS copy it can't use, then re-fetches. You've doubled the bandwidth.

11 Exercise

Exercise: Add Hints to a News Site

You're optimizing a news article page. The page loads:

  • Hero image from the same origin (the LCP element)
  • Body font from fonts.gstatic.com
  • Analytics from www.google-analytics.com
  • A hero video from cdn.example.com (loaded on user click)
  • An ES module entry from /js/article.js

The page also has links to the next article in a series at the bottom.

Tasks:

  1. Write the resource hints to add to the <head>.
  2. Decide which need crossorigin.
  3. Decide which resource should get fetchpriority="high".
  4. Add a prefetch for the next article.
  5. Replace any deprecated prerender usage with Speculation Rules.

12 Browser Support

preload: all modern browsers prefetch: all modern browsers (Firefox respects less aggressively) preconnect: all modern browsers dns-prefetch: all browsers including IE9+ modulepreload: Chrome 66+, Firefox 67+, Safari 14+ Speculation Rules: Chrome 121+ (others ignore safely) fetchpriority: Chrome 101+, Safari 17+ (Firefox: in development)
Real-World Use Case An e-commerce homepage added preconnect to its three primary third-party origins (font CDN, image CDN, payment API) and preload as=image fetchpriority="high" on the hero. LCP dropped from 2.8s to 1.4s — a 50% improvement on the same network. Conversion rate rose 3.2% as a direct result.
