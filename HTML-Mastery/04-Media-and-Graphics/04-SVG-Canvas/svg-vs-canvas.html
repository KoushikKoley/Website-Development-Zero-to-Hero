SVG vs Canvas — The Decision Matrix

Two ways to draw on the web. One is a vector DOM tree that scales forever; the other is a pixel surface you redraw every frame. Choosing correctly makes the difference between buttery 60 FPS and a janky mess.

1 The One-Line Answer

Rule of thumb

If you can describe your graphic with shapes and you want it to scale and be interactive, use SVG. If you have thousands of objects, per-pixel manipulation, or a real-time game loop, use Canvas.

3 SVG Strengths

Scales infinitely

Same SVG file works at 16px favicon or 4-meter billboard. No re-exporting at different sizes.

DOM-accessible

Every shape is an element. Inspect in DevTools, query with querySelector, animate with CSS.

CSS-stylable

Theme entire icon sets with color + currentColor. Hover, focus, transitions work natively.

Accessible by default

<title> + <desc> expose text to screen readers. Per-shape ARIA supported.

SEO-friendly

Text inside SVG is selectable and indexable. Charts with axis labels are crawlable.

Print-friendly

Stays vector when printed. Logos and diagrams look sharp on paper at 600 DPI.

4 Canvas Strengths

Handles thousands of objects

Particle systems with 100k sprites, real-time particle physics — Canvas thrives where SVG chokes.

Per-pixel control

getImageData / putImageData for filters, image processing, computer vision.

Real-time rendering

Direct pixel writes are faster than DOM mutations. 60 FPS games, 120 FPS simulators.

GPU acceleration

WebGL context offloads drawing to the GPU. Massive parallelism for 3D and shaders.

Fixed memory

Buffer is always width × height × 4 bytes regardless of scene complexity. Predictable.

Output to image / video

canvas.toDataURL() exports PNG; captureStream() exports to MediaRecorder.

5 Performance Comparison

Performance depends heavily on what you're doing. General guidance:

ScenarioSVGCanvasWinner
Static icon (1 element)~0.01 ms render~0.5 ms (JS overhead)SVG
100 simple shapes, static~1 ms~2 msTie
1,000 animated shapes~50 ms (slow)~5 msCanvas
10,000 particles> 500 ms (janky)~10 msCanvas
100k pixels of photo filterN/A (no pixel access)~3 msCanvas (only option)
Hover state on a shapeNative CSS hoverManual hit-testingSVG
Resize / zoom interactionFree (vector)Re-render entire sceneSVG
Why SVG gets slow Each shape is a DOM node. Browsers maintain layout, style, and accessibility trees for each. At ~5,000+ elements, the cost of DOM bookkeeping dominates rendering time.
Why Canvas stays fast One DOM node, one buffer. Drawing calls write pixels directly. No tree reconciliation. The browser only needs to composite the final buffer.

6 When to Choose SVG

  • Icons & logos — must scale, must theme, must be crisp on retina.
  • Diagrams & flowcharts — users may click individual nodes; labels need to be selectable.
  • Charts under ~1,000 points — built-in hover, tooltips via DOM events.
  • Illustrations & line art — maps, floor plans, technical schematics.
  • Anything for print / PDF — vector stays crisp at print DPI.
  • Animated icons & illustrations — CSS animations are easy and GPU-composited.
  • Accessible data viz — screen readers can read text labels and ARIA on shapes.

7 When to Choose Canvas

  • Games & real-time simulations — 60 FPS requirement, hundreds of sprites per frame.
  • Particle systems — smoke, fire, confetti, fluid sims with thousands of particles.
  • Massive data viz — heatmaps with 100k+ cells, genome browsers, scatter plots with 50k points.
  • Image manipulation — photo editors, filters, OCR preprocessing, computer vision.
  • Whiteboards & drawing apps — Excalidraw, tldraw, infinite-canvas editors.
  • Video processing — draw video frames, apply effects, capture to stream.
  • Generative art & creative coding — fractals, noise fields, procedural patterns.

8 Hybrid Approaches

The best solutions often combine both technologies:

SVG for UI, Canvas for the heavy work

A map application might render the base map as SVG (clickable regions, themed colors) but overlay a heatmap on a Canvas (10k+ gradient points). User clicks go to SVG; the canvas just renders pixels.

HTML overlay for controls

Even pure-canvas apps (games, editors) overlay HTML for menus, text inputs, and tooltips. Canvas draws the visuals; HTML handles accessibility, focus management, and text rendering.

Canvas → SVG export

Some apps use canvas for fast interactive editing and convert to SVG for export. The canvas has the speed; the SVG is the durable, scalable output.

SVG → Canvas rasterization

For complex SVGs that need to be redrawn thousands of times (e.g. game sprites), rasterize the SVG to a canvas once, then draw the canvas buffer repeatedly.

// Convert SVG to canvas once
const img = new Image();
img.src = 'data:image/svg+xml;base64,' + btoa(svgString);
img.onload = () => {
  ctx.drawImage(img, 0, 0);  // fast pixel blit
};

9 Decision Tree

How many objects on screen at once?
├─ < 1,000 → Is it interactive (hover, click, tooltips per shape)?
│    ├─ Yes → SVG (DOM events, CSS hover, accessible)
│    └─ No → SVG (simpler authoring, scalable)
├─ 1,000 – 10,000 → Need per-shape interactivity?
│    ├─ Yes → SVG with care (virtualize off-screen nodes)
│    └─ No → Canvas (faster rendering)
└─ > 10,000 → Canvas (SVG will jank)

Need per-pixel manipulation (filters, image processing)?
└─ Yes → Canvas (only option)

Need print / PDF export at high DPI?
└─ Yes → SVG (vector stays crisp)

Need full accessibility (screen readers, keyboard)?
└─ Yes → SVG (canvas a11y is hard)

11 Try It Yourself

Exercise 1 — Build the same thing twice Draw a 100×100 grid of colored squares in both SVG and Canvas. Use the same color per cell. Compare file size, render time (use performance.now()), and code complexity.
Exercise 2 — Push SVG to the limit Generate 1,000, then 5,000, then 20,000 SVG <circle> elements. Use DevTools Performance tab to measure frame rate. Note where it starts to jank.
Exercise 3 — Canvas particle storm Animate 5,000 colored particles bouncing in a canvas at 60 FPS. Verify it runs smoothly. Try the same particle count in SVG — observe the difference.
Exercise 4 — Hybrid pattern Build a simple bar chart on SVG with hover tooltips. Add a Canvas heatmap overlay on top showing density. Wire mouse events: SVG handles bar hover, canvas handles heatmap hover.

12 Summary

  • SVG = vector DOM tree, scalable, CSS-stylable, accessible, great for icons/charts/diagrams.
  • Canvas = pixel buffer, JS-driven, fast for thousands of objects, great for games/particles/image processing.
  • SVG wins on accessibility, theming, print, scaling, and small scenes.
  • Canvas wins on raw performance, pixel manipulation, and real-time rendering.
  • Hybrid patterns common: SVG for UI/labels, Canvas for heavy rendering, HTML overlay for controls.
  • Choose based on object count, interactivity needs, accessibility requirements, and print/SEO needs.
  • Always measure with DevTools — never assume; performance characteristics evolve with browser versions.
