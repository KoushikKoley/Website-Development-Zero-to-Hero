The <canvas> Element

A pixel-based drawing surface driven by JavaScript. The right tool for games, charts, image manipulation, and any scene with thousands of moving objects. Comes with real accessibility costs — read on.

1 Anatomy

<canvas id="scene" width="640" height="480">
  <p>Your browser doesn't support the canvas element.
     Here's a <a href="fallback-image.png">static image</a>
     showing the same content.</p>
</canvas>

The <canvas> element is just a rectangular surface. Everything drawn on it is done through JavaScript. Without JS, it renders nothing — only the fallback content shows.

2 Width & Height: Attributes vs CSS

This is the single most common canvas bug. There are two sizes for a canvas:

  • Drawing buffer size — set by the width and height attributes. Determines how many pixels of drawing surface exist.
  • Display size — set by CSS width/height. Determines how big the canvas appears on the page.
<!-- 800×600 drawing buffer, displayed at 400×300 -->
<canvas id="c" width="800" height="600"></canvas>
<style> #c { width: 400px; height: 300px; } </style>

If you set only CSS width/height and skip the attributes, the canvas defaults to a 300×150 drawing buffer that gets stretched to your CSS size. Result: blurry, pixelated mess.

Common mistake Setting CSS dimensions but forgetting the width/height attributes. The canvas renders at default 300×150 internal resolution and looks pixelated when scaled up.

High-DPR (retina) canvas

For crisp rendering on high-DPR screens, scale the buffer to match device pixels:

const canvas = document.querySelector('canvas');
const ctx = canvas.getContext('2d');
const dpr = window.devicePixelRatio || 1;
const cssWidth = 640;
const cssHeight = 480;

canvas.width  = cssWidth  * dpr;
canvas.height = cssHeight * dpr;
canvas.style.width  = cssWidth  + 'px';
canvas.style.height = cssHeight + 'px';
ctx.scale(dpr, dpr);   // all drawing now uses CSS px coords
Pro tip Always reset and rescale on window resize. Recompute DPR each time — some browsers let users change zoom level dynamically.

3 Fallback Content

Content inside <canvas>...</canvas> is shown only when the browser doesn't support canvas (rare today) or when JavaScript is disabled (more common — ~0.2% of users, plus users of certain privacy extensions).

<canvas id="chart" width="640" height="480">
  <!-- Shown only if canvas or JS is unavailable -->
  <img src="chart.png" alt="Q3 revenue rose 42% to $1.7M"
       width="640" height="480">
</canvas>
Pro tip For important content, generate a static fallback image at build time (server-side rendering of the chart) so users without JS still see something. For purely decorative canvas, fallback can be empty.

4 Getting the 2D Context

The drawing API lives on a "context" object. For 2D drawing, request the "2d" context. For 3D, request "webgl" or "webgl2" (covered elsewhere).

const canvas = document.getElementById('scene');
const ctx = canvas.getContext('2d');

// Always check — old browsers or unsupported contexts return null
if (!ctx) {
  console.error('Canvas 2D not supported');
}
Once you have the context… All drawing is done by calling methods on ctx. The canvas retains what you draw until you clear it. There's no "scene graph" — once pixels are placed, they're just pixels.

5 Basic Drawing

const canvas = document.getElementById('demo');
const ctx = canvas.getContext('2d');

// Clear the canvas
ctx.clearRect(0, 0, canvas.width, canvas.height);

// Rectangle
ctx.fillStyle = '#2563eb';
ctx.fillRect(20, 20, 100, 60);

// Stroked rectangle
ctx.strokeStyle = '#7c3aed';
ctx.lineWidth = 3;
ctx.strokeRect(150, 20, 100, 60);

// Path (triangle)
ctx.beginPath();
ctx.moveTo(280, 80);
ctx.lineTo(330, 20);
ctx.lineTo(380, 80);
ctx.closePath();
ctx.fillStyle = '#16a34a';
ctx.fill();

// Circle
ctx.beginPath();
ctx.arc(450, 50, 30, 0, Math.PI * 2);
ctx.fillStyle = '#f59e0b';
ctx.fill();

// Text
ctx.fillStyle = '#0f172a';
ctx.font = 'bold 20px sans-serif';
ctx.fillText('Hello Canvas', 20, 130);

// Line
ctx.beginPath();
ctx.moveTo(20, 160);
ctx.lineTo(500, 160);
ctx.strokeStyle = '#dc2626';
ctx.lineWidth = 2;
ctx.stroke();

6 Use Cases

Games

Real-time rendering of sprites, particles, physics. 60 FPS with thousands of objects. Libraries: Phaser, PixiJS, Kaboom.

Charts

Heavy data viz where SVG would choke. Libraries: Chart.js, ECharts, Recharts (SVG), D3 (either).

Image editing

Filters, transforms, pixel manipulation, OCR preprocessing. Use getImageData / putImageData.

Generative art

Procedural patterns, fractals, particles. Easier than SVG for thousands of elements.

Video effects

Draw <video> frame to canvas, apply shader-like effects, export to stream.

Whiteboards & drawing

Excalidraw, tldraw — infinite canvas with stylus input, smooth curves, pan/zoom.

7 Accessibility — The Hard Part

Canvas is a pixel surface. Screen readers can't see what's drawn — they only see the <canvas> element itself. This is canvas's biggest weakness.

Strategies

StrategyHowUse when
Provide an image fallbackInside <canvas>: <img src="alt.png" alt="description">Static content like a chart
Use role="img" + aria-labelOn the <canvas> itselfSingle, describable image
Maintain a parallel DOMHidden HTML with the same content; aria-describedby links themInteractive UIs (canvas-based editors)
Hit regions APIctx.addHitRegion({ id, control }) creates clickable regionsCharts where regions are buttons (limited browser support)
Don't use canvas for textRender text as HTML overlayLabels, headings, links — never draw them on canvas
 
<!-- Chart with accessible fallback -->
<canvas id="chart" role="img"
         aria-label="Bar chart of Q3 revenue rising from $1.2M to $1.7M"
         width="640" height="480">
  <img src="chart.png"
       alt="Bar chart of Q3 revenue rising from $1.2M to $1.7M"
       width="640" height="480">
</canvas>
Common mistake Drawing text and labels on canvas for an interactive dashboard. Keyboard users can't focus them, screen readers can't read them, and clicking coordinates require manual hit-testing. Render text and controls as HTML over the canvas.
Pro tip — the parallel DOM For interactive canvas apps (diagram editors, whiteboards), keep a hidden HTML representation of every visible element. Use aria-hidden="true" on the canvas (so screen readers ignore the pixels) and expose the hidden DOM. Both visual and assistive-tech users get the same information.

8 When Canvas Beats SVG

NeedChooseWhy
>1000 elements on screenCanvasSVG DOM chokes on that many nodes
Real-time animation (60 FPS game)CanvasDirect pixel writes faster than DOM updates
Per-pixel manipulationCanvasSVG has no concept of "pixels"
Photo filtering / shadersCanvas (or WebGL)Direct buffer access
Crisp scalable iconsSVGCanvas bitmaps blur on zoom
Charts with <100 points & interactive tooltipsSVGEasier hover, accessible labels
Diagrams users will editSVGPer-element DOM events, drag handles
Print / PDF exportSVGVector stays crisp at print DPI

9 Common Mistakes

MistakeWhy it's badFix
CSS-only dimensions, no attributesDefault 300×150 buffer, blurrySet both attributes and CSS
Forgetting DPR scalingBlurry on retina screensMultiply buffer by DPR, scale context
Drawing text on canvas for UIInaccessible, not selectableUse HTML overlay
No fallback contentNo-JS users see nothingAdd <img> or text inside canvas
Not clearing each framePrevious frame bleeds throughCall ctx.clearRect at frame start
Drawing outside requestAnimationFrameTearing, wasted cyclesUse rAF loop for animations
Allocating in tight loopGC pressure, jankPre-allocate arrays/objects once
Using canvas where SVG would doWorse accessibility, worse interactivityUse SVG for icons, small charts, diagrams

11 Summary

  • <canvas> = pixel surface driven entirely by JavaScript.
  • Set both attribute (buffer) and CSS (display) sizes; use DPR scaling for retina.
  • Inner content = fallback for no-JS / no-canvas browsers.
  • Get context via getContext('2d'); check for null.
  • Draw with fillRect, strokeRect, beginPath/arc/moveTo/lineTo, fillText, stroke.
  • Use cases: games, charts, image manipulation, generative art, video effects.
  • Accessibility is hard — provide role="img", aria-label, fallback images, or a parallel DOM.
  • Choose canvas over SVG when you need >1000 elements, real-time animation, or pixel manipulation.
