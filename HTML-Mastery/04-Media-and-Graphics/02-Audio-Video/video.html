The <video> Element

The web's native video player. Poster images, multiple codecs, captions via WebVTT, picture-in-picture, autoplay policies, and iOS Safari quirks — everything you need to ship reliable video.

1 Anatomy

<video
  width="1280"
  height="720"
  controls
  preload="metadata"
  poster="cover.jpg"
  playsinline
>
  <source src="movie.webm" type="video/webm">
  <source src="movie.mp4"  type="video/mp4">
  <track kind="captions" src="movie.en.vtt"
         srclang="en" label="English" default>
  <p>Your browser doesn't support HTML5 video.
     <a href="movie.mp4">Download the MP4</a>.</p>
</video>
[ movie.mp4 · 1280×720 ]

Just like <audio>, the inner content is fallback for ancient browsers. Modern browsers render the native player.

2 src & Multiple <source> Elements

Use nested <source> elements so the browser can choose a format. Order matters — list the most desirable format first.

<video controls width="1280" height="720">
  <source src="movie.av1.mp4" type='video/mp4; codecs="av01.0.05M.08"'>
  <source src="movie.webm"     type="video/webm">
  <source src="movie.h264.mp4" type="video/mp4">
</video>
Pro tip Including the codecs parameter in the type attribute lets the browser distinguish between H.264, H.265, and AV1 — all of which use the video/mp4 container. Without codecs, the browser may have to download a few KB to test.

3 The controls Attribute

Boolean — when present, the browser shows the native player UI: play/pause, seek bar, volume, fullscreen, captions menu, picture-in-picture, and (in some browsers) playback rate and download.

<!-- With native UI -->
<video src="movie.mp4" controls></video>

<!-- Without UI (custom JS-driven player) -->
<video id="v" src="movie.mp4"></video>

The native controls are keyboard accessible (space toggles, arrows seek), so prefer them over custom UI unless you have specific needs.

4 The poster Attribute

poster is the URL of an image shown in the player area before the video starts playing. Without it, the first frame is shown — which is often a black frame or a blurry thumbnail.

<video
  src="movie.mp4"
  poster="movie-cover.jpg"
  controls
  preload="metadata"
>
</video>
Pro tip Use a poster that's the same dimensions as the video. Use preload="metadata" so the browser fetches the first frame as a fallback if the poster fails. Generate the poster at design time — don't pick a frame from the middle of the video.
Common mistake A poster image that's a different aspect ratio than the video. The result is letterboxing or distortion. Match dimensions exactly.

5 Width, Height & Aspect Ratio

Just like images, set width and height attributes (in CSS pixels) so the browser reserves space and avoids layout shift while the video loads.

<video width="1280" height="720" controls>
  <source src="movie.mp4" type="video/mp4">
</video>

<style>
  video {
    max-width: 100%;
    height: auto;   /* preserves 16:9 from attributes */
  }
</style>

Common aspect ratios: 16:9 (YouTube, Vimeo), 9:16 (vertical/phone video, Stories), 1:1 (Instagram square), 21:9 (cinematic).

6 autoplay, muted, loop

Same autoplay policies as <audio>: browsers block autoplay with sound unless the user has interacted with the page. The combo autoplay muted works everywhere.

<!-- Background hero video (muted autoplay + loop) -->
<video autoplay muted loop playsinline
       poster="hero.jpg"
       width="1920" height="1080">
  <source src="hero.webm" type="video/webm">
  <source src="hero.mp4"  type="video/mp4">
</video>
Common mistake Setting only autoplay without muted on a hero video. Chrome, Firefox, and Safari all block it. The video will be paused and you'll see an uncaught Promise rejection in the console.
Pro tip Always include playsinline on autoplay videos — without it, iOS Safari may force the video into fullscreen mode, breaking your hero layout.

7 playsinline — The iOS Quirk

Historically, iOS Safari played all videos in the native fullscreen player. The playsinline attribute (a boolean) tells iOS to play the video inline within the page instead.

<video src="tutorial.mp4" controls playsinline></video>

Without playsinline:

  • Autoplay-mute loops break on iOS — the video gets yanked into fullscreen.
  • Video-based animations or background videos don't work as designed.
  • Custom UI overlays (play buttons, captions) become invisible behind the native player.
Pro tip Add playsinline to every video that should play within the page. There's no downside — desktop browsers ignore it.

8 The preload Attribute

Same values as <audio>: none, metadata, auto. Same hint semantics.

ValueBehaviorUse case
noneDon't buffer; user must press playListing pages with many videos
metadata (default)Fetch first frames & durationMost pages
autoDownload the whole fileRare; only when user is very likely to play
Common mistake preload="auto" on a video index page. The browser downloads all videos, destroying your mobile users' data plans. Use none or metadata.

9 The <track> Element & WebVTT

<track> adds timed text tracks to a video: captions, subtitles, descriptions, chapters. The track file format is WebVTT (.vtt) — a simple text format with timestamps.

<video controls poster="movie.jpg" width="1280" height="720">
  <source src="movie.mp4" type="video/mp4">
  <track kind="captions" src="movie.en.vtt"
         srclang="en" label="English" default>
  <track kind="subtitles" src="movie.es.vtt"
         srclang="es" label="Español">
  <track kind="captions" src="movie.fr.vtt"
         srclang="fr" label="Français">
</video>

WebVTT format example

WEBVTT

00:00:00.000 --> 00:00:03.500
Welcome to the HTML Mastery course.

00:00:03.500 --> 00:00:07.200
In this video we'll cover the <video> element.

00:00:07.200 --> 00:00:10.000
<c.highlight>Let's get started.</c>

The kind attribute

kindMeaningShown by default?
subtitlesTranslation of spoken audioOnly if user turns on
captionsTranscription incl. sound effects (for deaf users)Only if user turns on
descriptionsSpoken description of video for blind usersUsed by screen readers, not displayed
chaptersChapter titles for navigationShown in chapter menu
metadataMachine-readable, not shownUsed by scripts
Common mistake Hosting the .vtt file on a different domain without CORS headers. Browsers refuse to load it for security. Either serve from the same origin or send Access-Control-Allow-Origin.
Pro tip Mark one track default to enable it on first play. But also let users toggle it off — the native captions button does this automatically when controls is present.

10 Picture-in-Picture API

The Picture-in-Picture (PiP) API lets you programmatically pop a video out into a floating window that stays visible while the user browses other tabs or windows.

// Trigger PiP on a button click (must be user-gesture)
document.querySelector('#pip-btn').addEventListener('click', async () => {
  const video = document.querySelector('video');
  try {
    if (document.pictureInPictureElement) {
      await document.exitPictureInPicture();
    } else {
      await video.requestPictureInPicture();
    }
  } catch (err) {
    console.error('PiP failed:', err);
  }
});

// Listen for enter/exit
video.addEventListener('enterpictureinpicture', () => {
  console.log('Entered PiP');
});
video.addEventListener('leavepictureinpicture', () => {
  console.log('Exited PiP');
});

// Feature detection
if ('pictureInPictureEnabled' in document) {
  // safe to show PiP button
}
Hint attribute The boolean disablepictureinpicture on <video> opts out of PiP entirely — useful for proprietary or sensitive content.

11 JavaScript Control

The HTMLVideoElement interface extends HTMLMediaElement (same as audio) with video-specific properties.

const v = document.querySelector('video');

// Same API as audio
v.play();
v.pause();
v.currentTime = 60;     // seek to 60s
v.playbackRate = 2;      // 2× speed

// Video-specific
console.log(v.videoWidth, v.videoHeight);  // intrinsic px
console.log(v.poster);                       // poster URL
v.preservesPitch = true;  // keep audio pitch at non-1x rates

// Fullscreen API (often paired with video)
v.requestFullscreen();

12 Common Mistakes

MistakeWhy it's badFix
Only one source (no format fallback)Safari may not play WebM; Chrome may not play H.265Offer MP4 (H.264) + WebM (VP9)
Missing playsinlineiOS forces fullscreen; breaks hero layoutsAlways add playsinline
autoplay without mutedBlocked by every browserAdd muted or wait for user gesture
Missing posterBlack frame before play; ugly LCPProvide a designed poster image
No <track> for captionsExcludes deaf users; legally required in some regionsAlways include at least English captions

13 Try It Yourself

Exercise 1 — Multi-format video Download a short video. Convert it to MP4 (H.264) and WebM (VP9) using FFmpeg: ffmpeg -i input.mov -c:v libx264 -c:a aac movie.mp4 and ffmpeg -i input.mov -c:v libvpx-vp9 -c:a libopus movie.webm. Build a <video> with both sources.
Exercise 2 — Poster frame Extract a frame from your video: ffmpeg -i movie.mp4 -ss 00:00:02 -frames:v 1 poster.jpg. Use it as the poster attribute. Verify the player shows the image before play.
Exercise 3 — WebVTT captions Write a .vtt file with 5 caption cues matching a 30-second video. Add it as a <track kind="captions" default>. Verify the captions display and can be toggled via the controls.
Exercise 4 — Picture-in-Picture button Add a "Pop out" button below your video. Wire it to video.requestPictureInPicture() with feature detection. Test that clicking it pops the video into a floating window that stays visible when you switch tabs.

14 Summary

  • <video> embeds video with native player via controls.
  • Offer MP4 (H.264) + WebM (VP9) via <source> with type (and ideally codecs).
  • poster shows a designed image before play; width/height prevent layout shift.
  • playsinline is essential for iOS — without it videos force fullscreen.
  • autoplay muted loop playsinline is the safe combo for hero videos.
  • <track> with WebVTT provides captions, subtitles, descriptions, chapters.
  • Picture-in-Picture API lets users pop video into a floating window.
  • Always set preload="metadata"; use none on listing pages.
