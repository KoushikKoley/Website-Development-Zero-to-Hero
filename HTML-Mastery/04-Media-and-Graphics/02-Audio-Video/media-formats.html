Media Formats — Containers, Codecs & Browser Support

Every media file is two things: a container (the box) and a codec (how the bits inside are compressed). Knowing the difference is the key to choosing the right format.

1 Container vs Codec

Container

The box that holds the media. Defines the file extension and how audio, video, subtitles, and metadata are interleaved. Examples: .mp4, .webm, .ogg, .mkv, .wav, .flac.

Codec

The algorithm that encodes/decodes the audio or video stream inside the container. Examples: H.264, H.265, VP9, AV1 (video); MP3, AAC, Opus, FLAC (audio). A container can hold different codecs.

movie.mp4   ← container: MP4 │ codec: H.264 video + AAC audio
movie.webm  ← container: WebM │ codec: VP9 video + Opus audio
movie.mkv   ← container: MKV │ codec: AV1 video + AAC audio
Why it matters A browser that supports the .mp4 container doesn't necessarily support every codec that can live inside an MP4. video/mp4 alone is ambiguous — adding codecs="avc1.42E01E" tells the browser exactly which H.264 profile you used.

2 Video Formats

H.264 (AVC) — in MP4 container

The universal baseline. Every modern browser, device, and smart TV decodes H.264. Lossy, decent compression, hardware-accelerated everywhere.

  • Pros: Universal support; hardware decoding; mature tooling.
  • Cons: Larger files than VP9/AV1; patent royalties (handled by browser makers, not authors).
  • Use for: Universal fallback when you can only serve one file.

VP9 — in WebM container

Google's open-source codec, ~30% smaller than H.264 at the same quality. Hardware decoding on most Android and ChromeOS devices.

  • Pros: Royalty-free; smaller files than H.264; YouTube default for HD.
  • Cons: No Safari support historically (Safari 14+ added it for WebM only in macOS Sonoma / iOS 17).
  • Use for: Primary format alongside H.264 fallback.

AV1 — in MP4 or WebM

The next-generation royalty-free codec from the Alliance for Open Media. ~30% smaller than VP9, ~50% smaller than H.264.

  • Pros: Best compression; royalty-free; future-proof.
  • Cons: Slow to encode; older devices lack hardware decoding; encoding requires modern FFmpeg.
  • Use for: When you can afford encoding time and need maximum compression (4K HDR, streaming).

H.265 (HEVC)

Better compression than H.264 but encumbered by patent pools. Native to Apple ecosystem; not supported in Chrome or Firefox without OS-level help.

  • Pros: Apple-native; ~50% smaller than H.264.
  • Cons: Patent mess; not a web standard; only Safari/Edge support reliably.
  • Use for: Apple-only delivery; otherwise avoid.
Pro tip — the modern triple 
<video controls width="1280" height="720">
  <source src="movie.av1.mp4"  type='video/mp4; codecs="av01.0.05M.08"'>
  <source src="movie.webm"     type="video/webm">
  <source src="movie.h264.mp4" type="video/mp4">
</video>

JPEG

The classic photo format. Lossy, 24-bit color, no transparency, no animation. Still universally supported.

Use for: Photos when you can't generate modern formats. Quality 80-85 is a good default.

PNG

Lossless raster with 8-bit alpha transparency. Great for screenshots, UI mockups, logos with sharp edges. Files are large for photos.

Use for: Anything with text or sharp lines that JPEG would smear.

GIF

Ancient 256-color format with 1-bit transparency and animation support. Universally supported but huge files for animations.

Use for: Avoid. Convert animated GIFs to WebP or MP4 — typically 10-100× smaller.

WebP

Google's modern format. Supports lossy (like JPEG), lossless (like PNG), transparency, and animation. 25-35% smaller than JPEG/PNG at the same quality.

Use for: Primary format alongside JPEG fallback. ~98% browser support.

AVIF

Based on the AV1 video codec. Best-in-class compression — 40-50% smaller than JPEG. Supports HDR, wide gamut, and 12-bit color.

Use for: Photos where bandwidth matters most. ~95% browser support (Safari 16.4+).

SVG

Vector format — XML describing shapes, paths, text. Scales infinitely without quality loss. Styleable with CSS, scriptable with JS.

Use for: Icons, logos, charts, illustrations, anything that needs to scale.

Pro tip — the modern image pipeline For each image: produce AVIF + WebP + JPEG (or PNG for transparency), then use <picture> with format negotiation. See the Responsive Images page for the full pattern.

6 Encoding Basics (with FFmpeg)

FFmpeg is the de facto command-line tool for media encoding. Examples below cover the most common cases.

Video: encode to MP4 + WebM

# MP4 (H.264 + AAC) — universal baseline, 720p
ffmpeg -i input.mov \
  -c:v libx264 -preset slow -crf 22 \
  -c:a aac -b:a 128k \
  -movflags +faststart \
  output.mp4

# WebM (VP9 + Opus)
ffmpeg -i input.mov \
  -c:v libvpx-vp9 -crf 32 -b:v 0 \
  -c:a libopus -b:a 96k \
  output.webm

Audio: encode to MP3 + Opus

# MP3 — universal
ffmpeg -i input.wav -c:a libmp3lame -q:a 2 output.mp3

# Opus — modern, smallest
ffmpeg -i input.wav -c:a libopus -b:a 64k output.opus

Images: convert to WebP + AVIF

# WebP
cwebp -q 80 input.jpg -o output.webp

# AVIF (requires libavif)
avifenc --min 20 --max 40 input.jpg output.avif
Pro tip — -movflags +faststart This is essential for MP4. It moves the metadata (moov atom) to the front of the file so the browser can start playing before the download is complete. Without it, the entire file must download before playback begins.

7 When to Choose Each

Photos & art

AVIF → WebP → JPEG. Use <picture> with all three. Set dimensions to prevent layout shift.

Icons & logos

Inline SVG. Scales infinitely, CSS-stylable, tiny file size, scriptable for animations.

Screenshots

PNG (lossless, sharp text). For web delivery, convert to AVIF/PNG via <picture>.

Animated graphics

WebP animation or short MP4 instead of GIF. 10-100× smaller for the same content.

Podcast audio

Opus (64 kbps) + MP3 (128 kbps) via <source>. Opus for modern browsers, MP3 for legacy.

Streaming video

AV1 → VP9 → H.264. For 4K HDR, AV1 is essential. For 720p baseline, H.264 alone is fine.

Music streaming

Opus + AAC. AAC for Apple devices, Opus for everything else. Avoid MP3 unless you need Windows XP-era support.

Sound effects

WAV for short SFX (< 5 seconds). Opus for longer. Prefer small files — sounds preload eagerly.

9 Try It Yourself

Exercise 1 — Format comparison Take one source video. Encode it as H.264 MP4, VP9 WebM, and AV1 MP4 at the same target bitrate. Compare file sizes and visual quality at the same timecodes.
Exercise 2 — Multi-format image Take one JPEG photo. Convert it to AVIF and WebP at the same quality target. Build a <picture> with all three. Compare file sizes in DevTools → Network.
Exercise 3 — Convert a GIF Find an animated GIF (1-5 MB). Convert to WebP (gif2webp input.gif -o output.webp) and to MP4 (ffmpeg -i input.gif -movflags +faststart output.mp4). Compare sizes — you'll see 5-50× reduction.
Exercise 4 — Opus vs MP3 Encode a 3-minute WAV as Opus at 64 kbps and MP3 at 128 kbps. Compare file sizes and listen for quality differences. Opus should be ~half the size with similar perceived quality.

10 Summary

  • Every media file = container + codec. Container is the box; codec is how bits are compressed.
  • Video: H.264 universal baseline; VP9/AV1 for modern compression; H.265 only for Apple.
  • Audio: MP3 universal; Opus best-in-class; AAC for iOS; FLAC/WAV for archival.
  • Images: AVIF < WebP < JPEG in size; PNG for sharp graphics; SVG for vector; avoid GIF.
  • Always provide multiple formats via <source> with type (and codecs for video).
  • Use FFmpeg for encoding; always add -movflags +faststart to MP4.
  • Browser support matrices change — always check caniuse.com for the latest data.
