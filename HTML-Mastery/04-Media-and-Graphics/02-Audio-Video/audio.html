The <audio> Element

Embedding sound in a web page used to require Flash. Today it's a single HTML element with native controls, multiple format fallbacks, and full JavaScript access. This page covers every important attribute.

1 Anatomy

<audio src="episode-12.mp3" controls preload="metadata">
  <p>Your browser doesn't support HTML5 audio.
     <a href="episode-12.mp3">Download the MP3</a> instead.</p>
</audio>

The content inside <audio>...</audio> is fallback content — shown only in ancient browsers that don't support the element. Modern browsers render the player UI and ignore it.

(Demo player — no actual audio file is loaded.)

2 src & Multiple <source> Elements

You can put the URL directly on the <audio> element via src, or nest <source> children. The latter is preferred because it lets you offer multiple formats — the browser picks the first it can decode.

<audio controls preload="metadata">
  <source src="episode-12.opus" type="audio/ogg; codecs=opus">
  <source src="episode-12.aac"  type="audio/aac">
  <source src="episode-12.mp3"  type="audio/mpeg">
  <p>Your browser can't play HTML5 audio.
     <a href="episode-12.mp3">Download the file</a>.</p>
</audio>
Pro tip Always include the type attribute on <source>. Without it the browser has to download a chunk of each file to "sniff" the format — wasting bandwidth and time. With type, the browser picks instantly.

3 The controls Attribute

controls is a boolean attribute — its presence turns the native player UI on. Without it, the audio is invisible and silent until you drive it via JavaScript.

<!-- Visible player -->
<audio src="song.mp3" controls></audio>

<!-- Hidden, driven by JS (custom UI) -->
<audio src="song.mp3" id="player"></audio>
<button onclick="document.getElementById('player').play()">Play</button>

The native controls vary between browsers in appearance but always provide: play/pause, seek bar, volume, and (in some) download and playback rate. They're keyboard accessible out of the box.

4 autoplay & Browser Autoplay Policies

The autoplay boolean makes the audio start as soon as it can. Browsers block autoplay with sound unless the user has interacted with the site — clicking, tapping, or typing somewhere on the page. Background autoplay of unmuted audio is essentially dead.

CombinationWhat happens
autoplayBlocked by most browsers (Chrome, Firefox, Safari). The user sees a paused player.
autoplay mutedAllowed in most browsers — silent autoplay works.
autoplay after a clickAllowed — the user gesture "unlocks" audio for that origin.
Common mistake Setting autoplay on a landing-page hero audio. It will be blocked silently, and even when it works it annoys users. Never autoplay with sound.
Pro tip If you must autoplay (e.g. a game), start with muted and show a visible "Unmute" button. The user can opt in to sound.

5 loop & muted

  • loop — boolean. When the audio ends, it restarts from the beginning. Useful for ambient background tracks and ringtones.
  • muted — boolean. Sets the audio output to silent initially. The user can still unmute via the controls.
<!-- Muted ambient loop (good for landing pages) -->
<audio src="ambient.mp3" autoplay muted loop></audio>

6 The preload Attribute

preload hints to the browser whether to buffer the audio file when the page loads. It's a hint, not a command — the browser may ignore it based on user settings, network conditions, and autoplay policy.

ValueWhat the browser may doUse case
noneDon't buffer anything until the user hits playPages with many players; save bandwidth
metadataFetch only enough to know duration & dimensionsDefault behavior, good balance
autoDownload the entire file eagerlyRare; only when the user is very likely to play
Common mistake Using preload="auto" on a podcast index page listing 50 episodes. The browser may download all 50 simultaneously. Use preload="none" or metadata for lists.

7 Browser Format Support

Audio codecs are patent-encumbered mess. No single format works everywhere — but MP3 covers ~100% of browsers today.

FormatMIME typeChromeFirefoxSafariNotes
MP3audio/mpegYesYesYesUniversal baseline; lossy; patent-free since 2017
AAC (in MP4)audio/aac or audio/mp4YesYes*YesiOS native; better than MP3 at low bitrates
OGG/Vorbisaudio/oggYesYesNoOpen format; popular on Wikipedia
Opus (in OGG)audio/ogg; codecs=opusYesYesSafari 17+Best modern codec; low-bitrate king
FLACaudio/flacYesYesYesLossless; large files; audiophile use
WAVaudio/wavYesYesYesUncompressed; huge; short SFX only
Pro tip — the safe combo For maximum compatibility, offer Opus (modern, small) + AAC (Apple-friendly) + MP3 (universal). Order them in that priority inside <source> elements.

8 Accessibility & Transcripts

Audio is invisible to deaf and hard-of-hearing users. The native player provides keyboard accessibility (space toggles, arrow keys seek), but the content needs a transcript.

  • Always provide a transcript — a plain HTML page or a <details> element near the player.
  • Link to the transcript visibly, not as aria-describedby.
  • If the audio is music, a transcript isn't useful — but lyrics in a <section> below the player are.
  • For podcasts, a chapter list (table of contents) helps everyone navigate.
<audio controls preload="metadata">
  <source src="ep-12.opus" type="audio/ogg; codecs=opus">
  <source src="ep-12.mp3"  type="audio/mpeg">
</audio>

<details>
  <summary>Read transcript</summary>
  <article>
    <h3>Episode 12: The Web in 2030</h3>
    <p><strong>[00:00]</strong> Welcome back to the show...</p>
    <p><strong>[02:15]</strong> Today we're talking about...</p>
    <!-- ... -->
  </article>
</details>

9 JavaScript Control

The HTMLAudioElement interface exposes methods and events for full programmatic control.

const player = document.querySelector('audio');

// Methods
player.play();     // returns a Promise — may reject if not user-gesture
player.pause();
player.load();     // reload current src

// Properties
player.currentTime = 30;   // seek to 30s
player.volume = 0.5;       // 0..1
player.playbackRate = 1.5; // 1.5× speed
console.log(player.duration); // NaN until metadata loaded

// Events
player.addEventListener('play',     () => console.log('started'));
player.addEventListener('pause',    () => console.log('paused'));
player.addEventListener('ended',    () => console.log('finished'));
player.addEventListener('timeupdate', () => {
  console.log(`${player.currentTime.toFixed(1)}/${player.duration}`);
});
Common mistake Calling play() on page load without a user gesture. The returned Promise rejects and you get an uncaught error in the console. Always wrap autoplay attempts in .catch(() => {}).

11 Try It Yourself

Exercise 1 — Multi-format player Find a short audio clip. Convert it to MP3 and OGG (use Audacity or an online converter). Build an <audio> element with two <source> tags and proper type attributes. Verify it plays in Chrome, Firefox, and Safari.
Exercise 2 — Custom play button Build an <audio> without controls. Add a button with the text "Play" / "Pause" that toggles playback via JavaScript. Update the button text in a play / pause event listener.
Exercise 3 — Chapter list Build a podcast player with a chapter list (an ordered list of timestamps). Clicking a chapter seeks the audio to that time using currentTime. Highlight the current chapter on timeupdate.
Exercise 4 — Transcript accordion Add a <details> element under your player with a full transcript. Use <time> elements at each timestamp and a JavaScript handler that seeks the audio when clicked.

12 Summary

  • <audio> embeds sound; native controls provide accessible UI.
  • Use multiple <source> elements with type attributes for format fallback.
  • MP3 works everywhere; Opus is best for modern browsers; AAC is preferred on iOS.
  • autoplay with sound is blocked — use autoplay muted or wait for user gesture.
  • preload="metadata" is the safe default; use none on listing pages.
  • Always provide a transcript for accessibility and SEO.
  • The HTMLAudioElement JS API gives full programmatic control.
