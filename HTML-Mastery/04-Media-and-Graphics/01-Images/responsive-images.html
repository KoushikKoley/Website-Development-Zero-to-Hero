Responsive Images — srcset, sizes & <picture>

Serving a single 4K JPEG to a 320-pixel phone wastes bandwidth and slows your page. Responsive images let the browser pick the right file based on viewport, DPR, and supported format — all in pure HTML.

1 The Problem

Devices vary wildly. A flagship phone has a 3x DPR display at 430 CSS pixels wide; a 4K monitor renders at 1920 CSS pixels with a 1x DPR. Sending the same image to both means:

  • Sending a 4000-pixel image to a phone — blurry thumbnails & wasted bandwidth.
  • Sending a 400-pixel image to a 4K monitor — blocky, blurry on a high-end display.

Responsive images solve this in HTML, without JavaScript, letting the browser choose.

2 Device Pixel Ratio (DPR)

On high-density displays, one CSS pixel is backed by multiple physical pixels. The DPR is the ratio of physical pixels to CSS pixels.

Device classDPRCSS pixels per inch
Old desktop monitor1x96
Standard laptop1x – 1.5x96 – 144
Retina MacBook2x192
iPhone 12/13/143x~288
iPhone Pro Max3x~288
Galaxy S-series3x – 4x~288-384
Key idea A 400 CSS-pixel-wide image needs to be 1200 physical pixels wide on a 3x DPR screen to look crisp. That's why we offer multiple resolutions.

3 srcset with x Descriptors

The x descriptor tells the browser the DPR each file targets. The browser picks the one matching the device.

<img
  src="logo-1x.png"
  alt="Company logo"
  srcset="
    logo-1x.png 1x,
    logo-2x.png 2x,
    logo-3x.png 3x
  "
>

The browser fetches logo-2x.png on a Retina display, logo-3x.png on an iPhone, and logo-1x.png on an old monitor. src is the fallback for browsers that don't understand srcset.

When to use x descriptors x descriptors are ideal for fixed-size images — icons, logos, avatars, thumbnails. When the rendered size is the same regardless of viewport, only DPR matters.
Common mistake Mixing x and w descriptors in the same srcset. The spec forbids it — pick one strategy per image.

4 srcset with w Descriptors

The w descriptor tells the browser the intrinsic width of each candidate file in pixels. Combined with the sizes attribute, the browser computes which file fits best at the current viewport and DPR.

<img
  src="photo-800.jpg"
  alt="A mountain lake at dawn"
  srcset="
    photo-400.jpg   400w,
    photo-800.jpg   800w,
    photo-1200.jpg 1200w,
    photo-1600.jpg 1600w,
    photo-2400.jpg 2400w
  "
  sizes="100vw"
>
How it works The browser multiplies the rendered CSS width (from sizes) by the DPR, then picks the smallest file that is at least that wide. On a 320 CSS-px, 3x DPR phone displaying full-width: it needs 960 physical px → picks photo-1200.jpg.

5 The sizes Attribute

sizes tells the browser how wide the image will be rendered at different viewport widths. It's a list of media-condition : length pairs, ending with a default length.

<img
  src="photo-800.jpg"
  alt="..."
  srcset="
    photo-400.jpg   400w,
    photo-800.jpg   800w,
    photo-1200.jpg 1200w,
    photo-1600.jpg 1600w
  "
  sizes="
    (max-width: 600px) 100vw,
    (max-width: 1200px) 50vw,
    33vw
  "
>

Reading the sizes above: "On viewports ≤ 600px, the image fills 100% of viewport width. On viewports ≤ 1200px, the image is 50% (e.g. a 2-column grid). Otherwise, it's 33% (3-column grid)."

Common mistake Omitting sizes when using w descriptors. The spec defaults to 100vw, which causes the browser to over-fetch on multi-column layouts. Always provide sizes when you use w descriptors.
Pro tip sizes is a hint to the browser before layout runs. It doesn't have to be exact, but it should be close. If you lie (claim the image is 50vw when it's actually 100vw), the browser will under- or over-fetch.

6 The <picture> Element

<picture> is a container that lets you specify multiple <source> elements with different conditions, plus a final <img> as fallback. The browser picks the first matching <source>.

<picture>
  <source srcset="hero-wide.webp" type="image/webp" media="(min-width: 800px)">
  <source srcset="hero-narrow.webp" type="image/webp" media="(max-width: 799px)">
  <source srcset="hero-wide.jpg" media="(min-width: 800px)">
  <source srcset="hero-narrow.jpg" media="(max-width: 799px)">
  <img src="hero-wide.jpg" alt="Mountain lake at dawn" width="1600" height="900" loading="lazy">
</picture>

The <img> is mandatory — it provides the src, alt, dimensions, and is what gets rendered. <source> elements only override the URL.

srcset vs picture Use srcset when you have one image at multiple resolutions. Use <picture> when you need different images (art direction) or different formats (WebP/AVIF fallback).

7 Art Direction

"Art direction" means showing a different crop or composition at different viewport sizes. A wide hero shot of a mountain works on desktop, but the subject shrinks to nothing on a phone — so you crop tighter for small screens.

<picture>
  <!-- Desktop: full scenic shot -->
  <source
    media="(min-width: 1024px)"
    srcset="mountain-wide-1600.jpg 1600w, mountain-wide-2400.jpg 2400w"
    sizes="100vw"
  >
  <!-- Tablet: medium crop -->
  <source
    media="(min-width: 640px)"
    srcset="mountain-medium-800.jpg 800w, mountain-medium-1200.jpg 1200w"
    sizes="100vw"
  >
  <!-- Phone: tight portrait crop -->
  <source
    media="(max-width: 639px)"
    srcset="mountain-tight-400.jpg 400w, mountain-tight-800.jpg 800w"
    sizes="100vw"
  >
  <img src="mountain-wide-1600.jpg" alt="..." width="1600" height="900" loading="eager">
</picture>
Pro tip Art direction is expensive — it requires manually creating multiple crops. Reserve it for hero images and editorial photography where composition matters. For product images, gallery thumbnails, and user avatars, plain srcset + sizes is enough.

8 Format Negotiation (WebP, AVIF)

Modern formats like WebP and AVIF produce dramatically smaller files than JPEG/PNG at equivalent quality. Use <picture> with type attributes so supporting browsers get the modern format, and older ones fall back to JPEG.

<picture>
  <source srcset="hero.avif" type="image/avif">
  <source srcset="hero.webp" type="image/webp">
  <img src="hero.jpg" alt="..." width="1600" height="900" loading="lazy">
</picture>

Order matters: list the most desirable format first. The browser picks the first <source> whose type it can decode.

FormatCompressionBrowser supportTypical savings vs JPEG
JPEGLossy100% (everywhere)baseline
PNGLossless100%larger for photos
WebPLossy + lossless~98% (IE11 is the last holdout)25-35% smaller
AVIFLossy + lossless~95% (Chrome 85+, Safari 16.4+, Firefox 93+)40-50% smaller
Pro tip Combine format negotiation with srcset for both. Modern browsers get modern formats at the right resolution; old browsers still get a working JPEG. This is the gold standard pattern: 
<picture>
  <source
    type="image/avif"
    srcset="hero-400.avif 400w, hero-800.avif 800w, hero-1600.avif 1600w"
    sizes="(max-width: 600px) 100vw, 50vw"
  >
  <source
    type="image/webp"
    srcset="hero-400.webp 400w, hero-800.webp 800w, hero-1600.webp 1600w"
    sizes="(max-width: 600px) 100vw, 50vw"
  >
  <img
    src="hero-800.jpg"
    srcset="hero-400.jpg 400w, hero-800.jpg 800w, hero-1600.jpg 1600w"
    sizes="(max-width: 600px) 100vw, 50vw"
    alt="Mountain lake at dawn"
    width="1600" height="900"
    loading="lazy"
    decoding="async"
  >
</picture>

9 Lazy Loading Strategy

Combine responsive images with native lazy loading. The pattern below is what production sites ship:

  • LCP image (hero): loading="eager" fetchpriority="high", full <picture> with formats.
  • Above-the-fold secondary: loading="eager" without fetchpriority.
  • Below the fold: loading="lazy" with decoding="async" and width/height always set.
<!-- Hero/LCP -->
<picture>
  <source type="image/avif" srcset="hero-1600.avif" sizes="100vw">
  <source type="image/webp" srcset="hero-1600.webp" sizes="100vw">
  <img src="hero-1600.jpg" alt="..." width="1600" height="900"
       loading="eager" decoding="async" fetchpriority="high">
</picture>

<!-- Gallery image (lazy) -->
<picture>
  <source type="image/avif"
          srcset="photo-400.avif 400w, photo-800.avif 800w"
          sizes="(max-width: 600px) 50vw, 25vw">
  <source type="image/webp"
          srcset="photo-400.webp 400w, photo-800.webp 800w"
          sizes="(max-width: 600px) 50vw, 25vw">
  <img src="photo-800.jpg"
       srcset="photo-400.jpg 400w, photo-800.jpg 800w"
       sizes="(max-width: 600px) 50vw, 25vw"
       alt="..." width="800" height="600"
       loading="lazy" decoding="async">
</picture>
Common mistake Lazy-loading images that are inside the initial viewport (above the fold). The browser still waits for layout to confirm visibility, which can delay LCP by 100-300ms.

Using x and w in the same srcsetInvalid; browser ignores itPick one strategy per image

Putting type on the <img>Invalid; type only goes on <source>Move type to <source>

11 Try It Yourself

Exercise 1 — Avatar with x descriptors Generate three sizes of an avatar (1x, 2x, 3x). Use srcset with x descriptors. Open on a phone and a desktop, then use DevTools → Network → Img to confirm only the right file was fetched.
Exercise 2 — Article hero with w + sizes Build a hero image with w descriptors at 400/800/1200/1600/2400. Set sizes="(max-width: 800px) 100vw, 800px". Resize the browser and watch DevTools show different files being downloaded.
Exercise 3 — AVIF/WebP/JPEG fallback Find a JPEG. Convert it to WebP (cwebp photo.jpg -o photo.webp) and AVIF (use an online converter). Build a <picture> with all three sources. Open in Chrome, Firefox, and an old browser if available — confirm each picks the right format.
Exercise 4 — Art-directed hero Take a wide photo with a subject off-center. Create a desktop version (subject small) and a phone version (subject cropped tight). Use <picture> with media queries to swap crops. Resize your browser across the breakpoint.

12 Summary

  • Responsive images let the browser choose the right file in pure HTML.
  • srcset with x descriptors → fixed-size images (icons, avatars).
  • srcset with w descriptors + sizes → fluid images (heroes, gallery photos).
  • <picture> + <source> → art direction (different crops) and format negotiation (AVIF/WebP/JPEG).
  • Always set width/height, always include alt, always include final <img> in <picture>.
  • Lazy-load below the fold; eager + fetchpriority="high" for LCP.
  • List modern formats first (AVIF → WebP → JPEG/PNG).
