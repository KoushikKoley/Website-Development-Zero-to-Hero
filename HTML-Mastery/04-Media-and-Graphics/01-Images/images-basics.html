The <img> Element — src, alt & Beyond

Images are the heaviest assets on most web pages. Writing them correctly is the difference between a fast, accessible site and a slow, broken one. This page covers every important <img> attribute you should know.

1 Anatomy of an <img>

The <img> element is a void (self-closing) element that embeds a raster or vector image into the document. It has no closing tag and no content of its own — its behavior is entirely controlled by attributes.

<img
  src="hero.jpg"
  alt="A golden retriever catching a frisbee in a sunny park"
  width="800"
  height="533"
  loading="lazy"
  decoding="async"
>
Key idea The <img> element is replaced content — the browser replaces the tag with the external resource. Its intrinsic size comes from the file itself, but you can override with CSS or attributes.
[hero.jpg · 800×533]

2 The src Attribute

src (source) is required. It is a URL pointing to the image file. It can be:

  • Absolute — full URL including scheme: https://cdn.example.com/logo.png
  • Relative — path relative to the current document: ../images/logo.png
  • Root-relative — starts with /: /assets/img/logo.png
  • Data URI — the image is embedded directly: data:image/svg+xml;base64,...
<!-- Absolute URL -->
<img src="https://images.example.com/products/laptop.jpg" alt="...">

<!-- Root-relative (resolves from site root) -->
<img src="/assets/icons/star.svg" alt="...">

<!-- Document-relative -->
<img src="./thumbnails/preview.webp" alt="...">

<!-- Data URI (small icons, SVGs, base64) -->
<img src="data:image/svg+xml;utf8,<svg xmlns='http://www.w3.org/2000/svg'/>" alt="...">
Common mistake Using backslashes (..\images\logo.png) — that works only on Windows file systems, not in URLs. Always use forward slashes /.
Pro tip Use a CDN with a subdomain (e.g. cdn.yoursite.com) for images. Browsers open fewer connections per origin, so a separate subdomain can parallelize image downloads. Modern HTTP/2 and HTTP/3 reduce this benefit, but CDNs still win for caching and edge delivery.

3 The alt Attribute — Accessibility & SEO

alt (alternative text) is the most important attribute on an image. It is read aloud by screen readers, indexed by search engines, and shown when the image fails to load. Every <img> must have an alt attribute — even if it's empty.

When to write descriptive alt text

If the image conveys information, the alt text should describe what the image shows in the context of the page.

<img
  src="chart-q3-revenue.png"
  alt="Bar chart showing Q3 revenue rose 42% from $1.2M to $1.7M"
>

When to leave alt empty

If the image is purely decorative (background flourish, divider, eye candy adjacent to text that already says it all), use an empty alt attribute: alt="". This tells assistive tech to skip the image entirely. Do not omit the attribute — that makes some screen readers read the filename aloud.

<!-- Decorative icon next to a visible "Print" label -->
<button>
  <img src="printer.svg" alt="">
  Print
</button>

<!-- BAD: omitted alt — screen reader reads "printer.svg" -->
<img src="printer.svg">

Writing great alt text

Bad altWhyBetter alt
alt="image" Tells the user nothing alt="Golden retriever catching a frisbee"
alt="DSC_4471.jpg" Filename, not a description alt="Sunset over Mount Rainier"
alt="A picture of a dog which is brown and is sitting on grass and is looking at the camera..." Way too long, redundant phrasing alt="Brown dog sitting on grass"
alt="A brown dog" (on a page about a specific dog named Rex) Misses the meaningful context alt="Rex, a brown Labrador, sitting on the front lawn"
Pro tip — the 125-character rule Keep alt text under ~125 characters. Most screen readers truncate around that length. If you need more detail, put the long description in the surrounding text or use aria-describedby pointing to a hidden paragraph.
SEO bonus Google Images indexes alt text, and Google Search uses it to understand page content. Descriptive alt can drive significant image-search traffic — especially for product, recipe, and tutorial sites.

4 Width & Height Attributes

Setting width and height attributes (in CSS pixels, without units) lets the browser reserve the correct space before the image loads. This prevents layout shift (CLS — a Core Web Vital).

<!-- Good: browser reserves 800×533 box -->
<img src="hero.jpg" alt="..." width="800" height="533">

<!-- Bad: causes layout shift as image streams in -->
<img src="hero.jpg" alt="...">

Aspect-ratio magic

Modern browsers compute the aspect-ratio from width/height attributes automatically. You can then use CSS to scale responsively without losing the reserved space:

img {
  max-width: 100%;
  height: auto;       /* preserves aspect ratio set by attributes */
}
Common mistake Setting only one of width or height in CSS while the attribute provides the other. This squashes or stretches the image. Either set both attributes (and use height: auto in CSS), or set the aspect-ratio explicitly.
Pro tip If you don't know the image dimensions at authoring time, generate them server-side or compute them at build time. Frameworks like Next.js, Astro, and Eleventy have image components that inject dimensions automatically.

5 Lazy Loading with loading="lazy"

The loading attribute tells the browser when to fetch the image. The most useful value is lazy — defer loading until the image scrolls near the viewport.

ValueBehaviorUse case
lazyLoad when about to enter viewportBelow-the-fold images
eager (default)Load immediatelyAbove-the-fold hero images
 
<!-- Hero image: load immediately -->
<img src="hero.jpg" alt="..." width="1200" height="800" loading="eager" fetchpriority="high">

<!-- Gallery images: defer until needed -->
<img src="photo-1.jpg" alt="..." width="600" height="400" loading="lazy">
<img src="photo-2.jpg" alt="..." width="600" height="400" loading="lazy">
Common mistake Lazy-loading the LCP (Largest Contentful Paint) image — usually the hero. This delays the most important visual and tanks your performance score. Keep hero images loading="eager" and add fetchpriority="high".
Pro tip width and height are required for loading="lazy" to work reliably. Without dimensions the browser can't decide when to fetch — it must wait until layout is complete.

6 The decoding Attribute

decoding hints whether the browser should decode the image synchronously or asynchronously with the rest of page rendering.

ValueMeaning
asyncDecode off the main thread; don't block rendering
syncDecode synchronously (default for <img>)
autoBrowser decides
 
<img
  src="hero.jpg"
  alt="..."
  width="1200"
  height="800"
  decoding="async"
>
Pro tip For above-the-fold hero images, use decoding="async" with fetchpriority="high". For below-the-fold images, combine loading="lazy" with decoding="async".

7 The referrerpolicy Attribute

When a browser fetches an image, it normally sends a Referer header telling the hosting server which page requested the image. referrerpolicy controls how much information is sent.

ValueWhat it sends
no-referrerNo Referer header at all
originOnly the origin (e.g. https://example.com)
origin-when-cross-originFull URL same-origin, origin only cross-origin
same-originSend Referer for same-origin only; nothing cross-origin
strict-origin-when-cross-origin (default)Origin only cross-origin, full URL same-origin; downgrade HTTPS→HTTP to no referrer
 
<!-- Privacy-friendly: don't leak page URL to image host -->
<img src="https://third-party-tracker.com/pixel.png"
     alt="" referrerpolicy="no-referrer">
Why it matters If you embed images from a third party (e.g. an analytics pixel, ad network, or stock photo provider), the default policy can leak your full page URL — including query parameters that might contain session IDs or user info.

8 The crossorigin Attribute

crossorigin controls whether the image is fetched with CORS (Cross-Origin Resource Sharing) credentials. It's needed when you want to read image pixels via JavaScript (e.g. for canvas manipulation).

ValueBehavior
(omitted)No CORS request; canvas access throws security error
anonymousCORS request, no cookies
use-credentialsCORS request with cookies
 
<!-- Needed if you'll later draw this image to canvas and read pixels -->
<img
  src="https://cdn.example.com/photo.jpg"
  alt="..."
  crossorigin="anonymous"
>

<!-- Server MUST respond with: -->
<!-- Access-Control-Allow-Origin: * (or your origin) -->
Common mistake Adding crossorigin="anonymous" on an image whose host does not return Access-Control-Allow-Origin. The image will fail to load. CORS must be configured on the server side.

9 The title Attribute (And Why You Probably Shouldn't)

title adds a tooltip that appears when the user hovers. It's tempting but mostly harmful:

  • Touch devices have no hover — most users never see it.
  • Screen reader support is inconsistent.
  • It duplicates content that's already in alt, leading to confusion.
  • Tooltips appear after a 1-2 second delay and vanish quickly.
<!-- Avoid this pattern -->
<img src="logo.svg" alt="Acme Inc." title="Acme Inc. — We Make Everything">

<!-- Prefer visible text or a real caption instead -->
<figure>
  <img src="chart.png" alt="Bar chart of Q3 revenue">
  <figcaption>Q3 revenue rose 42% to $1.7M.</figcaption>
</figure>
Pro tip The legitimate use of title on an <img> is for <link rel="icon"> (the bookmark name) and the occasional data table cell. For images, prefer a <figcaption> or surrounding text.

11 Try It Yourself

Exercise 1 — Write proper alt text Save three images from https://picsum.photos. For each, write: (a) descriptive alt that would help a screen-reader user, (b) an empty alt="" version for when the same image is purely decorative. Write a one-line note explaining each choice.
Exercise 2 — Eliminate layout shift Create a page with 5 images, no width/height. Refresh and watch the content jump. Then add width/height attributes and max-width:100%; height:auto CSS. Refresh again — the page should be stable.
Exercise 3 — Lazy load audit Build a long page with a hero image and 10 gallery images. Add loading="lazy" to the gallery and loading="eager" fetchpriority="high" to the hero. Open DevTools → Network → filter by Img, then scroll. Watch the gallery images load on demand.
Exercise 4 — Decorative vs meaningful Build a button with an icon and a text label. Mark the icon alt="". Then build the same button with only the icon (no visible text) — what alt text do you write now? (Hint: alt="Print".)

12 Summary

  • <img> is a void element; behavior comes from attributes.
  • src is required and accepts absolute, relative, root-relative, or data-URI URLs.
  • alt is required on every image — descriptive when meaningful, empty (alt="") when decorative.
  • Always set width and height attributes to prevent layout shift.
  • Use loading="lazy" below the fold, loading="eager" fetchpriority="high" for the hero/LCP.
  • decoding="async" keeps the main thread responsive during image decoding.
  • referrerpolicy protects privacy when embedding third-party images.
  • crossorigin="anonymous" is needed for canvas pixel access (and requires server CORS).
  • Avoid the title attribute on images — prefer <figcaption> or visible text.
