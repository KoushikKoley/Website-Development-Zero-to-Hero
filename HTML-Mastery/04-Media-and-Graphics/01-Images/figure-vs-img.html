Figure vs <img> — When & Why

Plain <img> is for inline content. <figure> wraps self-contained media with an optional <figcaption>. Knowing which to reach for is one of the most useful semantic decisions in HTML.

1 What Is a Figure?

The HTML spec calls <figure> a unit of self-contained content, often with a caption, that is referenced from the main flow of the document but could be moved away without breaking the narrative.

Think of a magazine article: the paragraphs flow, and figures (photos, charts, sidebars) can be lifted to a different page or column without losing meaning. That's exactly the semantic of <figure>.

<figure>
  <img src="chart-q3.png" alt="Q3 revenue rose 42% to $1.7M"
       width="800" height="500" loading="lazy">
  <figcaption>Figure 1: Q3 2024 revenue by week.</figcaption>
</figure>

2 When to Use Figure

Use figure when…

The content is referenced from the surrounding text ("see Figure 1 below"), is self-contained, and would still make sense if moved to an appendix or sidebar.

Use plain img when…

The image is part of a sentence flow (a logo, an inline icon, a decorative bullet), or is the main visual of the page (like a hero image) and doesn't need a caption.

Photo with caption in an article<figure>Caption semantically tied to image

3 The <figcaption> Element

<figcaption> is the only valid caption child of <figure>. It can come first or last in the figure — convention is to put it last for images and first for code listings or blockquotes.

<figure>
  <img src="chart.png" alt="...">
  <figcaption>
    <strong>Figure 3.</strong> Weekly active users by region,
    Q4 2024. Source: <a href="/analytics">internal dashboard</a>.
  </figcaption>
</figure>

You can include rich content in a <figcaption>: links, citations (<cite>), source attributions, even small data tables. Keep it concise — it's a caption, not an essay.

Pro tip The <figcaption> should not duplicate the alt text on the image. Write alt for screen-reader users who can't see the image; write the caption for sighted users who need context.

4 Multiple Images in One Figure

A single <figure> can contain multiple images. This is great for "before/after" comparisons, photo series, or step-by-step tutorials where the caption describes the group.

<figure>
  <img src="before.jpg" alt="Untidy desk before organizing">
  <img src="after.jpg"  alt="Same desk after organizing">
  <figcaption>
    Figure 4: The author's desk before and after applying
    the KonMari method.
  </figcaption>
</figure>

CSS to display side-by-side:

figure { display: flex; gap: 16px; flex-wrap: wrap; }
figure img { flex: 1 1 45%; min-width: 200px; }
figcaption { flex-basis: 100%; text-align: center; }
Common mistake Each image still needs its own alt. If you only write one caption, the individual alts become even more important — they describe each image to non-sighted users.

5 Code Listings as Figures

A code listing with a caption is a perfect use of <figure>. Pair <pre><code> inside <figure>, with <figcaption> above.

<figure>
  <figcaption><strong>Listing 1.</strong> A basic HTTP server in Node.js.</figcaption>
  <pre><code class="language-js">const http = require('http');
const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain' });
  res.end('Hello, world!');
});
server.listen(3000);</code></pre>
</figure>

The same pattern works for tables, equations (in MathML), video clips, audio samples, and SVG illustrations — anything that is self-contained and benefits from a label.

6 When NOT to Use Figure

Don't use figure for…Use insteadWhy
An inline image in the middle of a sentencePlain <img>Figure is block-level; would break the paragraph
A decorative background imageCSS background-imageNot content, just styling
A logo in a navigation barPlain <img>Not referenced; branding element
An image that is the article (photo essay)<article> with <img>It's primary content, not supplementary
A pull-quote that duplicates surrounding textPlain <blockquote> with aria-hiddenNot self-contained — duplicates content
A decorative icon next to a button labelInline SVG or plain <img alt="">Captioned figure makes no sense for an icon
Common mistake Wrapping every image in <figure> "for semantics". This actually removes semantics — a figure implies the image is self-contained and referenced. If it's not, plain <img> is more honest.

7 Positioning the Caption

<figcaption> can be the first or last child of <figure>. By default it renders where you put it. Common patterns:

/* Caption below image (default) */
figure { margin: 0; }
figure img { display: block; width: 100%; }
figure figcaption { padding: 10px 0; font-size: 0.9rem; color: #555; }

/* Caption overlaid on image */
figure { position: relative; }
figure figcaption {
  position: absolute; bottom: 0; left: 0; right: 0;
  background: rgba(0,0,0,0.6); color: white;
  padding: 12px; margin: 0;
}

/* Caption above (great for code listings) */
figure figcaption { margin-bottom: 10px; font-weight: 600; }
figure pre { margin-top: 0; }
Pro tip For numbered figures ("Figure 1", "Figure 2"), use CSS counters so the numbering updates automatically — no manual renumbering when you insert a new figure mid-article. 
body { counter-reset: fig; }
figure > figcaption::before {
  counter-increment: fig;
  content: "Figure " counter(fig) ": ";
  font-weight: 700;
  color: var(--brand);
}

8 Quick Semantics Recap

ElementRoleCommon content
<figure>Self-contained content unitImage, code, table, blockquote, video
<figcaption>Figure caption (one per figure)Label, description, attribution
<img> (in figure)The visual contentAlways set alt, width, height
<pre><code> (in figure)Code listing contentWrap code; escape entities
<blockquote> (in figure)Quoted textAlways wrap text in <p>
Pro tip — combining elements A figure can contain a mix: an image, then a code snippet, then a paragraph — as long as the whole is self-contained and the caption labels them as a unit. Don't overdo this; one content type per figure is usually cleaner.

10 Try It Yourself

Exercise 1 — Captioned photo Find a photo. Wrap it in <figure> with a <figcaption>. Write alt text describing the image and a caption describing its context (e.g. "Figure 1: Sunset from the Eiffel Tower, July 2024.").
Exercise 2 — Before/after gallery Create a <figure> with two images side-by-side. Use CSS flex to lay them out. Write a single caption describing both. Give each image its own alt.
Exercise 3 — Code listing Write a <figure> containing a <figcaption> ("Listing 1: Hello world in Python.") followed by a <pre><code> block. Make the caption bold and blue.
Exercise 4 — Auto-numbered figures Add 3 figures to a page. Use CSS counters to auto-number them as "Figure 1", "Figure 2", "Figure 3". Insert a new figure in the middle and confirm the numbering shifts correctly.

11 Summary

  • <figure> = self-contained content, referenced from main flow, often captioned.
  • <figcaption> = the caption, must be the first or last child of <figure>.
  • Use <figure> for captioned photos, charts, code listings, pull-quotes, testimonials.
  • Use plain <img> for inline images, logos, avatars, hero shots.
  • One <figcaption> per figure; multiple images are fine inside one figure.
  • Don't repeat alt text in the caption — they serve different audiences.
  • Use CSS counters to auto-number "Figure N" sequences.
