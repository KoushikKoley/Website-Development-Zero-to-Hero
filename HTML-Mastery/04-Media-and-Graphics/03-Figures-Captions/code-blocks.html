Code Blocks — <pre><code>, Highlighting & More

Displaying code on a web page means escaping HTML entities, preserving whitespace, and ideally highlighting syntax. The <pre><code> pattern is the universal foundation.

1 The <pre> + <code> Pattern

Two elements work together: <pre> preserves whitespace and line breaks; <code> marks the content as computer code. Together they give you a code block.

<pre><code>function greet(name) {
  return `Hello, ${name}!`;
}
</code></pre>
function greet(name) {
  return `Hello, ${name}!`;
}
Why both? <pre> alone preserves formatting but doesn't tell screen readers this is code. <code> alone marks semantics but collapses whitespace (inline behavior). <pre> wrapping <code> gives you both — preserved whitespace and code semantics.

2 Escaping HTML Entities

If your code contains <, >, or &, the browser will interpret them as HTML — breaking your display. Replace them with HTML entities:

CharacterEntityWhen it appears
<&lt;Any HTML tag, generics like Array<T>
>&gt;Same as above
&&amp;Bitwise AND, &&, entity references themselves
"&quot;Inside attribute values (often optional)
'&apos; or &#39;Inside single-quoted attribute values
Non-breaking space&nbsp;Preserve leading spaces in <pre> if needed
 
<!-- WRONG: browser sees <div> as a real tag -->
<pre><code>
<div class="card">Hello</div>
</code></pre>

<!-- RIGHT: entities escape the angle brackets -->
<pre><code>
&lt;div class="card"&gt;Hello&lt;/div&gt;
</code></pre>
Common mistake Forgetting to escape & when your code contains entities. &amp;lt; renders as the literal text &lt;. To display &lt; on the page, the source must be &amp;lt;.
Pro tip Use a build tool or template language to auto-escape. Markdown processors, JSX, Astro, Eleventy, and most static site generators escape HTML inside code fences automatically.

3 Language Attribute & Class

HTML5 introduced the class="language-XXX" convention for marking the code's language. This isn't honored by browsers natively, but it's the standard hook for syntax highlighters and is also useful for CSS styling.

<pre><code class="language-js">const x = 1;</code></pre>
<pre><code class="language-python">x = 1</code></pre>
<pre><code class="language-html">&lt;p&gt;Hi&lt;/p&gt;</code></pre>
<pre><code class="language-css">body { color: red; }</code></pre>

Some authors also include data-lang="js" for explicit styling hooks without conflicting with highlighter libraries.

4 Inline vs Block Code

Use <code> alone (without <pre>) for inline code references — function names, variables, short snippets inside a sentence.

Use <pre><code> for multi-line blocks. Never wrap a paragraph in <pre> — it's strictly for preformatted text.

5 Syntax Highlighting Libraries

Native HTML has no syntax highlighting. Two libraries dominate: Prism and Highlight.js.

Prism

Lightweight (~2 KB core), modular — you include only the languages you need. Used by React docs, Tailwind, MDN. Customizable themes via CSS.

Highlight.js

Auto-detects language (~50 KB with all languages). Easier drop-in for sites with mixed content. Used by Stack Overflow, GitHub Gists (legacy).

Prism setup

<!-- In <head> -->
<link rel="stylesheet"
      href="https://cdn.jsdelivr.net/npm/prismjs@1/themes/prism-tomorrow.css">

<!-- At end of <body> -->
<script src="https://cdn.jsdelivr.net/npm/prismjs@1/components/prism-core.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/prismjs@1/components/prism-javascript.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/prismjs@1/components/prism-python.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/prismjs@1/components/prism-markup.min.js"></script>

<!-- Usage -->
<pre><code class="language-js">const x = 1;</code></pre>

Highlight.js setup

<link rel="stylesheet"
      href="https://cdn.jsdelivr.net/gh/highlightjs/cdn-release/build/styles/atom-one-dark.min.css">
<script src="https://cdn.jsdelivr.net/gh/highlightjs/cdn-release/build/highlight.min.js"></script>
<script>hljs.highlightAll();</script>

<!-- Usage -->
<pre><code class="language-python">print("hi")</code></pre>
Pro tip — server-side highlighting For best performance, highlight at build time using Shiki, Starry Night, or Prism's Node API. This produces static HTML with syntax classes already applied — no client-side JS, instant rendering, perfect for SEO.

6 Line Numbers

Line numbers help readers reference specific lines, but they're tricky because <pre> preserves whitespace exactly. Three approaches:

1. CSS counters (clean, no JS)

pre code { counter-reset: line; }
pre code > span.line { counter-increment: line; }
pre code > span.line::before {
  content: counter(line);
  display: inline-block;
  width: 2em; margin-right: 1em;
  color: #64748b; text-align: right;
  user-select: none;
}

/* HTML */
<pre><code><span class="line">line 1</span>
<span class="line">line 2</span></code></pre>

2. Prism Line Numbers plugin

<script src="prismjs/plugins/line-numbers/prism-line-numbers.min.js"></script>
<link rel="stylesheet" href="prismjs/plugins/line-numbers/prism-line-numbers.css">

<pre class="line-numbers"><code class="language-js">...</code></pre>

3. Two-column layout with grid

pre { display: grid; grid-template-columns: auto 1fr; gap: 0 1em; }
pre .gutter { color: #64748b; user-select: none; text-align: right; }
Common mistake Putting line numbers directly inside the <code> text. When users copy-paste, they get the numbers too. Always use CSS pseudo-elements or a separate column with user-select: none.

7 Copy Button Pattern

A copy-to-clipboard button is the most-requested feature for code blocks. Pattern below uses the Clipboard API with a fallback.

<style>
  .code-block { position: relative; }
  .copy-btn {
    position: absolute; top: 8px; right: 8px;
    padding: 4px 10px; font-size: 0.8rem;
    background: rgba(255,255,255,0.1); color: #fff;
    border: 1px solid rgba(255,255,255,0.2);
    border-radius: 6px; cursor: pointer;
  }
  .copy-btn:hover { background: rgba(255,255,255,0.2); }
  .copy-btn.copied { background: #16a34a; border-color: #16a34a; }
</style>

<div class="code-block">
  <button class="copy-btn" aria-label="Copy code">Copy</button>
  <pre><code class="language-js">const x = 1;</code></pre>
</div>

<script>
  document.querySelectorAll('.code-block').forEach(block => {
    const btn = block.querySelector('.copy-btn');
    const code = block.querySelector('code');
    btn.addEventListener('click', async () => {
      try {
        await navigator.clipboard.writeText(code.innerText);
        btn.textContent = 'Copied!';
        btn.classList.add('copied');
        setTimeout(() => {
          btn.textContent = 'Copy';
          btn.classList.remove('copied');
        }, 2000);
      } catch (err) {
        console.error('Copy failed:', err);
      }
    });
  });
</script>
Pro tip Use innerText instead of textContent — it accounts for line breaks added by CSS, giving cleaner clipboard output.

8 Accessibility for Code

  • Always use <code> — screen readers announce "code" before reading.
  • Provide a human-readable label via aria-label if the language isn't obvious from context: <code aria-label="JavaScript code">.
  • For long blocks, consider a <figure> wrapper with <figcaption> describing what the code does.
  • Avoid relying on color alone — syntax highlighting helps sighted users but doesn't replace semantic markup.
  • Make sure code is keyboard-scrollable — long lines shouldn't trap focus inside the <pre>.
  • Set tabindex="0" on scrollable <pre> blocks so keyboard users can scroll horizontally.
<pre tabindex="0">
  <code class="language-js" aria-label="JavaScript example">
    function add(a, b) { return a + b; }
  </code>
</pre>

10 Try It Yourself

Exercise 1 — Escape HTML Write a <pre><code> block that displays the HTML source: <article><h1>Title</h1></article>. Manually escape every < and >. View the page source to confirm you used &lt; and &gt;.
Exercise 2 — Add Prism Add Prism CSS + JS to a page from a CDN. Mark three code blocks with language-js, language-python, and language-html. Confirm each gets the correct highlighting colors.
Exercise 3 — Copy button Implement the copy button pattern from section 7. Verify the button text changes to "Copied!" for 2 seconds after click. Test that the clipboard contains the unescaped code (not the entities).
Exercise 4 — Line numbers Use the CSS counter approach to add line numbers to a 10-line code block. Confirm that selecting and copying the code does not include the line numbers.

11 Summary

  • Always use <pre><code> for code blocks — preserves whitespace, marks semantics.
  • Escape <, >, & as &lt;, &gt;, &amp; in source.
  • Add class="language-XXX" so highlighters know the language.
  • Prism (modular, lightweight) and Highlight.js (auto-detect) are the two main libraries.
  • For production: highlight at build time with Shiki or similar — zero client JS.
  • Line numbers via CSS counters — never in source text.
  • Copy button with navigator.clipboard.writeText + visual feedback.
  • Add tabindex="0" on scrollable <pre> for keyboard users.
