Section 3.3 · target & rel

target & rel Attributes

Two attributes that quietly control where a link opens, how much info leaks across origins, and how search engines treat the link. Master them — especially the security-critical rel="noopener" — and your links become both safer and more meaningful.

1 The target Attribute

By default, clicking a link replaces the current page in its own tab/window/frame. The target attribute overrides this — telling the browser which browsing context should display the destination.

Five values are defined by the HTML spec:

ValueBehaviorCommon Use
_self (default)Opens in the same tab/frame the link is in.Internal navigation, in-page links.
_blankOpens in a new tab or window.External sites, PDFs, "open in new tab" UX.
_parentOpens in the parent browsing context.Inside nested iframes — replaces the immediate parent frame.
_topOpens in the topmost browsing context (breaks out of ALL frames).Frame-busting, anti-clickjacking for trusted links.
framenameOpens in a window/iframe with a matching name.Targeting a specific iframe as a "viewer".
 
<!-- Same tab (explicit, default behavior) -->
<a href="/about" target="_self">About</a>

<-- New tab — ALWAYS pair with rel="noopener" -->
<a href="https://example.com" target="_blank" rel="noopener noreferrer">
  Visit Example
</a>

<-- Top of the frame hierarchy (break out of all iframes) -->
<a href="https://bank.com/login" target="_top">Login</a>

<-- Named frame — opens in iframe named "viewer" -->
<a href="chapter2.html" target="viewer">Chapter 2</a>
<iframe name="viewer" src="chapter1.html" title="Chapter viewer"></iframe>

2 _blank Deep Dive

Opening a link in a new tab is one of the most common UX patterns on the web — but it's also one of the easiest to get wrong. Here's everything you need to know:

When to Use _blank

  • External websites (keeps the user on your site in the original tab).
  • PDFs and other documents (so users don't lose their place in your content).
  • Auxiliary tools ("Open calculator", "View shipping rates").
  • Print-friendly versions, share dialogs, help articles.

When NOT to Use _blank

  • Internal site navigation — users expect "back" to work, and tabs accumulate.
  • Login/logout flows — the new tab won't have the user's session context they expect.
  • Form submission (use POST or a regular navigation, not a new tab).
  • Mobile-first designs where tabs are hidden behind a UI that users may not discover.
Pro Tip Some accessibility experts argue against target="_blank" by default because it removes user control — they can't predict the back button's behavior. Consider letting users opt in with middle-click or Ctrl/Cmd+click instead. If you do use _blank, indicate it visually (icon) and in the link's accessible name.

3 Security: Reverse Tabnabbing

When you open a link with target="_blank", the new page gets a reference to the original tab via window.opener. A malicious page can use this to redirect your tab to a phishing URL — a known attack called reverse tabnabbing.

// On the destination page (the attacker's site):
if (window.opener) {
  window.opener.location = 'https://evil-login-page-that-looks-like-yours.com';
}
// User switches back to "your" tab, sees a fake login page, types password.

The Fix: rel="noopener"

Adding rel="noopener" severs the window.opener reference. The new tab can no longer manipulate yours.

<!-- ✅ Safe — no window.opener access granted -->
<a href="https://untrusted-site.com" target="_blank" rel="noopener">
  Visit untrusted site
</a>

Browser Defaults Have Caught Up

Since 2019-2021, all major browsers (Chrome 88+, Firefox 79+, Safari 12.1+, Edge 88+) default to noopener behavior for target="_blank" links to cross-origin destinations. But you should still be explicit:

  • Older browsers don't have the protection.
  • Same-origin links (target="_blank" within your own site) are not protected.
  • It's a documentation signal — explicit rel="noopener" tells future maintainers "this is intentional".
Common Mistake — Forgetting noreferrer rel="noopener" blocks window.opener access, but the new page still sees the Referer header. If your URL contains sensitive tokens in the path (e.g., /reset-password/abc123), add rel="noopener noreferrer" to also suppress the referrer.

4 _parent & _top

These two values matter only when the current page is inside an iframe. They control how far "up" the frame hierarchy the navigation propagates.

<!-- Outer page: index.html -->
<iframe name="outer" src="outer.html"></iframe>

<-- outer.html -->
<iframe name="inner" src="inner.html"></iframe>

<-- inner.html — link is here -->
<a href="page.html" target="_self">    <!-- Replaces inner.html only -->
<a href="page.html" target="_parent">  <!-- Replaces outer.html only -->
<a href="page.html" target="_top">     <!-- Replaces the whole index.html tab -->
<a href="page.html" target="outer">    <!-- Same as _parent in this case -->

Modern Use: _top for Frame-Busting

Clickjacking attacks embed your site in a malicious iframe to capture clicks. If your site detects being framed, you can force a top-level navigation:

// JavaScript frame-busting
if (window.top !== window.self) {
  window.top.location = '/login?framed=true';
}

HTML can also help: links that must open at the top level (like "Login") should use target="_top".

Pro Tip Modern frame-busting prefers the X-Frame-Options HTTP header (DENY or SAMEORIGIN) or the Content-Security-Policy: frame-ancestors 'none' directive. Use these over HTML-level tricks — they're enforced before any HTML loads.

5 Named Frames

You can target any iframe or window with a matching name. This is how master-detail layouts worked before SPA frameworks, and it's still useful for embedded document viewers.

<!-- A "table of contents" on the left, content on the right -->
<nav style="float:left; width:200px;">
  <a href="ch1.html" target="viewer">Chapter 1</a>
  <a href="ch2.html" target="viewer">Chapter 2</a>
  <a href="ch3.html" target="viewer">Chapter 3</a>
</nav>
<iframe name="viewer" src="ch1.html" style="width: 80%; height: 600px;"
        title="Chapter viewer"></iframe>

Common Mistake If the named target doesn't exist, browsers create a new tab/window with that name — which can be confusing. Always verify your <iframe name="..."> matches the target="..." value.

6 The rel Attribute

rel (short for "relationship") is a space-separated list of tokens describing how the linked resource relates to the current document. The tokens serve three purposes:

  • Security — control cross-origin behavior.
  • SEO — tell search engines how to treat the link.
  • Semantics — describe the link's role (author, license, help, etc.).

There are over 20 recognized tokens. Below, we'll group them by purpose.

7 rel: Security Tokens

TokenEffectRequired For
noopenerSevers window.opener reference; new tab can't manipulate yours.Any target="_blank" link to external content.
noreferrerSuppresses the Referer HTTP header. Implies noopener.Links that shouldn't leak the source URL.
openerRe-enables window.opener when browsers default to noopener.Rare — when you explicitly want opener access.
 
<!-- Safe external link — no opener, no referrer -->
<a href="https://external.com" target="_blank" rel="noopener noreferrer">
  Visit external site
</a>

<-- If you NEED window.opener access (rare) -->
<a href="auth-callback.html" target="_blank" rel="opener">
  Continue authentication
</a>

8 rel: SEO Tokens

Google, Bing, and other engines use these tokens to decide whether to "follow" a link for ranking purposes.

TokenEffectUse Case
nofollowDon't pass PageRank; don't crawl destination.Untrusted links, paid placements, comment sections (pre-2019 catch-all).
sponsoredPaid placement (ads, sponsorships).Affiliate links, sponsored posts.
ugcUser-generated content.Forum signatures, comment links, wiki edits.
 
<!-- Paid/sponsored ad -->
<a href="https://sponsor.example.com" rel="sponsored nofollow">
  Sponsored deal
</a>

<-- User-submitted comment link -->
<a href="https://user-blog.example.com" rel="ugc nofollow">
  User's blog
</a>
Pro Tip — Combine Tokens Google treats sponsored and ugc as hints — they imply "no follow" but don't strictly enforce it. Add nofollow as well for older crawlers and maximum clarity: rel="sponsored nofollow".

9 rel: Semantic Tokens

These describe the relationship between documents. Browsers and assistive tech may use them; search engines certainly do.

TokenMeaningExample
alternateAlternative version: translation, RSS, PDF, print.RSS feed discovery: <link rel="alternate" type="application/rss+xml">
authorLink to the document's author.<a rel="author" href="/users/jane">Jane Doe</a>
bookmarkPermalink for the nearest ancestor section.Blog post permalinks.
externalLinks to an external site.Often styled with icon: ↗
helpContext-sensitive help.Form field tooltips.
licenseCopyright/license for current content.CC BY-SA links on Wikipedia.
tagTag/keyword for current content.Blog tag clouds.
searchSearch link/resource.Often paired with OpenSearch description.
prefetchHint to fetch the resource in idle time.Next likely navigation.
preloadHigh-priority fetch for current page.Critical fonts, CSS, hero images.
preconnectPre-warm the connection (DNS+TCP+TLS).Third-party origins you'll fetch from.
dns-prefetchResolve DNS for an origin.Lower-priority origins.
 
<!-- Author byline -->
<a href="/authors/jane-doe" rel="author">Jane Doe</a>

<-- License -->
<a href="https://creativecommons.org/licenses/by/4.0/" rel="license">CC BY 4.0</a>

<-- External link -->
<a href="https://news.ycombinator.com" rel="external">Hacker News ↗</a>

<-- Help -->
<a href="/help/password-reset" rel="help">How to reset your password</a>

<-- Tag -->
<a href="/tags/css" rel="tag">CSS</a>
Pro Tip — Style external links automatically CSS attribute selectors + rel="external" can add an icon to all external links automatically: a[rel~="external"]::after { content: " ↗"; color: var(--brand); }

10 rel: Pagination (next & prev)

For paginated content (article series, search results, product lists), rel="next" and rel="prev" tell search engines the canonical order — and they help browsers pre-fetch the next page.

<!-- On page 2 of an article -->
<a href="/article?page=1" rel="prev">← Previous</a>
<a href="/article?page=3" rel="next">Next →</a>

<-- In the <head> for SEO (preferred) -->
<link rel="prev" href="/article?page=1">
<link rel="next" href="/article?page=3">
Common Mistake Google deprecated using rel="next"/rel="prev" in the <head> for SEO in 2019. It still helps browsers and screen readers understand the relationship, so it's not useless — but don't expect a ranking boost.

11 Combining target & rel

The two attributes are independent but commonly used together. Here's a decision matrix:

Scenariotargetrel
Internal navigation, same tab(omit) or _self(omit)
External site, new tab_blanknoopener noreferrer external
Sponsored external link_blanknoopener noreferrer sponsored nofollow
PDF download in new tab_blanknoopener
Internal anchor link(omit)(omit)
Help link in modal(omit)help
Author byline(omit)author
License link in footer(omit)license
Pagination next(omit)next
Breadcrumb parent(omit)(omit) — use structured data instead
 
<!-- The "production-ready external link" -->
<a href="https://external.com/page"
   target="_blank"
   rel="noopener noreferrer external"
   aria-label="Visit External.com (opens in new tab)">
  Visit External.com
</a>

13 Common Mistakes

MistakeWhy It's WrongFix
target="_blank" without rel="noopener"Reverse tabnabbing attack surface (older browsers).Always add rel="noopener noreferrer".
target="_blank" for internal linksBreaks "back" button UX, accumulates tabs.Reserve for external/auxiliary resources.
No indication of new-tab behaviorScreen reader users surprised by tab switch.Add aria-label="... (opens in new tab)" or a visible icon.
Using rel="nofollow" everywhereOver-suppression kills legitimate link equity.Use only for untrusted/paid/UGC links.
Missing rel="license" on CC contentLicense unclear; legal risk.Always mark license links explicitly.
Confusing sponsored with nofollowGoogle treats them differently as hints.Use both: rel="sponsored nofollow".
Using target="framename" without matching iframeOpens a new window named "framename" — confusing.Verify the iframe's name matches.

14 Real-World Use Cases

External "Read More"

Article references with target="_blank" rel="noopener noreferrer external" — keeps readers on your site while citing sources.

Affiliate Marketing

Every affiliate link gets rel="sponsored nofollow" — required by Google guidelines and FTC disclosure rules.

Comment Systems

WordPress, Disqus, Reddit auto-add rel="ugc nofollow" to user-submitted links — preserving page rank.

Documentation Sites

"Edit on GitHub" / "View source" / "Report issue" links all use target="_blank" rel="noopener".

License Footers

Wikipedia, Creative Commons, MIT-licensed docs all use rel="license" to clarify licensing.

Author Bio Links

Blog platforms auto-add rel="author" to author names — historically used for Google Authorship (deprecated, but still useful semantically).

Search Boxes

<link rel="search" type="application/opensearchdescription+xml"> in <head> lets browsers add your site to the search bar.

RSS Auto-Discovery

<link rel="alternate" type="application/rss+xml" href="/feed.xml"> — enables the RSS icon in browser address bars.

15 Summary

  • target has 5 values: _self, _blank, _parent, _top, framename.
  • target="_blank" opens a new tab — always pair with rel="noopener noreferrer".
  • Reverse tabnabbing: without rel="noopener", the new tab can manipulate your tab via window.opener.
  • _parent affects one frame up; _top breaks out of all frames.
  • rel tokens: security (noopener, noreferrer), SEO (nofollow, sponsored, ugc), semantic (author, license, help, tag, search, alternate, external).
  • Pagination uses rel="next" and rel="prev" for document ordering (mostly UX now).
  • Combine tokens freely: rel="noopener noreferrer external sponsored nofollow".
  • For same-site navigation, omit both target and rel — defaults are correct.
