Section 3.8 · Site Nav

Site Navigation Patterns

Site navigation is more than a menu bar. It's a hierarchy of <nav> regions — main menu, breadcrumbs, pagination, footer nav — each with semantic structure and accessibility built in. Done well, it lets users (and search engines) understand your entire site architecture from any page.

1 The <nav> Element

The <nav> element is a landmark region that identifies a group of navigational links. Screen readers use it to let users jump directly to navigation. There's no rule about how many <nav> elements you can have — but each should be distinguishable via aria-label or aria-labelledby.

<!-- Primary site nav -->
<nav aria-label="Primary">
  <ul>
    <li><a href="/">Home</a></li>
    <li><a href="/products">Products</a></li>
    <li><a href="/about">About</a></li>
  </ul>
</nav>

<-- Footer nav (a separate region) -->
<nav aria-label="Footer">
  <ul>...</ul>
</nav>

<-- Pagination -->
<nav aria-label="Pagination">
  <ul>...</ul>
</nav>

<-- Breadcrumb -->
<nav aria-label="Breadcrumb">
  <ol>...</ol>
</nav>
Common Mistake — Wrapping Every Link List Don't wrap every group of links in <nav>. Reserve it for major navigation blocks. A footer with social icons, a sidebar with "related links", or an in-content list of citations don't need to be <nav> — they don't help users navigate the site.

2 Main Menu Pattern

The site's main menu is typically a horizontal bar of links. Semantically: <nav> containing a <ul> of <li>s with <a>s.

<header class="site-header">
  <a href="/" class="logo">Acme</a>
  <nav aria-label="Primary">
    <ul>
      <li><a href="/" aria-current="page">Home</a></li>
      <li><a href="/products">Products</a></li>
      <li><a href="/pricing">Pricing</a></li>
      <li><a href="/about">About</a></li>
      <li><a href="/blog">Blog</a></li>
      <li><a href="/contact">Contact</a></li>
    </ul>
  </nav>
</header>
ACME
  • Home
  • Products
  • Pricing
  • About
  • Blog
  • Contact
Pro Tip Wrap menu links in <ul>/<li>, not <div>. Screen readers announce list semantics ("List, six items"), giving users context about menu size and structure.

3 aria-current for Active Page

Use aria-current="page" on the link to the current page. Screen readers announce "current page"; browsers and CSS can style it distinctly.

<li><a href="/" aria-current="page">Home</a></li>
<li><a href="/products">Products</a></li>

<style>
  /* Style the current page link */
  nav a[aria-current="page"] {
    background: var(--brand);
    color: white;
    font-weight: 600;
  }
</style>

aria-current Values

ValueMeaning
pageThe current page within a set of pages.
stepThe current step within a process.
locationThe current location, e.g., in a breadcrumb trail.
dateThe current date in a calendar.
timeThe current time.
trueThe current item in a set.
falseDefault — not current.
Common Mistake — Using a Class Instead Don't just use class="active" — screen readers won't know it's the current page. Always pair with aria-current="page". CSS can then target [aria-current="page"] instead of a custom class.

4 Breadcrumbs

Breadcrumbs show the user's path from the homepage to the current page — essential for sites deeper than 2 levels. The pattern: <nav aria-label="Breadcrumb"> with an ordered list.

<nav aria-label="Breadcrumb">
  <ol>
    <li><a href="/">Home</a></li>
    <li><a href="/products">Products</a></li>
    <li><a href="/products/electronics">Electronics</a></li>
    <li><a href="/products/electronics/headphones" aria-current="page">Headphones</a></li>
  </ol>
</nav>

<style>
  nav[aria-label="Breadcrumb"] ol {
    list-style: none; display: flex; flex-wrap: wrap;
    gap: 6px; padding: 0; margin: 0;
  }
  nav[aria-label="Breadcrumb"] li {
    display: flex; align-items: center; gap: 6px;
  }
  nav[aria-label="Breadcrumb"] li:not(:last-child)::after {
    content: "›";
    color: var(--ink-soft);
    margin-left: 6px;
  }
  nav[aria-label="Breadcrumb"] [aria-current] {
    color: var(--ink); font-weight: 600;
  }
</style>
  1. Home
  2. Products
  3. Electronics
  4. Headphones
Pro Tip — Add Schema.org BreadcrumbList Pair breadcrumbs with structured data for rich Google search results: 
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    {"@type": "ListItem", "position": 1, "name": "Home", "item": "https://example.com/"},
    {"@type": "ListItem", "position": 2, "name": "Products", "item": "https://example.com/products"},
    {"@type": "ListItem", "position": 3, "name": "Headphones", "item": "https://example.com/products/electronics/headphones"}
  ]
}
</script>

5 Pagination

For paginated content (search results, blog lists, product grids), provide a pagination control wrapped in <nav aria-label="Pagination">.

<nav aria-label="Pagination">
  <ul>
    <li><a href="?page=1" rel="prev" aria-label="Previous page">← Previous</a></li>
    <li><a href="?page=1">1</a></li>
    <li><a href="?page=2" aria-current="page">2</a></li>
    <li><a href="?page=3">3</a></li>
    <li><a href="?page=4">4</a></li>
    <li><a href="?page=5">5</a></li>
    <li><a href="?page=3" rel="next" aria-label="Next page">Next →</a></li>
  </ul>
</nav>
← Previous 1 2 3 4 5 Next →
Pro Tip — Large Paginations For 20+ pages, show only a window: 1 ... 5 6 [7] 8 9 ... 20. Use aria-disabled="true" (not just CSS) on the ellipsis items to prevent them from being focusable.
Common Mistake — Pagination as Buttons Some designs render pagination as <button>s that trigger JS navigation. This breaks: deep-linking, browser back button, SEO crawling, and middle-click-to-open-in-new-tab. Always use real <a href> links for pagination — let the page reload for true URLs.

6 Footer Navigation

Footers typically contain secondary navigation — categories, legal links, social media. Often a multi-column layout with multiple <nav> regions.

<footer>
  <nav aria-label="Product">
    <h5>Product</h5>
    <ul>
      <li><a href="/features">Features</a></li>
      <li><a href="/pricing">Pricing</a></li>
      <li><a href="/changelog">Changelog</a></li>
    </ul>
  </nav>

  <nav aria-label="Company">
    <h5>Company</h5>
    <ul>
      <li><a href="/about">About</a></li>
      <li><a href="/blog">Blog</a></li>
      <li><a href="/careers">Careers</a></li>
    </ul>
  </nav>

  <nav aria-label="Legal">
    <h5>Legal</h5>
    <ul>
      <li><a href="/privacy">Privacy Policy</a></li>
      <li><a href="/terms">Terms of Service</a></li>
    </ul>
  </nav>
</footer>
Product
  • Features
  • Pricing
  • Changelog
Company
  • About
  • Blog
  • Careers
Legal
  • Privacy Policy
  • Terms of Service
  • Cookies

7 Mega Menus & Dropdowns

Large sites (e.g., e-commerce, university) often use mega menus — multi-column dropdowns that appear on hover/click. The HTML structure is nested <ul>s; the interactivity needs CSS and/or JS.

<nav aria-label="Primary">
  <ul>
    <li>
      <button aria-expanded="false" aria-controls="products-menu">
        Products ▾
      </button>
      <ul id="products-menu" hidden>
        <li><a href="/products/electronics">Electronics</a></li>
        <li><a href="/products/clothing">Clothing</a></li>
        <li><a href="/products/home">Home & Garden</a></li>
      </ul>
    </li>
    <li><a href="/about">About</a></li>
  </ul>
</nav>
Common Mistake — Hover-Only Dropdowns CSS-only hover dropdowns don't work on touch devices and break for keyboard users. Always:
  • Use a <button> to toggle (not <a href="#">).
  • Sync aria-expanded state.
  • Use hidden + JS to show/hide (not just CSS display).
  • Close on Escape key.
  • Restore focus to the trigger button on close.

8 Mobile Navigation

On mobile, the main menu collapses behind a "hamburger" button that reveals a slide-out panel or full-screen overlay.

<button class="menu-toggle"
        aria-expanded="false"
        aria-controls="mobile-menu">
  ☰ Menu
</button>

<nav id="mobile-menu" aria-label="Mobile" hidden>
  <ul>
    <li><a href="/">Home</a></li>
    <li><a href="/products">Products</a></li>
    <li><a href="/about">About</a></li>
  </ul>
</nav>

<script>
  const toggle = document.querySelector('.menu-toggle');
  const menu = document.querySelector('#mobile-menu');

  toggle.addEventListener('click', () => {
    const isOpen = toggle.getAttribute('aria-expanded') === 'true';
    toggle.setAttribute('aria-expanded', String(!isOpen));
    menu.hidden = isOpen;
  });

  // Close on Escape
  document.addEventListener('keydown', e => {
    if (e.key === 'Escape') {
      toggle.setAttribute('aria-expanded', 'false');
      menu.hidden = true;
      toggle.focus();
    }
  });
</script>
Pro Tip The hamburger menu has accessibility concerns — it hides primary navigation. Consider: bottom-tab navigation for 3-5 primary destinations, or always-visible nav with a "More" overflow. Test with one-handed mobile thumb reach.

9 Semantic Structure Recap

Putting it all together — a complete page with all four nav regions:

<!DOCTYPE html>
<html>
<body>
  <a href="#main" class="skip-link">Skip to main content</a>

  <header>
    <a href="/" class="logo">Acme</a>
    <nav aria-label="Primary">
      <ul>
        <li><a href="/" aria-current="page">Home</a></li>
        <li><a href="/products">Products</a></li>
      </ul>
    </nav>
  </header>

  <nav aria-label="Breadcrumb">
    <ol>
      <li><a href="/">Home</a></li>
      <li><a href="/blog" aria-current="page">Blog</a></li>
    </ol>
  </nav>

  <main id="main">
    <h1>Blog Posts</h1>
    <article>...</article>
    <article>...</article>
    <article>...</article>

    <nav aria-label="Pagination">
      <ul>
        <li><a href="?page=1" rel="prev">← Previous</a></li>
        <li><a href="?page=1">1</a></li>
        <li><a href="?page=2" aria-current="page">2</a></li>
        <li><a href="?page=3">3</a></li>
        <li><a href="?page=3" rel="next">Next →</a></li>
      </ul>
    </nav>
  </main>

  <footer>
    <nav aria-label="Footer">
      <ul>...</ul>
    </nav>
  </footer>
</body>
</html>

10 Try It Yourself

Exercise 1 — Main Menu with aria-current Build a horizontal main menu with 6 items. Mark the current page with aria-current="page" and style it distinctively (background color, white text). Test with a screen reader if available.
Exercise 2 — Breadcrumb with Schema.org Build a 4-level breadcrumb (Home > Products > Electronics > Headphones). Style separators with CSS ::after. Add the matching BreadcrumbList JSON-LD structured data in the <head>.
Exercise 3 — Pagination with Ellipsis Build pagination for 20 pages, showing: First, ..., 5 6 7 [8] 9 10 11, ..., Last. Use aria-current="page" on the current page. Disable (not link) the ellipsis items.
Exercise 4 — Footer with 3 Nav Regions Build a 3-column footer with separate <nav aria-label> regions for "Product", "Company", and "Legal". Each contains a list of 3-5 links.
Exercise 5 — Accessible Dropdown Build a navigation item with a dropdown submenu. Use a <button> trigger, sync aria-expanded, toggle the hidden attribute, close on Escape, and restore focus on close.
Exercise 6 — Mobile Hamburger Menu Implement a hamburger menu toggle. The button updates aria-expanded; the menu shows/hides via hidden; pressing Escape closes and returns focus to the toggle.

11 Common Mistakes

MistakeWhy It's WrongFix
Missing aria-label on <nav>Screen readers can't distinguish multiple navs.Add aria-label="Primary", aria-label="Footer", etc.
Using class="active" instead of aria-currentScreen readers don't announce current page.Use aria-current="page".
Pagination as <button>Breaks deep-linking, back button, SEO.Use <a href> links.
Dropdowns triggered only on hoverFails on touch; breaks keyboard nav.Use click + aria-expanded + Escape.
Hamburger menu without aria-expandedScreen reader users can't tell if it's open.Sync aria-expanded state on toggle.
Wrapping every link list in <nav>Overuse dilutes the landmark.Reserve <nav> for major navigation.
Menu as <div>s instead of <ul>/<li>Loses list semantics for screen readers.Use semantic list markup.
Mobile menu shown via CSS onlyVisible to screen readers even when "closed".Use hidden attribute; toggle with JS.

12 Real-World Use Cases

Marketing Sites

Main nav (5-7 items) + footer (3-4 columns). Often a CTA button in the header.

E-commerce

Mega menu categories + breadcrumbs + pagination on product lists + footer with policies.

Documentation Sites

Left sidebar TOC + breadcrumb + "Edit on GitHub" + footer with version selector.

News Publishers

Section-based main nav (World, Business, Tech) + breadcrumb + pagination + tag cloud.

SaaS Dashboards

Top utility nav + left sidebar nav + breadcrumb + footer (rarely).

Universities / Government

Mega menus with dozens of links organized by audience (Students, Faculty, Alumni).

Web Apps (SPA)

Client-side routing — but still use <a href> for accessible, crawlable links. React Router, Vue Router do this.

Mobile Web

Bottom tab bars (iOS-style), hamburger menus, drawer patterns. Consider thumb-zone accessibility.

13 Summary

  • Use <nav aria-label="..."> for each major navigation region — primary, footer, breadcrumb, pagination.
  • Main menu = <ul>/<li>/<a> inside <nav>.
  • aria-current="page" marks the current page; pair with CSS for visible active state.
  • Breadcrumbs: ordered list + CSS separators + Schema.org structured data.
  • Pagination: <a href> links (never buttons) + rel="prev"/rel="next".
  • Footer nav: multiple <nav aria-label> regions in columns.
  • Dropdowns and mobile menus: use <button> triggers + aria-expanded + hidden attribute.
  • Reserve <nav> for major navigation; don't wrap every link list.
  • Always test with keyboard: Tab, Enter, Escape, and verify focus is visible.
