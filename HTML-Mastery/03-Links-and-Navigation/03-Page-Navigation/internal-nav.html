Section 3.7 · Internal Nav

Internal Page Navigation

Long-form pages — docs, articles, one-pager landings — need to help users find content quickly without scrolling endlessly. Same-page anchors, sticky TOCs, scroll-spy indicators, and skip links combine into a great in-page navigation experience.

1 What Is Internal Navigation?

Internal navigation refers to links and UI elements that move users around within a single page, rather than loading a new URL. The web's most common internal navigation tool is the fragment link (<a href="#section">), but the pattern extends to sticky navs, scroll-spy indicators, skip links, and reading-progress bars.

This is most useful on long pages: documentation, blog posts, terms-of-service, one-page marketing sites, and tutorials. Without internal nav, users scroll aimlessly and miss content. With it, they can jump, orient, and re-orient quickly.

Pro Tip Internal navigation isn't just convenience — it's accessibility. Screen reader users navigate by headings and landmarks; keyboard users tab through links. Providing an in-page TOC and skip links makes your content usable for everyone.

2 Same-Page Anchors

The foundation of internal navigation is the fragment link — covered in detail in 02-URL-Types/fragments.html. Here's the quick pattern:

<!-- Table of contents -->
<nav class="toc">
  <ul>
    <li><a href="#intro">Introduction</a></li>
    <li><a href="#setup">Setup</a></li>
    <li><a href="#usage">Usage</a></li>
    <li><a href="#faq">FAQ</a></li>
  </ul>
</nav>

<-- Content sections with matching ids -->
<section id="intro">
  <h2>Introduction</h2>
  <p>...</p>
</section>

<section id="setup">
  <h2>Setup</h2>
  <p>...</p>
</section>
<!-- etc -->

With scroll-behavior: smooth and scroll-padding-top: 80px (for sticky header clearance), this gives users a one-click jump experience — no JavaScript required.

3 Table of Contents Pattern

The TOC pattern displays a structured list of section links. Common variants:

Static Sidebar TOC

Used on docs sites (MDN, Stripe). Sits in the left or right rail, sticky-positioned. Each link is a fragment.

<nav class="toc" aria-label="Table of contents">
  <h2>Contents</h2>
  <ol>
    <li><a href="#intro">Introduction</a></li>
    <li><a href="#setup">Setup</a>
      <ol>
        <li><a href="#setup-prereq">Prerequisites</a></li>
        <li><a href="#setup-install">Installation</a></li>
        <li><a href="#setup-config">Configuration</a></li>
      </ol>
    </li>
    <li><a href="#usage">Usage</a></li>
  </ol>
</nav>

<style>
  nav.toc {
    position: sticky; top: 16px;
    max-height: calc(100vh - 32px);
    overflow: auto;
  }
</style>
Pro Tip Use a nested <ol> for sub-sections to reflect hierarchy. The browser default numbering (1.1, 1.2, 1.3) gives readers context about the document's structure at a glance.

Top-of-Page TOC

For shorter pages (1,500-3,000 words), a top TOC is often enough — no sticky sidebar needed.

<header>
  <h1>Understanding CSS Grid</h1>
  <nav class="toc" aria-label="On this page">
    <h2>On this page</h2>
    <ul>
      <li><a href="#anatomy">Anatomy of a Grid</a></li>
      <li><a href="#containers">Grid Containers</a></li>
      <li><a href="#items">Grid Items</a></li>
      <li><a href="#examples">Examples</a></li>
    </ul>
  </nav>
</header>

Auto-Generated TOCs

Most static site generators auto-generate TOCs from headings:

  • Markdown: [TOC] or via rehype-slug + rehype-autolink-headings.
  • Hugo: {{ .TableOfContents }}
  • Eleventy: eleventy-plugin-toc
  • Docsify/Docusaurus: built-in

4 Sticky In-Page Nav

For long pages, a sticky TOC stays visible as the user scrolls. The simplest implementation is position: sticky; top: 16px;.

Common Mistake — Sticky Overlap Sticky navs cover content when you click a fragment link — the target scrolls under the nav. Always pair sticky nav with scroll-padding-top: 80px on <html> (or scroll-margin-top: 80px on sections).

5 Scroll Spy Concept (Without JS)

Scroll spy = the TOC highlights the section the user is currently reading. The full version requires JS (IntersectionObserver), but a pure-CSS approximation uses :target:

<style>
  .spy-nav a { color: var(--ink); }
  /* Highlight the active section's TOC link */
  #sec1:target ~ .spy-nav a[href="#sec1"],
  #sec2:target ~ .spy-nav a[href="#sec2"],
  #sec3:target ~ .spy-nav a[href="#sec3"] {
    background: var(--brand);
    color: white;
  }
</style>

This only highlights while the section is "targeted" (after a click) — not while scrolling. For true scroll-spy behavior, JS is required:

// Modern scroll-spy with IntersectionObserver
const sections = document.querySelectorAll("section[id]");
const navLinks = document.querySelectorAll(".spy-nav a");

const observer = new IntersectionObserver(entries => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      const id = entry.target.id;
      navLinks.forEach(link => {
        link.classList.toggle("active", link.getAttribute("href") === `#${id}`);
      });
    }
  });
}, { rootMargin: "-80px 0px -70% 0px" }); // account for sticky nav

sections.forEach(s => observer.observe(s));
Pro Tip The rootMargin: "-80px 0px -70% 0px" trick makes the "active" zone begin 80px from the top (clearing your sticky nav) and end 70% down — meaning the section becomes "active" when its top is near the top of the viewport.

6 Skip Links for Keyboard Users

A skip link is the first focusable element on a page — a hidden-then-shown-on-focus link that lets keyboard users jump past repetitive navigation to the main content.

<!-- First element in <body> -->
<a href="#main" class="skip-link">Skip to main content</a>

<nav>...long navigation...</nav>

<main id="main">
  <h1>Page content starts here</h1>
</main>

<style>
  .skip-link {
    position: absolute;
    top: -100px; left: 0;
    background: var(--brand); color: white;
    padding: 12px 20px; z-index: 1000;
    text-decoration: none; border-radius: 0 0 8px 0;
    transition: top 0.2s;
  }
  .skip-link:focus { top: 0; }
</style>
Common Mistake — Hidden Skip Links Never use display: none or visibility: hidden on skip links — they become unfocusable. Use position: absolute; top: -100px; and reveal on :focus.

Additional skip links to consider:

  • Skip to navigation: useful for screen reader users landing in main content.
  • Skip to footer: legal pages, contact info.
  • Skip to search: large e-commerce sites.
  • Skip to next section: in long-form articles.
Pro Tip WCAG 2.1 SC 2.4.1 (Bypass Blocks) requires a way to skip repetitive content. Skip links are the simplest compliance solution and benefit every keyboard user, not just screen reader users.

7 Reading Progress Indicators

A top progress bar shows users how far they've read. Pure JS, but lightweight:

<div class="reading-progress" aria-hidden="true"></div>

<style>
  .reading-progress {
    position: fixed; top: 0; left: 0;
    height: 4px; width: 0%;
    background: var(--brand);
    z-index: 1000;
    transition: width 0.1s;
  }
</style>

<script>
  const progress = document.querySelector(".reading-progress");
  window.addEventListener("scroll", () => {
    const scrollable = document.documentElement.scrollHeight - window.innerHeight;
    const scrolled = window.scrollY / scrollable * 100;
    progress.style.width = scrolled + "%";
  });
</script>
Pro Tip Mark progress bars aria-hidden="true" — they're decorative. Screen reader users get progress through heading navigation instead.

9 Try It Yourself

Exercise 1 — Static TOC Create a long-form article (1,500+ words) with 5 sections. Add a TOC at the top with fragment links. Apply scroll-behavior: smooth. Verify jumping works without JavaScript.
Exercise 2 — Sticky Sidebar TOC Move the TOC into a sticky left sidebar (260px wide). On mobile (< 900px), collapse it to the top. Test on both viewport sizes.
Exercise 3 — Skip Link Add a "Skip to main content" link as the first focusable element on your page. Use position: absolute; top: -100px; hidden until focused. Test by tabbing from the address bar.
Exercise 4 — Reading Progress Bar Add a fixed-position progress bar at the top of the page. Use JS to update its width based on scroll position. Add aria-hidden="true".
Exercise 5 — Scroll Spy with IntersectionObserver Implement scroll spy: as the user scrolls through sections, the corresponding TOC link gets an "active" class (e.g., bold + colored background). Use the IntersectionObserver snippet from this page.
Exercise 6 — Permalink Hover Pattern Add a hover-visible # icon next to each section heading. Clicking it copies pageURL#section-id to the clipboard using the Clipboard API. Show a toast confirming the copy.

11 Real-World Use Cases

Documentation Sites

MDN, Stripe, React docs: sticky left TOC + scroll-spy active highlighting. Gold-standard pattern.

One-Pager Marketing

Restaurant/hotel/agency sites: nav links scroll to #features, #pricing, #contact.

Long-Form Articles

Medium, Substack, NYT: TOC at top, section anchors for sharing.

Legal/Terms Pages

Privacy policies, ToS: TOC with skip-link to "What we collect", "Your rights", etc.

Recipe Blogs

"Jump to recipe" skip-link past the long story intro — universally appreciated UX.

Course Platforms

Lesson navigation: previous/next + section TOC + progress indicator.

API Reference

Stripe API docs: side TOC, every method is a fragment, deep-linkable.

Wiki/Glossary

Alphabetical index that scrolls to definitions; Wikipedia uses this for glossary pages.

12 Summary

  • Internal navigation helps users find content within a single page — essential for long-form pages.
  • Same-page anchors (#id) are the foundation; pair with scroll-behavior: smooth.
  • Table of contents pattern: nested <ol> of fragment links, sticky-positioned on long pages.
  • Scroll spy highlights the active section in the TOC; JS with IntersectionObserver is the modern approach.
  • Skip links are the first focusable element — let keyboard users bypass repetitive nav (WCAG 2.4.1).
  • Reading progress bars give visual feedback; mark them aria-hidden="true".
  • Always handle sticky-nav overlap with scroll-padding-top or scroll-margin-top.
  • Respect prefers-reduced-motion when using smooth scrolling.
  • Always label TOC nav: <nav aria-label="Table of contents">.
