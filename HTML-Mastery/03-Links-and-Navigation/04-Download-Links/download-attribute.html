Section 3.10 · download

The download Attribute

Normally, clicking a link to a PDF or image opens it in the browser. The download attribute on <a> forces the browser to save the file instead — and lets you suggest a filename. Perfect for reports, generated CSVs, and downloadable assets.

1 What download Does

The download attribute on an <a> element tells the browser: "when the user clicks this link, save the resource to their disk instead of navigating to it". You can optionally suggest a filename.

<!-- Without download: opens PDF in browser -->
<a href="report.pdf">View report</a>

<-- With download: saves PDF to disk -->
<a href="report.pdf" download>Download report</a>

<-- With download + filename: saves as "annual-report.pdf" -->
<a href="report.pdf" download="annual-report.pdf">Download annual report</a>
Download hello.txt
Pro Tip The download attribute is a suggestion, not a command. Browsers may override it based on user preferences ("Always open PDFs in browser"), Content-Type headers, or extensions. For guaranteed download behavior, configure the server to send Content-Disposition: attachment.

2 Basic Syntax

Two forms: bare attribute (no value) uses the original filename; with a value, it suggests a custom filename.

<!-- Boolean form: saves with original filename -->
<a href="/files/manual.pdf" download>Download manual</a>
<-- Saves as: manual.pdf -->

<-- With filename value -->
<a href="/files/manual.pdf" download="Acme-Manual-2024.pdf">Download manual</a>
<-- Saves as: Acme-Manual-2024.pdf -->

Combining with Other Attributes

<a href="/files/report.pdf"
   download="Q3-2024-Financials.pdf"
   type="application/pdf"
   aria-label="Download Q3 2024 Financial Report (PDF, 2.4 MB)">
  Download Q3 Financials (PDF, 2.4 MB)
</a>
  • download forces the save behavior.
  • type hints the MIME type (informational, not enforced).
  • aria-label gives screen readers full context.
  • Visible text includes the file type and size — best practice for UX.

3 Suggesting a Filename

The download attribute value is the suggested filename. The browser may modify it to ensure safety and OS compatibility:

  • Removes path separators (/, \).
  • Strips dangerous characters (depends on browser).
  • May add an extension if one isn't provided.
  • May sanitize Unicode characters.
<-- ✅ Simple ASCII filename -->
<a href="..." download="report-2024.pdf">

<-- ✅ Hyphens are fine -->
<a href="..." download="annual-report-2024.pdf">

<-- ✅ Underscores are fine -->
<a href="..." download="annual_report_2024.pdf">

<-- ⚠️ Spaces are allowed but discouraged -->
<a href="..." download="annual report 2024.pdf">

<-- ❌ Paths are stripped: saves as "report.pdf" -->
<a href="..." download="path/to/report.pdf">

<-- ❌ Most special chars are sanitized -->
<a href="..." download="report?v=2.pdf">
Pro Tip Stick to lowercase letters, numbers, hyphens, underscores, and a single period before the extension. This guarantees cross-platform compatibility.

4 MIME Types & the type Attribute

5 The Same-Origin Requirement

The download attribute is ignored for cross-origin resources — those served from a different scheme, host, or port. The browser will navigate to the resource instead of downloading it.

<!-- Same origin (works) -->
<a href="/files/report.pdf" download>Download</a>

<-- Cross-origin (download attribute ignored, browser navigates) -->
<a href="https://cdn.example.com/files/report.pdf" download>Download</a>

The Cross-Origin Workaround

To force a download of a cross-origin file, the destination server must send the Content-Disposition header:

Content-Disposition: attachment; filename="report.pdf"

If you don't control the destination server, you can proxy the file through your own backend:

// Server-side proxy (Node/Express example)
app.get('/download-proxy', async (req, res) => {
  const response = await fetch('https://cdn.example.com/report.pdf');
  res.setHeader('Content-Disposition', 'attachment; filename="report.pdf"');
  res.setHeader('Content-Type', 'application/pdf');
  response.body.pipe(res);
});

// Client-side link points to your proxy
<a href="/download-proxy" download="report.pdf">Download</a>
Common Mistake — Cross-Origin Confusion Many developers add download to a link to a third-party CDN and are surprised when it doesn't work. The browser is following the spec — without a same-origin check, any site could force-download arbitrary files from any origin, which is a security risk.

6 Dynamic Downloads with Blob URLs

For generated content (CSV exports, JSON configs, screenshots), create a Blob in JavaScript, get a blob: URL, and use it as the href for a download link.

<a id="download-link" class="download-btn">Download CSV</a>

<script>
  const data = [
    ["Name", "Email"],
    ["Alice", "alice@example.com"],
    ["Bob", "bob@example.com"],
  ];

  // Convert array to CSV string
  const csv = data.map(row => row.join(",")).join("\n");

  // Create a Blob
  const blob = new Blob([csv], { type: "text/csv" });

  // Get a blob: URL
  const url = URL.createObjectURL(blob);

  // Wire up the download link
  const link = document.getElementById("download-link");
  link.href = url;
  link.download = "contacts.csv";

  // Revoke when no longer needed (e.g., on page unload)
  window.addEventListener("beforeunload", () => URL.revokeObjectURL(url));
</script>
Download contacts.csv (generated)
Pro Tip Always call URL.revokeObjectURL(url) when the blob is no longer needed — typically after the user clicks the download, or when the page unloads. Otherwise the Blob stays in memory.

7 data: URLs as Downloads

For tiny downloads (a few KB), you can embed the file content directly as a data: URL. No server round-trip required.

<!-- Plain text download -->
<a href="data:text/plain;charset=utf-8,Hello%20World"
   download="hello.txt">
  Download hello.txt
</a>

<-- CSV with multi-line content (URL-encoded newlines) -->
<a href="data:text/csv;charset=utf-8,Name,Email%0AAlice,alice@x.com%0ABob,bob@x.com"
   download="contacts.csv">
  Download CSV
</a>

<-- JSON download -->
<a href='data:application/json;charset=utf-8,{"name":"Alice","age":30}'
   download="user.json">
  Download JSON
</a>
Download CSV (data: URL) Download JSON (data: URL)
Common Mistake Don't use data: URLs for large files. Base64 encoding (if needed) inflates size by ~33%, and the entire URL must fit in HTML — many browsers limit URL length to ~2MB. For files >4KB, use a Blob URL or serve from your backend.

9 Security Considerations

1. Cross-Origin Restriction

As mentioned, download is ignored for cross-origin URLs (different scheme/host/port). This prevents sites from force-downloading arbitrary files from other origins.

2. Filename Sanitization

The browser strips path separators and dangerous characters from the suggested filename. You can't trick a user into saving a file to a specific folder (e.g., ../../../autoexec.bat is sanitized).

3. MIME Type Confusion

The type attribute is a hint. The actual content type is determined by the server's Content-Type header. Don't rely on type for security — verify with the server if it matters.

4. HTML Files Are Dangerous

Downloading an HTML file with download doesn't execute it — but if the user opens it later, it runs in their local context. Warn users before downloading HTML files; consider zipping them.

5. Blob URL Leakage

Each URL.createObjectURL() holds memory until revoked. Long-running apps creating many blob URLs leak memory. Always revoke when done.

6. CSP Restrictions

If you use Content Security Policy, ensure blob: is allowed in default-src or specific directives where needed. Otherwise blob URL downloads fail silently.

Content-Security-Policy:
  default-src 'self';
  blob:;                   <!-- allow blob: URLs everywhere -->
  media-src 'self' blob:;  <!-- or just for media -->
Common Mistake — Forgetting to Revoke Blob URLs 
// ❌ Memory leak — blob never released
const url = URL.createObjectURL(blob);
link.href = url;

// ✅ Revoke after download
link.addEventListener("click", () => {
  setTimeout(() => URL.revokeObjectURL(url), 1000);
});

13 Real-World Use Cases

Report Downloads

Annual reports, white papers, case studies — PDFs that users want to read offline or share.

Software Releases

"Download v2.4.1" links to installer files (.exe, .dmg, .deb) or zipped source.

Generated Exports

Admin dashboards: "Export to CSV", "Export to Excel", "Download as JSON" — built client-side with Blobs.

Media Files

Podcast episodes, music tracks, video clips — sometimes preferred over streaming.

Templates & Assets

Design templates, document templates, sample data files.

Invoice Downloads

SaaS billing pages: "Download invoice" generates a PDF on the fly and downloads it.

Calendar Files

"Add to calendar" downloads .ics files (with type="text/calendar").

Backup Configurations

Export settings as JSON for backup/restore. Generated client-side, downloaded as a file.

14 Summary

  • download on <a> forces the browser to save instead of navigate.
  • Optional value suggests a filename — sanitized by the browser.
  • type attribute hints MIME type; informational only.
  • Same-origin requirement: download ignored for cross-origin (use Content-Disposition on server).
  • For dynamic content, use URL.createObjectURL(blob) — always revoke after use.
  • data: URLs work for tiny files; avoid for files >4KB.
  • Always include file type and size in visible text and aria-label.
  • Stick to ASCII filenames: lowercase, hyphens, underscores, single extension.
  • Don't auto-download on page load — require explicit click.
  • For guaranteed behavior, configure server Content-Disposition: attachment.
