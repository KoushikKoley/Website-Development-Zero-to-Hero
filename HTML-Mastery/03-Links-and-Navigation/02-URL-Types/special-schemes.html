Section 3.6 · Special Schemes

Special URL Schemes

Beyond http: and https:, browsers understand a family of special URL schemes that trigger native apps, generate downloads, and embed files inline. mailto:, tel:, sms:, data:, blob: — each has its own syntax and security profile.

1 Schemes Overview

The first part of any URL — before :// or : — is the scheme. Most web links use https, but browsers also recognize a handful of "special" schemes that don't fetch a resource. Instead, they trigger a native app action, generate content inline, or reference in-memory blobs.

mailto:

Opens the user's email client with a pre-filled message. Supports multiple recipients, subject, body, cc, bcc.

tel:

Opens the dialer (mobile) or calling app (desktop). Should always use E.164 international format with +.

sms:

Opens the SMS app with a recipient (and optionally body). Syntax varies by platform.

data:

Embeds small resources (text, images, files) directly in the URL. Useful for tiny images, generated downloads.

blob:

References an in-memory Blob object created by JavaScript. Used for large generated files, video streaming.

javascript:

Executes JS in the location bar context. Deprecated and insecure — avoid in modern code.

2 mailto: Scheme

Clicking a mailto: link opens the visitor's default email client with one or more fields pre-filled. The format is:

mailto:recipient@example.com[,recipient2@example.com]*[?key=value&key=value]

Parameters

ParameterPurposeExample
(none, before ?)One or more comma-separated "to" addressesmailto:a@x.com,b@x.com
subjectPre-fills the Subject line?subject=Hello
bodyPre-fills the message body?body=Just%20saying%20hi
ccCarbon-copy recipients?cc=boss@x.com
bccBlind-carbon-copy recipients?bcc=audit@x.com
 
<!-- Simple -->
<a href="mailto:hello@example.com">Email us</a>

<-- Multiple recipients -->
<a href="mailto:alice@example.com,bob@example.com">Email both</a>

<-- With cc and bcc -->
<a href="mailto:hello@example.com?cc=sales@example.com&bcc=archive@example.com">
  Contact us (cc sales, bcc archive)
</a>

<-- With subject and body (URL-encoded) -->
<a href="mailto:hello@example.com?subject=Order%20%2312345&body=Hi%20team%2C%0A%0AMy%20order%20has%20not%20arrived.">
  Report order issue
</a>
✉️ Click to compose an email →
Common Mistake — URL Encoding Spaces, ampersands, and newlines must be percent-encoded:
  • Space → %20
  • Line break → %0D%0A (CRLF)
  • & → %26
  • = → %3D
  • ? → %3F
  • # → %23
Otherwise the email client will misparse the parameters. Use encodeURIComponent() in JS to do this safely.
Pro Tip — Multiple Recipients For multiple to recipients, separate with commas (no spaces). For multiple cc or bcc recipients, the same applies: ?cc=a@x.com,b@x.com,c@x.com

mailto: Limitations

  • No attachments: you can't attach files via mailto:. Use a form + server-side mailer instead.
  • No HTML body: only plain text. HTML email requires server-side rendering.
  • Spam risk: emails scraped from mailto: links end up on spam lists. Consider using a contact form, or obfuscate with JS.
  • No reliable "send": the user can edit/cancel the email before sending. Don't use mailto: for transactional emails that must be sent.

3 tel: Scheme

On mobile devices — and increasingly on desktops with calling apps (FaceTime, Skype, Teams) — tel: opens the dialer with a number pre-filled. The user still has to tap "Call".

E.164 Format

Always use international E.164 format: starts with +, followed by country code, then national number. No spaces, dashes, or parentheses in the tel: value (though display text can format them).

<!-- US number: +1 (800) 555-1234 -->
<a href="tel:+18005551234">+1 (800) 555-1234</a>

<-- Display formatted, tel: in E.164 -->
<a href="tel:+18005551234">Call (800) 555-1234</a>

<-- UK number: +44 20 7183 8750 -->
<a href="tel:+442071838750">+44 20 7183 8750</a>

<-- Japan: +81 3-1234-5678 -->
<a href="tel:+81312345678">+81 3-1234-5678</a>

<-- With extension (pause) -->
<a href="tel:+18005551234,1234">Call support, ext. 1234</a>
<-- The comma tells the dialer to wait 2 seconds, then dial 1234. -->

<-- With "wait" (w) — dialer prompts user -->
<a href="tel:+18005551234;1234">Call with confirmation</a>
📞 +1 (800) 555-1234
Common Mistake — Local Numbers Without + A Tokyo office number written as tel:03-1234-5678 will dial correctly only for callers in Japan. A visitor from abroad using tel:03-1234-5678 will fail (or dial a wrong number). Always use tel:+81312345678.
Pro Tip — Always Display the Number Even with a clickable tel: link, show the human-readable number visibly. Users may want to write it down or call from a different phone. Don't hide the number behind "Click here to call".

4 sms: Scheme

Opens the SMS app with a recipient pre-filled (and optionally a message body). Support is uneven — iOS and Android use different syntax for the body parameter.

<!-- Open SMS app with number filled -->
<a href="sms:+18005551234">Text us</a>

<-- iOS: pre-fill body with &body= -->
<a href="sms:+18005551234&body=OPTIN">Text OPTIN to subscribe</a>

<-- Android (historical): pre-fill body with ?body= -->
<a href="sms:+18005551234?body=OPTIN">Text OPTIN to subscribe</a>

<-- Multiple recipients (commas, no spaces) -->
<a href="sms:+18005551234,+18005555678">Text both</a>
Common Mistake — Inconsistent Cross-Platform Syntax There's no universal syntax for the body parameter. iOS uses &body=; Android historically used ?body=. The WHATWG spec says ?body=, but iOS still requires &body=. Feature-detect or live with the inconsistency. For maximum reliability, link just the number and put the message in the link text: "Text 'OPTIN' to 800-555-1234".
Pro Tip — Modern WhatsApp / Telegram Deep Links Many messaging apps have their own URL schemes:
  • https://wa.me/18005551234?text=Hello — WhatsApp
  • https://t.me/share/url?url=...&text=... — Telegram
  • sgnl://signal.me/#p/+18005551234 — Signal
These are more reliable than sms: across platforms.

5 data: URLs

The data: scheme lets you embed small resources — text, images, audio, generated files — directly in the URL itself. The browser doesn't make an HTTP request; the content is decoded from the URL.

Syntax

data:[<mediatype>][;base64],<data>
  • mediatype: MIME type like text/plain, image/png, application/pdf. Defaults to text/plain;charset=US-ASCII.
  • ;base64: optional; indicates the data is base64-encoded.
  • data: the actual content (URL-encoded if not base64).

Examples

<!-- Plain text -->
<a href="data:text/plain;charset=utf-8,Hello%20World" download="hello.txt">
  Download hello.txt
</a>

<-- HTML -->
<a href="data:text/html;charset=utf-8,<h1>Hi</h1>">Open HTML</a>

<-- Tiny PNG (base64) -->
<img src="data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mNkYPhfDwAChwGA60e6kgAAAABJRU5ErkJggg==" alt="1x1 red pixel">

<-- Generated CSV download -->
<a href="data:text/csv;charset=utf-8,Name,Email%0Aalice,alice@x.com%0Abob,bob@x.com"
   download="contacts.csv">
  Download CSV
</a>

<-- Inline SVG -->
<img src="data:image/svg+xml;utf8,<svg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 100 100'><circle cx='50' cy='50' r='40' fill='red'/></svg>" alt="red circle">
⬇ Download a text file generated from a data: URL

When to Use data: URLs

  • Tiny images (1x1 tracking pixels, small icons) — saves HTTP requests.
  • CSS background-image for tiny decorative patterns.
  • Generated downloads (CSV, JSON, text files) — when the content is small.
  • Inline SVG icons used once.

When NOT to Use data: URLs

  • Large files — base64 encoding inflates size by ~33%, and the URL is cached as part of HTML (no separate cache).
  • Top-level navigation — Firefox blocks data: URLs from loading as top-level documents for security.
  • Files that change frequently — can't be cached independently.
  • Files over ~4KB — some browsers limit URL length.
Common Mistake — Security: Top-Level data: Navigation Firefox blocks top-level navigation to data: URLs (e.g., <a href="data:text/html,...">) since 2017. Chrome did the same in 2021. This prevents phishing attacks where a malicious data: URL impersonates a real site. Use data: only for inline resources (images, downloads) — never for navigation.

6 blob: URLs

Created by JavaScript, blob: URLs reference in-memory Blob objects. They're used for large generated files, video streaming, image uploads preview, and more.

<!-- Generate a CSV file in JS and offer it as a download -->
<a id="download-link">Download generated CSV</a>

<script>
  const csv = "Name,Email\nalice,alice@x.com\nbob,bob@x.com";
  const blob = new Blob([csv], { type: "text/csv" });
  const url = URL.createObjectURL(blob);

  const link = document.getElementById("download-link");
  link.href = url;
  link.download = "contacts.csv";

  // Important: revoke when no longer needed
  link.addEventListener("click", () => {
    setTimeout(() => URL.revokeObjectURL(url), 1000);
  });
</script>

Why blob: vs data:?

Aspectdata:blob:

Pro Tip — Always Revoke blob: URLs Each URL.createObjectURL() holds the Blob in memory until revoked. Long-running apps that create many blob URLs (e.g., photo galleries) will leak memory. Always call URL.revokeObjectURL(url) when done — typically after the download completes or the element is removed from the DOM.

Streaming Video with MediaSource + blob:

Video players (YouTube, Netflix) use MediaSource + blob: URLs to stream video chunks:

const mediaSource = new MediaSource();
const video = document.querySelector("video");
video.src = URL.createObjectURL(mediaSource);

mediaSource.addEventListener("sourceopen", () => {
  const sourceBuffer = mediaSource.addSourceBuffer('video/mp4; codecs="avc1.4d401e"');
  // ... append video chunks to sourceBuffer ...
});

8 Security Concerns

1. Phishing via data: URLs

A malicious data:text/html URL can render a fake login form. Modern browsers block top-level navigation to data: URLs to prevent this.

2. Spam Harvesting via mailto:

Email scrapers crawl websites for mailto: links. Common defenses:

  • Use a contact form instead.
  • Obfuscate the address with JS: store as data-user="hello" data-domain="example.com" and reconstruct on click.
  • Display as "hello [at] example [dot] com" — humans understand, scrapers miss.
<!-- JS-based email obfuscation -->
<a href="#" data-user="hello" data-domain="example.com"
   onclick="this.href='mailto:'+this.dataset.user+'@'+this.dataset.domain">
  Email us
</a>

3. tel: Premium Rate Fraud

Malicious sites may auto-dial premium-rate numbers via tel:. Mobile OSes now require user confirmation before dialing — but always display the number visibly so users can verify.

4. javascript: URLs = XSS Vector

Any time you accept user input and put it into a href, you risk XSS. Always sanitize URLs — only allow https:, mailto:, tel:, and known-safe schemes. Block javascript: entirely.

function sanitizeUrl(url) {
  try {
    const u = new URL(url);
    if (['https:', 'mailto:', 'tel:', 'sms:'].includes(u.protocol)) return url;
    return '#';
  } catch { return '#'; }
}

5. Blob: URL Lifetimes

Blob URLs persist for the page's lifetime. If a malicious script can grab a blob URL, it can access the underlying data (e.g., user-uploaded files). Use Content Security Policy to mitigate.

Common Mistake — CSP Without blob: Allowance If you set Content-Security-Policy: default-src 'self', blob URLs for media will be blocked. Add blob: explicitly where needed: media-src 'self' blob:.

9 Try It Yourself

Exercise 1 — Email with Body Build a mailto link to support@yoursite.com with subject "Bug report" and a body containing two paragraphs. URL-encode all special characters. Verify it opens in your email client with the fields pre-filled.
Exercise 2 — International Phone Write a clickable phone link for a Berlin office: +49 30 12345678. The display text should be in German format; the tel: value should be E.164.
Exercise 3 — Generated CSV via data: URL Create a link that downloads a CSV file with three rows of fake contact data. Use a data:text/csv URL with the download attribute. Verify the file opens correctly in a spreadsheet.
Exercise 4 — Blob URL Download Write JavaScript that builds a JSON object, converts it to a Blob, creates a blob: URL, and offers it as a download via an <a download>. Revoke the URL after the click.
Exercise 5 — URL Sanitizer Write a JavaScript function sanitizeUrl(input) that returns the URL if it uses a safe scheme (https, mailto, tel, sms) or '#' otherwise. Test with malicious inputs like javascript:alert(1).
Exercise 6 — WhatsApp Deep Link Build a "Share on WhatsApp" button that opens WhatsApp with the current page URL pre-filled as the message. Use the https://wa.me/ scheme. Test on mobile (it should open the WhatsApp app).

11 Real-World Use Cases

Click-to-Call CTAs

Restaurants, clinics, plumbers: phone numbers rendered as tel: links. Critical for mobile conversions.

Contact Forms Backup

Even with a contact form, a mailto: link in the footer is a fallback for users who prefer their email client.

SMS Opt-In

"Text JOIN to 12345" prompts: a sms: link pre-fills the message. Common in marketing.

Generated Reports

Browser-based tools (filters, charts, formatters) generate CSV/JSON and offer download via blob: URLs.

In-Line Tiny Images

1x1 tracking pixels, small icons, decorative SVG patterns — embedded as data: URLs to save HTTP requests.

Streaming Media

YouTube, Netflix use MediaSource + blob: URLs to stream video chunks adaptively.

Share Buttons

WhatsApp, Telegram, Signal deep links enable one-tap sharing — cross-platform reach.

Map Deep Links

geo: URLs open Google/Apple Maps at coordinates — useful for store locators and event pages.

12 Summary

  • mailto: opens email clients; supports subject, body, cc, bcc — all URL-encoded.
  • tel: opens dialers; always use E.164 format with + and country code.
  • sms: opens SMS apps; body parameter syntax varies between iOS and Android.
  • data: URLs embed small files inline; use only for images and small downloads — never top-level navigation.
  • blob: URLs reference in-memory Blobs; perfect for large generated files and streaming. Always revoke when done.
  • javascript: URLs are deprecated and insecure — use buttons instead.
  • Always URL-encode special characters in scheme parameters.
  • Sanitize user-input URLs to prevent XSS — only allow known-safe schemes.
  • Consider privacy (email scraping) and platform differences (SMS body syntax) when choosing schemes.
