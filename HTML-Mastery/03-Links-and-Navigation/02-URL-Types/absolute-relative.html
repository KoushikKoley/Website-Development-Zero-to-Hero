Section 3.4 · URL Types

Absolute vs Relative URLs

Every internal link on your site makes a choice: absolute (https://example.com/page) or relative (page.html, ./page, ../page, /page). Each style has tradeoffs in portability, SEO, performance, and developer experience. Let's settle it.

1 The Two URL Families

A URL is "absolute" if it includes everything needed to locate the resource on its own: scheme (https), host (example.com), and (optionally) port. A URL is "relative" if it's missing some of those pieces and must be resolved against a "base URL" (usually the current page's URL).

URLTypeStands Alone?
https://example.com/pageAbsoluteYes
//example.com/pageProtocol-relative (absolute-ish)No — needs scheme
/pageRoot-absolute (relative to domain root)No — needs host
page.htmlRelative (same dir)No
./page.htmlRelative (same dir, explicit)No
../page.htmlRelative (parent dir)No
?page=2Relative (modifies query only)No
#sectionFragment onlyNo

2 Absolute URLs

An absolute URL fully specifies the resource location. It works identically no matter where it's used — the same URL in a link, in an <img src>, in a CSS url(), or in an HTTP redirect will all resolve to the same destination.

<!-- Standard https absolute URL -->
<a href="https://example.com/about">About</a>
<a href="https://example.com/about?lang=en#team">Meet the team</a>

<-- With port (development server) -->
<a href="http://localhost:3000/admin">Dev admin</a>

<-- Subdomain absolute -->
<a href="https://blog.example.com/post-1">Read latest post</a>

Pros of Absolute URLs

  • Unambiguous — works the same regardless of where the link appears.
  • SEO-friendly — Google can fully canonicalize the URL.
  • Scraped/syndicated content — links still work when copied to other sites or RSS readers.
  • Email-safe — links work in HTML emails, where there's no "current page".

Cons of Absolute URLs

  • Verbose — repetitive for internal links.
  • Harder to migrate — every link must be rewritten if the domain changes.
  • Environment switching — links to https://staging.example.com/... must be changed for production.

3 Relative URLs

Relative URLs omit the scheme and host (and sometimes the path), relying on the current page's URL to fill in the gaps. They're shorter, more portable within a single site, and the standard for internal linking.

<!-- Same directory -->
<a href="contact.html">Contact</a>
<a href="./contact.html">Contact</a>  <!-- equivalent -->

<-- Up one directory -->
<a href="../index.html">Home</a>

<-- Up two directories, then into /products/ -->
<a href="../../products/widget.html">Widget</a>

<-- Root-absolute (preferred for internal links) -->
<a href="/products">All Products</a>

<-- Modify only the query string -->
<a href="?page=2">Next page</a>

<-- Modify only the fragment -->
<a href="#section-3">Jump to Section 3</a>

Pros of Relative URLs

  • Concise — shorter source code.
  • Portable — works on localhost, staging., www., and bare domains without change.
  • Migration-friendly — moving from example.com to example.org requires no link rewrites.
  • HTTPS upgrade-friendly — relative URLs inherit the current scheme, avoiding mixed-content warnings.

Cons of Relative URLs

  • Context-dependent — a link's destination depends on the page that contains it.
  • Scraping risk — if your content is scraped or RSS-syndicated, relative links may break.
  • Canonical ambiguity — Google may index example.com/page and example.com/page/ separately if relative links are inconsistent.

4 Four Relative Flavors

Relative URLs come in four distinct styles. Understanding the differences is critical:

SyntaxNameResolves To (current page: /blog/2024/post.html)
page.html or ./page.htmlSame-directory relative/blog/2024/page.html
../page.htmlParent-directory relative/blog/page.html
/page.htmlRoot-absolute (a.k.a. absolute path)/page.html
?key=valueQuery-only relative/blog/2024/post.html?key=value
#fragFragment-only relative/blog/2024/post.html#frag
page.html#fragPath + fragment/blog/2024/page.html#frag

The ./ Prefix

./page.html is identical to page.html. The ./ explicitly says "current directory". It's useful in two cases:

  • When you want to disambiguate from a fragment: ./about vs #about.
  • When working with bundlers or web frameworks that interpret the leading character differently.

The ../ Prefix

Each ../ moves one directory up. Multiple ../../../ chains are hard to read and prone to error. Prefer root-absolute (/path) over deep relative paths.

Common Mistake — Trailing Slash Matters /blog/ and /blog are different URLs in the eyes of the browser. /blog with no trailing slash usually 301-redirects to /blog/. If you link relatively from /blog/ vs /blog, your relative paths resolve differently:
  • From /blog/ + relative post.html → /blog/post.html ✓
  • From /blog + relative post.html → /post.html ✗ (probably a 404)

5 How Resolution Works

The browser resolves every relative URL by walking up from the current page's URL. Here's the algorithm in plain English:

  1. Take the base URL (current page URL, or the <base href> if set).
  2. Drop the fragment and query string.
  3. If the relative URL starts with /, replace the entire path.
  4. If it starts with ../, drop the last path segment; repeat for each ../.
  5. If it starts with ./ or no prefix, append to the current path's directory.
  6. Append any new query string or fragment.

Worked Example

Current page: https://shop.example.com/blog/2024/09/css-grid.html

../08/new-features.htmlhttps://shop.example.com/blog/2024/08/new-features.html
../../archive.htmlhttps://shop.example.com/blog/archive.html

6 The <base> Element

The <base> element in the <head> overrides the default base URL for all relative URLs on the page. It's powerful but rarely needed — and easy to misuse.

<!DOCTYPE html>
<html>
<head>
  <base href="https://cdn.example.com/v1/">
  <!-- All relative URLs now resolve against cdn.example.com/v1/ -->
</head>
<body>
  <img src="logo.png">  <!-- loads from https://cdn.example.com/v1/logo.png -->
  <a href="about.html">About</a>  <!-- navigates to https://cdn.example.com/v1/about.html -->
</body>
</html>

Attributes

  • href — the base URL (required for URL resolution).
  • target — default target for all links on the page (legacy, discouraged).
Common Mistake — Base Breaks In-Page Links If you set <base href="https://cdn.example.com/">, then <a href="#section"> no longer scrolls within the page — it navigates to https://cdn.example.com/#section. Same for <a href="page.html">. Use <base> cautiously; most modern sites don't need it.
Pro Tip If you must use <base>, also use root-absolute URLs (/section) for in-page navigation. That way they resolve against the actual domain, not the base.

7 SEO Implications

Google treats absolute and relative URLs the same in principle — both are followed and pass link equity. But there are practical SEO differences:

Canonical URL Clarity

If your site is accessible at example.com, www.example.com, https://, and http://, relative URLs work on all variants — but Google may index each as a separate URL. Use the <link rel="canonical"> tag to declare the canonical version:

<link rel="canonical" href="https://www.example.com/blog/post-1">

Scraping & Syndication

If your content is republished (RSS, partner sites, AI training data), absolute URLs preserve your links. Relative URLs may break or be replaced.

Crawl Efficiency

Googlebot follows both absolute and relative URLs equally. The crawler doesn't care.

ConcernAbsoluteRelative
Crawlability✓✓
Canonical clarityStrong — explicitWeak — relies on rel="canonical"
Scraped content survives✓✗
Domain migration✗ Every link must be rewritten✓ Just update the domain
Dev/staging/prod parity✗ Hard-coded domain✓ Identical across environments

8 Portability & Migration

Imagine migrating your blog from blog.example.com to example.com/blog:

  • Absolute URLs: every internal link must be rewritten. Thousands of edits, or a build script that knows the old/new domain.
  • Root-absolute URLs: /blog/post-1 works on both, assuming paths line up.
  • Same-dir relative URLs: works automatically, as long as file structure is preserved.

For static sites, GitHub Pages, Netlify, Vercel deploys, and dev/staging parity, relative or root-absolute is the safer choice.

Pro Tip — Use Build Tools for Absolute If you prefer absolute URLs for SEO but want portability, use a build variable: href="{process.env.SITE_URL}/blog/post-1". Your dev environment uses http://localhost:3000, production uses https://example.com. This is what Next.js, Hugo, Eleventy, and most SSGs do by default.

9 Performance Considerations

URL choice has minor performance implications:

  • URL length: shorter URLs save bytes in HTML. Relative saves the most.
  • Preconnect opportunities: absolute URLs to third-party origins let you <link rel="preconnect"> early.
  • Resource hints: preconnect, dns-prefetch, preload need absolute URLs to specific origins.
<!-- In <head>: warm up the connection before the browser needs it -->
<link rel="preconnect" href="https://cdn.example.com">
<link rel="dns-prefetch" href="https://fonts.googleapis.com">
<link rel="preload" href="/fonts/inter.woff2" as="font" type="font/woff2" crossorigin>

The deep dive on resource-hint rel tokens is in 04-Download-Links/link-types.html.

11 Modern Best Practice

For most modern web projects (Next.js, Astro, Eleventy, Hugo, plain static HTML), the recommendation is:

  1. Use root-absolute URLs (/about) for internal navigation.
  2. Use absolute URLs for <link rel="canonical">, Open Graph, hreflang, sitemaps.
  3. Use absolute URLs for any external link.
  4. Use fragment-only (#section) for in-page anchors.
  5. Avoid deep relative paths (../../../) — they're hard to read and fragile.
  6. Avoid protocol-relative URLs (//example.com) — use explicit https://.
  7. Don't use <base> unless you have a specific reason — it breaks fragment links and surprises maintainers.
Pro Tip — Use Absolute with Site URL Variable In a static site generator or framework, define SITE_URL as a config value. Templates output href="{{ SITE_URL }}/blog/post-1". Dev uses http://localhost:3000; prod uses https://example.com. Best of both worlds: SEO-friendly absolute URLs and full environment portability.

12 Try It Yourself

Exercise 1 — Resolve These URLs Current page: https://shop.example.com/blog/2024/09/post-1.html. Resolve each:
  1. post-2.html
  2. ../post-2.html
  3. /blog/post-2.html
  4. ../../post-2.html
  5. //shop.example.com/post-2.html
Exercise 2 — Convert a Site You have a static site at /home/user/mysite/ with index.html, about.html, and a blog/ subdir with post.html. Convert all internal links from absolute (https://example.com/...) to root-absolute (/...). Verify nothing breaks when deployed to https://staging.example.com/.
Exercise 3 — <base> Pitfall Create a page with <base href="https://cdn.example.com/v1/"> in the head. Add: (a) an <img src="logo.png"> that loads from the CDN, (b) an in-page <a href="#top"> link. Click the in-page link — observe that it navigates to the CDN. Fix it without removing the <base>.
Exercise 4 — Trailing Slash Trap Set up two pages: /dir/ (with trailing slash, serves index) and /dir (without, also serves index — your server treats them as equivalent). Put a relative link <a href="page.html"> on each. Verify that one resolves to /dir/page.html and the other to /page.html. Add <link rel="canonical"> to fix SEO duplication.
Exercise 5 — Build-Tool Pattern In a templating language of your choice (Handlebars, Jinja, EJS), set up a site_url variable. Write a partial that outputs <a href="{{ site_url }}/about">. Configure site_url differently for dev (http://localhost:3000) and prod (https://example.com).

14 Real-World Use Cases

Static Sites (GitHub Pages, Netlify)

Root-absolute (/about) is the standard. Deploy to multiple domains without changes.

Next.js / React Router

Frameworks use root-absolute under the hood: <Link href="/about">. Absolute URLs only for SEO meta tags.

WordPress

Default behavior: absolute URLs in database. Site URL change = mass search/replace. Use a plugin like "Better Search Replace" to migrate.

Email HTML

Always absolute. Email clients strip context; relative URLs silently fail.

Canonical Tags

Must be absolute per Google's spec: <link rel="canonical" href="https://example.com/page">.

Open Graph

og:url, og:image must be absolute. Otherwise scrapers (Facebook, Slack) won't render previews.

RSS Feeds

Always absolute — feed readers extract content脱离 your site context.

PDF Generation

When generating PDFs from HTML, internal links should be absolute (or use relative links relative to the PDF's source URL).

15 Summary

  • Absolute URLs include scheme + host; relative URLs omit them and resolve against the current page.
  • Four relative flavors: same-dir (page.html), parent (../page.html), root-absolute (/page.html), query-only (?key=value).
  • ./page.html ≡ page.html; both resolve to same directory.
  • Trailing slashes matter: /blog vs /blog/ differ for relative resolution.
  • <base> overrides the base URL — but breaks fragment links; avoid in modern sites.
  • For internal links, prefer root-absolute (/about) — portable and concise.
  • For canonical, Open Graph, RSS, emails, and external sites — use absolute.
  • Use a build-time SITE_URL variable for absolute URLs in templated sites.
  • Avoid deep ../../../ paths and protocol-relative // URLs.
