The <template> Element

Define reusable chunks of HTML that the browser parses but does not render. Scripts inside don't run, images don't load, styles don't apply — until you clone the template's contents into the live document.

1 What is <template>?

The <template> element holds HTML markup that the browser parses into a DocumentFragment but keeps inert: nothing inside is rendered, no script runs, no image is fetched, no stylesheet is applied. The contents live in a separate "template contents" fragment until you explicitly clone them into the document.

<template id="user-card">
  <div class="user-card">
    <img src="" alt="" class="avatar">
    <div>
      <h3 class="name"></h3>
      <p class="email"></p>
    </div>
  </div>
</template>

When the page loads, nothing visible appears — the browser parses the markup but never paints it.

2 Why It's Inert

Three guarantees the platform makes about content inside <template>:

ResourceBehavior inside template
HTML renderingNot painted. <template> has display: none by default.
<script>Does not execute. The parser stores it as inert text.
<img>, <video>, <iframe>Network requests are not made until the node is cloned into the live DOM.
<style> and CSSRules do not apply to the document.
<form> controlsNot validated, not submitted, not reset.
Pro Tip The "no image loading" guarantee is huge for performance. A 50-item list rendered with templates cloned on demand will not download 50 avatars upfront — only the ones you actually clone.

3 The .content Property

Every <template> element exposes a content property — a DocumentFragment containing all its children. You can read it like a normal DOM node:

const tpl = document.getElementById('user-card');
const frag = tpl.content;
console.log(frag.querySelector('.name'));  // <h3 class="name"></h3>
console.log(frag.children.length);         // 1 — the outer <div>

Directly appending the fragment to the live document empties it — fragments are move-once nodes. To use a template multiple times, you must clone the fragment.

4 Cloning with cloneNode(true)

function renderUser(user) {
  const tpl  = document.getElementById('user-card');
  const clone = tpl.content.cloneNode(true);   // deep clone
  clone.querySelector('.avatar').src   = user.avatar;
  clone.querySelector('.avatar').alt   = user.name;
  clone.querySelector('.name').textContent  = user.name;
  clone.querySelector('.email').textContent = user.email;
  document.getElementById('user-list').appendChild(clone);
}

const users = [
  { name: 'Ada Lovelace',   email: 'ada@analyticalengine.org',  avatar: 'ada.jpg'  },
  { name: 'Alan Turing',    email: 'alan@enigma.io',            avatar: 'alan.jpg' },
  { name: 'Grace Hopper',   email: 'grace@cobol.dev',           avatar: 'grace.jpg' }
];

users.forEach(renderUser);

Common Mistake Forgetting true in cloneNode(true) produces a shallow clone — only the top-level fragment node, with none of its children. Always pass true when cloning a template.

5 vs the <script type="text/template"> Pattern

Before <template> shipped (2013+), the community used a hack: stash markup inside a <script> tag with a non-executable type.

<script type="text/template" id="user-card">
  <div class="user-card">...</div>
</script>

<script>
  const html = document.getElementById('user-card').textContent;
  const div = document.createElement('div');
  div.innerHTML = html;
  document.body.appendChild(div);
</script>
Concern<script type="text/template"><template>
Parsed as HTML?No — text onlyYes — proper DocumentFragment
Requires manual innerHTML?YesNo — clone directly
SanitizationRisky — string concat enables XSSSafe — nodes already parsed
Re-parsing costPer renderOnce at page load
Recommended today?NoYes
Common Mistake Using <script type="text/template"> in 2025 codebases. Reach for <template> first; if you find yourself building strings, consider TrustedTypes or a sanitization library like DOMPurify.

6 Pattern: Repeated UI from Data

<template id="todo-row">
  <li class="todo">
    <input type="checkbox" class="todo-check">
    <label class="todo-text"></label>
    <button class="todo-delete" aria-label="Delete">×</button>
  </li>
</template>

<ul id="todo-list"></ul>

<script>
  const todos = [
    { id: 1, text: 'Write blog post', done: false },
    { id: 2, text: 'Review pull request', done: true },
    { id: 3, text: 'Refactor utils module', done: false }
  ];

  const list = document.getElementById('todo-list');
  const tpl  = document.getElementById('todo-row');

  todos.forEach(todo => {
    const node = tpl.content.cloneNode(true);
    const li = node.querySelector('li');
    li.dataset.id = todo.id;
    li.querySelector('.todo-check').checked = todo.done;
    li.querySelector('.todo-text').textContent = todo.text;
    li.classList.toggle('done', todo.done);
    list.appendChild(node);
  });
</script>
Pro Tip This "template + map" pattern is the foundation of vanilla-JS data binding. Many framework features — React's .map, Vue's v-for, Svelte's {#each} — are abstractions on top of this same idea.

7 Web Component Templates

The most common production use of <template> today is inside Custom Elements, providing the shadow DOM structure without re-parsing strings on every instance.

<template id="my-modal-tpl">
  <style>
    :host { display: none; }
    :host([open]) { display: block; }
    .backdrop { position: fixed; inset: 0; background: rgba(0,0,0,0.5); }
    .panel { background: white; padding: 24px; max-width: 480px;
              margin: 80px auto; border-radius: 12px; }
  </style>
  <div class="backdrop"></div>
  <div class="panel">
    <h2><slot name="title">Modal</slot></h2>
    <slot></slot>
  </div>
</template>

<script>
  class MyModal extends HTMLElement {
    constructor() {
      super();
      const root = this.attachShadow({ mode: 'open' });
      const tpl = document.getElementById('my-modal-tpl');
      root.appendChild(tpl.content.cloneNode(true));
    }
  }
  customElements.define('my-modal', MyModal);
</script>

Notice that the same template serves every instance — the browser parsed it once at page load, and cloning the fragment is a cheap operation.

8 Browser Support

Chrome 26+ Firefox 22+ Safari 8+ Edge 12+ Universal since 2014

The element is so well supported that you can rely on it without polyfilling in any modern project. The HTML <template> feature works back to IE 11 with a small polyfill, though it is rarely worth the effort today.

9 Common Mistakes

  • Appending tpl.content directly without cloning. The fragment is moved, not copied — your template becomes empty after the first use.
  • Using cloneNode(false). Produces an empty fragment. Always pass true.
  • Putting <script> tags inside a template expecting them to run when cloned. They do not. The browser marks them as already-parsed and inert. If you need a script to run after cloning, you must re-create it via document.createElement('script') or use new Function (with care).
  • Expecting <style> inside a template to apply once cloned into a shadow root. It will — but only after cloning. Style the shadow root directly.
  • Storing large data inside templates. Templates are for markup, not data. Use JSON in a <script type="application/json"> tag if you need to ship data inline.
  • Nesting templates incorrectly. A nested template's content lives in its own fragment; you must clone each level separately.

10 Try It Yourself

Exercise 1 — First template Create a <template> with a single <p>Hello</p>. Verify in the Network panel that no request fires. Then clone it into the body via a button click.
Exercise 2 — User list Build the user-card example from section 4 with three real users. Use a single template cloned three times. Inspect the cloned nodes in DevTools to confirm they are independent instances.
Exercise 3 — Image laziness Put an <img src="large.jpg"> inside a template. Open DevTools Network panel and reload the page. Confirm the image is NOT requested. Then clone the template — the image should now fetch.
Exercise 4 — Todo list Build the todo-row template from section 6. Add a button that adds a new todo from a text input. Confirm the same template is reused for each row.
Exercise 5 — Template in a custom element Build a <toast-notification> custom element that clones its markup from a <template> into a shadow root. Spawn three toasts with different messages on a button click.

11 Real-World Use Cases

List rendering

Render repeating list items from a JSON API without a templating library.

Web components

Define the shadow DOM structure once, clone into each instance.

Modal & dialog content

Hold dialog markup until first open, deferring heavy DOM creation.

Email clients

Per-message templates rendered on demand as the user scrolls.

Admin tables

Row templates reused for hundreds of paginated records.

SSR hydration

Server ships a template containing interactive markup; client clones it into the right place once JS loads.
