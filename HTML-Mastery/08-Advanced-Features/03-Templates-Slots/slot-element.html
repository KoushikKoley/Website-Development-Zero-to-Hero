The <slot> Element

Slots let consumers inject their own children into a component's shadow tree at designated points. Default slots, named slots, fallback content, the slot attribute, and the slotchange event — the full composition story.

1 The Composition Model

Shadow DOM hides internal structure, but you usually want consumers to provide some content (button labels, modal titles, list items). Slots are the bridge: they declare named insertion points inside the shadow tree. The browser takes the consumer's "light DOM" children and projects them into the matching slots at render time.

The model is called composition because the final rendered tree is a composition of the shadow tree (the component's own structure) and the light tree (the consumer's children). The two trees never actually merge in memory — only the rendering is composed.

Pro Tip Slotted children are not moved into the shadow root. They remain in the light DOM and you can still reach them with element.children. The browser just visually places them inside their slot's location.

2 Default Slot

A slot without a name attribute is the default — every light DOM child without an explicit slot attribute lands here.

<!-- Shadow DOM -->
<style>
  .box { border: 2px solid #2563eb; padding: 16px; border-radius: 12px; }
</style>
<div class="box">
  <slot></slot>
</div>
<!-- Consumer markup -->
<my-box>
  <p>Anything I put here shows up in the box.</p>
  <p>Including multiple paragraphs.</p>
</my-box>

3 Named Slots

A slot with name="header" only accepts children carrying slot="header".

<!-- Shadow DOM -->
<article>
  <header><slot name="title"></slot></header>
  <main><slot></slot></main>
  <footer><slot name="actions"></slot></footer>
</article>
<!-- Consumer markup -->
<my-article>
  <h2 slot="title">Big News Today</h2>
  <p>This is the body content — lands in the default slot.</p>
  <button slot="actions">Share</button>
  <button slot="actions">Save</button>
</my-article>

Multiple children with the same slot name are all projected — order in the light DOM is preserved.

4 Fallback Content

Anything you place inside a <slot> tag is shown when no consumer provides matching content. This is your component's default markup.

<slot name="avatar">
  <img src="default-avatar.png" alt="Default user">
</slot>

<slot name="title">Untitled</slot>

If the consumer passes <img slot="avatar" src="jane.png">, the default avatar is replaced entirely. If they pass nothing, the fallback renders.

5 The slot Attribute on Children

The slot attribute is a global attribute that tells the browser which named slot this child belongs to. It only has effect on direct children of the host element.

<my-card>
  <img slot="media" src="photo.jpg" alt="">        <!-- routed to slot="media" -->
  <h3 slot="title">Sunset Over the Bay</h3>       <!-- routed to slot="title" -->
  <p>A description goes here.</p>                  <!-- default slot -->
</my-card>
Common Mistake The slot attribute only works on direct children of the host. If you nest the slotted element inside another wrapper, it will land in the default slot — not the named one. Wrap children with display: contents if you need a structural wrapper that is invisible to the slot routing.

6 The slotchange Event

Whenever the set of nodes assigned to a slot changes (children added, removed, or their slot attribute changed), the slot fires a slotchange event. Listen on the slot itself inside the shadow root.

class LiveList extends HTMLElement {
  constructor() {
    super();
    const root = this.attachShadow({ mode: 'open' });
    root.innerHTML = `
      <ul><slot></slot></ul>
    `;
    const slot = root.querySelector('slot');
    slot.addEventListener('slotchange', () => {
      const items = slot.assignedElements();
      console.log(`List now has ${items.length} items`);
    });
  }
}
customElements.define('live-list', LiveList);

Two helper methods retrieve the assigned nodes:

  • slot.assignedNodes() — all nodes (including text nodes).
  • slot.assignedElements() — only Element children (usually what you want).

Pass { flatten: true } to recursively resolve nested slots inside other shadow trees.

7 Building a Card Component with Named Slots

Let's bring it all together — a card component with media, title, subtitle, body, and action slots.

<template id="card-template">
  <style>
    :host { display: block; font-family: inherit; }
    .card { border: 1px solid #e2e8f0; border-radius: 12px;
            overflow: hidden; background: white;
            box-shadow: 0 4px 12px rgba(2,6,23,0.06); }
    .media { height: 160px; background: linear-gradient(135deg, #2563eb, #7c3aed);
              display: flex; align-items: center; justify-content: center; color: white; }
    .body  { padding: 16px; }
    .title { margin: 0 0 4px; font-size: 1.25rem; color: #0f172a; }
    .subtitle { margin: 0 0 8px; font-size: 0.85rem; color: #64748b; }
    .actions { padding: 12px 16px; border-top: 1px solid #e2e8f0;
                display: flex; gap: 8px; justify-content: flex-end; }
    .actions ::slotted(button) {
      background: #2563eb; color: white; border: 0;
      padding: 6px 12px; border-radius: 6px; cursor: pointer;
    }
  </style>
  <div class="card">
    <div class="media">
      <slot name="media"><span>No image</span></slot>
    </div>
    <div class="body">
      <h3 class="title"><slot name="title">Untitled card</slot></h3>
      <p class="subtitle"><slot name="subtitle"></slot></p>
      <div><slot></slot></div>
    </div>
    <div class="actions"><slot name="actions"></slot></div>
  </div>
</template>

<script>
  class MyCard extends HTMLElement {
    constructor() {
      super();
      const root = this.attachShadow({ mode: 'open' });
      const tpl = document.getElementById('card-template');
      root.appendChild(tpl.content.cloneNode(true));
    }
  }
  customElements.define('my-card', MyCard);
</script>

Consumer usage:

<my-card>
  <img slot="media" src="sunset.jpg" alt="Sunset">
  <span slot="title">Sunset Over the Bay</span>
  <span slot="subtitle">Photographed by Mara O.</span>
  <p>A serene evening light over Bristol harbour.</p>
  <button slot="actions">Share</button>
  <button slot="actions">Save</button>
</my-card>

<my-card>
  <!-- Empty: all defaults render -->
</my-card>

8 Styling Slotted Content

Slotted children live in the light DOM, but you can style them from inside the shadow root using the ::slotted() pseudo-element.

/* Inside shadow root */
::slotted(p) {
  margin: 0 0 8px;
  color: #334155;
}

::slotted(.featured) {
  font-weight: 600;
  background: #fef3c7;
}
Common Mistake ::slotted() only matches top-level slotted elements, never descendants. ::slotted(.card .title) does not work. Style descendants by setting a class on the slotted element and letting consumer CSS handle inner styles.

9 Browser Support

Chrome 53+ Firefox 63+ Safari 10+ Edge 79+

Slots are universally supported in modern browsers. The legacy "Shadow DOM v0" spec had different slot semantics (<content select="…">) — long deprecated, do not use.

10 Common Mistakes

  • Putting slot on a grandchild. Slots route only direct children of the host.
  • Forgetting fallback content. Empty slots look broken. Always provide sensible defaults.
  • Trying to style slotted descendants with ::slotted(). It only matches the top-level slotted element.
  • Using document.querySelector to find slotted children inside the shadow root. They are not there — they live in the light DOM. Use this.children on the host, or slot.assignedElements() inside the shadow.
  • Expecting slotchange to fire on initial render. It does fire on first assignment, so be ready.
  • Mixing name on the slot with slot="…" on a default child. A child without a slot attribute goes to the default (unnamed) slot, regardless of what named slots exist.

11 Try It Yourself

Exercise 1 — Hello slot Create a custom element with a default slot. Pass text and an image as children; confirm both appear.
Exercise 2 — Named slots Build the <my-card> from section 7. Provide markup for two cards: one fully populated and one with only a title (all other slots should show fallback content).
Exercise 3 — slotchange logger Build a <live-list> with a slot. Add a button that programmatically appends a new <li> child via appendChild. Confirm the slotchange event fires and the count updates.
Exercise 4 — Slotted styling Add a ::slotted(.highlight) rule inside your shadow root. Add class="highlight" to one of the slotted children and confirm it styles only that one.
Exercise 5 — display: contents wrapper Wrap a slotted child in a <div style="display: contents"> and verify that the slot attribute on the inner element still routes correctly to the named slot.

12 Real-World Use Cases

Card layouts

Media object, title, body, and action slots — the canonical card pattern.

Modals & dialogs

Title, body, and footer action slots let consumers provide their own buttons.

App shells

Header, sidebar, main slots in a layout web component reused across pages.

Toolbars

Left/right slot groups let consumers add buttons without learning new APIs.

Data tables

Cell slots per column let teams inject custom renderers.

Page builders

Slot-based zones (header, hero, main, footer) let marketing teams compose pages from blocks.
