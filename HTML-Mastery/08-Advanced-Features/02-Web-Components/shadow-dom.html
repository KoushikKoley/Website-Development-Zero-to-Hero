Shadow DOM — attachShadow & Encapsulation

Attach a private, scoped subtree to any element. CSS inside the shadow root never leaks out; CSS outside never leaks in. The DOM inside is hidden from querySelector on the host document. The basis for real component isolation on the web.

1 Why Shadow DOM?

CSS's global namespace is the single biggest source of fragility in front-end code. One stray p { margin: 0 } rule can break layouts across thousands of pages. Shadow DOM solves this by giving an element its own shadow tree: a separate DOM that the browser treats as if it lived in its own document. Styles inside the shadow root cannot escape, and styles outside cannot reach in.

Shadow DOM also gives you a place to put private structure — buttons, icons, internal layout divs — without polluting the host document's tree. Consumers see a tidy <my-tooltip> tag; the internal SVG and floating logic are nobody's business.

Pro Tip Shadow DOM is independent of Custom Elements — you can attach a shadow root to a plain <div> via JavaScript. But 95% of real usage is inside a Custom Element's constructor.

2 attachShadow Basics

class FancyButton extends HTMLElement {
  constructor() {
    super();
    const shadow = this.attachShadow({ mode: 'open' });
    shadow.innerHTML = `
      <style>
        button {
          background: linear-gradient(135deg, #2563eb, #7c3aed);
          color: white; border: 0; padding: 10px 18px;
          border-radius: 10px; font-weight: 600; cursor: pointer;
        }
        button:hover { filter: brightness(1.1); }
      </style>
      <button><slot>Click me</slot></button>
    `;
  }
}
customElements.define('fancy-button', FancyButton);
<fancy-button>Save changes</fancy-button>
<fancy-button>Delete</fancy-button>

Anatomy of a shadow tree

  • Host element — the element the shadow root is attached to (e.g. <fancy-button>).
  • Shadow root — the special node returned by attachShadow. Has mode 'open' or 'closed'.
  • Shadow tree — the children you place inside the shadow root.
  • Light DOM — the children the consumer places inside the host tag (the "Save changes" text above). These get projected into <slot> elements.

Common Mistake Choosing closed thinking it provides security. It does not — a determined attacker can still reach the shadow tree via DevTools overrides or by intercepting attachShadow before your script runs. Use closed only to signal "this is private API"; use real authorization on the server for actual security.

Most production web components — including those in major design systems — use open because tests and integrators need access.

4 CSS Scoping Rules

Three rules govern styles in shadow DOM:

  1. Outer styles don't apply inside (with rare exceptions like inherit-able properties such as color and font-family).
  2. Inner styles don't leak out. A button { background: red } inside the shadow root will not affect buttons outside.
  3. Selector lists cross the shadow boundary only when they explicitly pierce it, using :host, ::part(), or ::slotted().
/* Outside the shadow root: this NEVER reaches <button> inside */
button { background: red; }   /* no effect on fancy-button's button */

/* The shadow root's style block is the only place that styles its button */

CSS Custom Properties DO cross

CSS custom properties inherit through the shadow boundary. This is the standard mechanism for theming components.

/* Consumer's global stylesheet */
:root {
  --brand-color: #16a34a;
}

/* Inside the component's shadow root */
button {
  background: var(--brand-color);  /* picks up the green from outside */
  color: white;
}

5 The :host Selector Family

/* Match the host element itself */
:host {
  display: inline-block;
}

/* Match only when host has a specific class */
:host(.dark) {
  background: #0f172a; color: #f8fafc;
}

/* Match only when an ancestor matches (NOT a descendant!) */
:host-context(.theme-dark) {
  --text-color: #f8fafc;
}
Common Mistake :host-context() is a Chrome/Safari feature that Firefox has historically not shipped. Avoid relying on it; pass theme info through attributes or custom properties instead.

::part() — punching selective holes

By default the outside world cannot style anything inside your shadow root. ::part() lets you expose specific inner elements that you have tagged with a part attribute.

/* Inside shadow root */
<div part="panel">Hello</div>

/* Outside (consumer CSS) */
my-widget::part(panel) {
  background: pink;
  border-radius: 8px;
}

6 Slots — Light DOM Projection

The <slot> element is the bridge between the consumer's light DOM and your shadow DOM. It says "render whatever children the user put inside my host tag, right here."

<!-- Component definition -->
<template id="card-template">
  <style> .card { border: 1px solid #ddd; padding: 16px; border-radius: 12px; } </style>
  <div class="card">
    <h3><slot name="title">Default Title</slot></h3>
    <div><slot>Default body text.</slot></div>
  </div>
</template>
<!-- Consumer markup -->
<my-card>
  <span slot="title">Project Update</span>
  <p>We shipped 12 stories this sprint.</p>
</my-card>

Children without a slot attribute land in the default slot (the one with no name). Named children route to matching named slots.

If the consumer provides no children, the slot's fallback content (whatever is inside <slot>…</slot>) is shown instead.

7 Combining with <template>

The <template> element gives you an inert, parsed-but-not-rendered chunk of markup. Cloning a template into a shadow root is the cleanest way to set up a component's structure.

<template id="weather-card">
  <style>
    :host { display: block; }
    .card { padding: 16px; border-radius: 12px;
            background: linear-gradient(135deg, #38bdf8, #6366f1); color: white; }
  </style>
  <div class="card">
    <p><slot name="city">Unknown city</slot></p>
    <p class="temp">--°C</p>
  </div>
</template>

<script>
  class WeatherCard extends HTMLElement {
    constructor() {
      super();
      const root = this.attachShadow({ mode: 'open' });
      const tpl  = document.getElementById('weather-card');
      root.appendChild(tpl.content.cloneNode(true));
    }
    connectedCallback() {
      // update the temperature via an API call, then:
      this.shadowRoot.querySelector('.temp').textContent = '21°C';
    }
  }
  customElements.define('weather-card', WeatherCard);
</script>
Pro Tip Always use template.content.cloneNode(true) rather than shadow.innerHTML = '…' when your markup is complex. innerHTML re-parses the string each time the constructor runs; templates are parsed once by the HTML parser.

8 Inspecting Shadow DOM in DevTools

Chrome, Edge, and Firefox DevTools all reveal shadow trees when you enable the right setting:

  • Chrome / Edge: DevTools → Settings (gear) → Preferences → Elements → check "Show user agent shadow DOM".
  • Firefox: Settings → Inspector → check "Show Browser Styles" and look for the #shadow-root node in the tree.
  • Safari: The Elements tab shows #shadow-root (open) nodes inline.

Once enabled, you'll see a #shadow-root node expandable like any other, with full style inspection and event listeners.

9 When to Use Shadow DOM

Use it when…

You're building a reusable widget that could be dropped into many sites with different CSS. You want guarantees that your visual style won't be clobbered.

Skip it when…

Your markup is the page's main content (articles, headings, navigation). Shadow DOM hides content from some crawlers and accessibility tools, and prevents global styles from reaching it.

Caveat — SEO & a11y

Content in a closed shadow root is not indexed by most crawlers. Keep primary content in light DOM; use shadow DOM for chrome (controls, panels, decorations).

Caveat — forms

Form controls inside a shadow root do not participate in the outer form by default. Use the ElementInternals API to wire them up.

10 Try It Yourself

Exercise 1 — Encapsulated button Build <neon-button> with a shadow root, internal <style>, and a glow effect. Drop two of them on a page that also has a global button { background: red } rule. Confirm the global rule does not leak in.
Exercise 2 — Theme via custom property Define --neon-color in your consumer CSS, read it inside the shadow root, and confirm the button color changes when you toggle a class on :root.
Exercise 3 — Named slots Build a <profile-card> with three named slots: avatar, name, bio. Author markup that fills all three, and a second instance that only fills name to confirm the other slots show fallback content.
Exercise 4 — Template-driven Move your shadow DOM markup into a <template> element and clone it via content.cloneNode(true). Use the Network panel to confirm no extra HTML requests are made.
Exercise 5 — Inspect & experiment Enable "Show user agent shadow DOM" in Chrome DevTools. Inspect the native <video> element to find its shadow root, and try overriding ::part() styles on the play button.

11 Real-World Use Cases

Design systems

Ship components immune to host-page CSS — perfect for embedded widgets and SaaS embeds.

Browser built-ins

The native <video> controls, <input type="range"> thumb, and <details> marker are all shadow DOM.

Third-party widgets

Disqus comments, Stripe payment iframe, Twitter embed buttons all isolate their styles.

Editor surfaces

Rich-text editors (ProseMirror, TipTap, Quill) use shadow boundaries for floating menus.

Micro-frontends

Independent teams' UIs can coexist without CSS clashes.

White-label theming

Custom properties crossing the boundary let one component serve many brands.
