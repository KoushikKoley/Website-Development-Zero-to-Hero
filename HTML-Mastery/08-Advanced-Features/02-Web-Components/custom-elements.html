Custom Elements — customElements.define()

Define your own HTML tags with a single JavaScript call. The Custom Elements API is the foundation of every web component — autonomous custom tags like <my-tabs> and upgraded native elements like <button is="my-button">.

1 Why Custom Elements?

The platform already ships dozens of elements, but teams repeatedly build the same handful of patterns: tabbed interfaces, modals, toggles, accordions, toasts, date pickers. Custom Elements let you encapsulate those patterns behind a tag name that any team member — or any framework — can use without reading the source.

A custom element is just a JavaScript class that extends HTMLElement (or a specific built-in), registered with a name via customElements.define(). From that point on, the parser treats your tag as a first-class citizen: it works in innerHTML, in templates, in JSX, in Markdown that allows raw HTML, in server-rendered output — everywhere.

Pro Tip Custom elements are framework-agnostic. The same <my-date-picker> works inside React, Vue, Svelte, Angular, plain HTML, and server-rendered templates without adaptation. This is the key reason design systems increasingly ship as web components.

2 Defining an Element

The minimum viable custom element has two parts: an ES class extending HTMLElement, and a call to customElements.define() with a tag name.

class TimePill extends HTMLElement {
  connectedCallback() {
    const now = new Date();
    this.textContent = now.toLocaleTimeString();
  }
}

customElements.define('time-pill', TimePill);

Now you can use it anywhere in your HTML:

<p>The current time is <time-pill></time-pill>.</p>

Naming rules

  • The tag name must contain a hyphen (e.g. time-pill, my-tabs). This guarantees your name can never clash with current or future HTML elements.
  • Letters must be lowercase ASCII.
  • The class name can be anything — only the tag name is constrained.
  • Re-defining an existing name throws NotSupportedError.

3 Autonomous vs Customized Built-in Elements

There are two flavors of custom element, each created differently:

FlavorExtendsUsage in HTMLBehavior inherited
AutonomousHTMLElement<my-tag>Generic div-like behavior
Customized built-ine.g. HTMLButtonElement<button is="my-button">Full native behavior of the base tag

Customized built-in example

class LoadingButton extends HTMLButtonElement {
  connectedCallback() {
    this.addEventListener('click', async () => {
      this.disabled = true;
      const original = this.textContent;
      this.textContent = 'Saving…';
      // simulate async work
      await new Promise(r => setTimeout(r, 1200));
      this.textContent = original;
      this.disabled = false;
    });
  }
}

customElements.define('loading-button', LoadingButton,
                       { extends: 'button' });
<button is="loading-button">Save</button>
Browser Support Caveat Safari historically refused to implement customized built-in elements. As of recent Safari versions, support exists but check your target browsers. Workarounds include using autonomous elements wrapping a native button inside a shadow root.

4 Lifecycle Callbacks

The platform calls four "reaction" methods on your class at specific moments. Override them to do work.

CallbackWhen it firesTypical use
constructor()Element instantiated (before attributes/children exist)Set up internal state, attach shadow root. Never read attributes here.
connectedCallback()Inserted into the DOMFetch data, start timers, add global listeners, render.
disconnectedCallback()Removed from the DOMStop timers, release references, clean up listeners.
attributeChangedCallback(name, old, new)An observed attribute changedRe-render when props change.
adoptedCallback()Moved to a new document (e.g. via an <iframe> adoption)Rare. Re-bind document-scoped listeners.

Full lifecycle demo

class MyCounter extends HTMLElement {
  static get observedAttributes() { return ['count']; }

  constructor() {
    super();               // ALWAYS call super() first
    this._shadow = this.attachShadow({ mode: 'open' });
    this._shadow.innerHTML = `
      <style>
        :host { display: inline-block; padding: 8px 14px;
                 border-radius: 8px; background: #2563eb; color: white;
                 font-weight: 600; cursor: pointer; user-select: none; }
      </style>
      <span><slot name="label">Count</slot>: <span class="n">0</span></span>
    `;
    this._n = this._shadow.querySelector('.n');
    this.addEventListener('click', () => {
      this.count = (this.count || 0) + 1;
    });
  }

  // Reflect the count attribute to a JS property for ergonomics
  get count() { return Number(this.getAttribute('count')) || 0; }
  set count(v) { this.setAttribute('count', String(v)); }

  attributeChangedCallback(name, oldV, newV) {
    if (name === 'count' && this._n) this._n.textContent = newV;
  }

  connectedCallback() {
    console.log('my-counter attached');
    this._n.textContent = String(this.count);
  }
  disconnectedCallback() { console.log('my-counter detached'); }
  adoptedCallback()      { console.log('my-counter adopted'); }
}

customElements.define('my-counter', MyCounter);
<my-counter count="3"></my-counter>
<my-counter><span slot="label">Clicks</span></my-counter>

5 observedAttributes

For performance, the browser does not watch every attribute. It only calls attributeChangedCallback for attributes listed in a static getter:

static get observedAttributes() {
  return ['open', 'disabled', 'value'];
}
Common Mistake Authors forget the static getter and wonder why attribute changes do nothing. Without observedAttributes, the callback never fires — silently.

Reflecting attributes to properties

It's idiomatic to mirror each attribute to a JavaScript property so consumers can use either API:

get open() { return this.hasAttribute('open'); }
set open(v) {
  if (v) this.setAttribute('open', '');
  else   this.removeAttribute('open');
}

6 customElements.whenDefined()

Returns a Promise that resolves when a given tag name is registered. Useful when you depend on another component's API:

// Wait until <my-charts> is upgraded before configuring it
customElements.whenDefined('my-charts').then(() => {
  document.querySelector('my-charts').configure({ theme: 'dark' });
});

This avoids the "FOUC" problem of calling methods on elements whose class hasn't loaded yet.

7 HTML-First Authoring

Although custom elements require a small amount of JavaScript to register, you should design the markup contract first. Ask: what attributes does the element accept? What does its default content look like? What events does it emit? The HTML contract is what consumers interact with — JS is the implementation.

<!-- Author-facing API of a hypothetical <my-modal> -->
<my-modal open>
  <h2 slot="title">Confirm deletion</h2>
  <p>Are you sure? This cannot be undone.</p>
  <button slot="footer" data-action="cancel">Cancel</button>
  <button slot="footer" data-action="confirm">Delete</button>
</my-modal>

This markup must work even before the script tag runs (progressive enhancement). When the class upgrades the element, the existing children should be slotted into the shadow DOM rather than wiped.

8 Browser Support

Chrome 54+ Edge 79+ Firefox 63+ Safari 10.1+ (autonomous) Safari — customized built-in: partial / polyfill needed

For legacy browsers, include the custom-elements polyfill as a feature-detection shim. It uses MutationObserver to upgrade elements retroactively.

9 Common Mistakes

  • Forgetting super() in the constructor. Throws immediately.
  • Reading attributes in the constructor. Attributes are not guaranteed present yet. Use connectedCallback or attributeChangedCallback.
  • Not implementing observedAttributes. Your callback silently never fires.
  • Tag name without a hyphen. customElements.define('tabs', …) throws SyntaxError.
  • Defining twice. The second call throws NotSupportedError. Guard with if (!customElements.get('my-tag')).
  • Heavy work in connectedCallback without guards. The element may connect/disconnect many times (e.g. during re-renders). Idempotent setup avoids leaks.
  • Forgetting to clean up in disconnectedCallback. Listeners attached to window or document will leak.
  • Using arrow functions as class methods. Class fields with arrows create per-instance methods — fine, but they break inheritance. Use regular methods and .bind(this) or arrow-bound listeners at call sites.

10 Try It Yourself

Exercise 1 — Hello world element Create <hello-world> whose connectedCallback sets this.textContent = "Hello, world!". Use it in a page. Verify it works inside innerHTML assignments.
Exercise 2 — Reactive count Build the <my-counter> shown in section 4. Add a button that programmatically sets el.count = 10 and confirm the visible number updates without you calling a render method.
Exercise 3 — Customized button Define a customized built-in <button is="copy-button"> that copies data-target's text content to the clipboard on click and shows a temporary "Copied!" label.
Exercise 4 — Lifecycle log Add console.log calls in all four lifecycle callbacks. Move your element between two documents using document.adoptNode in an iframe to trigger adoptedCallback.
Exercise 5 — Progressive enhancement Author an element's HTML contract first (children, slots, attributes). Load the page without the script tag and confirm the content still makes sense. Then add the script — the upgrade should be invisible to the user.
