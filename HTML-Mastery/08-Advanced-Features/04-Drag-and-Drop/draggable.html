The draggable Global Attribute

Every HTML element accepts draggable="true", "false", or "auto". Some elements are draggable by default — images, links, and text selections. Everything else needs you to opt in.

1 The draggable Attribute

draggable is a global HTML attribute — you can put it on any element. It tells the browser whether the user can grab the element with the mouse and drag it elsewhere on the page (or to another application).

<div draggable="true">Pick me up</div>
<div draggable="false">Locked in place</div>
<div draggable="auto">Browser decides</div>

The attribute alone does not complete a drag-and-drop interaction — you still need event handlers (covered in the drag events page) to define what happens during drag-over and on drop. But draggable is the on/off switch that gets you the first half.

2 Three Values

ValueEffect
trueThe element is draggable regardless of its type.
falseThe element cannot be dragged even if it would otherwise be draggable by default (e.g. an image).
autoUse the element's default draggable behavior. The default for most elements is false; for images, links, and text selections it is true.
Pro Tip If you omit the attribute entirely, the value is treated as auto. Writing draggable as a bare attribute (without a value) is treated as true — but for clarity, always write draggable="true".

4 Making Any Element Draggable

<div class="tile" draggable="true">A</div>
<div class="tile" draggable="true">B</div>
<div class="tile" draggable="true">C</div>
const tiles = document.querySelectorAll('.tile');
tiles.forEach(tile => {
  tile.addEventListener('dragstart', (e) => {
    e.dataTransfer.setData('text/plain', tile.textContent);
    tile.classList.add('dragging');
  });
  tile.addEventListener('dragend', () => {
    tile.classList.remove('dragging');
  });
});

5 Visual Cues

Good drag UX requires three cues:

  • Affordance — before drag, the element should look grabbable. Use cursor: grab on the source, and cursor: grabbing while active.
  • Source feedback — while dragging, reduce opacity on the source so users see it is "in flight."
  • Target feedback — when the cursor is over a valid drop zone, highlight the target (e.g. dashed border, background tint).
.tile {
  cursor: grab;
  transition: opacity 0.15s, transform 0.15s;
}
.tile.dragging {
  opacity: 0.4;
  transform: scale(0.95);
}
.drop-zone.over {
  background: #dbeafe;
  border-color: #2563eb;
  border-style: dashed;
}
Pro Tip The browser renders its own "ghost" of the dragged element automatically. You can override the ghost image with e.dataTransfer.setDragImage(element, x, y) inside dragstart — useful for showing a custom multi-item preview.

6 Source-Side Events

Two events fire on the draggable element itself:

EventFiresTypical use
dragstartWhen the user begins dragging the elementSet the data payload on dataTransfer; add a "dragging" class for visual feedback.
dragendWhen the drag ends (drop or cancel via ESC)Clean up visual feedback; trigger any post-drag UI.
 
tile.addEventListener('dragstart', (e) => {
  e.dataTransfer.setData('text/plain', tile.dataset.id);
  e.dataTransfer.effectAllowed = 'move';
  tile.classList.add('dragging');
});

tile.addEventListener('dragend', () => {
  tile.classList.remove('dragging');
  // Optional: re-render the source list, log analytics, etc.
});
Pro Tip effectAllowed sets what kinds of drops are allowed — copy, move, link, or combinations. The browser uses it to render the appropriate cursor (e.g. the green + for copy).

7 Touch Support Caveat

Important The HTML Drag and Drop API does not fire on touch devices. dragstart, dragover, and drop are pointer/mouse events only. On a phone or tablet, your draggable UI will silently not work.

For cross-device drag-and-drop, you have three options:

  • Use the Pointer Events API (pointerdown, pointermove, pointerup) and build drag manually — works everywhere.
  • Use a library like SortableJS or dnd-kit that abstracts the differences.
  • Use HTML DnD as a progressive enhancement and provide a fallback "move up / move down" button UI for touch users.

8 Browser Support

Chrome (all) Firefox (all) Safari (all) Edge (all) Touch devices — no DnD events

9 Common Mistakes

  • Forgetting draggable="true" on divs. Without it, the browser ignores dragstart handlers entirely.
  • Setting draggable="false" on an image you want users to not drag. This is correct — but remember it also breaks some assistive tech interactions; pair with CSS user-select: none for full lock-down.
  • Calling setData after dragstart returns. Data must be set synchronously inside the dragstart handler. After the event finishes, dataTransfer becomes read-only in some browsers.
  • Expecting touch support. Plan a fallback from day one.
  • Not setting effectAllowed. The default may not match what you want; explicit is better.
  • Forgetting to clean up classes in dragend. If you add a dragging class in dragstart, always remove it in dragend — including the cancel case.

10 Try It Yourself

Exercise 1 — First draggable Add draggable="true" to a paragraph. Open your browser console and confirm dragstart fires when you drag it (add a console.log).
Exercise 2 — Visual feedback Build three colored tiles. Add the dragging class with reduced opacity. Add cursor: grab and cursor: grabbing states.
Exercise 3 — Disable default Add an <img> to the page. Notice you can drag it. Add draggable="false" and confirm the browser no longer lets you drag the image.
Exercise 4 — Custom drag image Use e.dataTransfer.setDragImage(customEl, 0, 0) in dragstart to render a custom drag preview (e.g. an enlarged version of the tile). Inspect how the ghost differs from the default.
Exercise 5 — Touch fallback Test your draggable tile on a phone or in DevTools mobile emulation. Confirm nothing happens. Add a "Move up / Move down" button fallback for touch users.

11 Real-World Use Cases

Kanban boards

Trello, Linear, GitHub Projects — drag cards between columns.

File uploads

Drag a file from the desktop onto a drop zone — Gmail, Slack, Notion.

Sortable lists

Reorder playlist tracks, nav items, or photo galleries.

Reorderable tables

Drag rows to reorganize priorities or schedules.

Page builders

Drag blocks from a palette into the canvas — Webflow, Wix.

Cross-app drops

Drag an image from the browser into Photoshop, or text into another tab.
