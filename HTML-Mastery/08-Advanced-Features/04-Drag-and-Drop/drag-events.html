Drag Events Lifecycle

Seven events span the full drag-and-drop journey: dragstart, drag, dragenter, dragover, dragleave, drop, dragend. Master their ordering and the dataTransfer object and you can build anything from sortable lists to cross-window file uploads.

1 The Seven Events

EventFires onPurpose
dragstartSourceUser starts dragging. Set dataTransfer payload.
dragSource (continuously)Fires repeatedly during the drag. Use sparingly — it's expensive.
dragenterPotential targetDragged element enters a drop zone. Highlight the zone.
dragoverPotential target (continuously)Dragged element is moving over a drop zone. Must preventDefault() to allow drop.
dragleavePotential targetDragged element leaves the drop zone. Remove highlight.
dropDrop targetUser released the mouse over a valid zone. Read the payload and act.
dragendSourceDrag finished — either dropped or canceled (ESC). Final cleanup.

Three events fire on the source element (the thing being dragged). Four fire on potential targets (drop zones).

2 Event Ordering

A typical successful drag fires events in this order:

dragstart        (source)
  drag            (source, repeatedly)
  dragenter       (target A)
  dragover        (target A, repeatedly)
  dragleave       (target A)
  dragenter       (target B)
  dragover        (target B, repeatedly)
  drop            (target B)
dragend          (source)
Common Mistake dragleave fires when you move between child elements inside the drop zone — not just when you leave the zone entirely. This is the notorious "flicker bug." The robust fix is to track a counter (increment on dragenter, decrement on dragleave, clear only when it reaches zero), or use the relatedTarget property to check whether you're still inside the parent.

3 The dataTransfer Object

Every drag event's event.dataTransfer is the clipboard-like payload that carries data from source to drop target. The source sets it; the target reads it.

// Source
element.addEventListener('dragstart', (e) => {
  e.dataTransfer.setData('text/plain', element.dataset.id);
  e.dataTransfer.setData('application/json', JSON.stringify({ id: 7, label: 'Task' }));
  e.dataTransfer.effectAllowed = 'move';
});

// Target
zone.addEventListener('drop', (e) => {
  e.preventDefault();
  const id = e.dataTransfer.getData('text/plain');
  const raw = e.dataTransfer.getData('application/json');
  const data = raw ? JSON.parse(raw) : null;
});

Common MIME types used as "data kinds"

MIME typeUse
text/plainPlain text or simple IDs.
text/uri-listURLs being dragged from anchor tags.
application/jsonStructured data — custom payloads.
text/htmlHTML snippets (e.g. rich-text editors).
FilesNative OS file drops — read via e.dataTransfer.files.
Pro Tip You can call setData multiple times with different MIME types, and the target can probe them in priority order — falling back to text/plain if a richer format is missing.

4 Why dragover Needs preventDefault

By default, the browser disallows drops on most elements. To opt a zone in as a drop target, you must call preventDefault() on every dragover event (and on dragenter for safety). Without this, the drop event will never fire.

zone.addEventListener('dragover', (e) => {
  e.preventDefault();            // required for drop to fire
  e.dataTransfer.dropEffect = 'move';
});

zone.addEventListener('drop', (e) => {
  e.preventDefault();            // also required — browsers may otherwise navigate
  const id = e.dataTransfer.getData('text/plain');
  // ... handle the drop
});
Common Mistake Authors attach only a drop handler and find it never fires. The dragover preventDefault() is the single most-forgotten line in the entire drag-and-drop API. Without it, the browser shows a "no-drop" cursor and silently cancels the drop.

5 Source-Side Events

function onDragStart(e) {
  e.dataTransfer.setData('text/plain', e.target.dataset.id);
  e.dataTransfer.effectAllowed = 'move';
  e.target.classList.add('dragging');
}

function onDrag(e) {
  // Fires continuously. Avoid heavy work here —
  // useful for live position indicators, but expensive.
}

function onDragEnd(e) {
  e.target.classList.remove('dragging');
  // Optional: animate snap-back, fire analytics, refresh model
}

source.addEventListener('dragstart', onDragStart);
source.addEventListener('drag',     onDrag);    // optional
source.addEventListener('dragend',  onDragEnd);

6 Target-Side Events

let dragCounter = 0;   // track nested enters/leaves

zone.addEventListener('dragenter', (e) => {
  e.preventDefault();
  dragCounter++;
  zone.classList.add('over');
});

zone.addEventListener('dragover', (e) => {
  e.preventDefault();                // MUST call this
  e.dataTransfer.dropEffect = 'move';
});

zone.addEventListener('dragleave', (e) => {
  dragCounter--;
  if (dragCounter === 0) {
    zone.classList.remove('over');
  }
});

zone.addEventListener('drop', (e) => {
  e.preventDefault();
  dragCounter = 0;
  zone.classList.remove('over');
  const id = e.dataTransfer.getData('text/plain');
  const dragged = document.querySelector(`[data-id="${id}"]`);
  if (dragged) zone.appendChild(dragged);
});
Pro Tip The counter pattern handles nested children. Without it, entering a child div inside your zone fires dragleave on the zone, removing the highlight prematurely — even though the user is still inside the zone.

7 UX Patterns for Visual Feedback

Drop-zone highlight

Add a .over class on dragenter, remove on dragleave/drop. Use dashed border + tinted background.

Cursor hints

Set dropEffect to copy, move, link, or none inside dragover to show the right cursor.

Source fade

Add opacity: 0.4 on the source during drag so users see it is "in flight." Restore on dragend.

Placeholder insertion

For sortable lists, render a thin placeholder bar at the projected insertion point as dragover fires.

Custom drag image

e.dataTransfer.setDragImage(el, x, y) shows a custom ghost — useful for multi-select previews.

Cancel feedback

On dragend with no drop, animate the source back to its origin so users know it didn't move.

8 Full Example: Two-Column Kanban

<div class="board">
  <div class="column" data-column="todo">
    <h3>Todo</h3>
    <div class="item" draggable="true" data-id="1">Write blog</div>
    <div class="item" draggable="true" data-id="2">Review PR</div>
  </div>
  <div class="column" data-column="done">
    <h3>Done</h3>
    <div class="item" draggable="true" data-id="3">Ship release</div>
  </div>
</div>

<script>
  document.querySelectorAll('.item').forEach(setupSource);
  document.querySelectorAll('.column').forEach(setupDropZone);

  function setupSource(item) {
    item.addEventListener('dragstart', e => {
      e.dataTransfer.setData('text/plain', item.dataset.id);
      e.dataTransfer.effectAllowed = 'move';
      item.classList.add('dragging');
    });
    item.addEventListener('dragend', () => item.classList.remove('dragging'));
  }

  function setupDropZone(zone) {
    let count = 0;
    zone.addEventListener('dragenter', e => { e.preventDefault(); count++; zone.classList.add('over'); });
    zone.addEventListener('dragover',  e => { e.preventDefault(); e.dataTransfer.dropEffect = 'move'; });
    zone.addEventListener('dragleave', () => { if (--count === 0) zone.classList.remove('over'); });
    zone.addEventListener('drop', e => {
      e.preventDefault(); count = 0; zone.classList.remove('over');
      const id = e.dataTransfer.getData('text/plain');
      const item = document.querySelector(`[data-id="${id}"]`);
      if (item) zone.appendChild(item);
      log(`Moved ${id} → ${zone.dataset.column}`);
    });
  }
</script>

9 Common Mistakes

  • Missing preventDefault on dragover. Drop never fires; browser shows "no-drop" cursor.
  • Forgetting preventDefault on drop. Some browsers navigate to a dropped URL or open a file.
  • Reading dataTransfer in dragover. Security restrictions: in dragover, getData often returns empty — you can only read it inside drop.
  • Nested-element flicker. Forgetting the counter pattern for dragenter/dragleave.
  • Heavy work in drag. It fires dozens of times per second — keep it cheap.
  • Not handling dragend after cancel. The dragging class stays; the source looks faded forever.
  • Setting setData asynchronously. Must be set synchronously inside dragstart.
  • Expecting drag events to fire on touch devices. They don't — see the touch fallback note in the previous page.

10 Try It Yourself

Exercise 1 — Minimal drop Build a draggable <div> and a drop zone. Confirm that without preventDefault on dragover, the drop is silently ignored. Then add it and watch it work.
Exercise 2 — Event log Build the kanban example. Add a log panel that prints every drag event with a timestamp. Confirm the order matches section 2.
Exercise 3 — Counter pattern Add a nested <h3> and <p> inside your drop zone. Without the counter, confirm the highlight flickers when crossing the heading. Add the counter and confirm it stops flickering.
Exercise 4 — Two MIME types Set both text/plain and application/json in dragstart. In drop, try reading the JSON first, fall back to plain text. Confirm both work.
Exercise 5 — File drop Add a drop zone that reads e.dataTransfer.files on drop and lists the file names. Drag an image from your desktop into the zone — no <input type="file"> required.
