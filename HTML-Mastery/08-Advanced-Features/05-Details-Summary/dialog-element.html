The <dialog> Element

Native modal dialogs — focus trap, ESC-to-close, inert background, and a backdrop pseudo-element — all built into the browser. No more jQuery UI Bootstrap React-Modal ARIA-trap boilerplate.

1 Two Modes: Non-Modal vs Modal

Propertyshow() (non-modal)showModal() (modal)
Background interactionAllowed — page still clickableBlocked — background is inert
BackdropNo backdropDarkened ::backdrop
Focus trapNo — Tab can leave the dialogYes — focus stays inside
ESC closesNoYes
Stacking contextNormal flowTop layer (above all other content)
Common usePop-out panels, non-blocking toastsConfirmations, forms, lightboxes
Pro Tip The "top layer" concept is key: modal dialogs render above everything, including elements with z-index: 99999. You no longer have to play the z-index arms race with sticky headers and dropdowns.

2 The open Attribute (Non-Modal)

<dialog open>
  <p>I'm a non-modal dialog. The page behind me is still interactive.</p>
</dialog>

The open attribute marks the dialog as showing in non-modal mode. It's the declarative equivalent of calling dialog.show() from JavaScript:

const dialog = document.querySelector('dialog');
dialog.show();        // non-modal — equivalent to setting `open`
dialog.close();       // hides the dialog

Non-modal

Try clicking the page behind me — it still works. Press Tab; focus can leave this dialog. ESC does nothing.

3 showModal() — True Modal

const dialog = document.querySelector('dialog');
dialog.showModal();   // modal — inert background, focus trap, ESC closes

Confirm deletion

This action cannot be undone. The page behind me is inert — try clicking it. Press ESC to dismiss. Try Tabbing; focus stays inside.
Common Mistake Calling showModal() on a dialog that already has the open attribute (from show() or HTML) throws an InvalidStateError. Always call close() first, or use only one method per dialog instance.

4 The ::backdrop Pseudo-Element

When shown via showModal(), the dialog has a backdrop that you can style with the ::backdrop pseudo-element. It is rendered in the top layer behind the dialog but above all other page content.

dialog::backdrop {
  background: rgba(15, 23, 42, 0.6);
  backdrop-filter: blur(2px);
}

/* Vary backdrop per dialog */
dialog.confirm::backdrop { background: rgba(220, 38, 38, 0.4); }
dialog.success::backdrop { background: rgba(22, 163, 74, 0.4); }
Pro Tip Backdrop styling works only for showModal(). Non-modal dialogs have no backdrop at all — which is exactly why background interaction is allowed.

5 ESC to Close

Modal dialogs close automatically when the user presses Escape. The browser fires the cancel event first — you can prevent default to refuse dismissal:

dialog.addEventListener('cancel', (e) => {
  // e.g. user has unsaved form changes
  if (formIsDirty()) {
    e.preventDefault();     // keep dialog open
    showUnsavedWarning();
  }
});

If the cancel event is not prevented, the browser calls dialog.close() and the close event fires.

6 The close Event

The close event fires whenever the dialog closes — via close(), ESC, or a submit button with method="dialog". It is non-cancelable and does not bubble.

dialog.addEventListener('close', () => {
  console.log('Closed. returnValue =', dialog.returnValue);
});
Common Mistake Authors attach click handlers to their Cancel / Save buttons and call close(), then expect a custom event to fire. The platform already gives you close — and the returnValue lets you know which button was clicked.

7 returnValue

dialog.close(value) accepts an optional value that becomes dialog.returnValue. Combined with method="dialog" forms, this provides a clean way to know which button closed the dialog.

// Programmatic
dialog.close('confirmed');
console.log(dialog.returnValue);   // "confirmed"

// Form button (see next section)
<form method="dialog">
  <button value="save">Save</button>
  <button value="cancel">Cancel</button>
</form>

8 Form method="dialog"

A <form> with method="dialog" closes its containing dialog automatically when submitted. Each submit button's value becomes the dialog's returnValue.

<dialog id="confirm">
  <form method="dialog">
    <p>Delete this file?</p>
    <menu>
      <button value="cancel">Cancel</button>
      <button value="delete">Delete</button>
    </menu>
  </form>
</dialog>

<script>
  const d = document.getElementById('confirm');
  d.addEventListener('close', () => {
    if (d.returnValue === 'delete') {
      actuallyDeleteFile();
    }
  });
  d.showModal();
</script>
Pro Tip method="dialog" skips form validation by design — it never actually submits data anywhere. If you need validation, use a regular form with addEventListener('submit', …) and call dialog.close(value) manually once validation passes.

9 Browser Support

Chrome 37+ Firefox 98+ (March 2022) Safari 15.4+ (March 2022) Edge 79+ Universal since 2022

Firefox shipped full showModal() support in version 98. If your project supports older Firefox/Safari, include the dialog-polyfill as a fallback — it patches showModal() with manual inert/focus management.

10 Common Mistakes

  • Using open attribute for modal behavior. HTML open only opens in non-modal mode. Always use showModal() for true modals.
  • Calling showModal() when already open. Throws InvalidStateError. Call close() first.
  • Expecting close event to bubble. It does not — listen directly on the dialog.
  • Not handling ESC. The browser closes the dialog for you. If you have unsaved state, listen for cancel and preventDefault.
  • Using huge z-index on custom modal divs. With native <dialog>, the top layer is automatic; z-index is irrelevant.
  • Forgetting to focus the first input. showModal() moves focus to the dialog (or its first focusable child). Verify the focus order matches your visual order.
  • Nesting modal dialogs. Technically allowed, but UX is usually awful. Avoid stacking more than two.
  • Skipping the polyfill for older browsers. Pre-2022 Firefox/Safari users see a non-functional dialog.
  • Putting critical navigation inside a modal. Modal = "block the world for this one decision." Use it sparingly.

11 Try It Yourself

Exercise 1 — First dialog Create a <dialog> with a paragraph inside. Open it with both dialog.show() and dialog.showModal(). Notice the difference in background interactivity.
Exercise 2 — Confirm modal Build a delete-confirmation modal. Use two buttons with value="cancel" and value="delete" inside a method="dialog" form. Log the returnValue on close.
Exercise 3 — Styled backdrop Style dialog::backdrop with a blurred dark overlay. Add a class to the dialog and style its backdrop differently (e.g. red for destructive, green for success).
Exercise 4 — Dirty-form guard Put a form inside a modal. If the user has typed something and tries to ESC, intercept the cancel event and show a "discard changes?" sub-confirm before closing.
Exercise 5 — Lightbox Build an image lightbox: clicking a thumbnail opens a modal dialog containing the full-size image. Add Close on backdrop click (listen for click on the dialog and check e.target === dialog).
Exercise 6 — Focus management Open a modal with three inputs. Verify Tab cycles only inside the dialog. Then dynamically add a fourth input via JS while the dialog is open — confirm focus trapping still works.
