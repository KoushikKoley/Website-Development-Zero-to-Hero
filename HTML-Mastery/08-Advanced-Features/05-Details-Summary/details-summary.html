<details> & <summary>

The native disclosure widget — collapsible content with zero JavaScript. The browser handles the open/close toggle, keyboard focus, and accessibility for free. Perfect for FAQs, settings panels, and table-of-contents navigation.

1 Anatomy

<details>
  <summary>Click to expand</summary>
  <p>Hidden by default, this content appears when the summary is clicked.</p>
</details>

Two elements do all the work:

  • <details> — the wrapper. Tracks its own open/closed state via the open attribute.
  • <summary> — the visible label that the user clicks. Must be the first child of <details>. If omitted, the browser renders a default "Details" label.

Everything inside <details> that is not the summary is the disclosure content.

2 The open Attribute

The presence of the boolean open attribute on <details> means the content is expanded. Its absence means collapsed. The browser toggles this attribute automatically when the user clicks the summary — no JavaScript required.

<!-- Collapsed by default -->
<details>…</details>

<!-- Expanded by default -->
<details open>…</details>

Because open is reflected as an IDL attribute, you can both read and set it from JavaScript:

console.log(detailsEl.open);     // true or false
detailsEl.open = true;          // expands
detailsEl.open = false;        // collapses
detailsEl.toggleAttribute('open');

3 The toggle Event

Whenever the open state changes — by user click or programmatic toggle — the toggle event fires on the <details> element. This is non-cancelable and bubbles.

const details = document.querySelector('details');
details.addEventListener('toggle', () => {
  console.log(`Now ${details.open ? 'open' : 'closed'}`);
  // Update analytics, lazy-load images, save state to localStorage…
});
Pro Tip The toggle event is perfect for deferring expensive work. Put charts, video embeds, and large images inside collapsed <details> blocks; only initialize them when the user expands — listen for the toggle event and render then.

4 JavaScript Control

Three idiomatic patterns for controlling <details> from JS:

// 1. Single exclusive accordion (one open at a time)
const all = document.querySelectorAll('.accordion > details');
all.forEach(d => d.addEventListener('toggle', () => {
  if (d.open) {
    all.forEach(other => { if (other !== d) other.open = false; });
  }
}));

// 2. "Expand all" / "Collapse all" buttons
document.getElementById('expand-all').addEventListener('click', () => {
  document.querySelectorAll('details').forEach(d => d.open = true);
});

// 3. Persist state across page loads
const KEY = 'faq-state';
const saved = JSON.parse(localStorage.getItem(KEY) || '{}');
document.querySelectorAll('details[data-key]').forEach(d => {
  if (saved[d.dataset.key]) d.open = true;
  d.addEventListener('toggle', () => {
    saved[d.dataset.key] = d.open;
    localStorage.setItem(KEY, JSON.stringify(saved));
  });
});

5 Styling the Disclosure Marker

By default browsers render a triangle (▸) or arrow before the summary. You can hide, replace, or animate it.

Hide the marker entirely

details > summary {
  list-style: none;             /* Standard */
}
details > summary::-webkit-details-marker {
  display: none;               /* Chrome / Safari */
}

Marker hidden

No triangle here
Just the text label. Useful when you provide your own custom indicator.

Custom marker with + / −

details > summary {
  list-style: none;
  cursor: pointer;
}
details > summary::-webkit-details-marker { display: none; }
details > summary::before {
  content: "+";
  color: #2563eb;
  font-weight: 700;
  margin-right: 8px;
  display: inline-block;
  transition: transform 0.2s;
}
details[open] > summary::before {
  content: "−";
}

Custom + / − marker

Animated rotating chevron

details > summary {
  list-style: none;
  display: flex; align-items: center; gap: 8px;
}
details > summary::-webkit-details-marker { display: none; }
details > summary::before {
  content: "▶";
  font-size: 0.75rem;
  transition: transform 0.15s ease;
}
details[open] > summary::before {
  transform: rotate(90deg);
}

Rotating chevron

Chevron rotates when open
This pattern is the most common in modern design systems.

The new ::marker pseudo-element

Modern browsers also expose ::marker on the summary, which can be styled directly:

details > summary::marker {
  color: #7c3aed;
  font-size: 1.2em;
}
Common Mistake Setting list-style alone does not work in Chromium-based browsers — the disclosure marker is implemented as a separate pseudo-element. Always pair list-style: none with ::-webkit-details-marker { display: none } for cross-browser coverage.

6 Nested Accordions

You can nest <details> elements to build hierarchical disclosure UIs — perfect for table of contents, file trees, and product category filters.

<details>
  <summary>Front-end</summary>
  <details>
    <summary>Frameworks</summary>
    <ul>
      <li>React</li>
      <li>Vue</li>
      <li>Svelte</li>
    </ul>
  </details>
  <details>
    <summary>Styling</summary>
    <ul><li>Tailwind</li><li>CSS Modules</li></ul>
  </details>
</details>

7 Building an FAQ Accordion

<section aria-label="Frequently asked questions">
  <h2>FAQ</h2>

  <details>
    <summary>Do you offer refunds?</summary>
    <p>Yes, within 30 days of purchase. Just email support@example.com.</p>
  </details>

  <details>
    <summary>Can I cancel anytime?</summary>
    <p>Absolutely. Cancel from your account page; no email or call needed.</p>
  </details>

  <details>
    <summary>Do you support SSO?</summary>
    <p>Yes — SAML 2.0 and OIDC on Team and Enterprise plans.</p>
  </details>
</section>

Pair this with a matching FAQPage JSON-LD block (see the structured data page) so Google can render the questions directly in search results.

Pro Tip To make the FAQ keyboard-accessible without extra ARIA, just rely on <details>. The browser already exposes the summary as a button — Space and Enter toggle it. No role="button", no aria-expanded needed.

8 Browser Support

Chrome 12+ Firefox 49+ Safari 6+ Edge 79+ Universal since 2016

The toggle event has slightly newer support (Chrome 36+, Firefox 60+). For older browsers you can fall back to a click handler on the summary.

9 Common Mistakes

  • Putting <summary> anywhere except as the first child. The browser renders a default "Details" label instead of yours.
  • Using <summary> outside <details>. It has no effect and may produce odd accessibility tree results.
  • Adding role="button" or aria-expanded to the summary. Redundant — the platform already wires those up.
  • Trying to style the marker with list-style alone. Doesn't work in Chrome/Safari; pair with ::-webkit-details-marker.
  • Animating max-height for smooth open/close. The native open/close is instant. If you want animation, you have to fully custom-build with requestAnimationFrame and override the native toggle — nontrivial.
  • Naming the disclosure with <summary> containing only an icon. Always include a text label, even if visually hidden, for screen readers.
  • Forgetting to test keyboard navigation. The summary should be reachable with Tab and toggleable with Enter or Space — verify this works.

10 Try It Yourself

Exercise 1 — First disclosure Create a <details> with a summary "Show answer" and a paragraph of body text. Verify it toggles with mouse and keyboard.
Exercise 2 — Default open Add open so it starts expanded. Confirm you can still collapse it.
Exercise 3 — Custom chevron Hide the default triangle and replace it with a rotating ▶ using ::before and transform: rotate(90deg) when [open].
Exercise 4 — Event log Listen for the toggle event and log to console. Confirm it fires both when opening and closing, both via click and via JS-set open property.
Exercise 5 — Exclusive accordion Build four <details> elements. Add JS so opening one closes the others — the classic accordion pattern.
Exercise 6 — Persisted FAQ Add data-key attributes to each <details> and save each one's open state in localStorage on toggle. Reload the page — the open/closed state should be remembered.
