The <menu> Element

Twice invented, twice repurposed. The <menu> element has been a UI menu, a context menu, and is now being revived as the semantic home for command lists — paired with the emerging Popup API.

1 A Brief, Confusing History

The <menu> element has lived several lives:

EraWhat <menu> meant
HTML 2 / 3.2 / 4An unordered list rendered with menu styling — basically a synonym for <ul>. Few used it.
HTML5 (early 2010s)Re-purposed for UI menus — context menus, toolbars, menu buttons. <menuitem> was added for individual commands. Firefox implemented contextmenu attribute linking.
~2014Only Firefox ever implemented type="context". The spec was un-deprecated, simplified, and <menuitem> was removed.
Today (HTML Living Standard)<menu> is "a list of commands" with type="context", type="toolbar", or the implicit type="list". <li> children hold the commands. Browsers mostly render it as <ul>.
EmergingBeing revived as the semantic host for the Popup API and the related behavior attribute proposals.
Reality Check In all browsers today, <menu> renders exactly like <ul>. The type="context" and type="toolbar" attributes do not produce native UI. They are semantic hints only. To get an actual context menu or toolbar you must build it with JS + CSS.

2 What <menu> Is Today

In the current HTML Living Standard, <menu> is a semantic container for a list of commands. Its role in the accessibility tree is list, identical to <ul>. The distinction is purely semantic: <menu> says "this list represents user actions," <ul> says "this list represents generic items."

<menu>
  <li><button onclick="save()">Save</button></li>
  <li><button onclick="exportDoc()">Export…</button></li>
  <li><button onclick="print()">Print</button></li>
</menu>

If you used <ul> here instead, browsers would render it identically. Using <menu> conveys intent to assistive technology and to future maintainers.

3 The type Attribute

ValueMeaningBrowser rendering
list (default)A plain list of commands.Like <ul>
toolbarA horizontal strip of action buttons.Like <ul> — no native toolbar styling
contextA context menu (intended for use with the contextmenu attribute on another element).Like <ul> — no native context menu rendering (Firefox removed its implementation)
Common Mistake Believing type="context" creates a working native context menu. It does not. The contextmenu attribute on a target element used to wire to a <menu type="context"> in Firefox, but that feature was removed in 2017. Today you build context menus with JS — see section 7.

4 Menu Items with <li>

Inside a <menu>, individual commands are written as <li> elements containing the actual control — usually a <button>, <a>, or <label>. The list-item structure gives you semantic grouping and lets you nest submenus by placing another <menu> inside an <li>.

<menu type="toolbar" aria-label="Text formatting">
  <li><button data-cmd="bold"><b>B</b></button></li>
  <li><button data-cmd="italic"><i>I</i></button></li>
  <li>
    <button data-cmd="align">Align ▾</button>
    <menu>
      <li><button data-cmd="align-left">Left</button></li>
      <li><button data-cmd="align-center">Center</button></li>
      <li><button data-cmd="align-right">Right</button></li>
    </menu>
  </li>
</menu>

Nested <menu> elements inside <li> elements represent submenus semantically — but again, no browser renders them as a fly-out menu. You build that visual with CSS and JS.

5 The Deprecated <menuitem>

HTML5 originally introduced <menuitem> as a dedicated element for individual commands inside <menu type="context">:

<!-- DEPRECATED — do not use -->
<menu type="context" id="imageMenu">
  <menuitem label="Reload"  icon="reload.png" onclick="reload()">
  <menuitem label="Save As…" icon="save.png"   onclick="saveAs()">
</menu>

<img src="pic.jpg" contextmenu="imageMenu">

Only Firefox ever implemented this. The spec was simplified in 2014 to use plain <li> + <button>/<a>, and <menuitem> was removed. Today it has no effect and is not parsed as anything special.

Common Mistake Copying old tutorials that show <menuitem> markup. It will not work in any modern browser. Use <li><button>…</button></li> instead.

    7 Context Menu Pattern (Built with JS)

    Since browsers no longer implement native type="context" menus, you build them by listening for contextmenu (right-click) on a target element and showing your own <menu> as a positioned panel.

    <div id="canvas" class="ctx-target">Right-click me</div>

<div class="ctx-menu" id="ctx-menu">
  <menu type="context">
    <li><button data-cmd="copy">Copy</button></li>
    <li><button data-cmd="paste">Paste</button></li>
    <li><hr></li>
    <li><button data-cmd="delete">Delete</button></li>
  </menu>
</div>

<script>
  const canvas = document.getElementById('canvas');
  const menu   = document.getElementById('ctx-menu');

  canvas.addEventListener('contextmenu', (e) => {
    e.preventDefault();                 // suppress native menu
    menu.style.top  = `${e.pageY}px`;
    menu.style.left = `${e.pageX}px`;
    menu.classList.add('open');
  });

  document.addEventListener('click', () => menu.classList.remove('open'));
  document.addEventListener('contextmenu', (e) => {
    if (!canvas.contains(e.target)) menu.classList.remove('open');
  });

  menu.addEventListener('click', (e) => {
    const btn = e.target.closest('button[data-cmd]');
    if (!btn) return;
    console.log('Selected:', btn.dataset.cmd);
    menu.classList.remove('open');
  });
</script>

    8 The Popup API Revival

    The OpenUI community group is reviving <menu> as the semantic home for declaratively-declared popups. The proposal pairs popup attribute (or a <popup> element) with <menu> to give the browser native handling of: top-layer rendering, light-dismiss on outside click, ESC to close, and focus management.

    <!-- Proposed (still evolving in browsers) -->
<button popovertarget="file-menu">File</button>
<menu id="file-menu" popup>
  <li><button>New</button></li>
  <li><button>Open…</button></li>
  <li><button>Save</button></li>
</menu>

    Today the popover attribute (renamed from popup) is shipping in Chrome 114+, Edge, and Safari 17+, with Firefox in development. It handles top-layer, light-dismiss, and ESC for you. The semantic pairing with <menu> for command lists is the emerging convention.

    Pro Tip Even if you use the new popover API today, the actual command items inside are still plain <li><button> — the platform isn't bringing back <menuitem>.

    10 Common Mistakes

    • Using <menuitem>. Removed from the spec; does nothing.
    • Expecting type="context" to render a native menu. It does not — you must build it with JS.
    • Forgetting to preventDefault on the contextmenu event. The native menu appears alongside your custom one.
    • Forgetting to dismiss the menu on outside click and Escape. A menu that won't close is a usability disaster.
    • Naming the menu without aria-label. Screen readers say "list, three items" with no context. Add aria-label="Editor toolbar" or similar.
    • Using <div> + <button> instead of <menu> + <li>. The semantic structure matters for accessibility tooling and future maintenance.
    • Skipping keyboard navigation. Arrow keys, Home, End, and Escape should all work.
    • Putting non-interactive content inside <menu>. It's a list of commands, not a generic container.

    11 Try It Yourself

    Exercise 1 — Semantic toolbar Build a four-button formatting toolbar using <menu type="toolbar"> with <li><button>. Style it with flexbox.
    Exercise 2 — Active states Extend your toolbar so clicking a button toggles its active class. Wire up the bold/italic/underline buttons to actually format a contenteditable region.
    Exercise 3 — Custom context menu Right-click on an image to show a custom menu with "Copy image URL" and "Open in new tab" commands. Use the contextmenu event with preventDefault.
    Exercise 4 — Keyboard navigation Add arrow-key navigation to your custom menu: Up/Down moves between items, Enter activates, Escape closes. Test with the keyboard only.
    Exercise 5 — Nested submenu Build a menu with a nested submenu (an <li> containing a button and another <menu>). Use CSS hover to reveal the submenu.
    Exercise 6 — Try the Popover API In Chrome 114+ or Safari 17+, build a <menu popover> triggered by <button popovertarget="…">. Confirm the browser handles top-layer, ESC, and outside-click dismiss for you.
