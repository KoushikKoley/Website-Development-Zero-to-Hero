Structured Data — JSON-LD, Microdata & Schema.org

1 Why Structured Data?

HTML describes how content looks and what it is structurally (headings, paragraphs, lists). But it cannot tell a search engine: "this page is about a product that costs $29.99, is in stock, has 4.6 stars from 1,204 reviews, and was last updated on March 4." Structured data fills that gap by attaching typed properties to the things on your page.

Search engines like Google, Bing, Yandex, and Yahoo jointly maintain a vocabulary called Schema.org precisely for this purpose. By marking up your content, you become eligible for rich results — search listings with star ratings, image carousels, breadcrumbs, FAQ accordions, event times, recipe cook-times, and more.

Pro Tip Structured data does not directly improve your ranking, but it dramatically improves click-through rate (CTR) by making your listing richer and more trustworthy. Higher CTR then improves rankings indirectly.

2 The Three Formats Compared

FormatSyntax locationReadabilityMaintenance
JSON-LDOne <script type="application/ld+json"> blockSeparate from HTML — cleanEasiest (edit one JSON blob)
MicrodataInline attributes on existing HTML elementsMixed with contentHarder (attributes scattered)
RDFaInline vocab, typeof, property attributesMixed with contentHarder (verbose syntax)

Google explicitly recommends JSON-LD for most use cases. Microdata and RDFa are still supported but legacy.

3 JSON-LD — The Recommended Format

JSON-LD (Linked Data in JSON) is a JSON-based serialization of RDF. You place it in a single <script> block — typically inside <head> — and the HTML content stays untouched. This separation of concerns makes it the favorite of CMS authors, SEO teams, and template engines.

Basic Article markup

<head>
  <!-- other head content -->
  <script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "Article",
    "headline": "How to Bake Sourdough Bread",
    "image": [
      "https://example.com/photos/1x1/bread.jpg",
      "https://example.com/photos/4x3/bread.jpg",
      "https://example.com/photos/16x9/bread.jpg"
    ],
    "datePublished": "2025-03-04T08:00:00+00:00",
    "dateModified": "2025-03-10T14:30:00+00:00",
    "author": {
      "@type": "Person",
      "name": "Mara Okafor",
      "url": "https://example.com/author/mara"
    },
    "publisher": {
      "@type": "Organization",
      "name": "The Crusty Loaf",
      "logo": {
        "@type": "ImageObject",
        "url": "https://example.com/logo.png"
      }
    }
  }
  </script>
</head>

Product with offers and aggregateRating

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Acme Wireless Headphones",
  "image": "https://store.example.com/wh-9000.jpg",
  "description": "Over-ear noise-cancelling headphones with 40-hour battery.",
  "brand": { "@type": "Brand", "name": "Acme" },
  "sku": "WH-9000-BLK",
  "mpn": "ACME9000",
  "gtin13": "0123456789012",
  "offers": {
    "@type": "Offer",
    "url": "https://store.example.com/wh-9000",
    "price": "199.00",
    "priceCurrency": "USD",
    "availability": "https://schema.org/InStock",
    "priceValidUntil": "2025-12-31"
  },
  "aggregateRating": {
    "@type": "AggregateRating",
    "ratingValue": "4.6",
    "reviewCount": "1204"
  }
}
</script>
Pro Tip You can ship multiple JSON-LD blocks on the same page (one per entity) or use a @graph array to bundle several entities into a single script tag. Google handles both equally well.

4 Microdata — Inline Attributes

Microdata adds three attributes to ordinary HTML elements: itemscope (creates an item), itemtype (the schema type URL), and itemprop (a property name on the closest itemscope ancestor).

<article itemscope itemtype="https://schema.org/Article">
  <h1 itemprop="headline">How to Bake Sourdough Bread</h1>
  <img itemprop="image" src="bread.jpg" alt="A golden sourdough loaf">
  <p>By <span itemprop="author" itemscope
              itemtype="https://schema.org/Person">
       <a itemprop="url" href="/author/mara">
         <span itemprop="name">Mara Okafor</span>
       </a>
     </span>
  </p>
  <time itemprop="datePublished" datetime="2025-03-04">March 4, 2025</time>
</article>

Microdata is verbose but has one virtue: the marked-up content is the same content humans see, which guarantees alignment between visible text and structured data (something Google requires for rich results).

Common Mistake Google requires that every value in your structured data also appears visibly on the page (with rare exceptions like aggregateRating on some result types). Hiding markup that doesn't match visible content triggers a manual action.

5 RDFa Lite — A Bridge to the Semantic Web

RDFa Lite 1.1 is the simplest subset of RDFa. It uses four attributes: vocab, typeof, property, and resource (plus prefix for namespaces).

<article vocab="https://schema.org/" typeof="Article">
  <h1 property="name">How to Bake Sourdough Bread</h1>
  <img property="image" src="bread.jpg" alt="A golden sourdough loaf">
  <span property="author" typeof="Person">
    <a property="url" href="/author/mara">
      <span property="name">Mara Okafor</span>
    </a>
  </span>
  <time property="datePublished" datetime="2025-03-04">March 4, 2025</time>
</article>

RDFa is rare in modern web projects but you'll encounter it in Drupal, eGovernment platforms, and some academic publishing stacks.

6 Common Schema.org Vocabularies

Article / NewsArticle / BlogPosting

Headline, image, datePublished, author, publisher.

Product

Name, image, price, currency, availability, reviews, brand, GTIN.

Event

Name, startDate, endDate, location, offers, organizer, eventStatus.

Person

Name, jobTitle, email, address, sameAs (links to social profiles).

Organization

Name, logo, contactPoint, foundingDate, founder, sameAs.

LocalBusiness

Extends Organization + openingHours, priceRange, geo, address.

BreadcrumbList

Ordered list of page positions in site hierarchy — powers breadcrumb rich results.

FAQPage

Wraps Question / Answer pairs — eligible for FAQ accordions in search.

HowTo

Steps, tools, supplies, time, cost — powers step-by-step rich results.

Recipe

Cook time, ingredients, nutrition, ratings — eligible for recipe carousel.

VideoObject

Thumbnail, upload date, duration, content URL — eligible for video preview.

Course

Provider, name, description — eligible for course rich results.

Example — FAQPage (JSON-LD)

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "Do I need a Dutch oven for sourdough?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Not strictly, but a preheated Dutch oven traps steam and gives you a dramatically better crust. A baking stone plus a tray of boiling water below also works."
      }
    },
    {
      "@type": "Question",
      "name": "How long is the bulk ferment?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "At 24°C room temperature, plan for 4–6 hours with stretch-and-folds every 30 minutes for the first 2 hours."
      }
    }
  ]
}
</script>

Example — BreadcrumbList

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    { "@type": "ListItem", "position": 1, "name": "Home", "item": "https://example.com/" },
    { "@type": "ListItem", "position": 2, "name": "Recipes", "item": "https://example.com/recipes" },
    { "@type": "ListItem", "position": 3, "name": "Sourdough", "item": "https://example.com/recipes/sourdough" }
  ]
}
</script>

Example — HowTo

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "HowTo",
  "name": "How to bake sourdough bread",
  "totalTime": "PT18H",
  "estimatedCost": { "@type": "MonetaryAmount", "currency": "USD", "value": "3.50" },
  "supply": [{ "@type": "HowToSupply", "name": "500g bread flour" }],
  "tool":   [{ "@type": "HowToTool",   "name": "Dutch oven" }],
  "step": [
    { "@type": "HowToStep", "position": 1,
      "name": "Mix the levain",
      "text": "Combine 50g starter with 50g flour and 50g water. Rest 4 hours." },
    { "@type": "HowToStep", "position": 2,
      "name": "Autolyse",
      "text": "Mix flour and water. Rest 1 hour." }
  ]
}
</script>

7 Google Rich Results

Not every schema type earns a rich result. Google maintains a list of supported features per type:

Schema typeEligible rich result
Article, NewsArticle, BlogPostingTop stories carousel, image, author
ProductPrice, availability, star ratings, merchant listings
EventEvent card with date, location, ticket link
FAQPageFAQ accordion under the search snippet
HowToStep-by-step list with images
RecipeRecipe card with rating, cook time, calories
VideoObjectVideo preview thumbnail + "key moments"
BreadcrumbListBreadcrumb trail instead of URL
LocalBusinessKnowledge panel with hours, map, phone
Sitelinks SearchboxIn-SERP search box for your site
Common Mistake Rich results are not guaranteed even when your markup is valid. Google decides whether to show them based on content quality, query intent, and the overall search results page. Treat eligibility, not display, as the goal.

8 Testing Tools

Rich Results Test

The official Google tool. Paste a URL or raw HTML, see which rich result types were detected, and get specific error/warning messages. search.google.com/test/rich-results

Schema.org Validator

Neutral validator hosted by Schema.org. Useful when you want to confirm the JSON-LD parses without Google-specific assumptions. validator.schema.org

Search Console

The "Enhancements" reports show errors and warnings for structured data Google has crawled on your site over time.

Open Graph Debugger / Twitter Card Validator

Separate from Schema.org, but worth running alongside — they validate social-share markup.

Chrome Firefox Safari Edge Parsed by crawlers, not browsers

9 Common Mistakes

  • Markup that doesn't match visible content. Putting "price": "9.99" in JSON-LD when the page shows $19.99 will get your rich results stripped.
  • Using "@type" values that aren't in Schema.org. "@type": "Webpage" should be "@type": "WebPage" — capitalization matters.
  • Forgetting @context. Without "@context": "https://schema.org", property names like headline are unresolvable.
  • Date strings without timezone. Use ISO 8601 with offset (e.g. 2025-03-04T08:00:00+00:00) so Google interprets times correctly.
  • Duplicate, conflicting JSON-LD blocks. Two Product blocks on one product page confuse parsers — use one block with a single @type.
  • Rating markup on a page that has no visible reviews. Triggers a manual action for "spurious review markup."
  • Mixing formats. Pick JSON-LD or Microdata. Mixing both can produce duplicate signals that conflict.

10 Try It Yourself

Exercise 1 — Mark up an article Take any blog post you've written. Add a JSON-LD Article block in the <head> with headline, image, datePublished, dateModified, author, and publisher. Validate it at search.google.com/test/rich-results.
Exercise 2 — Product page with ratings Create a fake product page with visible price, stock status, and a 5-star rating widget. Add a matching Product JSON-LD block including offers and aggregateRating. Confirm the validator reports zero errors.
Exercise 3 — FAQ accordion Write 4 genuine Q&A pairs on a topic you know well. Wrap them in an FAQPage JSON-LD block. Also build a visible HTML accordion using <details>/<summary> so users see the same content Google reads.
Exercise 4 — Breadcrumb trail On a multi-level page (e.g. Home → Recipes → Sourdough), add a BreadcrumbList JSON-LD block and a visible breadcrumb nav. Confirm Google recognizes all three positions.
Exercise 5 — LocalBusiness Invent a fictional shop. Add full LocalBusiness markup with address, opening hours, geo coordinates (look up the real lat/long of a place you know), and a priceRange. Validate with the Schema.org validator (not just Google's tool).

11 Real-World Use Cases

Editorial & news sites

Article + NewsArticle markup feeds Google News, Top stories carousels, and Discover.

E-commerce

Product markup is mandatory if you want Merchant Listings experiences and free listings on Google Shopping.

Recipe blogs

Recipe markup drives the image-rich recipe carousel that dominates cooking searches.

Event ticketing

Event markup gets your listings into Google's Events search vertical.

Local SEO

LocalBusiness powers the knowledge panel that appears for branded and "near me" queries.

Support docs

HowTo markup on support articles surfaces step lists directly in search.

Video platforms

VideoObject enables "key moments" chapters in Google video results.

Course providers

Course markup makes MOOCs and bootcamps appear in course-specific rich results.

Voice search & AI

Assistants like Google Assistant and AI overviews often rely on schema to answer "what time does X open" or "how much is Y."
