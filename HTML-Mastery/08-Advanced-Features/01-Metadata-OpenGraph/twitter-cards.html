Twitter Card Meta Tags

Twitter (now X) created its own meta tag protocol in 2012 called "Twitter Cards". Like Open Graph, it powers rich link previews — but with Twitter-specific tag names. The good news: if you've already set up OG tags, Twitter will fall back to them, so adding Twitter Card tags is often just one extra line.

1 What Are Twitter Cards?

A "Twitter Card" is the rich preview that appears below a tweet when you include a link. Instead of just a bare URL, the tweet shows an image, title, and description — making the link much more engaging.

Twitter created its own meta protocol (rather than reusing Open Graph) because they wanted platform-specific features: video players embedded directly in the timeline, app-install cards with native deep links, and tighter image dimension constraints.

Twitter Card tags live in the <head>, using name (not property like OG) attributes prefixed with twitter::

<head>
  <meta name="twitter:card" content="summary_large_image">
  <meta name="twitter:site" content="@nytimes">
  <meta name="twitter:creator" content="@jane_doe">
  <meta name="twitter:title" content="The Hitchhiker's Guide to HTML">
  <meta name="twitter:description" content="A complete tutorial covering everything from DOCTYPE to Web Components.">
  <meta name="twitter:image" content="https://example.com/og/cover.jpg">
</head>
Note on the X rebrand Twitter rebranded to X in 2023, but the meta tag prefix remains twitter:. There has been no announcement of a switch to x: tags, and renaming would break billions of existing pages. Stick with twitter:.

2 The Four Card Types

The twitter:card tag is required and must be the first Twitter Card tag in your <head>. It declares which card layout to use.

Card typeLayoutUse for
summarySquare thumbnail on the left, title + description on the rightDefault for blog posts, articles, generic pages
summary_large_imageLarge image on top, title + description belowArticles and pages where the image is the main draw (most common in 2024)
playerEmbeds a video/audio player directly in the tweetVideo sites, podcast platforms, music services
appMobile-app install card with deep links to App Store / Google PlayPromoting a mobile app from a tweet
Pro Tip If you only ever use one card type, make it summary_large_image. The large image gets dramatically more engagement in timelines than the small thumbnail of plain summary.

Image dimensions for summary

For the summary card, the image must be a square. Recommended: 512 × 512 px. Maximum: 4096 × 4096 px. Image must be ≤ 5 MB.

5 The summary_large_image Card

The hero image card — large image on top, title and description below. This is the most engaging card type for content sites.

Image dimensions for summary_large_image

Recommended: 1200 × 628 px (a 1.91:1 ratio). Minimum: 300 × 157 px (will be upscaled, looking poor). Maximum: 4096 × 4096 px. File size ≤ 5 MB.

Pro Tip — reuse the OG image The OG image (1200 × 630) and the summary_large_image image (1200 × 628) are nearly identical in size — most people reuse the same image for both. The 2-pixel difference is irrelevant in practice.

6 The player Card

For sites hosting video or audio, the player card embeds a working media player directly in the tweet — no click-through required.

<meta name="twitter:card" content="player">
<meta name="twitter:site" content="@yourtube">
<meta name="twitter:title" content="Behind the scenes: how we built our player">
<meta name="twitter:image" content="https://example.com/og/video-poster.jpg">
<meta name="twitter:image:alt" content="A still from the video showing the engineering team">
<meta name="twitter:player" content="https://example.com/embed/abc123">
<meta name="twitter:player:width" content="480">
<meta name="twitter:player:height" content="270">
<meta name="twitter:player:stream" content="https://example.com/video/abc123.mp4">

Player card requirements

  • The twitter:player URL must be HTTPS.
  • The iframe player must respond to Twitter's JavaScript postMessage API for play/pause.
  • Provide both twitter:player (iframe) AND twitter:player:stream (direct MP4) — some Twitter clients only support one or the other.
  • The twitter:image poster frame shows before the user taps to play.
Approval required Player Cards used to require manual whitelisting by Twitter. As of 2023, the requirement has been relaxed for most accounts, but new domains may still need to be "validated" via the Card Validator before they render reliably.

7 The app Card

For promoting mobile apps, the app card shows the app icon, name, description, and direct install buttons for iOS and/or Android.

<meta name="twitter:card" content="app">
<meta name="twitter:site" content="@acmeapp">
<meta name="twitter:title" content="Acme — Task management reimagined">
<meta name="twitter:description" content="Get things done, beautifully. Free to download.">
<meta name="twitter:app:name:iphone" content="Acme">
<meta name="twitter:app:id:iphone" content="1234567890">
<meta name="twitter:app:url:iphone" content="acme://launch">
<meta name="twitter:app:name:googleplay" content="Acme">
<meta name="twitter:app:id:googleplay" content="com.acme.app">
<meta name="twitter:app:url:googleplay" content="acme://launch">
<meta name="twitter:app:name:ipad" content="Acme">
<meta name="twitter:app:id:ipad" content="1234567890">
<meta name="twitter:app:url:ipad" content="acme://launch">

How it appears

The tweet shows the app icon (from the App Store / Play Store), the app name, rating, and an "INSTALL" or "OPEN" button that deep-links into the App Store / Play Store or directly into the app if already installed.

8 The Open Graph Fallback

This is the most important thing to know about Twitter Cards: Twitter falls back to OG tags when Twitter-specific tags are missing.

So if you set up Open Graph properly, you only need to add one Twitter Card tag to get a working card:

<!-- All OG tags already set -->
<meta property="og:title" content="...">
<meta property="og:description" content="...">
<meta property="og:image" content="...">
<meta property="og:url" content="...">

<!-- This single Twitter tag enables the large-image card -->
<meta name="twitter:card" content="summary_large_image">

<!-- Optional: add your Twitter handles -->
<meta name="twitter:site" content="@yourbrand">
<meta name="twitter:creator" content="@yourauthor">

Twitter will use og:title, og:description, og:image, and og:url for the card content, and the Twitter twitter:card tag for the layout choice.

When to override OG

If you want different content on Twitter vs Facebook (e.g., a square image for Twitter, wide image for Facebook), set both og:* and twitter:* tags. Twitter always prefers its own tags when present.

Common Mistake Setting only twitter:* tags and forgetting OG. Then LinkedIn/Facebook/Slack previews break. Always set OG first, then layer Twitter on top.

10 Testing with Card Validator

Twitter Card Validator (official)

The official tool was at cards-dev.twitter.com/validator. In 2023, Twitter/X deprecated the standalone validator and folded the functionality into the main Tweet composer. To test today:

  • Method 1 — Tweet composer: Open twitter.com/compose/post, paste your URL. The card preview will render if your tags are correct.
  • Method 2 — Draft a tweet: Add your URL to a draft tweet; the card appears below.
  • Method 3 — Third-party tools: OpenGraph.xyz, MetaTags.io, HeyMeta all show Twitter card previews.

Common validation errors

ErrorCauseFix
"No card found"Missing or wrong twitter:card tagEnsure twitter:card is the first Twitter tag in <head>
"Image not found"Image URL is relative, HTTP, or 404Use absolute HTTPS URL, ensure the file exists
"Image too small"Image below minimum dimensionsRegenerate at the recommended size
"Card not rendering in timeline"Domain not whitelisted (for player cards)Submit domain for approval via Twitter support
Old card still showing after updateTwitter caches card data per URLCache typically expires in 7 days; for faster refresh, append a query string like ?v=2 to force a fresh fetch
Pro Tip To force Twitter to re-fetch your card, change the URL slightly (e.g., add ?v=2). Twitter treats each unique URL as a separate cached object.

11 Full Example

Complete Twitter Card setup with OG fallback for a blog article:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>The Hitchhiker's Guide to HTML — The Daily Probe</title>
  <meta name="description" content="A complete tutorial covering everything from DOCTYPE to Web Components.">

  <!-- Open Graph (used by FB, LinkedIn, Slack, iMessage, etc.) -->
  <meta property="og:type" content="article">
  <meta property="og:site_name" content="The Daily Probe">
  <meta property="og:title" content="The Hitchhiker's Guide to HTML">
  <meta property="og:description" content="A complete tutorial covering everything from DOCTYPE to Web Components.">
  <meta property="og:url" content="https://example.com/posts/html-guide">
  <meta property="og:image" content="https://example.com/og/html-guide-cover.jpg">
  <meta property="og:image:width" content="1200">
  <meta property="og:image:height" content="630">
  <meta property="og:image:alt" content="Stylized cover showing the title over a starfield">

  <!-- Twitter Card (uses OG fallback for title/description/image) -->
  <meta name="twitter:card" content="summary_large_image">
  <meta name="twitter:site" content="@dailyprobe">
  <meta name="twitter:creator" content="@jane_doe">
  <!-- Optional overrides — uncomment to customize for Twitter -->
  <!-- <meta name="twitter:title" content="..."> -->
  <!-- <meta name="twitter:description" content="..."> -->
  <!-- <meta name="twitter:image" content="..."> -->
  <!-- <meta name="twitter:image:alt" content="..."> -->

  <!-- Canonical -->
  <link rel="canonical" href="https://example.com/posts/html-guide">
</head>

12 Try It Yourself

Exercise 1 — Add a Twitter Card with one line If you already have OG tags on a page, add a single <meta name="twitter:card" content="summary_large_image"> tag and verify that Twitter now renders a large-image card. Test in the Tweet composer.
Exercise 2 — Author attribution Add twitter:site (your brand's @handle) and twitter:creator (your personal @handle) to a blog post page. Tweet a link to the page. The tweet should show "By @yourhandle" attribution in some Twitter clients.
Exercise 3 — Add image alt text Add twitter:image:alt (and the corresponding og:image:alt) to a page with an existing image. Verify in a screen reader or in the Twitter preview that the alt text is associated with the image.
Exercise 4 — Dual-stack: OG + Twitter Build a page where Twitter shows a different image than Facebook. Set og:image to a wide image (1200×630) and add an explicit twitter:image pointing to a square image (512×512) with twitter:card="summary". Test in both Facebook Debugger and the Twitter composer.

13 Real-World Use Cases

News & media sites

Every article page needs summary_large_image with a striking cover image to drive engagement in timelines.

Personal & dev blogs

Even hobbyist blogs benefit — Twitter Card previews measurably increase click-through rates.

Video platforms

YouTube, Vimeo, Twitch all use player cards so videos play inline in the timeline.

Mobile app marketing

App developers use app cards for app-install campaigns on Twitter.

E-commerce

Product pages benefit from summary_large_image with the product photo as the cover.

Podcasts

Podcast episode pages often use player cards so episodes play inline.
