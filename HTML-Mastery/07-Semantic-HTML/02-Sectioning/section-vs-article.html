<section> vs <article>

The most asked question in semantic HTML. Both have headings. Both group content. Both can nest inside each other. The difference comes down to one question: is this content self-contained and distributable? If yes — <article>. If it's just a thematic grouping — <section>. Here's the full decision framework.

1 Definitions

ElementSpec definitionPlain English
<section> "A thematic grouping of content, typically with a heading." A chapter, a tab, a themed region. It belongs with the rest of the page.
<article> "A self-contained composition that is, in principle, independently distributable or reusable." A blog post, a news story, a product card. It stands on its own.

Both elements accept headings, both create implicit sections, both can be nested. The difference is purely about portability: would this content make sense pulled out and shown on its own?

2 The key difference

The syndication test:

Would this content make sense if I put it
in an RSS feed or republished it on
another site, alone?

Yes — use <article>

A blog post. A news story. A product card. A recipe. A forum thread. A user comment.

These all stand alone. You could RSS-feed them or embed them on a partner site and they'd still make sense.

No — use <section>

The "Features" section of a homepage. The "About" section of a homepage. The "Ingredients" section of a recipe. The "Comments" wrapper around an article's comments.

These only make sense in the context of the surrounding content. Pull them out alone and they lose meaning.

Pro Tip A useful reframe: <article> answers "what is this?" (a post, a product, a comment). <section> answers "where does this fit?" (chapter 3, the ingredients list, the comments area). Both can have headings; the difference is portability.

4 When both apply (nesting)

It's common for a page to contain an <article> with multiple <section>s inside it, or for an <article> to contain other <article>s.

Pattern A: Article with thematic sections

<article>
  <h1>How to Brew Coffee</h1>
  <p>Intro…</p>

  <section aria-labelledby="ingredients-h">
    <h2 id="ingredients-h">Ingredients</h2>
    <ul>…</ul>
  </section>

  <section aria-labelledby="steps-h">
    <h2 id="steps-h">Steps</h2>
    <ol>…</ol>
  </section>

  <section aria-labelledby="tips-h">
    <h2 id="tips-h">Pro Tips</h2>
    <p>…</p>
  </section>
</article>

The whole article is syndicatable (RSS-able). Inside, sections organize it into themes. Sections wouldn't make sense alone — "Steps" without "Ingredients" and the article title would be useless.

Pattern B: Article with nested comment articles

<article>
  <h1>Blog Post Title</h1>
  <p>Body…</p>

  <section aria-labelledby="comments-h">
    <h2 id="comments-h">Comments</h2>

    <article>
      <h3>Comment by Bob</h3>
      <p>Great post!</p>
    </article>

    <article>
      <h3>Comment by Carol</h3>
      <p>I disagree because…</p>
    </article>
  </section>
</article>

The comments are wrapped in a <section> (it's a thematic group: "the comments area"). Inside, each comment is its own <article> — because each comment is independently distributable (you could quote it elsewhere).

Pattern C: Article inside a section inside an article

Deeply nested structures are legal. Don't go more than 3 levels deep without good reason — it confuses both authors and assistive tech.

<article>                  <!-- blog post -->
  <h1>Title</h1>

  <section>                <!-- comments area -->
    <h2>Comments</h2>

    <article>              <!-- a comment -->
      <h3>Bob's reply</h3>
      <p>…</p>

      <article>            <!-- a reply to that comment -->
        <h4>Carol's reply</h4>
        <p>…</p>
      </article>
    </article>
  </section>
</article>

5 When neither applies (use <div>)

If the content is purely for layout or styling — a flex container, a CSS Grid wrapper, a card that holds three icon+label pairs for visual reasons — use a <div>. Neither <section> nor <article> should be your default wrapper.

SituationUseWhy
Two-column grid wrapper around main + sidebar <div class="layout"> No semantic content of its own; just a layout shell
Card grid of three icon+text features <section> wrapping the grid; <div> per card The section has a heading; the cards are just visual units (no individual heading)
A row of buttons in a toolbar <div role="toolbar"> A toolbar is a UI pattern; use ARIA role + div, not section/article
A modal dialog body <div> inside <dialog> The dialog itself is the semantic container; inner divs are layout
An icon library sprite <svg> hidden, or <div hidden> No content to group semantically
Common Mistake Replacing every <div> with <section> "to be more semantic". A <section> without a heading is no more semantic than a div — and worse, it pollutes the a11y tree with phantom "region" landmarks that screen readers will try (and fail) to name. Use <section> only when there's a heading; otherwise stick with <div>.

6 Real-world examples

Example A: Landing page

<main>
  <!-- Hero: a themed region with heading -->
  <section aria-labelledby="hero-h">
    <h1 id="hero-h">Build Better Websites</h1>
    <p>Tagline…</p>
    <a href="/signup" class="cta">Get started</a>
  </section>

  <!-- Features: a themed region -->
  <section aria-labelledby="features-h">
    <h2 id="features-h">Features</h2>
    <div class="feature-grid">
      <div class="feature">…</div>
      <div class="feature">…</div>
      <div class="feature">…</div>
    </div>
  </section>

  <!-- Testimonials: each one is an article -->
  <section aria-labelledby="testimonials-h">
    <h2 id="testimonials-h">Testimonials</h2>
    <article class="testimonial">
      <blockquote>Acme saved us 40 hours a week.</blockquote>
      <p>— Bob, CTO at Startup</p>
    </article>
    <article class="testimonial">
      <blockquote>Best decision we made.</blockquote>
      <p>— Carol, Founder</p>
    </article>
  </section>
</main>

Each section is themed (hero, features, testimonials). Each testimonial is an article because it's a self-contained, quotable unit.

Example B: Blog post page

<main>
  <article>
    <header>
      <h1>Why Semantic HTML Matters</h1>
      <p>By Ada on <time datetime="2024-03-12">March 12</time></p>
    </header>

    <section aria-labelledby="intro-h">
      <h2 id="intro-h">Introduction</h2>
      <p>…</p>
    </section>

    <section aria-labelledby="why-h">
      <h2 id="why-h">Why It Matters</h2>
      <p>…</p>
    </section>

    <section aria-labelledby="how-h">
      <h2 id="how-h">How To Do It</h2>
      <p>…</p>
    </section>

    <footer>Tags: …</footer>
  </article>
</main>

Example C: Product listing

<main>
  <h1>Coffee Makers</h1>

  <section aria-label="Filters">
    <h2 class="visually-hidden">Filters</h2>
    <form>…</form>
  </section>

  <section aria-labelledby="products-h">
    <h2 id="products-h" class="visually-hidden">Products</h2>
    <div class="grid">
      <article>
        <h3><a href="/p/1">French Press</a></h3>
        <p>$24.99</p>
      </article>
      <article>
        <h3><a href="/p/2">Pour Over</a></h3>
        <p>$39.99</p>
      </article>
    </div>
  </section>
</main>

Each product card is an <article> — self-contained, could be embedded on a partner site. The grid wrapper is a <section> (themed region: "the products"). The grid itself is a <div> (purely visual).

7 The decision flowchart

1. Does this content have a heading?
   No  → use <div>
   Yes → continue

2. Is this content self-contained — could you put it
   in an RSS feed alone and it would make sense?
   Yes → use <article>
   No  → continue

3. Is this content a thematic grouping — a chapter,
   tab, themed region inside a larger piece?
   Yes → use <section>
   No  → continue

4. Does this content need to be addressable as a
   fragment (#section-name) for navigation?
   Yes → use <section>
   No  → use <div>
Pro Tip When in doubt, default to <div>. An unsemantic div is recoverable; an article-wrapping-everything page creates phantom landmarks that confuse screen reader users. Reach for <section> and <article> only when they genuinely fit.

8 Common mistakes

MistakeWhy it's wrongFix
Using <section> as a generic wrapper (no heading inside) Creates unnamed "region" landmarks that screen readers try to label and fail Use <div> for wrappers without headings
Using <article> for the entire page body A page is not a syndicatable composition Use <main>; reserve <article> for the actual article content
Using <article> for every card on a homepage Not every card is syndicatable. A "newsletter signup" card is not an article. Use <section> for non-syndicatable themed cards
Nesting <section> inside <section> inside <section> Levels of nesting obscure the outline; harder for SR users to track depth Keep nesting shallow; use headings, not section nesting, to convey depth
Forgetting aria-labelledby on <section> Section becomes an unnamed landmark; SR users can't distinguish multiple sections Always pair <section> with a heading that has an id, referenced via aria-labelledby
Replacing all <div>s with <section>s "for semantics" Creates a flood of unnamed region landmarks Keep <div> for layout-only wrappers
Using <article> for a single image A bare image isn't a composition Use <figure> instead
Wrapping comment threads in <section> but each comment in <div> Each comment IS a self-contained piece — should be <article> Wrap each comment in <article>

9 Try it yourself

Exercise 1 — Syndication audit Take a homepage or landing page. For each major block, ask: "Would this make sense in an RSS feed alone?" Mark each as article, section, or div. Refactor the markup to match.
Exercise 2 — Recipe page Build a recipe as an <article> with <section>s inside: Ingredients, Steps, Tips. Add aria-labelledby to each section pointing at its heading's id. Verify the heading outline in DevTools' Accessibility tab.
Exercise 3 — Product listing Build a product listing with three products. Wrap each in <article> (they're self-contained — could be embedded on a partner site). Wrap the whole list in <section>. Wrap each card image+text in a <div> for layout. Verify the structure makes sense when CSS is disabled.
Exercise 4 — Blog with comments Build a blog post as <article> with a "Comments" <section> containing three comment <article>s (one of which has a nested reply article). Test the heading outline — does it form a coherent tree?

10 Browser support

Chrome Firefox Safari Edge All modern mobile browsers

Both <section> and <article> have universal support in every modern browser. They are block-level by default with no built-in styling — same as <header>, <nav>, and <footer>.

The implicit ARIA roles differ:

  • <section> exposes role region only if it has an accessible name (via aria-label or aria-labelledby). Without a name, it has no role — just a generic element.
  • <article> exposes role article always, regardless of whether it has a name.

This is why naming your <section>s matters: an unnamed section is invisible to the accessibility tree as a landmark.

11 Real-world use cases

Blog posts

<article> wraps the post; <section>s divide it into chapters.

Documentation sites

Each doc page is an <article>; sub-topics are <section>s.

E-commerce listings

Each product card is <article>; the listing wrapper is <section>.

News sites

Article is <article>; "Related coverage" sidebar is <aside>; each related story inside it is <article>.

Forums

Thread is <article>; each reply is a nested <article>.

SaaS dashboards

Each panel/widget is a <section> with its own heading; rare to use <article> in dashboards.

Tutorials / courses

Course module is <section>; lesson is <article>.

Recipe sites

Recipe is <article>; ingredients/steps/nutrition are <section>s.

Email newsletters

Each story teaser is an <article>; newsletter masthead is <header>.
