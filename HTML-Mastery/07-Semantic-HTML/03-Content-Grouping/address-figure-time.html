<address>, <figure>, <time>, <mark>

Four content-with-meaning elements. <address> is the most misused — it's for contact info for the page or article author, not arbitrary addresses. <time> carries machine-readable datetimes. <figure> groups captioned content. <mark> highlights text semantically.

1 <address> — Author Contact Info

Of all the elements covered here, <address> is the most consistently misused. The HTML spec is crystal clear:

Definition The <address> element represents contact information for the author(s) of the current <article> or <body>. This includes physical addresses, email, phone, URL, social media handle, or geocoordinates — as long as it's how to contact the author.

The #1 misunderstanding

<address> is NOT a generic wrapper for any postal address on the page. A company's office address, a list of store locations, or a customer's shipping address are not what this element is for. Use a plain <p> with <br> or a structured format for those.

Rendered output (correct usage)

Written by Jane Doe.
Email: jane@example.com
Visit us at: example.com 
<footer>
  <address>
    Written by <a href="/authors/jane">Jane Doe</a>.<br>
    Email: <a href="mailto:jane@example.com">jane@example.com</a><br>
    Visit us at: <a href="https://example.com">example.com</a>
  </address>
</footer>

What goes inside <address>

AllowedNot allowed
Email links, phone links, web URLs, physical mailing address, social media handle, geocoordinates (lat/long), publication date Arbitrary text, document publication dates (use <time>), company mailing address when it's not the author's contact, addresses inside fictional content

Article-scoped vs page-scoped

If <address> is inside an <article>, it represents the contact info for that article's author. If it's directly in the <body> (not nested in an article), it represents the contact info for the entire document — typically placed in the <footer>.

<article>
  <h1>How to brew pour-over coffee</h1>
  <p>...</p>
  <footer>
    <address>
      By <a href="/authors/alice">Alice Ray</a> —
      <a href="mailto:alice@example.com">alice@example.com</a>
    </address>
  </footer>
</article>
Common Mistake Using <address> to mark up a customer's shipping address on an invoice, or the office address on a "Contact Us" page. These are NOT author contact details. Use <p>, optionally paired with structured data (JSON-LD PostalAddress) for SEO.

Default styling

Browsers render <address> as display:block with font-style:italic. This is one of the few UA styles you should usually leave alone — italics signal "this is meta-information".

2 <figure> — Review

The <figure> element was covered in depth in Section 4 — Figure & Figcaption. Here's a focused recap as part of the content-grouping family.

A <figure> represents content that is optionally captioned and is referenced from the main flow as a single unit. Its position in the document is independent of where it's referenced from — it could move to the top, side, or appendix without breaking the surrounding prose.

Rendered output

<figure>
  <blockquote>
    "The best way to predict the future is to invent it."
  </blockquote>
  <figcaption>— Alan Kay, 1971 Xerox PARC meeting</figcaption>
</figure>

What goes inside <figure>

Any flow content: <img>, <video>, <code> (a code listing), <blockquote>, <table>, <svg>, even another <figure>. The key test is: could this content be moved to an appendix without breaking the surrounding text?

Figure vs aside vs main content

Testfigureasidemain content
Referenced from main text?Yes (as a unit)Not necessarilyN/A — it IS the main text
Position-independent?YesSomewhatNo
Captioned?Optionally, via <figcaption>Usually notNo

3 <time> — Machine-Readable Dates

The <time> element represents a specific moment in time (a date, a date with time, a duration, or a time without a date). Its superpower is the datetime attribute, which lets you give the same value in a machine-readable form while displaying it however you like for humans.

Basic usage

<p>Published on <time>2024-03-15</time>.</p>

<p>Event starts at <time datetime="2024-03-15 19:30">
  March 15th at 7:30 PM</time>.</p>

<p>The meeting lasted <time datetime="PT2H30M">two and a half hours</time>.</p>

Rendered output

Published on 2024-03-15.

Event starts at March 15th at 7:30 PM.

The meeting lasted two and a half hours.

The datetime attribute — machine-readable formats

The datetime attribute uses a strict subset of ISO 8601. The visible text can be anything (e.g. "yesterday", "last Tuesday", "Spring 2024"), but the attribute value must follow these formats:

FormatExampleMeaning
Year only2024The year 2024
Year + month2024-03March 2024
Full date2024-03-15March 15, 2024
Date + time (local)2024-03-15 19:30March 15, 2024 at 7:30 PM (no timezone)
Date + time + timezone2024-03-15T19:30:00-05:00March 15, 2024 at 7:30 PM, US Eastern
UTC2024-03-15T19:30:00ZMarch 15, 2024 at 7:30 PM UTC
Time only19:30 or 19:30:007:30 PM (no date)
Duration (basic)PT2H30M2 hours, 30 minutes
Duration (alt)P2DT4H2 days, 4 hours
Recurring time09:00 with text "every weekday"9 AM, daily

Duration syntax explained

Durations use the pattern P[n]Y[n]M[n]DT[n]H[n]M[n]S — the P marks the start of the period, T separates date parts from time parts:

P1Y2M3D       — 1 year, 2 months, 3 days
PT4H30M       — 4 hours, 30 minutes
PT30S         — 30 seconds
P1DT12H       — 1 day, 12 hours
P1M           — 1 month (note: ambiguous with minutes, but minutes need the T prefix)
PT1M          — 1 minute

The pubdate attribute — deprecated!

An early HTML5 draft had a boolean pubdate attribute on <time>, marking the publication date of the nearest <article> ancestor. It was deprecated and removed from the spec in 2013.

Common Mistake Some tutorials still show <time datetime="..." pubdate>. This attribute does nothing in modern browsers. To indicate publication date, use structured data instead: 
<meta property="article:published_time" content="2024-03-15T19:30:00Z">

<!-- or JSON-LD -->
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "datePublished": "2024-03-15T19:30:00Z"
}
</script>

Why does machine-readable matter?

  • Search engines can extract event times for rich results.
  • Calendar apps can offer "Add to calendar" buttons from a page.
  • Browsers can offer to convert times to the user's timezone.
  • Assistive tech can announce dates more usefully.
Pro Tip When the visible text already matches the ISO format (e.g. "2024-03-15"), you can omit the datetime attribute — the parser will use the text content. But explicit is better than implicit; include datetime for any value more complex than a bare date.

4 <mark> — Semantic Highlight

The <mark> element represents a run of text that is marked or highlighted for reference or notation purposes, due to its relevance in another context. Browsers render it with a yellow background by default, mimicking a highlighter pen.

Rendered output

When you search for semantic HTML, the result page highlights the matching term in each result snippet.

The three semantic contexts

1. Search-result highlighting

<p>The page describes <mark>accessibility</mark>
   best practices for web developers.</p>

The most common use case: when showing a search result snippet, the matching query term is highlighted with <mark>.

2. Quotation emphasis (not in the original)

<blockquote>
  "The most important thing is to ship. Everything else is detail.
   <mark>Ship early, ship often.</mark>"
</blockquote>
<p>[emphasis added]</p>

When quoting a passage and adding your own emphasis to part of it, <mark> makes the addition explicit. (Use the cite attribute or a footnote to disclose "[emphasis added]" for full transparency.)

3. Marked as currently relevant in context

<p>Today we're reviewing the <mark>2024 audit</mark>
   findings. Please turn to page 12.</p>

Used to draw the reader's attention to a particular phrase because of the current viewing context (e.g. the same word elsewhere on the page is being discussed).

mark vs strong vs em

ElementSemanticsDefault styling
<mark>Relevant in a different context (search hit, quote emphasis)Yellow background
<strong>Important, serious, urgentBold
<em>Stress emphasis (would change pronunciation)Italic
<b>Stylistically offset, no extra meaningBold
Common Mistake Using <mark> purely as a yellow highlighter for aesthetic effect. If you just want a yellow background, use <span class="highlight"> with CSS. Reserve <mark> for cases where the highlighting has semantic meaning (search hit, quote emphasis).

6 Browser Support

<address> — all browsers, all versions <figure> — IE 9+, all modern <time> — IE 9+, all modern <mark> — IE 9+, all modern

All four elements have universal support. <time>'s datetime duration syntax is the only feature with any nuance — older parsers may not recognize all duration forms, but browsers do.

7 Try It Yourself

Exercise 1 — Fix the address This snippet misuses <address>. Rewrite it correctly, separating the author contact info from the store locations: 
<address>
  Author: Jane Doe
  HQ: 123 Main St, Anytown, USA
  Store 1: 456 Oak Ave, Springfield
  Store 2: 789 Pine Rd, Shelbyville
</address>
Exercise 2 — Mark up an event card Build an event listing with: title, a date/time marked up with <time datetime="..."> (visible text in friendly format), and a brief description. Make sure your datetime value is a valid ISO 8601 string with timezone.
Exercise 3 — Search results page Build a fake search results page where the user searched for "CSS grid". Each result snippet should use <mark> to highlight the matching term. Add a result count: "About 1,240,000 results (0.42 seconds)" with the time value wrapped in <time datetime="PT0.42S">.
Exercise 4 — Quotation emphasis Find a quote you love and present it as a <figure> with <blockquote> inside, using <mark> to highlight one phrase you want to draw attention to. Add a <figcaption> with the attribution.

8 Real-World Use Cases

address

Footer "About the author" block on a blog post; article footer contact info on news sites.

figure

Captioned images in articles, pull-quotes in long-form posts, code listings in documentation.

time

Blog post publication dates, event start times, comment timestamps, cooking recipe durations.

mark

Search result snippets, quotation emphasis, scroll-to-text fragments.

Combined: article footer

News article footer typically uses <address> (author), <time> (pub date), sometimes <figure> for related photo credit.

SEO rich results

Combined with JSON-LD Article schema, <time> + <address> power event rich results in Google.
