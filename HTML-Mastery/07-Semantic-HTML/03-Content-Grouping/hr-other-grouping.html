<hr>, <bdi>, <bdo>, <wbr>, <ruby>

Five specialized elements with narrow but important jobs: <hr> marks a thematic break (not just a line). <bdi> isolates bidirectional text. <bdo> overrides direction explicitly. <wbr> hints where a long word can break. <ruby>/<rt>/<rp> annotate CJK characters with pronunciation.

1 <hr> — Thematic Break

Long called a "horizontal rule", <hr> was redefined in HTML5 as a thematic break — a transition between topics within a single section. It carries actual semantic meaning: "what comes next is a different topic".

Rendered output

First, we'll cover the history of HTML.

Now, let's look at where HTML is going next.

<p>First, we'll cover the history of HTML.</p>
<hr>
<p>Now, let's look at where HTML is going next.</p>

When to use it

  • Switching between two distinct topics within the same article.
  • Separating the main story from an "About the author" note.
  • Transitioning from narrative to a sidebar callout box (when not using <aside>).
  • In poetry, separating stanzas where a clear thematic shift occurs (otherwise use <p>).

When NOT to use it

Common Mistakes
  • Using <hr> for visual decoration (a line for the sake of a line). Use a styled <div> or CSS border instead.
  • Adding <hr> between every paragraph. That's not a thematic break — that's a typographic choice.
  • Using it to separate sections that should be marked up with <section>.

Styling

Default UA styling renders <hr> as a 1-2px gray line with margins. You can heavily customize it:

/* Modern flat style */
hr {
  border: 0;
  height: 2px;
  background: linear-gradient(90deg,
              transparent, var(--brand), transparent);
  margin: 32px 0;
}

/* Dotted */
hr { border: 0; border-top: 2px dotted #94a3b8; }

/* Decorative centered glyph */
hr {
  border: 0;
  text-align: center;
  height: 30px;
}
hr::after {
  content: '❧';
  color: var(--brand);
  font-size: 1.4rem;
}

Accessibility

Screen readers may announce <hr> as "separator" or "thematic break" depending on the reader. It's a useful navigation cue. Don't replace it with a styled <div> unless you add role="separator" to maintain parity.

2 <bdi> — Bidirectional Isolation

The <bdi> element isolates a span of text from the surrounding bidirectional algorithm. Use it when you're displaying user-generated content whose writing direction you don't know in advance.

The problem it solves

The Unicode Bidirectional Algorithm assumes neighboring text shares a direction. When you mix LTR (left-to-right, e.g. English) and RTL (right-to-left, e.g. Arabic or Hebrew) text without isolation, the algorithm can produce garbled output.

Imagine a chat application displaying messages from users with usernames in mixed scripts:

<!-- Without bdi -->
<p>User <b>إبراهيم</b>: 5 wins</p>

<!-- The "5 wins" may render to the LEFT of the username
     on RTL-aware browsers, because the algorithm thinks
     the surrounding context inherits direction from "إبراهيم". -->
<!-- With bdi — correctly isolated -->
<p>User <bdi><b>إبراهيم</b></bdi>: 5 wins</p>

When to use bdi

  • Displaying usernames, handles, or display names from user accounts (any language).
  • Embedding numbers or codes between RTL and LTR text.
  • Anywhere you insert content of unknown direction into a sentence.
Pro Tip <bdi> defaults to dir="auto" — it figures out its own direction from the content's first strong directional character. You rarely need to add an explicit dir attribute.

3 <bdo> — Bidirectional Override

While <bdi> isolates direction, <bdo> forces a specific direction on its contents, overriding the Unicode Bidi algorithm entirely. It's a stronger, more invasive tool.

The dir attribute is required

<bdo> requires an explicit dir attribute — either "ltr", "rtl", or "auto". Without it, the element does nothing meaningful.

<p>The Hebrew word for "peace" is
   <bdo dir="rtl">שלום</bdo>,
   written right-to-left.</p>

Rendered output

The Hebrew word for "peace" is שלום, written right-to-left.

bdi vs bdo — when to pick which

Criterion<bdi><bdo>
PurposeIsolate (let content's direction win)Override (force a direction)
dir attributeOptional (defaults to auto)Required (ltr/rtl)
Typical useUser-generated content of unknown directionYou know the direction should be different from context
ExampleUsername from a databaseDisplaying Hebrew text in an English sentence
Common Mistake Using <bdo dir="rtl"> just to right-align text. <bdo> changes the direction of characters, not their alignment. To right-align text, use CSS text-align: right and direction: rtl on a regular element.

4 <wbr> — Word Break Opportunity

The <wbr> element represents a position in the text where the browser may break a line if needed. It produces no visible character, no hyphen, and no extra space — it's purely a hint that "if you need to wrap, here is a good place".

Use cases

  • Long URLs or email addresses that should wrap gracefully.
  • CamelCase identifiers in code samples (break between word boundaries).
  • Long compound words in German or other languages that allow mid-word breaks.
  • Path strings like /usr/local/bin/some-very-long-tool-name.
<p>For details, see
   https://example.com/very/long/path<wbr>/that/might/wrap</p>

<p>The exception was thrown by
   FileSystem<wbr>Interactor<wbr>Factory<wbr>Impl.</p>

Rendered output (resize the window to see wrapping)

For details, see https://example.com/very/long/path/that/might/wrap/and/continue/on/for/ever

wbr vs zero-width space (U+200B)

Both achieve the same effect, but <wbr> is a real HTML element visible in source code, while &#8203; is invisible and easy to copy-paste accidentally. Prefer the element form for clarity.

wbr vs soft hyphen (&shy;)

The soft hyphen &shy; (U+00AD) also marks a break opportunity, but adds a visible hyphen when the line breaks there. <wbr> never adds a hyphen. Choose based on whether you want the break to be visible.

5 <ruby>, <rt>, <rp> — CJK Annotations

Ruby annotations are small pronunciation guides (or other annotations) placed above or beside CJK (Chinese, Japanese, Korean) characters. They're common in:

  • Japanese furigana — hiragana above kanji to indicate pronunciation.
  • Chinese pinyin/bopomofo — romanized or zhuyin pronunciation above characters.
  • Korean hangul — for hanja characters.

The three elements

ElementPurpose
<ruby>Container for the base text plus its annotation(s)
<rt>Ruby text — the annotation itself (e.g. pronunciation)
<rp>Fallback parenthesis shown only by browsers that DON'T support ruby

Basic example — Japanese furigana

<ruby>
  漢<rp>(</rp><rt>かん</rt><rp>)</rp>
  字<rp>(</rp><rt>じ</rt><rp>)</rp>
</ruby>

Rendered output

漢(かん)字(じ)

Chinese pinyin example

<ruby>
  北<rp>(</rp><rt>běi</rt><rp>)</rp>
  京<rp>(</rp><rt>jīng</rt><rp>)</rp>
</ruby>

Rendered output

北(běi)京(jīng)

Why the <rp> element matters

In browsers that don't support <ruby>, the <rt> content would render inline with the base text — turning "漢字" into "漢かん字じ" — which is unreadable. The <rp> ("ruby parenthesis") element wraps parentheses that browsers with ruby support hide, but browsers without ruby support render. So unsupported browsers show "漢(かん)字(じ)" — at least readable as "kanji with annotations".

Pro Tip All modern browsers support <ruby>. You can technically skip the <rp> element today, but including it costs nothing and provides a graceful fallback for ancient browsers and some screen readers that don't process ruby.

Styling ruby

/* Position annotation above by default */
ruby { ruby-position: over; }

/* For Chinese pinyin (or any language where annotation
   below is preferred) */
ruby { ruby-position: under; }

/* Larger, colored furigana */
rt { font-size: 0.55em; color: var(--brand); }

6 Bidirectional Text Deep Dive

HTML's bidirectional support is rooted in Unicode's Bidi Algorithm (UAX #9). The HTML-level tools layer on top:

ToolLevelWhat it does
dir attribute on any elementHTMLSets the base direction for that element's content
<bdo dir="...">HTMLForces the direction regardless of content
<bdi>HTMLIsolates content so it can't influence surrounding text
Unicode Bidi Control chars (LRE, RLE, PDF)UnicodeDeprecated in favor of HTML elements
Unicode Isolate chars (FSI/PDI)UnicodeEquivalent to <bdi> at character level

When mixing content from multiple users

This is the canonical case for <bdi>:

<ul class="leaderboard">
  <li>
    <span class="rank">1</span>
    <bdi class="name">محمد</bdi>
    <span class="score">12,450</span>
  </li>
  <li>
    <span class="rank">2</span>
    <bdi class="name">David</bdi>
    <span class="score">11,830</span>
  </li>
</ul>

Wrapping each name in <bdi> ensures the Arabic name doesn't cause the score number to render in the wrong position.

7 Browser Support

<hr> — universal <bdi> — Chrome 16+, Firefox 11+, Safari 5.1+ <bdo> — universal <wbr> — IE 5.5+, all modern <ruby>/<rt>/<rp> — IE 5+, all modern

All five element groups have universal support in modern browsers. <bdi> is the youngest, but it shipped in 2011, so you don't need polyfills.

8 Try It Yourself

Exercise 1 — Thematic breaks Take a 5-paragraph article on a topic of your choice. Insert <hr> elements only between paragraphs where the topic genuinely shifts. Style the <hr> with a custom CSS gradient.
Exercise 2 — Chat message list Build a chat interface with three messages from three different users. Use mixed-script usernames (one English, one Arabic, one Hebrew or Chinese). Wrap each username in <bdi>. Verify in a browser that messages render correctly without bizarre reordering.
Exercise 3 — Long URL wrap Insert a long URL into a narrow column (200px wide) and demonstrate the difference between no wrapping, overflow-wrap: break-word, and strategic <wbr> placement.
Exercise 4 — Furigana Mark up the Japanese phrase "おはようございます" (ohayō gozaimasu) with <ruby> annotations providing romaji pronunciation above each segment. Add <rp> parentheses for fallback.

9 Real-World Use Cases

hr

Blog posts switching topics, recipe "method" to "serving suggestion", legal document section transitions.

bdi

Chat apps, leaderboards, comment sections, anywhere user-generated names appear.

bdo

Language-learning sites, dictionaries, multilingual marketing pages with deliberate RTL/LTR mixing.

wbr

Code samples in documentation, URLs in forum posts, file paths in error messages.

ruby/rt/rp

Japanese learning apps, Chinese study sites, Bopomofo teaching tools, dictionaries.
