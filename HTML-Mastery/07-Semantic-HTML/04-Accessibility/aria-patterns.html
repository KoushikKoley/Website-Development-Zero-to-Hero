Common ARIA Patterns in HTML

ARIA attributes are tools for fixing accessibility gaps that HTML alone can't fill. Most pages only need a handful of patterns — naming things with aria-label/aria-labelledby/aria-describedby, announcing dynamic changes with aria-live, tracking collapsible state with aria-expanded/aria-controls, and pointing at the current page with aria-current. Master these and you've covered 90% of real-world ARIA.

1 The First Rule of ARIA

Before learning any ARIA pattern, internalize the First Rule of ARIA from the WAI-ARIA spec:

First Rule of ARIA If you can use a native HTML element or attribute with the semantics and behavior you require already built in, instead of re-purposing an element and adding an ARIA role, state or property to make it accessible, then do so.

In practice, this means:

  • Use <button>, not <div role="button">.
  • Use <a href>, not <span role="link">.
  • Use <input type="checkbox">, not <div role="checkbox" aria-checked>.
  • Use <nav>, not <div role="navigation">.
  • Use <details>/<summary> for native disclosure widgets instead of custom ARIA ones — though with the caveat that <details> has limited animation support.

ARIA's actual job is to fill the gaps where no native element exists: live regions, complex widgets (tabs, menus, comboboxes, tree views), and naming things that HTML can't name on its own.

Pro Tip Run your page through the W3C validator before adding ARIA. The validator catches many "you added ARIA where a native element would do" mistakes automatically.

2 Naming Things: aria-label & aria-labelledby

The most common ARIA task: giving an element an accessible name. Two attributes do this job, in two different ways.

aria-label — string literal

Use when the name is short, fixed, and not visible elsewhere on the page.

<button aria-label="Close dialog">
  <svg aria-hidden="true">...× icon...</svg>
</button>

<nav aria-label="Primary navigation">...</nav>

<input type="search" aria-label="Search this site">

aria-labelledby — reference to visible text

Use when there's already visible text on the page that names the element. The attribute takes a space-separated list of element IDs.

<section aria-labelledby="weather-heading">
  <h2 id="weather-heading">Today's weather</h2>
  ...
</section>

<button aria-labelledby="btn-label">
  <span id="btn-label">Read more</span>
  <svg aria-hidden="true">...arrow icon...</svg>
</button>

When to use which

UseWhenExample
aria-labelName not visible on page (icon-only button)Close button with just an × icon
aria-labelledbyName IS visible and you want to reuse itSection heading also serves as the region label
Common Mistake Don't duplicate the visible text via aria-label. If your <button> already says "Submit", do NOT add aria-label="Submit" — the visible text already provides the accessible name. Adding the attribute can cause some screen readers to announce the word twice.
Pro Tip aria-labelledby can reference multiple IDs (space-separated). The names are concatenated in order. This is great for "Save" buttons that should announce as "Save [filename]". 
<button aria-labelledby="action-verb target-name">
  <span id="action-verb">Save</span>
  <span id="target-name">report.pdf</span>
</button>

3 Describing Things: aria-describedby

While aria-labelledby provides the name (short label), aria-describedby provides a longer description — typically rendered by screen readers after the element is announced, often on user request.

<label for="cc">Credit card number</label>
<input type="text" id="cc"
       aria-describedby="cc-hint cc-error">
<p id="cc-hint">16 digits, no spaces.</p>
<p id="cc-error" class="error">Card number is invalid.</p>

Screen reader users hear: "Credit card number, edit text. 16 digits, no spaces. Card number is invalid."

Typical uses

  • Form fields with hint text or error messages.
  • Buttons that need explanation beyond their visible label.
  • Tooltip content (paired with role="tooltip" on the description element).
  • Dialog descriptions that appear after the dialog title is announced.

4 Live Regions: aria-live

When content on a page changes dynamically (e.g. a chat message arrives, a form validation error appears, a search results count updates), sighted users see the change instantly. Screen-reader users would otherwise have no idea. Live regions tell AT to announce these changes.

The three values

ValueWhen announcedUse for
off (default)Never announcedStatic content
politeWhen the user pauses — the screen reader finishes the current utterance, then announcesMost cases: status messages, chat messages, search result counts
assertiveImmediately — interrupts the current utteranceCritical errors only: "Form submission failed", "Session expiring"
 
<!-- Status update that doesn't interrupt -->
<div aria-live="polite" id="status"></div>
<script>
  document.getElementById('status').textContent = 'Saved.';
</script>

<!-- Critical error that interrupts -->
<div aria-live="assertive" role="alert" id="error"></div>
<script>
  document.getElementById('error').textContent =
    'Connection lost. Reconnecting...';
</script>
Common Mistake Overusing assertive. Most status messages should be polite. Interrupting a screen-reader user mid-utterance is jarring and disorienting — reserve assertive for situations where missing the message would cause real harm (data loss, security issue).

Companion attributes

  • aria-atomic="true" — announce the entire region, not just the changed node. Useful when a small update only makes sense in context.
  • aria-relevant="additions removals text" — what kinds of changes should be announced. Defaults to "additions text" which is usually right.

role="alert" and role="status" — the shortcuts

Two ARIA roles imply a live region with sensible defaults, so you don't need aria-live alongside them:

  • role="alert" implies aria-live="assertive" and aria-atomic="true".
  • role="status" implies aria-live="polite" and aria-atomic="true".
<!-- Equivalent — but role="status" is shorter -->
<div role="status" id="save-status"></div>
<div aria-live="polite" aria-atomic="true" id="save-status"></div>

5 Collapsibles: aria-expanded & aria-controls

Any time you build a custom toggle (accordion, dropdown, disclosure panel), you need two ARIA attributes to make it accessible: aria-expanded on the trigger, and aria-controls linking the trigger to the panel it controls.

aria-expanded

Boolean state. true when the controlled panel is open; false when closed. The screen reader announces "expanded" or "collapsed" accordingly.

aria-controls

The id of the element being controlled. Lets AT users jump from the trigger directly to the panel.

<button aria-expanded="false"
        aria-controls="panel-1"
        id="trigger-1">
  Show more
</button>
<div id="panel-1"
     role="region"
     aria-labelledby="trigger-1"
     hidden>
  <p>Here's the hidden content.</p>
</div>

<script>
  const btn = document.getElementById('trigger-1');
  const panel = document.getElementById('panel-1');
  btn.addEventListener('click', () => {
    const isOpen = btn.getAttribute('aria-expanded') === 'true';
    btn.setAttribute('aria-expanded', String(!isOpen));
    panel.hidden = isOpen;
    btn.textContent = isOpen ? 'Show more' : 'Show less';
  });
</script>

Live demo (click to expand)

Here is the hidden content! The trigger's aria-expanded attribute toggles between "true" and "false", so screen-reader users hear whether the panel is open before deciding to expand it.
Pro Tip — when to prefer <details> For simple show/hide with no animation, the native <details>/<summary> elements handle all of this for free — no ARIA, no JavaScript. Only reach for the custom aria-expanded pattern when you need finer control (animation, custom keyboard behavior, async-loaded content).

6 aria-current for Navigation

The aria-current attribute indicates the element that represents the current item within a set — most commonly the current page in a nav menu, the current step in a multi-step process, or the current date in a calendar.

Values

ValueUse
pageCurrent page in a nav menu
stepCurrent step in a multi-step process
locationCurrent location in a breadcrumb trail
dateCurrent date in a calendar
timeCurrent time in a timetable
trueGeneric "current item" when no specific token fits
false (default)Not the current item
 
<nav aria-label="Primary">
  <ul>
    <li><a href="/" aria-current="page">Home</a></li>
    <li><a href="/blog">Blog</a></li>
    <li><a href="/about">About</a></li>
  </ul>
</nav>

Screen readers announce: "Home, link, current page".

Common Mistake Removing the href attribute from the current-page link (turning it into a non-link). Keep it a real link so users can bookmark, refresh, or copy the URL via right-click. Use aria-current="page" to mark it as the current location, not disabled or removing the href.
Pro Tip Browsers apply a default style of outline: thin solid to elements with aria-current="page" in some user stylesheets — but don't rely on that. Add your own visual cue (color, background, underline, a marker dot) so sighted users can see which page they're on too.

7 aria-hidden — Removing from the a11y Tree

The aria-hidden="true" attribute removes an element from the accessibility tree entirely. Screen readers will not announce it, even though it's still visible on screen.

Valid uses

  • Decorative icons next to text labels: <svg aria-hidden="true">. The text conveys the meaning; the icon is just decoration.
  • Repetitive content: a duplicate of a visible label that's already announced via aria-labelledby.
  • Off-canvas or visually-collapsed UI that shouldn't be announced while collapsed.
<button aria-label="Search">
  <svg aria-hidden="true" focusable="false">
    <path d="M11 4a7 7 0 1 0 0 14 7 7 0 0 0 0-14Zm9 16l-4.5-4.5"/>
  </svg>
</button>

The big DON'T

Critical Mistake Never put aria-hidden="true" on an element that contains focusable children (links, buttons, inputs). The element disappears from the a11y tree, but its focusable descendants remain keyboard-focusable — producing "ghost focus" where the user can tab to an element they can't perceive. This is one of the most common and harmful ARIA bugs.

❌ Wrong: focusable inside aria-hidden

<div aria-hidden="true">
  <button>Ghost button</button>
</div>

✅ Right: use the hidden attribute

<div hidden>
  <button>Truly hidden button</button>
</div>

The HTML hidden attribute removes the element from both the visual layout AND the accessibility tree, AND removes its focusable descendants from the tab order. It's the correct tool for hiding content from everyone. Use aria-hidden only when the content should remain visible but unannounced.

9 Browser & AT Support

aria-label — all browsers, all AT aria-labelledby — all browsers, all AT aria-describedby — all browsers, all AT aria-live — all modern AT (some old NVDA builds miss assertive) aria-expanded — all browsers, all AT aria-controls — NVDA, JAWS, VoiceOver aria-controls — TalkBack support varies aria-current — all modern browsers and AT aria-hidden — all browsers, all AT

None of these attributes require polyfills. The only "soft spot" is aria-controls support in TalkBack (Android's screen reader), which is incomplete in some versions — but the attribute does no harm even when unsupported.

10 Try It Yourself

Exercise 1 — Fix an icon-only button Take this snippet and make it accessible. The button currently has no accessible name: 
<button>
  <svg viewBox="0 0 24 24">
    <path d="M18 6L6 18M6 6l12 12" />
  </svg>
</button>
Hint: add an aria-label on the button AND aria-hidden on the SVG.
Exercise 2 — Build an accessible accordion Build a 3-section accordion (closed by default) using buttons with aria-expanded and aria-controls, plus collapsible panels with role="region". Add JavaScript to toggle the state. Test with the tab key — only the closed buttons should be focusable.
Exercise 3 — Live status updates Build a "Save" button that simulates an async save: clicking it shows a "Saving..." message, then 1.5 seconds later updates to "Saved!". Use role="status" on the status container. Test with a screen reader to confirm the announcements happen without focus moving.
Exercise 4 — Current nav item Build a 4-link navigation menu. Pick one link to be "current" using aria-current="page". Style the current link with a CSS attribute selector (a[aria-current="page"]) so it's visually distinct.

11 Real-World Use Cases

Icon-only buttons

Close, hamburger menu, search magnifier — every UI toolbar needs aria-label on these.

Form validation

aria-describedby links inputs to error messages; role="alert" announces them when they appear.

SPAs & dynamic UIs

React/Vue/Svelte apps updating state need aria-live regions to announce results.

Accordions & tabs

Custom disclosure widgets need aria-expanded/aria-controls (or just use <details>).

Active nav states

Every multi-page site uses aria-current="page" in its nav menus.

Decorative SVGs

Every site with icons needs aria-hidden="true" on decorative SVGs paired with text labels.
