1 Document Skeleton

The minimum valid HTML document. Every page on the web is a variation of this.

<!-- HTML5 always starts with this doctype -->
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Page Title</title>
    <meta name="description" content="A 150–160 char summary.">
  </head>
  <body>
    <!-- visible content goes here -->
  </body>
</html>

Why each piece matters

PiecePurpose
<!DOCTYPE html>Forces standards mode. Without it, browsers enter quirks mode (box model breaks).
lang="en"Tells screen readers which language voice to use. Required for accessibility.
<meta charset>Must be in the first 1024 bytes. Otherwise the browser may misread special characters.
viewportWithout it, mobile browsers render at desktop width and zoom out — text becomes unreadable.
<title>The single most important on-page SEO signal. Shows in the browser tab and search results.

2 Metadata Elements

Live in <head>. Invisible to the user, but critical for browsers, search engines, and social platforms.

<title>

Page title. Required. 50–60 chars for SERP display.

<base> VOID

Sets default URL and target for all relative links. Rarely used.

<link> VOID

External resources: stylesheets, favicons, preconnect, preload.

<meta> VOID

Page metadata: charset, viewport, description, OG tags, robots.

<style>

Embedded CSS. Prefer external stylesheets in production.

<script>

JavaScript. Use type="module" and defer by default.

<!-- Standard meta tags -->
<meta name="description" content="...">
<meta name="author" content="Maya Kowalski">
<meta name="robots" content="index, follow">
<meta name="theme-color" content="#0f172a">

<!-- Open Graph (Facebook, LinkedIn, Slack) -->
<meta property="og:title" content="...">
<meta property="og:description" content="...">
<meta property="og:image" content="https://example.com/og.png">
<meta property="og:url" content="https://example.com/page">
<meta property="og:type" content="article">

<!-- Twitter Card -->
<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:site" content="@yourhandle">

<!-- Performance hints -->
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preload" as="image" href="hero.webp" fetchpriority="high">
<link rel="icon" href="/favicon.ico">
<link rel="canonical" href="https://example.com/page">

<!-- CSS -->
<link rel="stylesheet" href="/styles.css">
<style>body { margin: 0; }</style>

<!-- JS -->
<script src="/app.js" type="module" defer></script>
Pro Tip Always include theme-color — it tints the mobile browser UI bar to match your brand. Costs nothing, looks polished.

3 Sectioning Elements

HTML5 added semantic sectioning elements. Use them instead of <div class="header"> — they expose landmarks to screen readers automatically.

<header>

Introductory content or navigational aids. Page or section level.

<footer>

Footer for its nearest section. Author, copyright, related links.

<main>

The main content. Only one per page. Excludes header, footer, nav, aside.

<nav>

A major navigation block. Skip for footer link lists.

<section>

Themed grouping, always with a heading.

<article>

Self-contained, distributable content. Blog post, product card, news item.

<aside>

Tangentially related. Sidebar, pull quote, related links.

<address>

Contact information for the nearest article or body.

<hgroup> NEW

Groups a heading with its subheading(s). Re-defined 2020.

<search> NEW

Wraps a search form or filter UI. Added 2023.

<body>
  <header>
    <a href="/"><img src="logo.svg" alt="Acme"></a>
    <nav aria-label="Primary">...</nav>
  </header>

  <main>
    <article>
      <header>
        <h1>Article Title</h1>
        <p>By Maya · March 12, 2025</p>
      </header>
      <section>
        <h2>First section</h2>
        <p>...</p>
      </section>
      <aside>
        <h2>Related</h2>
        ...
      </aside>
    </article>
  </main>

  <footer>
    <address>Contact: hello@acme.com</address>
    <small>© 2025 Acme Inc.</small>
  </footer>
</body>

4 Headings & Paragraphs

<h1> – <h6>

Six levels of headings. Use one <h1> per page.

<p>

Paragraph. Block-level. Most-used text element.

<hr> VOID

Thematic break. Use between topic shifts, not as decoration.

<pre>

Preformatted text. Preserves whitespace. Pair with <code>.

<blockquote>

Block quotation. Always include a <cite> source.

<address>

Contact info for nearest section. Italic by default.

<h1>Site Title</h1>
<h2>Section Heading</h2>
<h3>Subsection Heading</h3>

<p>A paragraph. Wrap inline elements like <strong>bold</strong>
and <em>italic</em> inside.</p>

<hr>

<pre><code>function hello() {
  return "world";
}</code></pre>

<blockquote>
  <p>Simplicity is the soul of efficiency.</p>
  <footer>— <cite>Austin Freeman</cite></footer>
</blockquote>
Common Mistake Don't skip heading levels (e.g. <h1> → <h4>). Screen reader users navigate by heading hierarchy. Use them in order: h1 → h2 → h3 → h4.

6 Edits: <ins> and <del>

Track edits inline. Useful for diffs, changelogs, and legal text. Both accept datetime and cite attributes.

<p>
  The new price is <del datetime="2025-03-01" cite="/changelog#price-update">$89</del>
  <ins datetime="2025-03-01">$79</ins> per month.
</p>

7 Lists

<ul>

Unordered list. Bullet points.

<ol>

Ordered list. Use start, reversed, type.

<li>

List item. Required child of ul/ol/menu.

<dl>

Description list (terms + descriptions).

<dt>

Description term.

<dd>

Description details.

<menu>

Semantic list of commands. Like <ul> but for actions.

<!-- Unordered -->
<ul>
  <li>First item</li>
  <li>Second item</li>
</ul>

<!-- Ordered with options -->
<ol type="A" start="3">
  <li>Starts at C</li>
  <li>Then D</li>
</ol>
<ol reversed>
  <li>Counts down</li>
</ol>

<!-- Description list -->
<dl>
  <dt>HTML</dt>
  <dd>HyperText Markup Language — the structure of the web.</dd>
  <dt>CSS</dt>
  <dd>Cascading Style Sheets — presentation.</dd>
</dl>

<!-- Nested -->
<ul>
  <li>Top level
    <ul>
      <li>Nested item</li>
    </ul>
  </li>
</ul>

8 Links & Anchors

<!-- Internal page link (fragment) -->
<a href="#section">Jump to section</a>

<!-- Relative -->
<a href="/about.html">About</a>

<!-- Absolute -->
<a href="https://example.com/" rel="external">Example</a>

<!-- Email (opens mail client) -->
<a href="mailto:hello@example.com?subject=Hello">Email</a>

<!-- Phone -->
<a href="tel:+15551234567">+1 (555) 123-4567</a>

<!-- SMS -->
<a href="sms:+15551234567?body=Hi%20there">Text us</a>

<!-- Download -->
<a href="report.pdf" download="annual-report.pdf">Download PDF</a>

<!-- New tab (use sparingly, with rel) -->
<a href="https://example.com" target="_blank" rel="noopener noreferrer">
  Opens in new tab
</a>

<!-- Image link -->
<a href="/" aria-label="Home"><img src="logo.svg" alt=""></a>

9 Images

<img> VOID

Raster or SVG image. Always include alt.

<picture>

Container for art direction. Wraps <source> + <img>.

<source> VOID

Media query alternative for <picture> or <video>.

<figure>

Self-contained content with optional caption.

<figcaption>

Caption for <figure>. First or last child.

<map>

Image map (clickable regions).

<area> VOID

Region inside <map>. Use shape + coords.

<!-- Basic -->
<img src="hero.jpg" alt="Mountain landscape at sunrise"
     width="1600" height="900" loading="lazy" decoding="async">

<!-- Responsive with srcset -->
<img src="hero-800.jpg"
     srcset="hero-400.jpg 400w, hero-800.jpg 800w, hero-1600.jpg 1600w"
     sizes="(max-width: 600px) 100vw, 50vw"
     alt="...">

<!-- Art direction with <picture> -->
<picture>
  <source srcset="hero-mobile.webp" media="(max-width: 600px)">
  <source srcset="hero.webp" type="image/webp">
  <img src="hero.jpg" alt="...">
</picture>

<!-- Figure with caption -->
<figure>
  <img src="chart.png" alt="Q3 revenue by region">
  <figcaption>Q3 revenue grew 18% YoY, led by EMEA.</figcaption>
</figure>
Always set width & height Even when CSS resizes the image, explicit attributes let the browser reserve space, preventing layout shift (CLS). Pair with loading="lazy" for below-the-fold images.

10 Audio & Video

<video>

Video player. Native controls, captions, poster.

<audio>

Audio player. Same model as <video>.

<source> VOID

Multiple format fallbacks.

<track> VOID

WebVTT subtitles, captions, descriptions.

<embed> VOID

External content (legacy — prefer <iframe>).

<object>

External resource (legacy — prefer <iframe>).

<param> VOID DEPR

Parameters for <object>. Avoid.

<video controls preload="metadata" poster="poster.jpg"
       width="1280" height="720">
  <source src="movie.mp4" type="video/mp4">
  <source src="movie.webm" type="video/webm">
  <track kind="subtitles" src="subtitles.en.vtt"
         srclang="en" label="English" default>
  <track kind="captions" src="captions.en.vtt"
         srclang="en" label="English captions">
  Your browser does not support the video tag.
</video>

<audio controls preload="none">
  <source src="song.mp3" type="audio/mpeg">
  <source src="song.ogg" type="audio/ogg">
</audio>

Video attributes

AttributeEffect
controlsShow native play/pause/volume UI.
autoplay mutedAutoplay allowed only when muted.
loopRestart when finished.
mutedAudio off by default.
poster="img.jpg"Image shown before play.
preload="none|metadata|auto"How much to buffer up front.
playsinlineiOS: don't force fullscreen.

12 Tables

For tabular data only — not for layout. Use semantic structure for screen readers.

<table>

Container for tabular data.

<caption>

Title of the table. Always include.

<thead>

Header rows.

<tbody>

Body rows.

<tfoot>

Footer (totals) rows.

<tr>

Table row.

<th>

Header cell. Use scope.

<td>

Data cell.

<colgroup>

Groups columns for styling.

<col> VOID

Defines a column inside <colgroup>.

<table>
  <caption>Q3 Revenue by Region (in $M)</caption>
  <colgroup>
    <col span="1" style="background: #f1f5f9;">
  </colgroup>
  <thead>
    <tr>
      <th scope="col">Region</th>
      <th scope="col">Q3 2024</th>
      <th scope="col">Q3 2025</th>
      <th scope="col">Change</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">North America</th>
      <td>42.1</td>
      <td>48.6</td>
      <td>+15.4%</td>
    </tr>
    <tr>
      <th scope="row">EMEA</th>
      <td>31.8</td>
      <td>38.2</td>
      <td>+20.1%</td>
    </tr>
  </tbody>
  <tfoot>
    <tr>
      <th scope="row">Total</th>
      <td colspan="2">160.7</td>
      <td>+17.9%</td>
    </tr>
  </tfoot>
</table>
Common Mistake Don't use tables for page layout. They break responsive design, hurt screen reader UX, and complicate maintenance. Use CSS Grid or Flexbox.

13 Forms

The richest part of HTML. Native validation, input types, and accessibility all live here.

<form>

Form container. action, method, enctype.

<fieldset>

Groups related fields. Always pair with <legend>.

<legend>

Caption for a <fieldset>.

<label>

Caption for a form control. Use for + matching id.

<input> VOID

22+ type variants. The workhorse.

<button>

Submit, reset, or generic button. Type defaults to "submit".

<select>

Dropdown. Pair with <optgroup> + <option>.

<optgroup>

Group of options in a <select>.

<option>

Single <select> choice. Use value.

<textarea>

Multi-line text. Cols/rows + CSS resize.

<output>

Computed result. Live region for screen readers.

<progress> VOID

Progress of a task (0 → max). Indeterminate if no value.

<meter> VOID

Gauge: known range, current value.

<datalist> NEW

Autocomplete suggestions for <input>.

14 Interactive Elements

<details>

Disclosure widget. Open/close without JS.

<summary>

Summary for <details>. Always first child.

<dialog>

Modal or non-modal dialog. show() / showModal().

<menu>

List of commands. Context menus, toolbars.

<template>

Inert HTML for later cloning. Not rendered.

<slot>

Placeholder in shadow DOM. Named or default.

<!-- Disclosure (FAQ accordion) -->
<details>
  <summary>What is your return policy?</summary>
  <p>Items can be returned within 30 days...</p>
</details>

<details open>
  <summary>Shipping options</summary>
  <ul>
    <li>Standard: 5–7 days</li>
    <li>Express: 2–3 days</li>
  </ul>
</details>

<!-- Modal dialog -->
<dialog id="confirm">
  <form method="dialog">
    <p>Delete this file?</p>
    <menu>
      <button value="cancel">Cancel</button>
      <button value="delete">Delete</button>
    </menu>
  </form>
</dialog>
<button onclick="document.querySelector('#confirm').showModal()">
  Open dialog
</button>

<!-- Template for client-side rendering -->
<template id="card-tmpl">
  <article class="card">
    <h3></h3>
    <p></p>
  </article>
</template>
<script>
  const tmpl = document.querySelector('#card-tmpl');
  const clone = tmpl.content.cloneNode(true);
  clone.querySelector('h3').textContent = 'Hello';
  document.body.appendChild(clone);
</script>

15 Scripting

<!-- Inline script -->
<script>
  console.log('hello');
</script>

<!-- External, blocking (default) -->
<script src="app.js"></script>

<!-- External, deferred — runs after HTML parsed -->
<script src="app.js" defer></script>

<!-- External, async — runs when downloaded -->
<script src="analytics.js" async></script>

<!-- ES module (always deferred) -->
<script type="module" src="app.mjs"></script>

<!-- No-JS fallback -->
<noscript>
  <p>This app requires JavaScript.</p>
</noscript>

<!-- JSON-LD structured data -->
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "How to Bake Sourdough",
  "author": { "@type": "Person", "name": "Maya Kowalski" }
}
</script>

Script loading modes

ModeBlocks HTML parse?When runs
DefaultYes (download + exec)Immediately when reached
asyncNo (download) / Yes (exec)As soon as downloaded, in any order
deferNoAfter HTML parsed, in DOM order
type="module"NoImplicit defer, strict mode
Pro Tip Use type="module" + defer on all your scripts. Modules are always deferred, execute in DOM order, support imports natively, and run in strict mode. Default to this everywhere.

Common Mistake Don't put complex logic in inline on* handlers — they're hard to test and create global namespace pollution. Use them only for one-line demos and always pair with proper addEventListener in real apps.

Pro Tip The five rules of ARIA: (1) If you can use a native HTML element, do that instead. (2) Don't change native semantics. (3) All interactive ARIA elements must be keyboard-operable. (4) Don't use role="application" unless you really mean it. (5) All interactive elements need an accessible name.

19 Meta Tag Reference

The complete production-ready <head>. Steal this template.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">

  <!-- Primary -->
  <title>Page Title (50–60 chars) | Brand</title>
  <meta name="description" content="150–160 char summary.">
  <link rel="canonical" href="https://example.com/page">

  <!-- Robots -->
  <meta name="robots" content="index, follow, max-image-preview:large">
  <meta name="googlebot" content="notranslate">

  <!-- Open Graph (Facebook, LinkedIn, Slack) -->
  <meta property="og:type" content="article">
  <meta property="og:title" content="...">
  <meta property="og:description" content="...">
  <meta property="og:url" content="https://example.com/page">
  <meta property="og:image" content="https://example.com/og.png">
  <meta property="og:image:width" content="1200">
  <meta property="og:image:height" content="630">
  <meta property="og:site_name" content="Brand">
  <meta property="og:locale" content="en_US">
  <meta property="article:published_time" content="2025-03-12T09:00:00Z">
  <meta property="article:author" content="Maya Kowalski">

  <!-- Twitter Card -->
  <meta name="twitter:card" content="summary_large_image">
  <meta name="twitter:site" content="@brand">
  <meta name="twitter:creator" content="@author">
  <meta name="twitter:title" content="...">
  <meta name="twitter:description" content="...">
  <meta name="twitter:image" content="https://example.com/twitter.png">

  <!-- i18n -->
  <link rel="alternate" hreflang="en" href="https://example.com/page">
  <link rel="alternate" hreflang="es" href="https://example.com/es/page">
  <link rel="alternate" hreflang="x-default" href="https://example.com/page">

  <!-- Icons -->
  <link rel="icon" href="/favicon.ico">
  <link rel="icon" href="/favicon.svg" type="image/svg+xml">
  <link rel="apple-touch-icon" href="/apple-touch-icon.png">
  <link rel="manifest" href="/manifest.webmanifest">

  <!-- Theme -->
  <meta name="theme-color" content="#0f172a" media="(prefers-color-scheme: dark)">
  <meta name="theme-color" content="#ffffff" media="(prefers-color-scheme: light)">
  <meta name="color-scheme" content="dark light">

  <!-- Performance hints -->
  <link rel="preconnect" href="https://fonts.googleapis.com" crossorigin>
  <link rel="dns-prefetch" href="https://cdn.example.com">
  <link rel="preload" as="image" href="/hero.webp" fetchpriority="high">
  <link rel="preload" as="font" href="/fonts/inter.woff2"
        type="font/woff2" crossorigin>
  <link rel="modulepreload" href="/app.mjs">

  <!-- Structured data (JSON-LD) -->
  <script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "Article",
    "headline": "...",
    "image": "https://example.com/og.png",
    "datePublished": "2025-03-12",
    "author": { "@type": "Person", "name": "Maya Kowalski" }
  }
  </script>

  <!-- CSS & JS -->
  <link rel="stylesheet" href="/styles.css">
  <script src="/app.mjs" type="module" defer></script>
</head>
Exercise Take any web page you've built and audit its <head> against this template. Most pages are missing canonical, theme-color, or proper og:image dimensions. Add them — they're free wins for SEO and social sharing.

∎ Final Notes

This cheat sheet covers the elements and attributes you'll use 95% of the time. The HTML Living Standard has more — deprecated elements like <frame>, <center>, <font>, <marquee>, <blink>, and experimental ones like <portal> — but you should avoid them.

For the canonical reference, always check MDN Web Docs. For the spec itself, the WHATWG HTML Living Standard is the source of truth.

Three habits that will save you (1) Validate your HTML with the W3C validator. (2) Use semantic elements first, ARIA second. (3) Test with a keyboard — if you can't use it without a mouse, neither can your screen reader users.
