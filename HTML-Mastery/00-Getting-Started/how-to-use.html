1 Opening Files

This project is a collection of static .html files. They will open in any browser on any operating system without a server. There are three common ways to open them:

Double-click

Open the file's folder in your OS file manager and double-click. The file opens with your default browser using the file:// protocol. Great for reading.

Drag & drop

Drag the .html file onto an open browser window. Useful when your default browser differs from the one you develop in.

Live Server (recommended)

The VS Code Live Server extension serves the file over http://127.0.0.1:5500/ and auto-refreshes on save. Covered in detail below.

CLI

Run python -m http.server or npx serve inside the project folder for a quick local server.

Common Mistake Some features (like fetch() of local JSON, ES modules, or video with captions) won't work over file:// due to browser security rules. Get in the habit of using Live Server for everything.

3 Doing Exercises

Every page ends with one or more Try it yourself blocks. These are not optional. Reading about a <form> is not the same as typing one. The exercises are designed to be doable in 5–15 minutes each.

How to make the most of exercises

  • Type the code by hand. Don't copy-paste. The act of typing — and the small typos you'll make and fix — is where learning happens.
  • Break it on purpose. After you get a working example, deliberately remove a tag, misspell an attribute, or nest things wrongly. Watch what the browser does. This builds a mental model of error recovery.
  • Keep an "experiments" folder. A junk drawer of test1.html, form-playground.html, etc. Refer back to it later.
  • Solve before peeking. If an exercise shows a solution, try it yourself first. Only reveal the answer when you're stuck for 10+ minutes.
Try it yourself — 5 minutes Create a file called first-exercise.html. Reproduce this exact structure from memory: 
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>My First Exercise</title>
</head>
<body>
  <h1>I did it!</h1>
  <p>Typed by hand.</p>
</body>
</html>
Open it in your browser. Modify the <h1> text, save, refresh. Notice the instant feedback loop — that's the magic of web development.

4 Browser Dev Tools

Every modern browser ships with a powerful set of developer tools. They are your X-ray vision into the page. Open them now in any browser with:

OSChrome / EdgeFirefoxSafari
Windows / LinuxF12 or Ctrl+Shift+IF12 or Ctrl+Shift+I—
macOS⌘+⌥+I⌘+⌥+I⌘+⌥+I (enable in Settings → Advanced → Show Develop menu first)
Right-click any element →Inspect — opens DevTools focused on that element.

The five panels you'll use most

Elements

Live, editable DOM tree. Click an element to see its computed styles, accessibility properties, and event listeners. Edit HTML/CSS in place and see results instantly.

Console

Run JavaScript, see errors and warnings. console.log($0) logs the currently-inspected element.

Network

See every file the page requested — HTML, CSS, JS, images — with timing and size. Invaluable for performance work.

Application

Inspect storage: localStorage, sessionStorage, cookies, service workers. Essential for forms and progressive web apps.

Lighthouse

One-click audit for performance, accessibility, best practices, and SEO. Run it on every project you build.

Accessibility panel

See the accessibility tree, ARIA attributes, and contrast issues. Found under Elements → Accessibility in Chrome and Firefox.

Pro Tip In the Elements panel, click the :hov button to force :hover, :focus, :active states without actually triggering them. Critical for testing keyboard and touch UX.

5 Validating Your HTML

Valid HTML is HTML that conforms to the WHATWG / W3C specification. Validity is not the same as correctness — but invalid HTML is almost always wrong, and browsers' error-recovery behaviour is unpredictable. Validate early, validate often.

Three ways to validate

  1. The W3C Validator. Visit validator.w3.org and paste your HTML, upload a file, or give a URL. The gold standard.
  2. Browser extension. Install the "Web Developer" browser extension to validate with one click from any page.
  3. VS Code extensions. HTMLHint and vscode-htmlhint flag issues inline as you type.
Common Mistake Don't treat the validator as an annoying gatekeeper. It is a teacher. Every error it raises is a chance to learn a rule you didn't know. Read the message, understand it, fix it, move on. 
Common validator messages and what they mean:

ERROR: Element "img" is missing required attribute "src"
  → You forgot the most important attribute on an <img>.

ERROR: Stray end tag "p"
  → You closed a <p> that wasn't open. Likely a nesting issue.

ERROR: Bad value "fr" for attribute "lang" on element "html"
  → Typo. The correct value is "fr" (it actually IS valid — example of a false alarm).

WARNING: Section lacks heading. Consider using "h2"–"h6"
  → A <section> should generally have a heading for accessibility.

INFO: Trailing slash on void elements has no effect
  → <br /> is fine but unnecessary in HTML5. Pick a style and be consistent.

6 VS Code Setup

Visual Studio Code is a free, open-source editor from Microsoft. It has become the de facto standard for web development. The setup below takes about 5 minutes and will dramatically improve your quality of life.

Step 1 — Install VS Code

Download from code.visualstudio.com and install for your platform. Launch it once.

Step 2 — Install essential extensions

ExtensionWhy
Live Server (Ritwick Dey)Serves files over HTTP, auto-refreshes on save.
HTML CSS SupportAutocompletes class names from your CSS files.
Auto Rename TagWhen you rename <div>, automatically renames </div>.
PrettierFormats your HTML on save — no more arguing about indentation.
HTMLHintInline HTML linting.
Path IntellisenseAutocompletes file paths in href and src attributes.

Step 3 — Configure formatting on save

Open VS Code Settings (JSON) and add:

{
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "html.format.wrapLineLength": 100,
  "html.format.wrapAttributes": "auto",
  "files.associations": {
    "*.html": "html"
  },
  "emmet.triggerExpansionOnTab": true
}

Step 4 — Use Emmet (built-in!)

Emmet is a built-in abbreviation engine. Type these and press Tab:

!            → full HTML5 boilerplate
ul>li*5      → <ul> with 5 <li> children
a:link       → <a href="http://"></a>
img          → <img src="" alt="" />
div.card*3   → three divs with class="card"
nav>ul>li*4>a   → navigation list pattern
Pro Tip Type ! in an empty .html file and press Tab. VS Code generates the entire boilerplate. Memorise it anyway — knowing what's in the boilerplate is more important than having it generated.

7 Browser Choice

For learning HTML, you want two browsers installed: your primary dev browser and one secondary browser for cross-testing.

Chrome / Edge (Chromium)

Best dev tools, most-used engine, ~65% market share. Pick as your primary dev browser.

Firefox

Independent engine. Excellent accessibility inspector and CSS tools. The Chromium antidote.

Safari (macOS only)

iOS / iPadOS engine. Test here before shipping — it has quirks Chromium doesn't.

Optional: Edge, Brave, Arc

Chromium-based. Useful to verify that a behaviour is Chromium-wide vs Chrome-specific.

Pro Tip Install Firefox Developer Edition — it ships with experimental dev tools and the most thorough accessibility tree in the business.

9 Your Daily Workflow

Once you're set up, a typical 30-minute study session looks like this:

  1. Open the project folder in VS Code.
  2. Right-click today's .html file → Open with Live Server.
  3. Read the page in the browser first — it renders the way the curriculum intends.
  4. Switch to VS Code to view the source. Follow along by editing a copy.
  5. Complete every "Try it yourself" exercise in your copy.
  6. Run the W3C validator on your exercise output.
  7. Open DevTools → Elements and inspect the DOM. Compare it to the page's source — notice how the browser has normalised your HTML.
  8. Click the Prev / Next links at the bottom of the page to advance.
Pro Tip Use the Ctrl+` shortcut to open VS Code's integrated terminal. Run python -m http.server 8000 for an instant dev server even without the Live Server extension.
